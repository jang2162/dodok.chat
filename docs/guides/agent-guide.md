# 에이전트 가이드 — dodok 채널에서 에이전트 쓰기

에이전트를 채널에 넣어 쓰는 사람을 위한 문서다. 에이전트가 매 턴 무엇을 받는지, 다른 에이전트에게 어떻게 일을 넘기는지, 카드(components v1)·파일·승인이 어떻게 오가는지를 적고, 끝에 **에이전트 지시 파일과 채널 프롬프트에 그대로 붙여 넣을 블록**을 둔다.

플러그인은 이 사용법을 에이전트에게 따로 주입하지 않는다. 에이전트가 매 턴 받는 것은 아래 「에이전트가 받는 것」의 헤더와 채널 프롬프트뿐이고, 카드 쓰는 법은 `message` 툴 스키마의 짧은 설명(`packages/openclaw-plugin/src/components-schema.ts` 의 `COMPONENTS_DESCRIPTION`)에만 있다. 나머지는 「붙여 넣을 블록」을 에이전트 쪽에 넣어야 에이전트가 안다.

설치(서버·플러그인·브리지 토큰)는 `docs/guides/deploy.md` 가 정본이다. 이 문서의 동작 서술이 코드와 다르면 코드가 맞다 — 절마다 정본 파일을 적어 둔다.

## 에이전트가 받는 것

### 세션

에이전트는 **채널마다 세션 하나**를 갖는다 — 세션 키 `agent:<OpenClaw agentId>:dodok:channel:<channelId>`. 같은 채널 안의 대화는 세션 기억으로 이어지고, 다른 채널의 대화는 서로 모른다.
스레드 안에서는 **스레드마다 세션이 따로** 있다 — `…:thread:<루트 메시지 id>`(아래 「스레드」). 키는 서버가 만든다(`packages/shared/src/session-key.ts` 의 `dodokSessionKey`).
「새 대화」(채널 설정의 에이전트 줄, 또는 작성기에서 `/new @에이전트`)는 그 채널의 그 에이전트 세션을 리셋한다 — 툴 결과·긴 대화 같은 세션 기억이 사라지고 다음 턴이 새 세션으로 시작한다.

### 매 턴의 인바운드 — 컨텍스트 헤더 + 메시지

사람이 멘션하거나 릴레이·카드가 에이전트를 부르면, 플러그인이 메시지 앞에 **컨텍스트 헤더**를 붙여 Gateway 로 넣는다(`packages/openclaw-plugin/src/context.ts` 의 `formatInboundContext`). 모양은 이렇다.

```text
[dodok context] channel=01999f0e-7c1a-7b3e-9c2d-5a1f0e2b3c4d you=@dev
참여자: @owner(사람), @dev(에이전트, 나), @fin(에이전트)
릴레이 규칙: 다른 에이전트에게 일을 넘길 때만 @핸들을 쓰세요 — @멘션하면 그 에이전트가 이어받습니다(최대 4턴). 언급만 할 때는 @ 없이 이름만 쓰세요.
최근 대화:
[04:12] @owner: 지난주 배포 로그 정리해 줘
[04:13] @fin: 비용 쪽은 제가 볼게요
[이미지 1장]
---
@dev 장애 부분만 요약해 줘
```

- **`---` 아래가 지금 받은 메시지**다. 위는 모두 문맥이다.
- **참여자**는 그 채널에 참여한 사람과 채널에 넣은 에이전트의 핸들이다. 헤더에는 핸들만 있고 사용자 id 는 없다.
  - 사람은 워크스페이스에 여럿일 수 있지만(초대로 들인 멤버 — `docs/guides/deploy.md` 「멤버 초대·비밀번호 재설정·내보내기」 절) **그 채널에 한 번이라도 쓰거나 그 채널에서 멘션된 사람만** 실린다 — 채널을 읽기만 한 사람은 없다. 내보낸(나간) 사람은 빠진다.
  - 에이전트가 쓴 `@사람핸들` 은 이 참여자 목록으로만 풀린다 — 참여자가 아닌 사람을 불러도 그 사람에게 알림이 가지 않는다.
- **릴레이 규칙**은 채널의 릴레이 정책에서 만든 한 문단이다(서버 `apps/server/src/modules/runs/context.ts` 의 `relayRulesFor`). 괄호 안 턴 수는 채널의 「턴 상한」이다. 쌍 허용을 좁혀 두면 끝에 「당신이 부를 수 있는 에이전트: @fin.」 또는 「당신은 다른 에이전트를 부를 수 없습니다.」가 붙는다.
- **최근 대화**는 트리거 메시지 **앞**의 일반 메시지를 최대 20개(`RECENT_MESSAGES_MAX`) 싣는다. 시스템 메시지(릴레이 한도·실패 알림 등)는 들어가지 않는다. 시각은 **UTC** 의 `HH:MM` 이다. 첨부는 `[이미지 N장]`·`[파일: 이름]` 자리표시로만 적고 경로·URL 은 쓰지 않는다.
- 트리거 메시지에 붙은 첨부는 본문과 따로 온다 — 「파일·이미지」 절.
- 카드를 눌러 생긴 턴은 메시지 자리에 `[dodok interaction] …` 줄이 온다 — 「누른 결과가 다음 턴에 오는 글」.
- 스레드 안의 턴은 첫 줄에 `thread=` 가 붙고 「최근 대화」 대신 스레드 루트와 스레드 최근 메시지가 온다 — 「스레드」 절.
- 채널의 「최근 대화」에는 스레드 답글이 들어가지 않는다 — 채널 세션은 스레드에서 오간 말을 모른다.

### 채널 프롬프트와 채널 지시

채널에 적은 프롬프트는 헤더가 아니라 OpenClaw 의 채널 메타데이터(`ChannelPromptContext`)로 그 턴에 붙는다(`context.ts` 의 `channelPromptContext`).

```text
채널 프롬프트: <채널 설정의 「채널 프롬프트」>
채널 지시: <채널 설정 멤버 줄의 「채널 프롬프트 오버라이드」 — 이 에이전트에게만>
```

| 무엇 | 어디서 적나 | 에이전트에게 닿는 길 | 언제 반영되나 |
| --- | --- | --- | --- |
| 채널 프롬프트 | 채널 설정 「채널 프롬프트」 | ① Gateway 채널 설정 `systemPrompt` → **새 세션의 시스템 프롬프트** ② 세션이 시작된 뒤 채널 프롬프트·릴레이 정책·채널 지시 중 무엇이든 바뀌었으면 매 턴 `채널 프롬프트:` 항목 | 새 세션은 처음부터. 이미 도는 세션은 다음 턴부터 `채널 프롬프트:` 항목으로 — 시스템 프롬프트는 세션이 시작될 때의 값 그대로다 |
| 채널 지시 | 채널 설정 멤버 줄 「채널 프롬프트 오버라이드」 | 매 턴 `채널 지시:` 항목 | 다음 턴부터 |
| 에이전트 지시 파일(`AGENTS.md`) | Gateway 호스트의 에이전트 작업 공간 | OpenClaw 가 세션을 시작할 때 읽는다 | 새 세션부터 — 고친 뒤 「새 대화」 |
| 에이전트의 「기본 프롬프트」 | 설정 → 에이전트 | **닿지 않는다** — 서버에 저장되고 목록에 보일 뿐, 인바운드 어디에도 싣지 않는다 | — |

- **시스템 프롬프트가 세션 시작 때 고정되는 까닭** — 1차 백엔드(claude-cli)는 채널 `systemPrompt` 를 CLI 세션이 처음 만들어질 때 고정한다. 설정을 바꿔도, Gateway 를 재시작해도 이미 도는 세션에는 들어가지 않는다. 그래서 서버가 세션마다 「시작 때의 리비전」을 기억해 두고, 달라졌으면 `채널 프롬프트:` 항목으로 현재 값을 싣는다(ADR 0003 「채널 프롬프트 주입 경로」 절).
- **행동 규칙을 바꿨으면 「새 대화」가 확실하다.** 실측은 사실 회상 실험에서 이 항목이 낡은 시스템 프롬프트를 이긴다는 것까지였다. 말투·금지 같은 행동 규칙에서 시스템 프롬프트만큼 권위를 갖는지는 재지 않았다. 채널 설정 화면도 저장할 때 같은 안내(「이미 진행 중인 대화에 온전히 반영하려면 에이전트별 「새 대화」를 누르세요」)를 띄운다.
- 채널 프롬프트·채널 지시는 각각 20,000자까지다(`packages/shared/src/domain/index.ts` 의 `Channel.prompt`·`ChannelMember.promptOverride`).

## 채널 프롬프트 쓰는 법

채널 프롬프트는 **그 채널의 일**을 적는 자리다 — 목적, 범위, 결과물의 모양, 누가 무엇을 맡고 누구에게 넘기는가. dodok 자체의 사용법(멘션·카드·파일 규칙)은 채널마다 되풀이하지 말고 에이전트 지시 파일에 한 번 넣는다(「붙여 넣을 블록」).

- **에이전트가 여럿이면 넘기는 방향을 적는다.** 「누가 끝나면 누구를 부른다」와 「누구는 다시 부르지 않는다」를 같이 적으면 릴레이가 핑퐁으로 번지지 않는다. 턴 상한·쌍 허용(채널 설정 「릴레이 정책」)이 뒤를 받치지만, 막히면 사람이 풀어야 한다.
- **에이전트마다 다른 말은 채널 지시로.** 채널 프롬프트는 채널의 모든 에이전트가 받는다. 한 에이전트에게만 줄 지시는 그 멤버 줄의 「채널 프롬프트 오버라이드」에 둔다.
- **사람에게 확인받을 지점을 적는다.** 「배포 전에는 버튼 카드로 묻는다」처럼 적어 두면 에이전트가 카드를 쓴다.
- **짧게.** 이미 도는 세션에서는 이 글 전체가 매 턴 다시 실린다.

**예 1 — 에이전트 하나, 운영 채널**

```text
이 채널은 운영 알림 채널이다. 사람이 장애·경보를 붙여 넣으면 원인 후보를 세 개 이내로 정리하고,
각 후보마다 확인할 명령이나 대시보드를 적는다. 되돌리기·재시작처럼 서비스에 영향을 주는 조치는
직접 하지 말고 버튼 카드(「진행」·「보류」)로 사람에게 묻는다. 답은 한국어, 제목 없이 목록으로.
```

**예 2 — 에이전트 둘, 조사 → 작성**

```text
이 채널은 주간 보고서를 만든다. @researcher 는 사람이 준 주제로 자료를 모아 핵심 사실과 출처를
목록으로 정리한 뒤, 마지막 줄에서 @writer 에게 넘긴다. @writer 는 넘겨받은 목록만으로 한 쪽짜리
초안을 쓰고, 끝나면 사람에게 확인을 받는다. @writer 는 @researcher 를 다시 부르지 않는다 —
자료가 모자라면 무엇이 모자란지 사람에게 적는다.
```

채널 설정 「릴레이 정책」에서 「모든 에이전트끼리 허용」을 끄고 `researcher → writer` 쌍 하나만 허용하면, 프롬프트를 어긴 역방향 멘션은 라우터가 막는다.

**예 3 — 양식으로 일을 받는 채널**

```text
이 채널은 디자인 요청 창구다. 사람이 요청하면 먼저 모달 카드 하나로 제목(필수)·설명·기한·크기(셀렉트)를
받는다. 제출이 오면 그 값으로 작업 계획을 세 줄로 요약하고, 계획대로 진행할지 버튼 카드로 묻는다.
```

## 릴레이 — 에이전트가 에이전트를 부를 때

정본: `apps/server/src/modules/router/decide.ts`(누가 런을 받나)·`router/service.ts`(막혔을 때의 시스템 메시지)·`packages/shared/src/domain/index.ts` 의 `RelayPolicy`.

### 누가 답하나

- **사람 메시지** — 멘션된 에이전트마다 런이 하나씩 생긴다. 멘션이 없으면 「자동 응답」을 켠 에이전트(채널에 하나) 하나가 받는다. 멘션한 에이전트가 모두 비활성이면 아무도 받지 않는다(자동 응답으로 넘어가지 않는다).
- **사람 멘션은 런을 만들지 않는다** — 사람이든 에이전트든 `@사람핸들` 을 쓰면 그 사람에게 알림(푸시)만 간다. 에이전트 멘션 없이 사람만 멘션한 사람 메시지는 멘션이 없는 메시지와 같다 — 자동 응답 에이전트가 켜져 있으면 그 에이전트가 받는다. 사람 메시지가 멘션한 사람은 채널에 참여된다 — 다음 턴부터 「참여자:」에 실린다(에이전트의 멘션은 누구도 참여시키지 않는다).
- **에이전트 메시지** — 본문 속 `@다른에이전트` 가 **릴레이**다. 자기 자신 멘션은 무시한다.
- **멘션으로 읽히는 것** — `@핸들` 또는 채널에서 붙인 별칭. 대소문자를 가리지 않고, 앞이 줄 처음·공백·구두점이어야 한다. **백틱 코드(`` `@dev` ``)와 코드 블록 안은 멘션이 아니다.** 서술 속 `@핸들` 도 호출이 되므로, 언급만 할 때는 @ 없이 이름을 쓰거나 백틱으로 감싼다(`packages/shared/src/mention.ts` 의 `tokenize`).

### 릴레이가 멈추는 네 가지

에이전트 메시지의 멘션 대상마다 차례로 본다. 걸리면 그 대상은 런을 받지 않고 채널에 시스템 메시지가 남는다.

| 사유 | 조건 | 채널에 남는 글 | 이어가기 |
| --- | --- | --- | --- |
| 비활성 | 대상 에이전트를 사용 안 함으로 꺼 두었다 | 「@fin 은 비활성 상태입니다」 | 없음 |
| 쌍 허용 밖 | 「릴레이 정책」에서 `보낸 쪽 → 대상` 쌍을 허용하지 않았다 | 「@dev 는 @fin 을 부를 수 없습니다(허용 목록 밖)」 | 없음 |
| 턴 상한 | 사람 메시지에서 시작한 사슬의 릴레이 깊이가 「턴 상한」(기본 4, 0~32 — 0 이면 릴레이 없음)을 넘는다 | 「릴레이 한도(4턴)에 도달했습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 | 있음 |
| 반복 | 같은 사슬에서 같은 `보낸 쪽 → 대상` 에게 같은 본문(멘션을 빼고 공백·대소문자를 정리한 앞 300자)이 이미 갔다 | 「같은 내용의 릴레이가 반복되어 멈췄습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 | 있음 |

- **이어가기** — 턴 상한·반복 메시지의 1회용 「이어가기」 버튼. 누르면 막혔던 대상 에이전트에게 런이 간다. 그 런의 메시지는 카드를 누른 것과 같은 꼴이고(`… item=continue_relay` + 「@owner 님이 "이어가기" 버튼을 눌렀습니다.」), 최근 대화에는 막힌 지점까지의 대화가 들어 있다. 사슬 깊이는 0 에서 다시 센다.
- 사람이 직접 멘션해도 새 사슬이 시작된다(깊이 0).
- **Gateway 의 봇 루프 보호** — 플러그인은 에이전트가 쓴 인바운드에 OpenClaw 코어의 봇 루프 보호 사실을 넘긴다. 코어 예산을 넘기면 그 인바운드는 런 없이 떨어지고 채널에 「@fin 이 봇 루프 보호로 메시지를 받지 않았습니다」가 남는다(다시 실행 버튼 없음). 예산은 Gateway 쪽 채널 설정이다(ADR 0002 「봇 루프 보호」 절).

### 일일 런 한도

런을 만드는 모든 길 — 사람 멘션·자동 응답·릴레이·카드 상호작용·이어가기·다시 실행 — 이 한 관문(`apps/server/src/modules/ops/budget.ts` 의 `createRunGate`)을 지난다.

- **워크스페이스 한도** — 기본 300(`OPS_DEFAULT_DAILY_RUN_LIMIT`), 운영 화면(`/settings/operations`)의 한도에서 바꾸고 비우면 무제한. **채널 한도** — 채널 설정 「릴레이 정책」의 「일일 실행 상한」. 둘 다 있으면 워크스페이스를 먼저 본다.
- 막히면 채널에 「오늘 런 한도(300)에 도달했습니다 — 내일 0시에 풀립니다」(채널 한도면 앞에 「이 채널의 」)가 범위마다 하루 한 번 남는다. 「하루」는 서버 `TZ` 의 자정이다.
- 한도에 막힌 카드 버튼은 **소비되지 않는다** — 한도가 풀린 뒤 다시 누르면 된다.

### 실패와 다시 실행

런이 타임아웃·어댑터 끊김·프로토콜 오류로 실패하면 채널에 「@dev 실행이 실패했습니다: TIMEOUT」 꼴의 시스템 메시지와 1회용 「다시 실행」 버튼(24시간)이 남는다. 다시 실행은 **트리거 메시지가 있는 런**에만 붙는다 — 카드 상호작용·이어가기로 생긴 런은 다시 만들 트리거가 없다. 릴레이 런을 다시 실행할 때는 쌍 허용을 지금 정책으로 다시 본다(턴 상한·반복은 다시 보지 않는다).

## 스레드

사람은 아무 채널 메시지(사람·에이전트 메시지 모두)에서 스레드를 열어 그 안에서 대화한다. 스레드 안의 스레드는 없고, 에이전트가 스레드를 스스로 열지는 못한다.
정본: 서버 `apps/server/src/modules/router/decide.ts`(누가 답하나)·`runs/context.ts`(스레드 문맥)·플러그인 `packages/openclaw-plugin/src/context.ts`(헤더)·`outbound.ts`(스레드 밖 전송 거절), 설계 `docs/superpowers/specs/2026-09-25-threads-search-design.md`.

### 스레드 세션은 따로다

- 스레드 안의 에이전트는 **스레드마다 하위 세션**으로 답한다 — 세션 키 `agent:<agentId>:dodok:channel:<channelId>:thread:<루트 메시지 id 소문자>`. 채널 세션·다른 스레드 세션과 기억을 나누지 않는다.
- 그래서 **채널 런과 스레드 런은 동시에 돈다**(같은 에이전트라도). 같은 스레드의 두 멘션은 차례로 돈다.
- 채널 프롬프트·채널 지시는 채널과 같다. 채널 `systemPrompt` 도 스레드 세션이 새로 시작될 때 들어간다.
- 「새 대화」는 스레드 패널의 에이전트 줄(또는 스레드 작성기의 `/new @에이전트`)에서 **그 스레드의 그 에이전트 세션만** 리셋한다. 채널 세션은 그대로다. 채널 쪽 「새 대화」도 스레드 세션을 건드리지 않는다.

### 스레드에서 받는 헤더

스레드 턴의 헤더는 채널 턴과 같고 두 가지가 다르다 — 첫 줄에 `thread=<루트 id>`, 그리고 「최근 대화」 대신 **스레드 루트**와 **스레드 최근**이 온다. 채널에서 오간 대화는 싣지 않는다.

```text
[dodok context] channel=01999f0e-7c1a-7b3e-9c2d-5a1f0e2b3c4d thread=01999f10-2b4c-7d1e-8f3a-6b2c1d0e9f8a you=@dev
참여자: @owner(사람), @dev(에이전트, 나), @fin(에이전트)
릴레이 규칙: 다른 에이전트에게 일을 넘길 때만 @핸들을 쓰세요 — @멘션하면 그 에이전트가 이어받습니다(최대 4턴). 언급만 할 때는 @ 없이 이름만 쓰세요.
스레드 루트: [04:12] @dev: 지난주 배포 장애 세 건을 정리했습니다. …
스레드 최근:
[04:20] @owner: 두 번째 건 원인이 뭐였지?
---
@dev 두 번째 건 로그 더 자세히 봐 줘
```

- **스레드 루트**는 스레드를 연 메시지다. 본문은 4,000자에서 자른다(`THREAD_ROOT_TEXT_MAX`).
- **스레드 최근**은 트리거 앞의 그 스레드 일반 메시지 최대 20개다(`RECENT_MESSAGES_MAX` — 채널과 같은 상한). 시각·첨부 자리표시 규칙은 채널과 같다.
- 채널 대화가 필요하면 루트가 담는다 — 스레드는 채널의 소음과 떨어지려고 연다.

### 누가 답하나

- **사람 답글** — 멘션된 에이전트마다 그 스레드에서 런. 멘션이 없으면 ① 루트가 에이전트 메시지면 그 에이전트(활성·채널 멤버일 때) ② 아니면 채널의 자동 응답 에이전트. 「에이전트 답에 이어서 묻기」는 멘션 없이 스레드에 쓰면 된다.
- **에이전트 답글의 `@다른에이전트`** — 같은 스레드 안의 릴레이다. 릴레이 런도 그 스레드의 세션이다. 턴 상한·반복 감지·쌍 허용은 채널과 같고, 막히면 한도 메시지·「이어가기」도 그 스레드에 남는다.
- 스레드 런도 일일 런 한도를 쓴다. 한도 알림은 막힌 곳(스레드면 스레드)에 남되 **채널마다 하루 한 번**이라, 그날 첫 알림이 스레드에 남았으면 최상위에는 다시 남지 않는다.
- 카드 버튼·셀렉트·모달, 「이어가기」, 「다시 실행」이 스레드 안 메시지에 있으면 새 런도 그 스레드다.

### 스레드에서 보내는 것 — 최상위로 보내지 못한다

- 그냥 쓴 답·`message` 툴 전송·`MEDIA:` 파일·카드는 모두 **그 스레드**에 올라간다. 모델이 `threadId` 를 따로 넣을 필요는 없다.
- **스레드 세션의 에이전트는 채널 최상위나 다른 스레드·다른 채널로 보내지 못한다.** 그런 `message` 툴 호출(`to` 가 다른 채널이거나 `threadId` 가 이 스레드가 아닌 값)은 보내지지 않고 툴 오류 `dodok: 이 대화는 스레드라 이 스레드에만 보낼 수 있습니다` 로 돌아온다. 채널 전체에 알릴 일이면 스레드에 그렇게 쓰고 사람이 올리게 한다.
- 채널 세션에서 `threadId` 인자를 줘도 스레드로 가지 않는다 — 채널 세션의 전송은 채널 최상위다.

### 플러그인이 옛 판이면

스레드 런은 **스레드를 아는 플러그인**(hello 에 `threads`)이 붙어 있어야 돈다. 옛 플러그인이 붙어 있으면 스레드 멘션은 에이전트가 돌지 않고(런은 `PLUGIN_OUTDATED` 오류로 곧바로 끝난다) 스레드에 「@dev 가 스레드에서 답하지 못했습니다 — 플러그인을 새로 설치해야 합니다(연결 페이지)」 카드와 「다시 실행」 버튼을 남긴다. 채널 멘션은 그대로 돈다. 설치는 `docs/guides/deploy.md` 「업데이트」 절.

## components v1 — 카드로 묻고 받기

정본: 제약 값은 `packages/shared/src/components/index.ts` 의 `ComponentsV1`, 모델에게 가는 설명은 `packages/openclaw-plugin/src/components-schema.ts`, 누른 결과의 글은 `apps/server/src/modules/components/interact.ts` 의 `formatInteractionText`. 설계는 `docs/superpowers/specs/2026-09-21-components-v1-design.md`.

이 절의 `json dodok-components` 예시는 `packages/shared/test/agent-guide-examples.test.ts` 가 뽑아 `ComponentsV1` 로 파싱한다 — 유효 예시는 통과해야 하고 모르는 키가 없어야 한다(`ComponentsV1` 은 오타 키를 오류 없이 버린다). 틀린 예는 펜스 정보 문자열 뒤에 적어 둔 경로·코드의 위반 **하나만**으로 실패해야 한다(`json dodok-components-invalid <경로> <Zod issue 코드>`). 위반이 둘 섞인 예는 한 규칙이 풀려도 다른 위반 때문에 계속 실패해 아무것도 지키지 않는다.

### 보내는 법

카드는 **`message` 툴**(action `send`)의 `components` 인자로만 보낸다. 최종 답(그냥 쓴 글)에는 카드를 실을 수 없다.

```json dodok-message
{
  "action": "send",
  "message": "배포 방식을 골라 주세요.",
  "components": {
    "blocks": [
      {
        "type": "actions",
        "items": [
          { "type": "button", "id": "deploy_now", "label": "지금 배포", "style": "primary" },
          { "type": "button", "id": "deploy_later", "label": "나중에" }
        ]
      }
    ]
  }
}
```

- `to` 는 비워 두면 지금 채널이다.
- `message` 는 카드 위의 본문이다. 비워도 되지만 카드가 무엇을 묻는지 한 줄 적어 둔다 — 다음 턴의 최근 대화에는 메시지 **글만** 실리고 카드 내용은 실리지 않는다.
- **같은 채널로 `message` 툴을 쓴 런은 최종 텍스트 답이 채널에 올라가지 않을 수 있다** — Gateway 판에 따라 갈린다. OpenClaw 2026.9.4 는 그 답을 억제한다(`docs/adr/0002-channel-plugin-spike.md` 「`message` 툴 — `describeMessageTool` 과 `handleAction`」 절) — 오류가 나지 않아 사라진 줄도 모른다. 2026.9.5 는 억제하지 않아 최종 답이 **따로 한 메시지로** 올라온다(채널·스레드 모두 — `docs/guides/live-smoke.md` 「스레드(Phase 4 ①) 실연」 절). 어느 판이든 맞게: 카드와 함께 전할 말(설명·질문·다음 단계)은 `message` 본문에 다 적고, 최종 답은 짧은 한 줄로 둔다(9.5 에서는 그 줄도 채널에 보인다).
- 스키마를 어기면 툴 호출이 `components: v1 스키마 위반 — <경로> <사유>` 오류로 돌아온다(앞 다섯 개). 고쳐서 다시 보낸다.
- **`ask_user` 를 쓰지 않는다.** OpenClaw 의 `ask_user` 는 dodok 채널에서 선택지를 그리지 못하고 전달도 실패한다(`docs/plan.md` 「이월」의 「결함 2(`ask_user`)」). 실측에서 모델은 「셀렉트로 물어봐 줘」 같은 요청에 `ask_user` 를 먼저 골랐다(`docs/guides/live-smoke.md` 「components v1(Phase 2 ②) 실물 확인」 절) — 붙여 넣을 블록이 이것을 막는다.

### 카드의 모양과 제약

카드 최상위:

| 필드 | 뜻 | 제약 |
| --- | --- | --- |
| `blocks` | 위에서 아래로 그리는 블록 | 0~10개 |
| `modal` | 양식 하나 — 카드에 `triggerLabel` 버튼으로 붙는다 | 카드당 1개 |
| `reusable` | `false`(기본) 1회용 · `true` 재사용 | — |
| `ttlMs` | 만료까지 밀리초 | 1,000 ~ 86,400,000(24시간), 기본 1,800,000(30분) |
| `text` | 대체 텍스트 | 2,000자. 지금 웹·푸시는 쓰지 않는다 — 카드의 제목·설명은 `message` 본문이나 `section` 에 |

블록 다섯 종:

| 블록 | 필드 | 제약 |
| --- | --- | --- |
| `section` | `text`(마크다운 — 메시지 본문과 같은 렌더러) | 1~2,000자 |
| `separator` | — | — |
| `actions` | `items`, 선택 `id` | **버튼 1~5개 또는 셀렉트 정확히 1개** — 한 블록에 섞지 않는다 |
| `media` | `items: [{ url, alt? }]` | 1~10개, `alt` 200자 |
| `file` | `url`, `name`, 선택 `size` | `name` 1~255자 |

아이템:

- **버튼** — `id`, `label`(1~80자), `style`(`primary`·`secondary`(기본)·`success`·`danger`), `emoji`(8자), `url`(있으면 **링크 버튼** — 새 탭으로 열고 상호작용은 없다), `allowedUsers`.
- **셀렉트** — `id`, `placeholder`(150자 — 결과 줄과 다음 턴의 글에서 이 셀렉트의 이름으로 쓰인다. 없으면 `id`), `multi`(기본 `false`), `minValues`(0~25)·`maxValues`(1~25), `options`(1~25개: `value`·`label` 각 1~100자, `description` 100자, `emoji`), `allowedUsers`. 웹은 단일·다중 모두 목록에서 고른 뒤 「보내기」로 확정한다.
- **모달** — `id`, `title`(1~45자), `triggerLabel`(1~80자 — 이 글의 버튼이 카드에 생겨 모달을 연다. **여는 버튼을 따로 만들지 않는다**), `fields`(**1~5개**), `allowedUsers`.
- **모달 칸** — 모두 `id`·`label`(1~45자)·`required`(기본 `false`). 종류별로 `text`(`placeholder` 100자·`minLength`·`maxLength` 4,000 이하·`default`) · `textarea`(`placeholder`·`maxLength`·`default`) · `number`(`min`·`max`·`step`·`default`) · `date`(`default` 는 `YYYY-MM-DD`) · `select`(`multi`·`options` 1~25개·`default` 는 값 배열) · `checkbox`(`default`) · `radio`(`options` **2~10개**·`default`). `checkbox` 의 `required` 는 아무것도 강제하지 않는다 — 체크하지 않은 채로도 제출된다.
- **id** — 블록 `id`·아이템 `id`·모달 `id`·칸 `id` 모두 `[a-z0-9_-]` 1~40자이고, **카드 안에서 겹치지 않는다.** 대문자·공백·한글은 안 된다.
- **`url`** — `https://` 또는 `artifact://` 만. `http://`·상대 주소는 스키마가 막는다.
- **`allowedUsers`** — 누를 수 있는 사람의 **사용자 id(UUID)** 목록(50개). 헤더에는 핸들만 있고 id 가 없으므로 에이전트는 대개 쓰지 않는다. 핸들(`"owner"`)을 넣으면 스키마 위반이다. 빈 배열은 제한 없음이다.

### 수명 — 1회용과 재사용

- **1회용**(기본)은 **아이템마다 한 번**이다. 누가 「지금 배포」를 누르면 그 버튼만 잠기고, 같은 카드의 다른 버튼은 살아 있다 — 다른 사람이 이어서 「취소」를 누를 수 있다. **여럿 중 하나만 받아야 하면 셀렉트 하나**로 묻는다(셀렉트는 한 번 제출하면 잠긴다). 모달도 한 번 제출하면 잠긴다.
- **재사용**(`"reusable": true`)은 몇 번이든 누를 수 있다. 누를 때마다 에이전트에게 런이 가니 일일 한도를 쓴다.
- **만료** — `ttlMs` 가 지나면 카드 전체가 잠긴다. 사람에게 시간이 필요한 질문이면 늘린다(최대 24시간).
- 누른 기록은 카드 안 **결과 줄**(「@owner — 보고서 형식: PDF」)로 남고 새로고침해도 보인다. 재사용 카드는 최근 20건까지 보인다.

### 누른 결과가 다음 턴에 오는 글

사람이 누르거나 제출하면 **그 카드를 보낸 에이전트**에게 새 런이 간다. 메시지 자리에 기계가 읽는 머리줄 하나와 사람이 읽는 본문이 온다. 최근 대화에는 그 카드 메시지까지의 대화가 들어 있다.

```text
[dodok interaction] user=@owner kind=button component=cmp_… item=deploy_now
@owner 님이 "지금 배포" 버튼을 눌렀습니다.
```

```text
[dodok interaction] user=@owner kind=select component=cmp_… item=report_format values=["pdf"]
@owner 님이 "보고서 형식"에서 PDF을 골랐습니다.
```

```text
[dodok interaction] user=@owner kind=modal component=cmp_… item=new_task
@owner 님이 "새 작업 등록" 양식을 제출했습니다.
- 제목: 9월 배포 회고
- 기한: 2026-09-30
- 우선순위: 높음
- 끝나면 알림: 예
```

- `item` 은 누른 버튼·셀렉트·모달의 `id` 다. 에이전트는 이 값으로 분기한다 — 그래서 id 는 뜻이 드러나게 짓는다.
- `values` 는 셀렉트가 고른 `value` 배열(JSON)이다. 본문에는 `label` 이 쓰인다.
- 모달은 채운 칸만 `- 라벨: 값` 줄로 온다. 셀렉트·라디오 칸은 `label`, 체크박스는 「예」·「아니요」.
- `component=cmp_…` 는 서버가 저장할 때 붙인 카드 id 다. 에이전트가 정하지 않는다(보내는 `components` 에 `id` 를 넣지 않는다).
- 카드를 보낸 에이전트가 그 사이 비활성이 되거나 채널에서 빠졌으면 누르기가 거절되고, 버튼은 잠기지 않는다.

### `artifact://` — 같은 메시지의 파일을 카드에서 가리키기

`media` 항목·`file` 블록·링크 버튼의 `url` 에 `artifact://<파일 이름>` 을 쓰면 **같은 `message` 호출에서 `media`·`mediaUrls` 로 보낸 파일**을 가리킨다. 모델은 첨부 id 를 모르므로 이름으로 가리킨다(이름은 「파일·이미지」 절의 이름 규칙대로 정해진다).

```json dodok-message
{
  "action": "send",
  "message": "9월 매출 요약입니다.",
  "mediaUrls": ["/srv/openclaw/workspace/out/sales-chart.png", "/srv/openclaw/workspace/out/sales-report.pdf"],
  "components": {
    "blocks": [
      { "type": "media", "items": [{ "url": "artifact://sales-chart.png", "alt": "9월 매출 그래프" }] },
      { "type": "file", "url": "artifact://sales-report.pdf", "name": "9월 매출 보고서.pdf" }
    ]
  }
}
```

- 카드가 가리킨 파일은 카드 안에만 그려지고, 메시지 아래 첨부 목록에 한 번 더 그려지지 않는다.
- 이름에 공백이 있어도 그대로 쓴다 — 플러그인이 검증 전에 인코딩한다(`packages/openclaw-plugin/src/outbound.ts` 의 `encodeArtifactWhitespace`).
- **다른 메시지의 첨부는 가리킬 수 없다.** 못 찾으면 그 자리에 「첨부를 찾을 수 없습니다」가 보인다.
- `https://` 이미지는 보는 사람의 브라우저가 그 호스트에서 직접 불러온다(보는 사람의 IP·시각이 그 호스트에 남는다). 에이전트가 만든 이미지는 `artifact://` 로 보내는 편이 낫다.

## 파일·이미지

정본: 한도는 `packages/shared/src/domain/index.ts` 의 `ATTACHMENT_LIMITS`, 플러그인 쪽은 `packages/openclaw-plugin/src/inbound-media.ts`·`outbound-media.ts`. 설계는 `docs/superpowers/specs/2026-09-23-attachments-design.md`.

### 받기

- 사람은 **이미지만** 올린다 — PNG·JPEG·GIF·WebP, 장당 5 MiB, 메시지당 10장.
- **트리거 메시지의 이미지**는 모델에게 이미지로 붙는다(플러그인이 받아 Gateway 미디어 저장소에 두고 넘긴다). 릴레이된 에이전트 메시지의 이미지도 다음 에이전트가 받는다.
- 이미지가 아닌 첨부(에이전트가 보낸 PDF 등)는 본문 끝에 `[첨부 파일: report.pdf]` 줄로만 온다 — **내용은 오지 않는다.**
- 이미지를 받지 못하면 그 장은 빠지고 본문 끝에 `[이미지를 불러오지 못했습니다: 이름]` 이 붙는다. 런은 막지 않는다.
- 최근 대화의 이전 메시지 첨부는 `[이미지 N장]`·`[파일: 이름]` 자리표시뿐이다. 그 턴에 이미지로 붙는 것은 트리거 메시지의 이미지다.

### 보내기 — 두 길

1. **`message` 툴** — `media`(하나) 또는 `mediaUrls`(여럿), 첫 파일의 표시 이름은 `filename`. 값은 Gateway 호스트의 경로 또는 `https://` URL 이다. 본문 없이 첨부만 보내도 된다. 이 길을 쓴 런은 최종 답이 채널에 안 올라갈 수 있으니(「components v1」 절의 「보내는 법」) 파일과 함께 할 말은 그 호출의 본문에 쓴다. **하나라도 실패하면 툴 호출이 실패로 돌아온다** — `dodok: 첨부를 보내지 못했습니다 — report.pdf: 20 MiB 초과` — 고쳐서 다시 보낸다.
2. **최종 답의 `MEDIA:` 줄** — OpenClaw 관례대로 답에 `MEDIA:<경로 또는 URL>` 줄을 **따로 한 줄로** 둔다. Gateway 가 그 줄을 첨부로 뽑아 글에서 빼고, 서버도 스트리밍 글에서 그 줄을 한 번 더 걷는다 — 줄 자체는 채널에 남지 않는다. 모델에게 실패를 돌려줄 길이 없어 실패하면 본문 끝에 `_첨부 1개를 보내지 못했습니다: report.pdf (20 MiB 초과)_` 가 붙는다.

- **한도** — 파일당 20 MiB(Gateway 쪽 플러그인 계정 설정 `mediaMaxMb` 로 1~20 사이에서 더 낮출 수 있다), 메시지당 10개.
- **보이는 모양** — 서버가 내용의 첫 바이트로 판별한다. PNG·JPEG·GIF·WebP 는 이미지 격자(크게 보기 됨), 그 밖(SVG 포함)은 파일 카드(내려받기)다.
- **이름** — 모델이 준 이름(`filename`) → 로더가 알려 준 이름 → 경로의 마지막 조각. 한 메시지 안에서 겹치면 확장자 앞에 ` (2)`.
- **실패 사유는 정해진 문구**다 — 「파일을 찾을 수 없음」·「허용되지 않은 경로」(Gateway 호스트의 파일 접근 정책이 막음)·「20 MiB 초과」(상한을 낮췄으면 그 값)·「파일을 읽지 못함」·「서버 상한 초과」·「서버가 거절함 (N)」·「서버에 올리지 못함」·「메시지당 10개 초과」. 원문(경로가 든)은 Gateway 로그에만 남는다.
- 어떤 경로를 읽을 수 있는지는 Gateway 호스트 설정(`tools.fs.workspaceOnly` 등)이 정한다 — `docs/guides/deploy.md` 「[웹 → B] 플러그인 설치·브리지 토큰」 절의 첨부 항목.

### 호스트 경로를 글에 쓰지 않는다

`/Users/…`·`/home/…`·`~/.openclaw…` 같은 Gateway 호스트 경로를 **답 본문에 쓰지 않는다.**

- 본문에 적은 경로는 채널 글·기록에 그대로 남아 채널의 모든 사람에게 Gateway 호스트 구조가 드러난다. 서버가 걷는 것은 **줄 머리의 `MEDIA:`** 뿐이다 — 문장 중간의 경로, 활동 탭에 보이는 툴 인자·결과의 경로는 걷지 않는다.
- 반대로 **보통 글 줄을 `MEDIA:` 로 시작하지 않는다**(대소문자 무관 — `Media:`·`media:` 도). 첨부가 아니어도 그 줄은 채널에서 사라진다.
- 파일을 보여 주려면 첨부로 보내고, 가리키려면 파일 이름만 쓴다.

## 승인 카드

정본: 설계 `docs/superpowers/specs/2026-09-20-activity-approvals-design.md`. 승인 정책(어떤 툴에 승인을 요구할지)은 OpenClaw 쪽 설정이고 dodok 에는 설정 화면이 없다 — 켜는 법의 예는 `docs/guides/live-smoke.md` 「승인(Phase 2 ①)을 실물에서 보기」 절.

- 에이전트가 승인이 필요한 툴을 부르면 런이 「승인 대기」로 멈춘다. 채널 흐름과 활동 탭에 같은 승인 카드가 뜬다 — 제목·심각도·툴 이름·인자·남은 시간, 버튼은 Gateway 가 허용한 결정만(「이번만 허용」·「항상 허용」·「거절」). 브라우저 알림·웹 푸시도 간다.
- **에이전트 쪽에서 일어나는 일** — 허용이면 툴이 그대로 돈다. 거절이면 툴이 오류 결과로 돌아온다. Gateway 가 정한 시간 안에 아무도 누르지 않으면 거절로 확정된다(카드에는 「만료됨」). 어느 쪽이든 런은 그 결과를 받아 이어 간다. 사람이 런을 중지하면 남은 승인은 취소된다.
- 승인을 기다리는 동안 런의 무응답 타임아웃은 멈춘다.
- 에이전트에게 줄 요령: 승인이 걸릴 만한 일(파일 쓰기·명령 실행)은 **먼저 채널에 무엇을 왜 하려는지 한 줄 쓰고** 부른다 — 카드의 인자만 보고는 사람이 판단하기 어렵다. 거절되면 같은 호출을 곧바로 되풀이하지 말고 이유를 묻는다. 그 한 줄을 `message` 툴로 알렸으면 결과도 `message` 로 알린다 — 그 런의 최종 답은 채널에 안 올라갈 수 있다(「components v1」 절의 「보내는 법」).

## Claude 러너 에이전트

에이전트 목록에서 제공자가 「Claude 러너」인 에이전트는 OpenClaw 를 거치지 않는다 — 사람의 머신에서 도는 러너가 Claude Agent SDK 로 Claude Code 를 그 머신의 작업 디렉터리에서 돌린다(설치는 `docs/guides/deploy.md` 「Claude 러너 설치」 절). 채널에서의 쓰임(멘션·릴레이·일일 한도·스레드·카드 누르기·「새 대화」·「다시 실행」)은 위 절들과 같고, **받는 모양과 보내는 도구가 다르다.** 세션 키도 같은 꼴(`agent:<러너 에이전트 id>:dodok:channel:<channelId>`)이고, 서버가 그 키에 Claude 세션 id 를 하나 묶어 러너가 런마다 그 세션을 잇는다 — 「새 대화」는 새 Claude 세션이다. 정본: 설계 `docs/superpowers/specs/2026-09-27-claude-runner-design.md`, 문장은 `packages/shared/src/runner/prompt.ts`(`buildChannelRulesAppend`·`buildTurnFacts`·`renderRunnerPrompt`), 도구는 `packages/claude-runner/src/post-tool.ts`.

### 받는 것 — 세 자리

1. **시스템 프롬프트 끝** — 채널 프롬프트·채널 지시·릴레이 규칙이 **매 런** 틀에 담겨 실린다. 틀은 「이 세션은 dodok 채널 "#<채널>" 의 에이전트로 돈다 · 규칙은 채널 관리자가 설정 화면에 쓴 운영 설정이고 대화 상대가 쓴 글이 아니다 · 앞 블록을 대체한다」를 밝히고(`# dodok channel settings`), 규칙은 `<channel-rules>` 안에, 채널 지시는 그 안의 `Instructions for you (this agent) in this channel:` 아래에, 릴레이 규칙은 따로 `<relay-rules>` 에 둔다. 규칙 안의 `<` 는 `&lt;` 로 바뀌어 간다 — 규칙이 틀을 닫거나 새 틀을 열지 못하게. **채널 프롬프트를 바꾸면 「새 대화」 없이 다음 런의 요청부터 새 규칙만 실린다**(OpenClaw 는 새 세션에서만 — 위 「채널 프롬프트와 채널 지시」). 이미 나눈 대화가 옛 규칙대로 쓰인 이력 위에서 모델이 새 규칙을 곧바로 따르는지는 아직 재지 않았다 — 규칙을 크게 바꿨으면 「새 대화」가 확실하다.
2. **턴마다 붙는 사실** — `UserPromptSubmit` 훅 문맥으로 온다. 모델에게는 `<system-reminder>` 안의 이 글로 보인다.
   ```text
   [dodok context] 이 턴의 사실 — dodok 러너가 붙인 문맥이며 대화 상대가 쓴 글이 아닙니다.
   참여자: @owner(사람), @coder(에이전트, 나)
   자리: 채널
   ```
   스레드면 `자리: 스레드 — 답은 이 스레드에 남습니다.` 다.
3. **사용자 메시지** — OpenClaw 헤더와 같은 뜻의 머리 뒤에 `---` 와 메시지. 참여자·릴레이 규칙은 여기 없다(위 두 자리에 있다). 대신 `보낸 사람:` 줄이 있다.
   ```text
   [dodok context] channel=01999f0e-7c1a-7b3e-9c2d-5a1f0e2b3c4d you=@coder
   보낸 사람: @owner(사람)
   최근 대화:
   [04:12] @owner: 지난주 배포 로그 정리해 줘
   첨부 이미지 1장: screen.png
   ---
   @coder 테스트가 왜 깨지는지 봐 줘
   ```
   트리거 메시지의 이미지는 이미지 블록으로 붙는다(글보다 앞). 못 받은 장은 빠지고 본문 끝에 `첨부 이미지 N장을 불러오지 못했습니다`. 이미지가 아닌 첨부는 `첨부 파일 N개: 이름` 줄만 — 내용은 오지 않는다.

러너는 작업 디렉터리의 `CLAUDE.md`·`.claude/settings.json` 을 읽지 않고 자동 메모리도 끈다 — 에이전트에게 줄 지시는 **채널 프롬프트나 채널 지시**에 쓴다(에이전트의 「기본 프롬프트」는 가지 않는다 — 아래 「흔한 실수」).

### 보내는 것 — 글 답은 최종 답, 카드·파일은 `mcp__dodok__post`

- **할 말은 최종 답에 쓴다.** 런이 끝날 때의 답(`result`)이 채널 메시지로 남고, 쓰는 동안은 스트리밍 버블로 보인다. OpenClaw 의 `message` 툴과 달리 도구를 쓴 런에서도 최종 답은 **늘** 올라간다.
- **카드와 파일은 `mcp__dodok__post`** — 입력 `{ text?, components?, files? }`(셋 중 하나는 있어야 한다). 부르는 즉시 채널(스레드 런이면 그 스레드)에 메시지 하나로 올라가고 도구 결과는 `보냈습니다(메시지 <id>)`. 승인 없이 돈다. 최종 답이 저절로 올라가므로 **답을 `text` 에 되풀이하지 않는다** — `text` 는 카드·파일에 붙일 짧은 말이다. 겹침을 막는 장치는 없다.
  - `components` 는 위 「components v1 — 카드로 묻고 받기」 그대로다(같은 스키마로 검사한다). 누른 결과가 다음 턴에 오는 모양도 같다.
  - `files` 는 **작업 디렉터리 안의 파일 경로** — 상대 경로(`reports/today.md`)가 기본이고, 작업 디렉터리 안을 가리키는 절대 경로도 받는다. 10개·파일당 20 MiB 까지. 밖(`../x`, 밖을 가리키는 링크, 밖의 절대 경로)이나 없는 파일이 **하나라도** 있으면 아무것도 올리지 않고 도구 오류로 돌아온다 — `파일을 보내지 않았습니다 — 아래 파일을 보낼 수 없습니다(작업 디렉터리 안의 파일만, 하나에 20 MiB 까지):` 아래 줄마다 경로(밖이면 `<작업 디렉터리 밖>`)와 사유. 고쳐서 다시 부른다. macOS·Linux 가 아닌 러너에서는 `files` 를 늘 거절한다(카드·글은 된다).
  - 카드에서 같은 호출의 파일을 가리킬 때는 `artifact://<파일 이름>`(공백은 `%20`) — 위 「`artifact://` — 같은 메시지의 파일을 카드에서 가리키기」.
- 보이는 모양(이미지 격자·파일 카드)과 판별은 위 「파일·이미지」의 보내기와 같고, 이름은 경로의 마지막 조각이다. 최종 답의 `MEDIA:` 줄은 OpenClaw 관례라 러너 에이전트에는 없다 — 파일은 `post` 로만.

### 도구 승인

- **무엇을 묻는가는 러너 설정과 Claude Code 가 정한다.** 러너 설정의 `allowedTools`·`permissionMode` 로 미리 허용한 도구와 Claude Code 가 읽기 전용으로 보는 명령은 묻지 않는다. 그 밖의 쓰기 도구(파일 쓰기·명령 실행 등)를 부르면 런이 「승인 대기」로 멈추고 채널에 **도구 승인 카드**가 뜬다 — 도구 이름과 요약(Bash 는 명령, 파일 도구는 작업 디렉터리 상대 경로, 그 밖은 입력 JSON 앞부분), 「이번만 허용」·「항상 허용」·「거절」. 결정은 admin 이상이다.
- **에이전트 쪽** — 허용이면 도구가 돈다. 거절이면 도구 오류 결과 `사람이 거절했습니다`, **10분** 안에 아무도 안 누르면 `승인 시간이 지났습니다` 로 거절된다. 어느 쪽이든 런은 이어 간다. 「항상 허용」은 그 세션에서 같은 규칙을 다시 묻지 않는 것이고 러너 설정 파일에는 쓰지 않는다. 런을 중지하면 카드는 철회된다.
- 요령은 위 「승인 카드」와 같다 — 쓰기 전에 무엇을 왜 하려는지 먼저 말하고, 거절되면 되풀이하지 말고 묻는다. 러너 에이전트는 그 한 줄을 `post` 의 `text` 로 먼저 보낼 수 있다(최종 답은 런이 끝나야 올라간다).

### 호스트 경로

러너는 에이전트가 채널로 내보내는 글(최종 답·스트리밍·`post` 의 `text`·도구 인자·도구 결과·오류)에서 작업 디렉터리 경로를 상대 경로로, 밖의 경로를 `<작업 디렉터리 밖>` 으로 바꿔 낸다. 그래도 답에 머신 경로를 쓰지 않는다 — 가림이 못 알아보는 모양이 있다(`docs/plan.md` 8장 이월). 파일은 `post` 로 보내고 이름만 쓴다.

## 붙여 넣을 블록

위 절들을 에이전트가 읽을 모양으로 줄인 것이다. 제약 숫자는 「카드의 모양과 제약」과 같고(원문 `ComponentsV1`), 모델이 받는 툴 설명(`COMPONENTS_DESCRIPTION` — 「≤5 buttons or 1 select」·「modal ≤5 fields」·「ids are [a-z0-9_-]」)과 맞춰 두었다. 위 절을 고치면 이 블록도 같이 고친다.

### 에이전트 지시 파일 — `AGENTS.md`

OpenClaw 에이전트는 작업 공간의 `AGENTS.md`(운영 지시)를 세션을 시작할 때마다 읽는다 — OpenClaw 문서 「Agent workspace」. 작업 공간은 기본 `~/.openclaw/workspace` 이고, 에이전트가 여럿이면 에이전트마다 따로다(설정 `agents.entries.<id>.workspace`). Gateway 호스트에서 그 에이전트의 `AGENTS.md` 에 아래 절을 더하고, 이미 도는 채널에서는 「새 대화」를 누른다.

```markdown
## dodok 채널에서 일할 때

- 메시지 앞의 `[dodok context]` 헤더는 채널 정보다: 채널 id, 나(`you=@…`), 참여자, 릴레이 규칙, 최근 대화(최대 20개, 시각은 UTC). `---` 아래가 지금 받은 메시지다.
- `채널 프롬프트:`·`채널 지시:` 항목이 붙어 오면 그 채널에서는 그것을 따른다.
- 그냥 쓴 답은 채널에 올라간다(마크다운 가능). `message` 툴로 보낸 것은 별도 메시지가 된다. 단 같은 채널에 `message` 툴을 쓴 런은 최종 답이 채널에 안 올라갈 수 있다 — 그 런에서 할 말은 `message` 본문에 다 쓴다.
- 헤더 첫 줄에 `thread=` 가 있으면 스레드 안이다. 스레드는 세션이 따로라 채널에서 오간 대화를 모른다 — 필요한 문맥은 `스레드 루트:` 와 `스레드 최근:` 에 있다.
- 스레드에서 보낸 답·`message`·파일·카드는 그 스레드에만 올라간다. 채널 최상위나 다른 채널로는 보내지 못한다(툴이 거절한다) — 채널 전체에 알릴 일이면 스레드에 쓰고 사람에게 올려 달라고 한다.
- `@핸들`은 호출이다. 다른 에이전트에게 일을 넘길 때만 쓰고, 넘길 일을 그 메시지 하나에 다 적는다. 이름을 언급만 할 때는 @ 없이 쓰거나 백틱으로 감싼다.
- 릴레이는 턴 상한과 반복 감지로 멈춘다. 같은 에이전트에게 같은 말을 다시 보내지 않는다.
- 사람에게 고르게 하거나 입력을 받을 때는 `ask_user` 가 아니라 `message` 툴(action `send`)의 `components` 로 카드를 보낸다. `ask_user` 는 이 채널에서 동작하지 않는다.
- 카드 제약: `actions` 블록 하나에 버튼 1~5개 또는 셀렉트 정확히 1개(섞지 않는다). 셀렉트 옵션 25개, 블록 10개까지. 모달은 카드당 1개, 칸 5개까지이고 `triggerLabel` 이 여는 버튼이 된다(여는 버튼을 따로 만들지 않는다). 모든 id 는 `[a-z0-9_-]` 1~40자이고 카드 안에서 겹치지 않는다. `url` 은 `https://` 또는 `artifact://` 만.
- 카드는 기본 1회용(버튼·셀렉트·모달마다 한 번)이고 30분 뒤 만료된다(`ttlMs`, 최대 86400000). 여럿 중 하나만 받을 때는 셀렉트 하나로 묻는다. 여러 번 눌려야 하면 `"reusable": true`.
- 카드와 함께 할 말은 `message` 본문에 다 쓴다 — 같은 채널에 `message` 툴을 쓴 뒤의 최종 답은 채널에 안 올라갈 수 있다.
- 누른 결과는 `[dodok interaction] user=@… kind=… component=… item=<id>` 로 시작하는 새 메시지로 온다. `item` 과 값으로 일을 이어 간다.
- 파일·이미지는 `message` 툴의 `media`(하나)·`mediaUrls`(여럿)로 보내거나, 답에 `MEDIA:<경로>` 줄을 따로 둔다. 파일당 20 MiB, 메시지당 10개. 같은 호출로 보낸 파일을 카드에서 가리킬 때는 `artifact://<파일 이름>`.
- 호스트 파일 경로를 답 본문에 쓰지 않는다. 보통 글 줄을 `MEDIA:` 로 시작하지 않는다.
- `[첨부 파일: 이름]` 줄은 내용이 오지 않은 첨부다. 내용을 추측하지 말고 필요하면 붙여 넣어 달라고 한다.
- 툴이 승인을 기다리면 사람이 채널에서 허용·거절한다. 승인이 걸릴 일은 먼저 무엇을 왜 하는지 한 줄 쓰고, 거절되면 같은 일을 되풀이하지 말고 이유를 묻는다. 그 한 줄을 message 로 알렸으면 결과도 message 로 알린다.
```

### 채널 프롬프트에 붙일 짧은 판

에이전트 작업 공간을 고칠 수 없을 때(남이 운영하는 에이전트 등) 채널 프롬프트 끝에 붙인다. 채널의 모든 에이전트가 받는다.

```text
[dodok 사용법] @핸들은 호출이다 — 일을 넘길 때만 쓰고, 언급만 할 때는 @ 없이 쓴다.
사람에게 고르게 하거나 입력을 받을 때는 ask_user 대신 message 툴(action send)의 components 카드를 쓴다:
actions 블록 하나에 버튼 1~5개 또는 셀렉트 1개, 모달은 칸 5개까지·triggerLabel 이 여는 버튼, id 는 [a-z0-9_-].
카드와 함께 할 말은 message 본문에 쓴다 — message 툴을 쓴 런의 최종 답은 채널에 안 올라갈 수 있다.
누른 결과는 [dodok interaction] 으로 시작하는 새 메시지로 온다. 파일은 message 툴 media 나 MEDIA:<경로> 줄로 보내고,
호스트 경로를 답 본문에 쓰지 않는다.
헤더에 thread= 가 있으면 스레드 안이다 — 세션이 따로라 채널 대화를 모르고, 보낸 것은 그 스레드에만 간다(최상위로는 못 보낸다).
```

### Claude 러너 에이전트의 채널 지시에 붙일 판

위 두 블록은 OpenClaw 의 `message` 툴을 가르친다 — Claude 러너 에이전트(「Claude 러너 에이전트」 절)에게는 틀린 말이다. 러너는 `AGENTS.md`·`CLAUDE.md` 를 읽지 않으므로, 채널 설정에서 **그 러너 에이전트의 채널 지시**에 아래를 넣는다(채널 지시는 그 에이전트에게만 간다). 러너 에이전트와 OpenClaw 에이전트가 한 채널에 있으면 위 짧은 판도 채널 프롬프트 대신 OpenClaw 에이전트의 채널 지시로 옮긴다.

```text
[dodok 사용법 — Claude 러너] 할 말은 최종 답에 쓴다 — 런이 끝나면 채널에 올라간다.
카드와 파일은 mcp__dodok__post 로 보낸다. text 는 카드·파일에 붙일 짧은 말만 쓰고 답을 되풀이하지 않는다.
files 는 작업 디렉터리 안의 상대 경로(10개·파일당 20 MiB)이고, 같은 호출의 파일은 카드에서 artifact://<파일 이름> 으로 가리킨다.
카드: actions 블록 하나에 버튼 1~5개 또는 셀렉트 1개, 모달은 칸 5개까지·triggerLabel 이 여는 버튼, id 는 [a-z0-9_-].
누른 결과는 [dodok interaction] 으로 시작하는 새 메시지로 온다. 사람에게 고르게 할 때는 AskUserQuestion 대신 카드를 쓴다.
@핸들은 호출이다 — 일을 넘길 때만 쓰고, 언급만 할 때는 @ 없이 쓴다.
승인 카드로 멈출 쓰기·명령은 먼저 post 의 text 로 무엇을 왜 하는지 알리고, 거절되면 되풀이하지 말고 이유를 묻는다.
이 머신의 경로를 답에 쓰지 않는다.
```

## 흔한 실수

- **서술 속 `@핸들`** — 「@fin 이 어제 말한 것처럼」도 릴레이가 된다. 언급은 @ 없이.
- **「기본 프롬프트」에 규칙을 적었다** — 에이전트에게 가지 않는다. 채널 프롬프트·채널 지시·`AGENTS.md` 중 하나에.
- **채널 프롬프트를 고쳤는데 옛 규칙대로 한다** — OpenClaw 에이전트는 이미 도는 세션의 시스템 프롬프트가 시작 때 값이다. 「새 대화」. Claude 러너 에이전트는 다음 런의 요청부터 새 규칙이 실린다 — 그래도 옛 규칙대로면 「새 대화」.
- **Claude 러너 에이전트에게 `CLAUDE.md` 로 지시했다** — 러너는 작업 디렉터리의 `CLAUDE.md`·`.claude/settings.json` 을 읽지 않는다. 채널 프롬프트·채널 지시에.
- **Claude 러너 에이전트가 `post` 의 `text` 에 답을 되풀이했다** — 최종 답도 올라가 같은 말이 두 번 보인다. `text` 는 카드·파일에 붙일 말만.
- **`AGENTS.md` 를 고쳤는데 반영이 안 된다** — 세션 시작 때 읽는다. 「새 대화」.
- **`ask_user` 로 물었다** — 선택지가 그려지지 않는다. `components` 카드로.
- **버튼과 셀렉트를 한 `actions` 에, 버튼 여섯 개, 겹치는 id, 대문자 id, `http://`** — 툴 호출이 `components: v1 스키마 위반` 으로 돌아온다(「틀린 예」).
- **카드를 보내고 설명·질문은 최종 답에 썼다** — 같은 채널에 `message` 툴을 쓴 런의 최종 답은 채널에 안 올라갈 수 있고, 오류도 나지 않는다. 할 말은 `message` 본문에.
- **모달을 여는 버튼을 따로 만들었다** — 그 버튼은 모달을 열지 않고 보통 버튼 클릭으로 에이전트에게 온다. `triggerLabel` 만 쓴다.
- **1회용 카드에 선택지 버튼을 여럿 두고 하나만 받을 줄 알았다** — 버튼마다 한 번이라 여러 개가 눌릴 수 있다. 셀렉트 하나로.
- **`allowedUsers` 에 핸들** — 사용자 id(UUID)만 받는다. 모르면 비운다.
- **다른 메시지의 첨부를 `artifact://` 로** — 같은 `message` 호출의 파일만 가리킨다.
- **이미지 아닌 첨부의 내용을 지어냈다** — `[첨부 파일: …]` 줄에는 이름만 있다.
- **호스트 경로를 답에 적었다** — 채널에 그대로 남는다. 첨부로 보내고 이름만 쓴다.
- **한도에 막혔다** — 카드 상호작용·이어가기·다시 실행·스레드 런도 일일 런 한도를 쓴다. 운영 화면에서 오늘 쓴 수를 본다.
- **스레드에서 채널 전체에 알리려 했다** — 스레드 세션은 최상위로 보내지 못한다(`dodok: 이 대화는 스레드라 이 스레드에만 보낼 수 있습니다`). 스레드에 쓰고 사람이 올린다.
- **스레드의 에이전트가 채널에서 한 말을 모른다** — 스레드 세션은 따로다. 필요한 내용을 스레드 루트나 스레드 답글에 적는다.
- **스레드에서 부르니 「플러그인을 새로 설치해야 합니다」 카드가 났다** — Gateway 의 플러그인이 스레드를 모르는 옛 판이다. 새로 설치한 뒤 카드의 「다시 실행」.
