# 사용자 매뉴얼 — dodok 웹 앱 쓰기

dodok 웹 앱을 쓰는 사람(owner·admin·member)을 위한 문서다. 로그인부터 채널에서 에이전트를 부르고, 카드에 답하고, 도구 실행을 승인하고, 스레드와 검색을 쓰고, 멤버와 연결을 관리하는 법을 화면에 보이는 말 그대로 적는다.

- 서버 설치·`.env`·백업·업데이트, 플러그인·러너 설치는 `docs/guides/deploy.md` 가 정본이다.
- 에이전트가 무엇을 받고 어떻게 답하는지(헤더·릴레이 규칙·카드 스키마·에이전트 지시 파일에 붙일 블록)는 `docs/guides/agent-guide.md` 가 정본이다.

화면 문구는 「」로 적는다. 이 문서의 서술이 앱과 다르면 앱이 맞다 — 문구의 정본은 `apps/web/src/features/` 와 `apps/web/src/app/layout/` 이다.

## 역할 — 누가 무엇을 하나

워크스페이스의 사람은 셋 중 한 역할을 갖는다. **owner**(멤버 화면의 「소유자」)는 한 명(서버 `.env` 의 `LOCAL_AUTH_TOKEN` 으로 로그인하는 계정), **admin**(멤버 화면의 「관리자」)과 **member**(「멤버」)는 초대로 들어온다. 「admin 이상」은 owner 를 포함한다.

| 할 일 | member | admin | owner |
| --- | --- | --- | --- |
| 채널 읽기·쓰기·만들기, 채널 이름·주제 바꾸기, 멘션, 카드·모달 누르기, 이미지 첨부, 검색, 실행 중지 | ✅ | ✅ | ✅ |
| 채널에 에이전트 넣기·빼기 | ✅ | ✅ | ✅ |
| 채널의 에이전트 동작·비용 설정 — 채널 프롬프트, 에이전트별 채널 프롬프트 오버라이드, 릴레이 정책, 자동 응답, 일일 실행 상한 | — | ✅ | ✅ |
| 「새 대화」, 도구 실행 승인·거절 | — | ✅ | ✅ |
| 에이전트 등록·수정(「에이전트 가져오기」·사용 스위치·기본 프롬프트)·삭제·되살리기 | — | ✅ | ✅ |
| member 초대, 재설정 링크 발급, member 내보내기 | — | ✅ | ✅ |
| admin 초대, 역할 바꾸기(관리자 ↔ 멤버), admin 내보내기 | — | — | ✅ |
| 운영 화면(사건 확인·워크스페이스 한도) | — | ✅ | ✅ |
| 연결 페이지(Gateway 추가·수정·끄기·삭제, Gateway 마다 브리지 토큰, 러너 토큰, 「이 러너로 묶기」), 에이전트의 「Gateway 옮기기」 | — | — | ✅ |

- 이 표의 정본은 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md` 「역할과 권한」 절(Gateway 줄은 멀티 Gateway 스펙 `docs/superpowers/specs/2026-10-04-multi-gateway-design.md` 「권한」 절)이고, 막는 것은 서버다(`apps/server/src/auth/roles.ts`). 화면이 버튼을 숨기거나 잠그는 것은 편의다. 스펙 표의 「채널에 사람 넣기·빼기」는 API 에만 있고 화면에는 없다 — 사람은 「채널 참여」 절처럼 저절로 참여한다.
- 권한이 모자라는 칸은 잠기고 그 자리에 「관리자만 바꿀 수 있습니다」가 붙는다. 권한이 없는 설정 탭은 탭 목록에 없고, 주소로 직접 열면 「권한이 없습니다 — …」가 뜬다(그때도 탭 목록에는 나타나지 않는다).
- 역할이 바뀌면 열린 화면도 곧바로 따른다(다시 로그인하지 않아도 된다).

## 로그인

로그인 화면(`/login`)에는 이메일·비밀번호 폼이 있고, 그 아래에 접힌 「owner 로컬 토큰으로 로그인」이 있다. 공개 가입은 없다 — 사람은 초대 링크로만 들어온다.

### 멤버 — 이메일·비밀번호

「이메일」·「비밀번호」를 넣고 「로그인」. 이메일은 대소문자를 가리지 않는다.

- 틀리면 「이메일 또는 비밀번호가 맞지 않습니다」. 비밀번호 칸만 비워지고 이메일은 남는다.
- 한 주소에서 1분에 다섯 번을 넘으면 「잠시 뒤 다시 시도하세요(1분 5회)」 — 1분 기다린다.

### owner — 로컬 토큰

「owner 로컬 토큰으로 로그인」을 펼쳐 「로컬 토큰」에 서버 `.env` 의 `LOCAL_AUTH_TOKEN` 값을 넣고 「토큰으로 로그인」. 틀리면 「토큰이 맞지 않습니다」. owner 는 이메일·비밀번호 폼으로 로그인할 수 없다.

### 초대 링크로 가입

관리자에게 받은 링크(`…/join/dit_…`)를 열면 「<워크스페이스>에 가입」 폼이 뜨고 그 아래에 받을 역할(「멤버로 초대받았습니다」 또는 「관리자로 초대받았습니다」)이 보인다.

1. 「핸들」 — @멘션에 쓰는 이름. 영문 소문자·숫자·`_`·`-` 로 2~32자. 사람과 에이전트를 통틀어 겹칠 수 없고(「이 핸들은 이미 쓰이고 있습니다」), `left-` 로 시작할 수 없다(「이 핸들은 쓸 수 없습니다」).
2. 「표시 이름」(1~64자), 「이메일」, 「비밀번호」(12자 이상)와 「비밀번호 확인」.
3. 「가입」 — 곧바로 로그인되어 첫 채널로 간다.

- 링크는 **한 번만, 7일 안에** 쓴다. 쓰였거나 만료됐거나 폐기된 링크는 「링크를 쓸 수 없습니다」 화면에 「초대가 만료됐거나 이미 쓰였습니다 — 초대한 사람에게 새 링크를 받으세요」가 뜬다(까닭을 가르지 않는다).
- 이미 다른 계정으로 로그인된 브라우저에서 열면 「지금 @<핸들> 로 로그인돼 있습니다 — 가입하면 이 브라우저는 새 계정으로 바뀝니다」가 뜬다.

### 비밀번호 재설정 링크

메일은 보내지 않는다 — 비밀번호를 잊으면 관리자에게 재설정 링크(`…/reset/drt_…`)를 받는다(관리자 쪽은 아래 「멤버·역할」).

- 링크를 열면 「<워크스페이스> 비밀번호 재설정」 폼이다. 「새 비밀번호」·「비밀번호 확인」을 넣고 「비밀번호 바꾸기」 — 곧바로 로그인되고, **그 사람의 다른 기기·탭의 로그인은 모두 끊긴다.**
- 링크는 **한 번만, 24시간 안에** 쓴다. 지난 링크는 「링크가 만료됐거나 이미 쓰였습니다 — 관리자에게 새 링크를 받으세요」.
- owner 에게는 재설정 링크가 없다 — owner 비밀번호는 로컬 토큰이다(`docs/guides/deploy.md` 「멤버 초대·비밀번호 재설정·내보내기」 절).

## 화면 구성

- **사이드바(왼쪽)** — 위에서부터 워크스페이스 이름, 「검색」(`⌘K`), 「채널」 목록과 「채널 만들기」. 맨 아래 줄에 연결 점 둘과 톱니 「설정」 — 에이전트·멤버·연결·운영·알림·내 계정·로그아웃은 모두 「설정」 안의 탭에 있다(아래 「설정」). admin 이상에게는 확인하지 않은 운영 사건이 있으면 「설정」에 숫자 배지가 붙는다.
  - **연결 점 둘** — 왼쪽이 Gateway, 오른쪽이 플러그인이다. Gateway 가 여럿이어도 켜진 Gateway 를 모아 점 하나로 보인다 — 초록은 모두 연결, 노랑은 일부 끊김이거나 다시 연결하는 중, 빨강은 켜진 Gateway 가 모두 끊기고 다시 붙는 중인 것도 없을 때다(끊긴 Gateway 는 보통 「다시 연결 중」이라 노랑으로 보인다), 회색은 켜진 Gateway 가 없거나(「Gateway 없음」) 서버와의 실시간 연결이 끊겨 모르는 상태다. 꺼 둔 Gateway 는 세지 않는다. 점에 마우스를 올리거나 Tab 으로 가면 「Gateway 연결됨」·「Gateway 일부 끊김」 같은 이름과 Gateway 마다 한 줄(「집 — 다시 연결 중」 꼴)이 뜬다.
  - **좁은 화면(폰)** 에서는 사이드바가 접혀 헤더의 메뉴 버튼으로 연다.
- **채널 화면(가운데)** — 머리에 `#채널 이름`·주제, 채널에 넣은 에이전트 얼굴, 톱니바퀴(「채널 설정」). 그 아래 메시지 목록, 맨 아래 작성기.
- **오른쪽 패널** — 「설정」·「활동」·「스레드」 탭이 같은 자리에 열린다. 톱니바퀴는 설정 탭을, 메시지의 스레드 버튼은 스레드 탭을 연다. X 로 닫는다. 주소가 탭마다 다르므로(`/c/<채널>/settings`·`/activity`·`/t/<루트>`) 새로고침이나 링크로 바로 열 수 있다.
- **화면 위 띠** — 연결이 흔들리면 채널 위에 띠가 뜬다. 문구별 뜻은 끝의 「자주 겪는 문제」.

## 채널

### 채널 만들기

사이드바 「채널 만들기」 → 「이름」과 「주제」(선택) → 「만들기」. 누구나 만들 수 있다. 만들면 그 채널의 설정 패널이 열린다 — 「멤버」 칸의 「에이전트 추가」에서 에이전트를 고르고 「추가」로 넣는다. 에이전트가 하나도 등록돼 있지 않으면 먼저 admin 이 「에이전트」 화면에서 등록해야 한다(아래 「에이전트 등록」).

### 채널 참여

채널은 워크스페이스의 모든 사람이 사이드바에서 보고 연다. 따로 「참여」 버튼은 없다 — 그 채널에 **처음 쓰거나 누가 나를 멘션하면** 저절로 참여된다. 참여한 사람만 에이전트가 받는 「참여자:」 줄에 실리고, 채널 알림(릴레이 한도)을 받는다.

## 메시지 쓰기

작성기에 「메시지 보내기 — @로 에이전트 부르기」가 보인다. **Enter** 로 보내고 **Shift+Enter** 로 줄을 바꾼다. 한글을 조합하는 중의 Enter 는 조합만 끝낸다.

같은 채널 작성기에 다른 사람이 쓰고 있으면 작성기 위에 「@<핸들> 작성 중…」(여럿이면 「@mia, @jo 작성 중…」처럼 쉼표로)이 보이고, 입력이 멈추면 몇 초 안에 사라진다. 자기 입력(다른 탭 포함)과 스레드 작성기의 입력은 보이지 않고, 에이전트도 여기에 뜨지 않는다 — 에이전트가 일하는 중인지는 답 버블이 보인다(아래 「스트리밍 버블과 중지」).

### @멘션

`@` 를 치면 「멘션 후보」 목록이 뜬다 — 이 채널에 넣은 에이전트가 먼저, 그다음 워크스페이스의 사람이다. 핸들·이름의 앞부분으로 좁혀지고 한 번에 8개까지 보인다. 화살표로 고르고 Enter(또는 클릭)로 넣는다. 사용을 꺼 둔 에이전트는 흐리게 「꺼짐」이 붙는다(부를 수는 있지만 답하지 않는다).

- **에이전트를 멘션하면** 그 에이전트가 답한다. 여럿을 멘션하면 각자 답한다.
- **에이전트 멘션이 없으면**(사람만 멘션했어도) 채널 설정에서 「자동 응답」을 켠 에이전트(채널에 하나)가 답한다. 켠 에이전트가 없으면 아무도 답하지 않는다.
- **사람을 멘션하면** 그 사람에게 알림이 간다. 사람 멘션은 에이전트를 부르지 않지만, 에이전트 멘션이 없는 메시지라서 자동 응답 에이전트는 답한다.
- 에이전트가 다른 에이전트를 멘션하면 그 에이전트가 이어받는다(릴레이 — 아래 「에이전트 답 보기」).
- OpenClaw 에이전트는 후보 옆에 Gateway 이름이 작게 붙는다. 두 Gateway 에 같은 id 의 에이전트(예: 둘 다 `main`)가 있으면 등록할 때 정한 핸들로 가른다(`@main`·`@main-home`) — 멘션은 그 핸들의 Gateway 로 간다.

누가 무엇을 받는지의 규칙은 `docs/guides/agent-guide.md` 「릴레이 — 에이전트가 에이전트를 부를 때」 절.

### 서식·코드 블록

작성기는 마크다운을 그 자리에서 바꾼다 — `- `·`1. ` 은 목록, `> ` 는 인용, `**굵게**`, `` `코드` ``, 그리고 ```` ``` ```` 다음에 언어 이름과 공백(예: ```` ```ts ````)을 치면 코드 블록이 된다. 코드 블록 안에서는 Shift+Enter 가 코드 줄을 바꾼다. 제목(`#`)은 쓰지 않는다 — 평문으로 간다.

받은 메시지는 마크다운으로 그려지고, 코드 블록은 언어별로 칠해지며 「코드 복사」 버튼이 붙는다.

### 이미지 첨부

작성기 왼쪽의 「이미지 첨부」 버튼, **붙여넣기**, **작성기 상자에 끌어다 놓기** 세 길이 있다.

- 형식은 PNG·JPEG·GIF·WebP 만이다(SVG 는 안 된다). 다른 파일은 「이미지만 올릴 수 있습니다」로 빠진다.
- 한 장 5 MiB(「5 MB 를 넘습니다」), 한 메시지에 10장까지(「이미지는 한 번에 10장까지 보낼 수 있습니다」).
- 고른 이미지는 작성기 위에 칩으로 올라가며 바로 업로드된다. 칩의 X 로 뺀다. 올리는 중에는 「이미지를 올리는 중입니다」, 실패한 칩이 있으면 「올리지 못한 이미지를 빼 주세요」라며 보내기가 잠긴다.
- 작성기 밖(메시지 목록 등)에 놓으면 받지 않고 「이미지는 입력 칸에 놓아 주세요」.
- 에이전트는 멘션한 메시지에 붙은 이미지를 본다.

### 명령 — `/stop`·`/new`

메시지 맨 앞에 쓰면 보내지 않고 명령으로 처리한다.

- `/stop` — 이 채널(스레드 작성기면 그 스레드)에서 돌고 있는 에이전트 실행을 모두 멈춘다. 없으면 「진행 중인 실행이 없습니다」.
- `/new @에이전트` — 그 에이전트와의 「새 대화」 대화상자를 연다(admin 이상 — member 에게는 「「새 대화」는 관리자만 시작할 수 있습니다」). 에이전트를 붙이지 않으면 「/new 뒤에 @에이전트를 붙이세요」.

### 보내지 못했을 때

연결이 끊긴 동안은 「연결되면 보낼 수 있습니다」로 보내기가 잠긴다. 보낸 메시지가 서버에 닿지 못하면 그 자리에 「전송 실패」와 「다시 보내기」·「삭제」가 붙는다. 너무 빨리 보내면 「너무 빠르게 보내고 있습니다 — 잠시 뒤 다시」 — 「다시 보내기」는 같은 메시지라 에이전트가 두 번 답하지 않는다.

## 에이전트 답 보기

### 스트리밍 버블과 중지

에이전트가 답을 쓰는 동안 그 자리에 버블이 뜨고 글이 실시간으로 늘어난다. 버블 머리에 상태가 붙는다 — 「대기 중」, 「도구 사용 중」, 「승인 대기 중」. 답이 끝나면 버블이 확정 메시지로 바뀐다.

- 오른쪽 위 「중지」 — 그 실행을 멈춘다(누구나). 멈추면 잠시 「중지됨」이 보이고 버블이 사라진다. 작성기의 `/stop` 도 같다.
- 실행이 실패하면 버블에 잠시(3초) 「실행 실패: <코드>」가 보인다. 무엇이 있었는지는 「활동」 탭에 남는다.

### 실패와 「다시 실행」

에이전트에게 닿지 못했거나(연결 끊김) 시간 안에 끝나지 않은 실행은 채널에 「@<에이전트> 실행이 실패했습니다: <코드>」 시스템 카드와 1회용 「다시 실행」 버튼을 남긴다.

- 「다시 실행」은 채널의 사람 누구나 누를 수 있고, **24시간** 동안 쓸 수 있다. 같은 메시지로 새 실행을 만든다 — 연결을 고친 뒤 누른다.
- 카드나 「이어가기」로 생긴 실행에는 붙지 않는다(다시 만들 메시지가 없다).
- 코드별 뜻은 끝의 「자주 겪는 문제」.

### 릴레이와 한도 알림

에이전트가 다른 에이전트를 멘션해 일을 넘기는 사슬(릴레이)은 채널 설정의 「턴 상한」(기본 4)을 넘거나 같은 말이 되풀이되면 멈추고, 채널에 이렇게 남는다.

- 「릴레이 한도(<N>턴)에 도달했습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 또는 「같은 내용의 릴레이가 반복되어 멈췄습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 — 1회용 「이어가기」를 누르면 멈췄던 에이전트에게 이어서 간다. 이 채널에 참여한 사람에게 푸시도 간다.
- 일일 실행 한도에 닿으면 「오늘 런 한도(<N>)에 도달했습니다 — 내일 0시에 풀립니다」(채널 한도면 앞에 「이 채널의 」)가 그날 한 번 남는다. 사람의 메시지는 그대로 저장되고 에이전트만 답하지 않는다. admin 이상에게는 카드 아래 「채널 설정에서 한도 바꾸기」 또는 「운영에서 한도 바꾸기」 링크가 붙는다. 「0시」는 서버 시간대의 자정이다.

멈추는 네 가지 사유와 이어가기의 동작은 `docs/guides/agent-guide.md` 「릴레이가 멈추는 네 가지」 절.

## 에이전트 카드 — 버튼·셀렉트·모달

에이전트는 답에 카드를 붙여 선택이나 입력을 받는다. 카드를 누른 결과는 에이전트에게 다음 턴으로 가고, 에이전트가 그것을 받아 이어 답한다.

- **버튼** — 누르면 곧바로 보낸다.
- **셀렉트** — 목록에서 고르고(여럿을 고르는 셀렉트는 「최대 <N>개까지 고를 수 있습니다」) 「보내기」. 덜 골랐으면 「하나를 고르세요」·「<N>개 이상 고르세요」가 남는다.
- **모달** — 버튼을 누르면 양식이 열린다. 칸을 채우고 「제출」(「취소」로 닫는다). 칸 아래에 「필수 항목입니다」·「숫자를 입력하세요」 같은 까닭이 뜨면 고친 뒤 제출한다.
- **결과 줄** — 카드 아래에 누가 무엇을 보냈는지 오래된 것부터 「@<핸들> — <항목>: <값>」 꼴로 남는다(새로고침·다른 기기에서도 보인다). 20줄이 차면 「최근 20건」이 붙는다.
- **눌리지 않을 때** — 버튼 아래에 까닭이 보인다: 「이미 처리되었습니다」(1회용 카드를 누가 이미 눌렀다), 「만료되었습니다」, 「이 항목을 쓸 권한이 없습니다」(에이전트가 누를 사람을 정해 두었다), 「연결이 끊겨 지금은 보낼 수 없습니다」, 「보내는 중입니다」.
- 일일 한도에 막힌 클릭은 「오늘 런 한도에 도달했습니다 — 한도가 풀리면 다시 누를 수 있습니다」 — 카드가 소비되지 않으니 한도가 풀린 뒤 다시 누른다.

카드의 모양·제약·에이전트가 받는 글은 `docs/guides/agent-guide.md` 「components v1 — 카드로 묻고 받기」 절.

## 에이전트가 보낸 이미지·파일

- **이미지** — 메시지 안에 격자로 보인다. 누르면 크게 보기가 열리고, 여러 장이면 「이전 이미지」·「다음 이미지」로 넘기며, 「원본 내려받기」로 받는다.
- **파일** — 이름·크기·종류가 적힌 파일 카드의 「내려받기」로 받는다. 에이전트 파일은 한 개 20 MiB 까지다.
- 카드가 같은 메시지의 파일을 가리킬 수 있다(「열기」). 가리킨 파일이 없으면 「첨부를 찾을 수 없습니다」.

## 도구 승인 카드

에이전트가 승인이 필요한 도구(파일 쓰기·명령 실행 등)를 부르면 실행이 「승인 대기 중」으로 멈추고, 채널 흐름과 「활동」 탭 맨 위에 같은 승인 카드가 뜬다.

- 카드에는 제목·심각도(「정보」·「주의」·「위험」), `@에이전트 · 도구 이름`, 남은 시간(「<n>분 <n>초 남음」)이 있다. 「인자 보기」로 도구에 넘길 값을 펼친다 — 길면 「잘렸습니다.」가 붙는다.
- **admin 이상**이 「이번만 허용」·「항상 허용」·「거절」 중 하나를 누른다(에이전트 쪽이 허용한 결정만 버튼이 된다). member 에게는 버튼 대신 「관리자가 결정합니다」가 보인다.
- 결정하면 카드가 「허용됨」·「거절됨」으로 바뀌고 「선택: <결정>」이 남는다. 다른 사람이 먼저 눌렀으면 그 결과가 모든 화면에 같이 반영된다.
- 아무도 누르지 않고 시간이 지나면 「만료됨」·「시간이 지나 답할 수 없습니다.」 — 거절로 확정된다. 기한은 OpenClaw 에이전트면 Gateway 가 정하고, Claude 러너 에이전트면 10분이다. 실행을 중지하면 기다리던 승인은 「취소됨」.
- 승인 요청은 워크스페이스의 owner·admin 전원에게 브라우저 알림·푸시로도 간다(아래 「알림·앱 설치·오프라인」).
- 「항상 허용」의 범위와 어떤 도구에 승인을 걸지는 에이전트 쪽 설정이다 — `docs/guides/agent-guide.md` 「승인 카드」 절, Claude 러너는 `docs/guides/deploy.md` 「Claude 러너 설치」 절.

## 활동 탭 — 실행과 도구 기록

채널 패널의 「활동」 탭은 이 채널의 실행(런) 목록이다. 줄마다 `@에이전트`, 상태(「대기 중」·「응답 중」·「도구 사용 중」·「승인 대기」·「마무리 중」·「완료」·「실패」·「중지됨」), 시작 시각·걸린 시간.

줄을 고르면 아래에 그 실행의 도구 타임라인이 열린다 — 도구 이름, 진행 상태(「진행 중」·완료·실패), 걸린 시간, 「인자 보기」·「결과 보기」, 승인이 걸린 도구에는 「승인」 표시와 결정. 도구를 쓰지 않은 실행은 「도구 기록이 없습니다.」. 도는 중인 실행은 실시간으로 늘어난다.

## 스레드

어떤 메시지든(사람·에이전트 모두) 마우스를 올리면 오른쪽 위에 「스레드에서 답하기」 버튼이 보인다(터치 화면에서는 늘 보인다). 누르면 오른쪽 패널에 「스레드」 탭이 열리고, 「스레드에 답하기 — @로 에이전트 부르기」 작성기에서 그 스레드 안으로 쓴다.

- 채널의 원래 메시지 아래에는 「답글 <N>개」와 마지막 답글 시각이 적힌 칩이 붙고, 누르면 스레드가 열린다.
- **에이전트는 스레드마다 대화가 따로다** — 스레드에서 오간 말은 채널 대화에 섞이지 않고, 채널의 에이전트도 스레드 대화를 모른다.
- **누가 답하나** — 스레드에서 멘션한 에이전트가 그 스레드에 답한다. **에이전트 멘션이 없으면** 스레드를 연 메시지가 에이전트의 것일 때 그 에이전트가, 아니면 채널의 자동 응답 에이전트가 답한다 — 에이전트 답에 이어 물을 때는 멘션 없이 스레드에 쓰면 된다.
- 스레드 패널 위의 「새 대화」 줄(admin 이상)은 이 스레드의 그 에이전트 대화만 새로 시작한다 — 채널 대화는 그대로다.
- 스레드 안의 스레드는 없다. 답글에서 「스레드에서 답하기」를 누르면 그 스레드가 열린다.

## 검색

사이드바 「검색」 또는 **`⌘K`**(Windows·Linux 는 `Ctrl+K`). 「메시지 검색」 칸에 치면 바로 찾는다.

- **2글자 이상**이어야 찾는다(「2글자 이상 입력하세요」). 2글자 검색은 최근 90일에서 50개까지만 찾는다(「2글자는 최근 90일에서 50개까지만 찾습니다」). 3글자 이상은 전체 기간에서 찾고 「더 보기」로 더 받는다.
- 위의 거르개로 채널(「모든 채널」), 작성자(「모두」·「사람」·「에이전트」), 시작·끝 날짜를 좁힌다.
- 결과는 채널·작성자·시각과 일치한 부분을 보인다. 일치한 부분은 메시지에 보이는 글자로 나온다 — 멘션은 `@핸들`(모르는 대상은 `@알 수 없음`), 굵게·코드·링크 같은 서식 기호는 빠진다. 스레드 답글은 「스레드 답글」 표시가 붙는다.
- **`@핸들`로 찾으면 그 멘션이 든 메시지를 찾는다** — 「@dev」는 dev 를 멘션한 메시지, 「@dev 보고서」는 dev 멘션 바로 뒤에 「보고서」가 오는 메시지다. 에이전트·사람의 지금 핸들(나간 멤버는 옛 핸들)과 채널 별칭으로 찾고, 핸들이 바뀌기 전에 쓴 메시지도 지금 핸들로 찾힌다. 같은 핸들이 사람·에이전트 둘이면 둘 다 찾는다. 멘션이 되지 않고 글자로 남은 `@핸들`(그 채널에 없는 대상, 코드 안)도 함께 찾는다. 모르는 핸들은 글자 그대로 찾는다.
- **결과를 누르면 그 메시지로 간다** — 오래된 메시지면 그 주변을 불러와 그 자리를 보여 준다. 스레드 답글이면 그 스레드가 열린다. 그 사이 지워진 메시지면 「메시지를 찾을 수 없습니다」.
- 첨부 파일 이름으로도 찾힌다.

## 채널 설정

채널 머리의 톱니바퀴(「채널 설정」) 또는 패널의 「설정」 탭. 저장은 칸마다 「저장」 버튼으로 하고, 저장되면 「저장했습니다」가 잠깐 뜬다.

- **기본**(누구나) — 「이름」·「주제」.
- **채널 프롬프트**(admin 이상) — 이 채널의 모든 에이전트가 매 턴 함께 받는 지시. 20,000자까지. 저장하면 「다음 턴부터 반영됩니다. …」 안내가 뜬다 — OpenClaw 에이전트의 진행 중인 대화에 행동 규칙을 확실히 반영하려면 에이전트별 「새 대화」를 누른다. Claude 러너 에이전트는 채널 프롬프트·릴레이 정책(턴 상한·쌍·일일 실행 상한)·어느 에이전트의 오버라이드든 바뀌면 다음 실행을 저절로 새 대화로 시작하고, 그 자리(스레드면 스레드)에 「채널 규칙이 바뀌어 @<에이전트> 의 대화를 새로 시작했습니다」가 남는다.
- **릴레이 정책**(admin 이상)
  - 「턴 상한」 — 에이전트끼리 이어 부르는 횟수(0~32, 기본 4). 0 이면 릴레이가 없다.
  - 「일일 실행 상한」 — 이 채널에서 하루에 만들 실행 수(1~999,999,999). 비우면 상한 없음.
  - 「모든 에이전트끼리 허용」 — 끄면 쌍 목록이 나와, 체크한 쌍(보내는 쪽 → 받는 쪽)만 릴레이한다(64쌍까지). 에이전트가 둘 이상이어야 고를 수 있다.
- **멤버** — 이 채널의 에이전트 목록과 「에이전트 추가」. 목록과 「에이전트 추가」 고르기 모두 OpenClaw 에이전트에 Gateway 이름이 붙는다. 줄마다:
  - 「자동 응답」(admin 이상) — 에이전트 멘션이 없는 메시지에 답할 에이전트. 채널에 하나뿐이라 다른 에이전트를 켜면 「자동 응답 바꾸기」 확인이 뜬다.
  - 「채널 프롬프트 오버라이드」(admin 이상, 「편집」) — 이 채널에서 이 에이전트에게만 더하는 지시. 20,000자까지.
  - 「새 대화」(admin 이상) — 이 채널에서 그 에이전트와의 대화 기록을 새로 시작한다. 진행 중인 실행은 중지된다. 채널에 「@<에이전트> 의 대화를 새로 시작했습니다」가 남는다.
  - 「제거」(누구나) — 채널에서 뺀다. 그 에이전트의 오버라이드·자동 응답 설정도 사라진다.

프롬프트가 에이전트에게 언제 어떤 꼴로 닿는지, 무엇을 적으면 좋은지는 `docs/guides/agent-guide.md` 「채널 프롬프트와 채널 지시」·「채널 프롬프트 쓰는 법」 절.

## 설정

사이드바 맨 아래 「설정」(`/settings`). 탭은 역할대로 보인다 — 「내 계정」·「알림」·「에이전트」는 누구나, 「멤버」·「운영」은 admin 이상, 「연결」은 owner.

| 탭 | 주소 | 이 문서의 절 |
| --- | --- | --- |
| 내 계정 | `/settings/account` | 「내 계정」 |
| 알림 | `/settings/notifications` | 「알림·앱 설치·오프라인」 |
| 에이전트 | `/settings/agents` | 「에이전트 등록·삭제」 |
| 멤버 | `/settings/members` | 「멤버·역할」 |
| 연결 | `/settings/connection` | 「연결 페이지 (owner)」 |
| 운영 | `/settings/operations` | 「운영 화면 (admin 이상)」 |

- **넓은 화면** — 채널 목록 옆에 왼쪽 탭 목록이 붙어 있고, 오른쪽 탭 내용만 따로 스크롤한다. `/settings` 를 열면 「내 계정」으로 간다.
- **좁은 화면(폰)** — 「설정」을 누르면 탭 목록이 먼저 나온다. 탭을 누르면 그 화면으로 들어가고, 위에 메뉴 버튼과 「← 설정」이 붙는다(스크롤해도 위에 남는다). 「← 설정」으로 탭 목록에 돌아온다.
- 탭 목록에서 탭을 고르면 초점이 그 탭의 제목으로 간다.
- 운영 탭에도 「설정」과 같은 숫자 배지가 붙는다(admin 이상).
- 옛 주소 `/agents`(즐겨찾기·옛 링크)는 `/settings/agents` 로 넘어간다.

## 에이전트 등록·삭제

「설정」 → 「에이전트」 탭(`/settings/agents`). 누구나 목록을 보고, 등록·수정·삭제·되살리기는 admin 이상이다.

- **「에이전트 가져오기」** → 「제공자」를 고른다.
  - 「OpenClaw」 — 「Gateway」에서 Gateway 를 고르면(꺼진 것은 「(꺼짐)」) 그 Gateway 에 있는 에이전트 중 아직 등록하지 않은 것이 체크 목록으로 나온다 — 같은 Gateway 에 같은 id 로 등록한 것만 숨고, 다른 Gateway 에 등록한 같은 id 는 나온다. 고르면 핸들·이름 칸이 열린다. 핸들은 id 로 채워지고 이미 쓰이는 핸들이면 「이미 쓰이는 핸들입니다 — 다른 핸들을 입력하세요」 — 다른 Gateway 의 같은 id 는 다른 핸들(예: `main-home`)로 바꿔 「<N>개 등록」. Gateway 가 하나도 없으면 「Gateway 를 먼저 추가하세요 — 연결 페이지에서 추가할 수 있습니다」, 고른 Gateway 가 끊겼으면 「Gateway 에 연결되지 않았습니다」.
  - 「Claude 러너」 — 지금 붙어 있는 러너들이 알린 에이전트가 나온다(줄 맨 앞이 러너 이름). 붙은 러너가 없으면 「연결된 러너가 없습니다 — 연결 페이지에서 러너를 붙이세요」. 러너를 설치하고 붙이는 것은 `docs/guides/deploy.md` 「Claude 러너 설치」 절. 러너를 붙이고 묶는 것은 owner 가 연결 페이지에서 한다.
  - 목록을 못 받을 때는 「직접 입력」으로 id·핸들·이름을 적어 등록한다. OpenClaw 에이전트 id 는 같은 Gateway 안에서, Claude 러너 에이전트 id 는 워크스페이스 안에서 겹칠 수 없다(두 Gateway 에, 그리고 OpenClaw 와 Claude 러너에 같은 id 가 함께 있을 수 있다). 핸들은 워크스페이스에서 하나다.
- **줄마다** — 핸들, 제공자별 id, 사용 스위치(끄면 멘션해도 답하지 않는다 — 사람이 멘션하면 아무 표시 없이 답이 없고, 다른 에이전트가 넘기면 채널에 「@<에이전트> 는 비활성 상태입니다」 꼴이 남는다), 「기본 프롬프트 편집」. OpenClaw 에이전트는 핸들 옆에 Gateway 이름(`@main-home · 집`)이 붙고, Claude 러너 에이전트는 묶인 러너를 보인다(「러너 <이름>」).
- **「Gateway 옮기기」**(owner) — OpenClaw 에이전트 줄마다 있다. 그 에이전트가 답할 Gateway 를 고르고 「옮기기」. 그 Gateway 의 OpenClaw 에 같은 id 의 에이전트가 있어야 답하고, 그 Gateway 로 이미 등록된 같은 id 가 있으면 「옮길 Gateway 에 같은 id 의 에이전트가 이미 있습니다」. Gateway 를 지우면 그 Gateway 의 에이전트는 남고 연결이 빈다 — owner 에게는 「Gateway 가 삭제됨 — 다른 Gateway 로 옮기세요」, admin·member 에게는 「Gateway 가 삭제됨 — owner 가 다른 Gateway 로 옮길 때까지 답하지 못합니다」가 보이고, 그동안 멘션하면 `ADAPTER_UNAVAILABLE` 로 실패한다. 옮긴 뒤 실패 카드의 「다시 실행」은 새 Gateway 로 간다.
- ⚠ 에이전트의 「기본 프롬프트」는 지금 에이전트에게 전달되지 않는다 — 기록용이다. 에이전트에게 줄 지시는 채널 프롬프트나 에이전트 쪽 지시 파일에 적는다(`docs/guides/agent-guide.md` 「채널 프롬프트와 채널 지시」 절).
- 등록한 뒤 채널 설정 「에이전트 추가」로 채널에 넣어야 멘션할 수 있다.

### 삭제·되살리기

삭제는 지우는 것이 아니라 숨기는 것이다 — 채팅 기록은 남고, 되살리면 채널·대화가 그대로 돌아온다.

- **삭제** — 줄의 「삭제」(admin 이상) → 「에이전트 삭제」 대화상자 「@dev 를 삭제합니다. 채팅 기록은 남고, 되살리면 채널·대화가 그대로 돌아옵니다.」 → 「삭제」. 목록에서 빠지고, 아래 접힌 「삭제된 에이전트 N」 묶음으로 간다(누르면 펼친다).
- **삭제하면**
  - 멘션 후보·채널 설정의 멤버 줄·「에이전트 추가」 목록·채널 머리의 에이전트 얼굴에서 빠진다. 손으로 친 `@핸들` 은 그냥 글자로 남고 아무도 답하지 않는다.
  - 그 에이전트가 돌던 실행은 「중지」와 같이 멈추고, 걸려 있던 도구 승인 카드는 「취소됨」이 된다.
  - 채팅 기록의 작성자 이름 옆과 멘션 칩에 「삭제됨」이 붙는다. 운영 화면 에이전트별 표에도 「삭제됨」이 붙는다.
  - 그 에이전트의 실패 카드에서 「다시 실행」을 누르면 「삭제된 에이전트입니다」 — 카드는 그대로 남아 되살린 뒤 다시 누를 수 있다.
- **되살리기** — 「삭제된 에이전트 N」을 펼쳐 줄의 「되살리기」(admin 이상). 핸들·채널 참여·대화가 그대로 돌아와, 같은 채널에서 멘션하면 앞 대화를 이어 답한다. 삭제한 동안 그 채널에서 다른 에이전트의 자동 응답을 켰으면 되살린 에이전트의 자동 응답은 꺼진 채로 돌아온다 — 자동 응답은 채널에 하나다.
- **다시 가져오려 할 때** — 「에이전트 가져오기」 목록에서 삭제한 에이전트는 체크 대신 「삭제됨 — 되살리기」 버튼으로 나온다. 「직접 입력」에 삭제한 에이전트의 id 를 넣으면 「삭제된 에이전트입니다」와 「되살리기」가 뜬다 — 새로 만들지 않고 되살린다. 삭제한 에이전트의 핸들은 그대로 그 에이전트 몫이라 새 에이전트에 쓸 수 없다.
- 채널 설정에서 삭제한 에이전트를 넣으려 하면 「삭제된 에이전트입니다」.

## 멤버·역할

「설정」 → 「멤버」 탭(`/settings/members`, admin 이상). 표에 핸들·이름·이메일·역할·가입일과 줄마다의 동작이 있고, 아래에 「대기 중인 초대」가 있다.

- **초대** — 「초대」 → 「역할」(「멤버」 또는 「관리자」 — 관리자 초대는 owner 만) → 「링크 만들기」. 「초대 링크를 만들었습니다」 대화상자에 링크가 **한 번만** 보인다 — 「복사」해서 메신저로 건네고 「복사했습니다」로 닫는다. 닫으면 다시 볼 수 없다. 잃었으면 「대기 중인 초대」에서 「폐기」하고 새로 만든다.
- **재설정 링크** — 줄의 「재설정 링크」 → 「링크 만들기」. 앞서 만든 그 사람의 재설정 링크는 쓸 수 없게 된다. 링크를 건네는 법은 초대와 같다. admin 은 member 에게만, owner 는 owner 를 뺀 누구에게나 만든다.
- **역할 바꾸기**(owner) — 줄의 역할 칸에서 「관리자」 ↔ 「멤버」. 확인 없이 곧바로 바뀐다.
- **내보내기** — 줄의 「내보내기」 → 확인. 그 사람은 곧바로 로그아웃되고, 다시 들어오려면 새 초대가 필요하다. 쓴 메시지는 남아 「나간 멤버 @<옛 핸들>」로 보인다. admin 은 member 만, owner 는 owner 를 뺀 누구나 내보낸다.

링크가 만료되는 때, 역할을 내리면 폐기되는 링크, 내보내기가 실패했을 때는 `docs/guides/deploy.md` 「멤버 초대·비밀번호 재설정·내보내기」 절.

## 내 계정

「설정」 → 「내 계정」 탭(`/settings/account`).

- 「표시 이름」(1~64자)을 바꾸고 「저장」.
- 「비밀번호 바꾸기」 — 「현재 비밀번호」, 「새 비밀번호」(12자 이상), 「새 비밀번호 확인」. 바꾸면 「비밀번호를 바꿨습니다 — 다른 기기의 로그인은 끊겼습니다」 — 이 기기는 남는다.
- owner 에게는 비밀번호 칸 대신 「owner 비밀번호는 로컬 토큰입니다 — …」 안내가 있다.

「로그아웃」은 이 탭 아래에 있다. 로그아웃하면 이 기기의 푸시 구독과 오프라인 사본도 지워진다.

## 알림·앱 설치·오프라인

「설정」 → 「알림」 탭(`/settings/notifications`)이 이 기기에서 받을 알림이다.

- **푸시 알림** — 「푸시 알림 켜기」 → 브라우저가 권한을 물으면 허용 → 「이 기기에서 알림을 받습니다」. 「끄기」로 끈다. 기기마다 따로 켠다.
  - 받는 것: 나를 멘션한 메시지, 도구 승인 요청(owner·admin), 내가 참여한 채널의 에이전트 릴레이 한도. 알림에는 누가·어디만 실리고 본문은 실리지 않는다. 누르면 그 채널(또는 스레드)이 열린다.
  - 그 채널을 지금 보고 있으면 푸시를 보내지 않는다.
  - 「브라우저 설정에서 알림을 허용해 주세요」 — 전에 거절한 것이다. 브라우저의 사이트 설정에서 알림을 허용한다.
  - 「이 브라우저는 푸시 알림을 지원하지 않습니다」 — 대신 「탭이 열려 있을 때만 알림 켜기」가 있으면 그것으로 탭이 열린 동안의 승인 알림을 받는다(owner·admin — member 에게는 탭 알림이 없다).
- **앱 설치** — 크롬·엣지 등에서는 이 탭의 「앱 설치」로 설치형 앱(PWA)으로 둔다. iPhone·iPad 는 Safari 의 공유 → 「홈 화면에 추가」로 설치해야 푸시를 받는다(이 탭에 「홈 화면에 추가하면 알림을 받을 수 있습니다 — 공유 → 홈 화면에 추가」). 새 버전이 나오면 「새 버전이 있습니다」 토스트의 「새로고침」으로 바꾼다.
- **오프라인 사본** — 최근 본 채널 5개의 최근 메시지 50개가 이 기기에 7일 동안 남는다. 연결이 없을 때 「오프라인 — 저장된 내용을 보여 줍니다」 띠와 함께 그것을 보여 주고, 연결되면 새로 받는다. 오프라인에서는 보낼 수 없다.

폰에서 설치·푸시를 처음 확인하는 순서는 `docs/guides/deploy.md` 「체크리스트 — 처음 배포」 절의 폰 단계.

## 연결 페이지 (owner)

「설정」 → 「연결」 탭(`/settings/connection`). 서버·OpenClaw Gateway(Gateway 마다 카드 — 상태·플러그인·브리지 토큰)·Claude 러너가 이 서버에 어떻게 붙어 있는지 보이고, 할 일과 명령을 「복사」로 건넨다. 처음 설치 순서와 토큰 교체 절차는 `docs/guides/deploy.md` 「체크리스트 — 처음 배포」·「브리지 토큰 교체」·「Gateway 수정·끄기·삭제」·「Claude 러너 설치」 절이 정본이다 — 여기는 화면에서 하는 일만 적는다.

- **「OpenClaw Gateway」 블록 머리** — 「Gateway 추가」(이름·주소·토큰 → 「추가」, 저장하면 서버가 곧바로 붙는다)와 「플러그인 받기」(서버에 하나인 플러그인 파일과 Gateway 호스트에서 돌릴 설치 명령 — Gateway 가 여럿이면 호스트마다 같은 파일을 설치한다). Gateway 가 없으면 「OpenClaw Gateway 를 추가하면 그 안의 에이전트를 채널에 데려올 수 있습니다」.
- **Gateway 카드** — Gateway 마다 하나. 머리에 이름·상태 배지(「연결됨」·「재연결 중」·「페어링 대기」·「꺼짐」·「연결 안 됨」)와 「수정」·「끄기」(꺼져 있으면 「켜기」)·「삭제」.
  - 상태 — 주소·호스트·버전, 페어링을 기다리면 승인 명령(「승인 명령 복사」). 버전이 저장소가 검증한 것과 다르면 「— 저장소가 검증한 버전(<핀>)과 다릅니다」.
  - 「플러그인」 — 그 Gateway 에 붙은 플러그인의 상태(「접속됨」)·버전과 「서버와 같은 빌드입니다」. 다른 빌드면 「다른 빌드입니다 — 받아서 다시 설치하세요」 — 블록 머리의 「플러그인 받기」로 받아 그 Gateway 호스트에 다시 설치한다. 붙은 플러그인이 없으면 「접속한 플러그인이 없습니다.」.
  - 「브리지 토큰」 — 이 Gateway 의 플러그인이 쓰는 토큰. 「새 토큰 발급」 → 라벨 → 「발급」. 원문(`dbt_…`)과 플러그인 설정 조각은 **발급 직후 한 번만** 보인다 — 복사한 뒤 「복사했습니다」. 대화상자가 화면보다 길면 대화상자 안에서 스크롤한다. 토큰은 발급한 카드의 Gateway 에 묶이므로 그 Gateway 호스트의 플러그인에 넣는다. 목록에서 지금 붙어 있는 토큰에 「지금 접속 중」이 붙는다. 새 토큰으로 옮겨 간 뒤 옛 줄에 「이제 폐기해도 됩니다 — 플러그인이 새 토큰으로 접속해 있습니다」가 뜨면 옛 줄의 「폐기」. 폐기는 되돌릴 수 없고, 마지막 남은 토큰을 폐기하려 하면 「활성 토큰이 하나도 남지 않습니다」 확인이 한 번 더 뜬다. 쓸 수 있는 토큰이 없으면 「쓸 수 있는 토큰이 없습니다 — 발급하세요」.
  - 「수정」 — 이름·주소·토큰(토큰 칸은 「바꾸려면 입력」 — 비우면 그대로). 주소나 토큰을 바꾸면 이 Gateway 만 다시 붙고, 진행 중인 런은 「다시 실행」 카드로 닫힌다.
  - 「끄기」 — 곧바로 끊는다. 진행 중인 런은 「다시 실행」 카드로 닫히고, 꺼진 동안 그 Gateway 의 에이전트를 부르면 곧바로 실패 카드가 남는다. 다른 Gateway 는 그대로다.
  - 「삭제」 — 카드 안에서 「「<이름>」 Gateway 를 삭제할까요?」와 「이 Gateway 의 에이전트 N개는 남고 연결이 비어 옮기기를 기다립니다 · 브리지 토큰 M개가 지워집니다」로 한 번 더 묻는다. 남은 에이전트는 「에이전트」 화면의 「Gateway 옮기기」로 다른 Gateway 에 옮긴다.
- **Claude 러너** — 붙은 러너마다 카드(라벨·판본·「서버와 같은 빌드입니다」·붙은 시각·그 러너가 알린 에이전트). 「러너 토큰」의 「새 러너 토큰 발급」은 브리지 토큰과 같은 꼴로 원문(`drn_…`)과 러너 설정 조각을 한 번만 보인다. 그 아래 「설치」에 러너 받기·로그인·설정·실행 명령이 있다.
- **「AI 에게 맡기기」** — 브리지 토큰·러너 토큰 발급 대화상자의 원문 바로 아래에 있다. 「복사」로 한 줄(`<서버 주소>/llms.txt 를 읽고 「OpenClaw Gateway 호스트」 절대로 이 호스트에 dodok 플러그인을 설치해 줘. 브리지 토큰: <원문>` — 러너는 「Claude 러너 머신」 절·「러너 토큰:」)을 복사해, 설치할 머신에서 도는 AI(Claude Code 등)에게 건네면 AI 가 서버의 설치 안내서(`/llms.txt`)대로 받기·설치·설정을 한다. 토큰이 들어 있으니 원문처럼 다룬다. AI 는 사람이 할 단계(러너 전용 Claude 로그인, 에이전트 id·작업 디렉터리 고르기, 페어링 승인 확인)에서 멈추고 묻는다 — 끝나면 이 페이지에서 그 카드가 「접속됨」(러너는 「연결됨」)·「서버와 같은 빌드입니다」인지 본다. 안내서가 하는 일과 멈추는 자리는 `docs/guides/deploy.md` 「[웹 → B] 플러그인 설치·브리지 토큰」·「Claude 러너 설치」 절의 「AI 에게 맡기는 길」.
- **「이 러너로 묶기」** — Claude 러너 에이전트는 러너 토큰 하나에 묶여 그 토큰의 러너만 그 에이전트를 맡는다. 러너를 새 머신·새 토큰으로 옮겼으면:
  1. 새 머신에서 새 토큰으로 러너를 띄운다 — 카드가 생긴다.
  2. 옛 토큰을 폐기했으면 새 카드의 에이전트 줄에 「<옛 라벨>(폐기됨)에 묶여 있어 배정되지 않습니다」가 보인다(「에이전트」 화면에는 「러너 <옛 라벨> — 토큰이 폐기돼 맡을 러너가 없습니다. 연결 페이지에서 다시 묶으세요」). 그동안 그 에이전트를 멘션하면 `ADAPTER_UNAVAILABLE` 로 실패한다.
  3. 그 줄의 「이 러너로 묶기」를 누른다 — 경고가 사라지고 다음 멘션부터 새 러너가 답한다.

  두 러너가 같은 에이전트 id 를 알리면 「다른 러너와 id 가 겹쳐 배정되지 않습니다」 — 한쪽 러너 설정에서 그 에이전트를 뺀다.

## 운영 화면 (admin 이상)

「설정」 → 「운영」 탭(`/settings/operations`). 지난밤 무슨 일이 있었는지 보는 화면이다 — 「상태」(켜진 Gateway 마다 「Gateway 「<이름>」」·「플러그인 「<이름>」」·「Gateway 「<이름>」 버전」 줄, Claude 러너 연결, 디스크 여유, 직전 종료, 서버 — 꺼진 Gateway 는 줄이 없다), 「런」(「오늘」·「7일」, 채널별·에이전트별 런·실패·중지·차단·토큰·금액), 「한도」(「워크스페이스 일일 런 상한」 — 기본 300, 1~10,000, 비우면 무제한), 「최근 사건」(심각도 거르개·「모두 확인」·「더 보기」 — Gateway 사건에는 「Gateway 「집」 연결 끊김」처럼 Gateway 이름이 붙는다).

사이드바 「설정」과 「운영」 탭의 숫자 배지는 확인하지 않은 주의·오류 사건 수다(좁은 화면에서는 메뉴 버튼의 빨간 점). 「모두 확인」을 누르면 사라진다. 칸마다의 뜻(「측정 불가」·「환산 포함」·「런 m/n개만」, 사건 종류, 한도를 세는 법)은 `docs/guides/deploy.md` 「운영 화면」 절이 정본이다.
