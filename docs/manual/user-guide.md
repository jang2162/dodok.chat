# 사용자 매뉴얼 — dodok 웹 앱 쓰기

dodok 웹 앱을 쓰는 사람(owner·admin·member)을 위한 문서다. 로그인부터 채널과 세션에서 에이전트를 부르고, 에이전트·다른 사람과 다이렉트 메시지로 대화하고, 카드에 답하고, 도구 실행을 승인하고, 스레드와 검색을 쓰고, 자동화로 정한 시각·웹훅에 글을 올리고, 멤버와 연결을 관리하는 법을 화면에 보이는 말 그대로 적는다.

- 서버 설치·`.env`·백업·업데이트, 플러그인·러너 설치는 `docs/guides/docker-deploy.md` 가 정본이다.
- 에이전트가 무엇을 받고 어떻게 답하는지(헤더·릴레이 규칙·카드 스키마·에이전트 지시 파일에 붙일 블록)는 `docs/guides/agent-guide.md` 가 정본이다.

화면 문구는 「」로 적는다. 이 문서의 서술이 앱과 다르면 앱이 맞다 — 문구의 정본은 `apps/web/src/features/` 와 `apps/web/src/app/layout/` 이다.

## 역할 — 누가 무엇을 하나

워크스페이스의 사람은 셋 중 한 역할을 갖는다. **owner**(멤버 화면의 「소유자」)는 한 명(서버 `.env` 의 `LOCAL_AUTH_TOKEN` 으로 로그인하는 계정), **admin**(멤버 화면의 「관리자」)과 **member**(「멤버」)는 초대로 들어온다. 「admin 이상」은 owner 를 포함한다.

- 권한이 모자라는 칸은 잠기고 그 자리에 「관리자만 바꿀 수 있습니다」가 붙는다. 권한이 없는 설정 탭은 탭 목록에 없고, 주소로 직접 열면 「권한이 없습니다 — …」가 뜬다(그때도 탭 목록에는 나타나지 않는다).
- 역할이 바뀌면 열린 화면도 곧바로 따른다(다시 로그인하지 않아도 된다).

## 로그인

로그인 화면(`/login`)에는 이메일·비밀번호 폼이 있고, 그 아래에 접힌 「owner 로컬 토큰으로 로그인」이 있다. 공개 가입은 없다 — 사람은 초대 링크로만 들어온다.

### 멤버 — 이메일·비밀번호

「이메일」·「비밀번호」를 넣고 「로그인」. 이메일은 대소문자를 가리지 않는다.

- 틀리면 「이메일 또는 비밀번호가 맞지 않습니다」. 비밀번호 칸만 비워지고 이메일은 남는다.
- 한 주소에서 1분에 다섯 번을 넘으면 「잠시 뒤 다시 시도하세요(1분 5회)」 — 1분 기다린다.
- 비활성화된 계정이면 비밀번호가 맞을 때 「비활성화된 계정입니다. 관리자에게 문의하세요.」 — 관리자에게 다시 활성화를 부탁한다(비밀번호가 틀리면 위의 보통 문구다).

### owner — 로컬 토큰

「owner 로컬 토큰으로 로그인」을 펼쳐 「로컬 토큰」에 서버 `.env` 의 `LOCAL_AUTH_TOKEN` 값을 넣고 「토큰으로 로그인」. 틀리면 「토큰이 맞지 않습니다」. owner 는 이메일·비밀번호 폼으로 로그인할 수 없다.

### 초대 링크로 가입

관리자에게 받은 링크(`…/join/dit_…`)를 열면 「<워크스페이스>에 가입」 폼이 뜨고 그 아래에 받을 역할(「멤버로 초대받았습니다」 또는 「관리자로 초대받았습니다」)이 보인다.

1. 「핸들」 — @멘션에 쓰는 이름. 영문 소문자·숫자·`_`·`-` 로 2~32자. 사람과 에이전트를 통틀어 겹칠 수 없다(「이 핸들은 이미 쓰이고 있습니다」 — 비활성 멤버의 핸들도 그 사람 몫이다).
2. 「표시 이름」(1~64자), 「이메일」, 「비밀번호」(12자 이상)와 「비밀번호 확인」.
3. 「가입」 — 곧바로 로그인되어 첫 채널로 간다.

- 링크는 **한 번만, 7일 안에** 쓴다. 쓰였거나 만료됐거나 폐기된 링크는 「링크를 쓸 수 없습니다」 화면에 「초대가 만료됐거나 이미 쓰였습니다 — 초대한 사람에게 새 링크를 받으세요」가 뜬다(까닭을 가르지 않는다).
- 이미 다른 계정으로 로그인된 브라우저에서 열면 「지금 @<핸들> 로 로그인돼 있습니다 — 가입하면 이 브라우저는 새 계정으로 바뀝니다」가 뜬다.
- 넣은 이메일이 비활성화된 멤버의 것이면 이메일 칸 아래에 「비활성 멤버의 이메일입니다 — 관리자에게 다시 활성화를 요청하세요」. 초대 링크는 쓰이지 않고 남는다 — 그 계정을 다시 쓰려면 관리자가 다시 활성화한다(아래 「멤버·역할」).

### 비밀번호 재설정 링크

메일은 보내지 않는다 — 비밀번호를 잊으면 관리자에게 재설정 링크(`…/reset/drt_…`)를 받는다(관리자 쪽은 아래 「멤버·역할」).

- 링크를 열면 「<워크스페이스> 비밀번호 재설정」 폼이다. 「새 비밀번호」·「비밀번호 확인」을 넣고 「비밀번호 바꾸기」 — 곧바로 로그인되고, **그 사람의 다른 기기·탭의 로그인은 모두 끊긴다.**
- 링크는 **한 번만, 24시간 안에** 쓴다. 지난 링크는 「링크가 만료됐거나 이미 쓰였습니다 — 관리자에게 새 링크를 받으세요」.
- 본인이 「내 계정」에서 비밀번호를 바꾸면 그때까지 쓰이지 않은 재설정 링크는 무효가 된다(같은 문구).
- owner 에게는 재설정 링크가 없다 — owner 비밀번호는 로컬 토큰이다(`docs/guides/docker-deploy.md` 「멤버 초대·비밀번호 재설정·비활성화」 절).

## 화면 구성

- **사이드바(왼쪽)** — 위에서부터 워크스페이스 이름, 「검색」(`⌘K`), 「파일」(아래 「파일함」), 「채널」 목록(새 글이 있는 채널은 굵게, 나를 멘션한 수는 빨간 배지 — 아래 「읽지 않음」)과 「채널 만들기」, 「다이렉트 메시지」 목록과 「+」(아래 「다이렉트 메시지」). 맨 아래 줄에 연결 점 둘과 톱니 「설정」 — 에이전트·자동화·멤버·연결·운영·알림·내 계정·로그아웃은 모두 「설정」 안의 탭에 있다(아래 「설정」). admin 이상에게는 확인하지 않은 운영 사건이 있으면 「설정」에 숫자 배지가 붙는다.
  - **연결 점 둘** — 왼쪽이 Gateway, 오른쪽이 플러그인이다. Gateway 가 여럿이어도 켜진 Gateway 를 모아 점 하나로 보인다 — 초록은 모두 연결, 노랑은 일부 끊김이거나 다시 연결하는 중, 빨강은 켜진 Gateway 가 모두 끊기고 다시 붙는 중인 것도 없을 때다(끊긴 Gateway 는 보통 「다시 연결 중」이라 노랑으로 보인다), 회색은 켜진 Gateway 가 없거나(「Gateway 없음」) 서버와의 실시간 연결이 끊겨 모르는 상태다. 꺼 둔 Gateway 는 세지 않는다. 점에 마우스를 올리거나 Tab 으로 가면 「Gateway 연결됨」·「Gateway 일부 끊김」 같은 이름과 Gateway 마다 한 줄(「집 — 다시 연결 중」 꼴)이 뜬다.
  - **좁은 화면(폰)** 에서는 사이드바가 접혀 헤더의 메뉴 버튼으로 연다.
- **채널 화면(가운데)** — 머리에 `#채널 이름`, 그 아래 지금 세션의 제목(주제가 있으면 「· 주제」), 「세션 목록」·「새 세션」·「세션 닫기」(권한이 있을 때), 채널에 넣은 에이전트 얼굴, 톱니바퀴(「채널 설정」). 그 아래 지금 세션의 메시지 목록, 맨 아래 작성기. 넓은 화면에서는 메시지 목록 왼쪽에 세션 목록 칸이 펼쳐진다(아래 「세션」).
- **오른쪽 패널** — 「설정」·「활동」·「파일」·「스레드」·프로필(아래 「프로필과 접속 상태」) 탭이 같은 자리에 열린다. 톱니바퀴는 설정 탭을, 머리의 「파일」 단추(폴더 아이콘)는 파일 탭을, 메시지의 스레드 버튼은 스레드 탭을, 작성자 이름·아바타는 프로필을 연다. X 로 닫는다. 주소가 세션·탭마다 다르므로(`/c/<채널>/s/<세션>` 아래 `/settings`·`/activity`·`/files`·`/t/<루트>`·프로필) 새로고침이나 링크로 바로 열 수 있다.
- **화면 위 띠** — 연결이 흔들리면 채널 위에 띠가 뜬다. 문구별 뜻은 끝의 「자주 겪는 문제」.

## 채널

### 채널 만들기

사이드바 「채널 만들기」 → 「이름」과 「주제」(선택) → 「만들기」. 누구나 만들 수 있다. 만들면 그 채널의 설정 패널이 열린다 — 「멤버」 칸의 「에이전트 추가」에서 에이전트를 고르고 「추가」로 넣는다. 에이전트가 하나도 등록돼 있지 않으면 먼저 admin 이 「설정」 → 「연결」에서 데려와야 한다(아래 「연결」 절 「에이전트 데려오기·만들기」). 새 채널에는 세션이 없다 — 채널을 열면 새 세션 창이고, 첫 메시지가 첫 세션을 만든다(아래 「세션」).

### 채널 참여

채널은 워크스페이스의 모든 사람이 사이드바에서 보고 연다(다이렉트 메시지는 참여자만 본다 — 아래 「다이렉트 메시지」). 따로 「참여」 버튼은 없다 — 그 채널에 **처음 쓰거나 누가 나를 멘션하면** 저절로 참여된다. 참여한 사람만 에이전트가 받는 「참여자:」 줄에 실리고, 채널 알림(릴레이 한도)을 받는다.

### 채널 보관

다 쓴 채널은 지우지 않고 보관한다 — 기록은 남고 누구나 읽을 수 있으며, 보관 해제하면 그대로 돌아온다. 보관·보관 해제는 admin 이상이다. 채널을 지우는 길은 없다.

- **보관** — 채널 설정 패널 맨 아래 「채널 보관」 → 「채널 보관」 대화상자 「#<이름> 을 보관합니다.」 → 「보관」.
- **보관하면**
  - 사이드바 채널 목록에서 빠진다. 그 채널을 열어 두었던 사람의 화면은 그 자리에서 읽기 전용으로 바뀐다.
  - 채널 머리에 「보관됨」, 작성기 자리에 「보관된 채널입니다.」가 붙는다(admin 이상에게는 옆에 「보관 해제」). 스레드 패널에도 답글 입력이 없고, 「새 세션」·세션 이름 바꾸기·「세션 닫기」도 없으며, 채널 설정 패널은 편집 대신 「보관된 채널입니다.」만 보인다.
  - 카드의 버튼·셀렉트·모달이 잠기고 사유는 「보관된 채널입니다」. 「다시 실행」·「이어가기」도 누를 수 없다 — 카드는 쓰이지 않고 남아 보관 해제 뒤 누를 수 있다.
  - 「반응 추가」 버튼이 없고 달린 반응 칩은 눌러도 바뀌지 않는다 — 마우스를 올리거나 Tab 으로 가면 누가 달았는지는 보인다.
  - 돌던 실행은 「중지」와 같이 멈추고, 걸려 있던 도구 승인 카드는 「취소됨」이 된다. 그 채널에는 새 실행이 생기지 않고 그 채널의 알림(푸시)도 오지 않는다.
  - 보관을 모른 채 보내던 메시지는 「보관된 채널입니다」로 실패하고 「삭제」만 남는다. 채널 설정·파일 첨부도 「보관된 채널입니다」로 막힌다.
- **보관한 채널 찾기** — 「설정」 → 「채널」 탭(`/settings/channels`, 누구나)에 최근 보관한 것부터 `#이름` 과 보관한 날이 있다. 이름을 누르면 그 채널을 읽기 전용으로 연다. 보관한 채널이 없으면 「보관된 채널이 없습니다」. 검색 결과에도 나오고 「보관됨」이 붙는다(아래 「검색」).
- **보관 해제** — 보관한 채널의 작성기 자리 「보관 해제」 또는 「설정」 → 「채널」 탭 줄의 「보관 해제」(admin 이상). 사이드바와 작성기가 돌아오고, 에이전트는 세션마다 같은 대화로 이어 답한다.

## 세션

한 채널 안에서 대화를 주제마다 **세션**으로 나눈다. 세션마다 메시지 목록이 따로이고, 에이전트도 세션마다 따로 기억한다 — 같은 채널의 다른 세션에서 오간 말은 모른다. 채널에 넣은 에이전트·채널 프롬프트·릴레이 정책·자동 응답·일일 실행 상한은 채널 것이라 모든 세션에 같다. 채널의 메시지는 모두 어느 세션 하나에 속하고, 스레드는 그 세션 안에 있다.

- **지금 세션** — 채널 머리 둘째 줄이 지금 세션의 제목이다. 주소는 `/c/<채널>/s/<세션>` 이다. 사이드바에서 채널을 누르면 열린 세션 가운데 최근 활동한 세션으로 가고, 열린 세션이 없으면 새 세션 창으로 간다.
- **세션 목록** — 머리의 「세션 목록」 버튼. 넓은 화면에서는 메시지 목록 왼쪽 칸을 펼치고 접는다. 좁은 화면(폰)에서는 시트로 열리고, 고르거나 닫으면 초점이 「세션 목록」 버튼으로 돌아온다.
  - 최근 활동순(마지막 메시지, 없으면 만든 때)이고 지금 세션이 표시된다. 닫기·한도 알림 같은 시스템 알림은 순서를 올리지 않는다.
  - 「열림」·「닫힘」으로 거르고, 「제목 검색」 칸으로 제목을 찾는다(영문만 대소문자를 가리지 않는다). 20개씩 보이고 「더 보기」로 더 받는다. 없으면 「찾는 세션이 없습니다.」.
  - 줄마다 제목·마지막 활동 시각. 안 읽은 글이 있으면 굵게·점, 나를 멘션한 글이 있으면 그 수의 배지(「나를 멘션한 글 N개」)가 붙는다(「읽지 않음」 절).
- **새 세션** — 머리나 세션 목록의 「새 세션」 → 빈 창(`/c/<채널>/s/new`)이 열린다. **첫 메시지를 보내야 세션이 생긴다** — 눌렀다 떠나면 아무것도 남지 않는다.
  - 제목은 첫 메시지의 앞 40자로 저절로 지어진다(멘션은 `@핸들`, 서식 기호는 빼고 줄바꿈은 공백, 비면 「새 세션」). 바꾸려면 아래 「이름 바꾸기」.
  - 보내면 주소가 그 세션으로 바뀌고, 그사이 쓰던 글·넣은 첨부는 그대로 들고 간다. 첫 메시지의 답(ack)이 오기 전에 둘째 글을 보내도 같은 세션으로 간다.
- **이름 바꾸기** — 머리의 세션 제목을 누른다(권한이 있을 때만 버튼이다) → 「세션 이름 바꾸기」의 「세션 제목」(1~80자 — 비우면 「제목은 1~80자로 씁니다」) → 「저장」. 이 채널의 모든 사람에게 바뀐 이름이 보인다. 닫힌 세션도 이름은 바꿀 수 있다.
- **닫기** — 머리의 「세션 닫기」 → 「「<제목>」 세션을 닫습니다 — 진행 중인 실행은 멈춥니다.」 → 확인. 닫힌 세션은 읽기만 되고 다시 열 수 있다. 세션을 지우는 길은 없다.
  - 그 세션에 「@<핸들> 이(가) 이 세션을 닫았습니다」가 남고, 작성기 자리가 「닫힌 세션입니다」로 바뀐다(권한이 있으면 옆에 「다시 열기」). 다른 사람·다른 탭의 화면도 곧바로 바뀌고, 그때 쓰던 사람의 초점은 그 안내로 간다. 스레드 패널도 답글 입력 대신 안내다.
  - 돌던 실행은 「중지」와 같이 멈추고, 걸려 있던 도구 승인 카드는 「취소됨」이 된다. 카드의 버튼·셀렉트·모달은 「닫힌 세션입니다」로 잠기고 「반응 추가」도 없다. 닫힌 줄 모르고 보내던 메시지는 「닫힌 세션입니다」로 실패하고 「삭제」만 남는다.
  - 닫힌 세션도 세션 목록(「닫힘」)·검색·주소·알림 링크로 열어 읽는다.
- **다시 열기** — 닫힌 세션의 작성기 자리 「다시 열기」 → 「@<핸들> 이(가) 이 세션을 다시 열었습니다」가 남고 작성기가 돌아와 초점이 거기로 간다. 닫히기 전 쓰던 초안도 남아 있다.
- **누가 무엇을** — 열린 세션에 쓰는 것은 누구나다. 새 세션은 채널의 세션 정책대로다(아래). 이름 바꾸기·닫기·다시 열기는 그 세션을 만든 사람, 그 채널의 세션 관리자, admin 이상이다. 권한이 없으면 제목이 버튼이 아니고 「세션 닫기」·「다시 열기」가 보이지 않는다. 보관한 채널에서는 owner 에게도 「새 세션」·이름 바꾸기·「세션 닫기」가 없다.
- **세션 정책·세션 관리자** — 채널 설정의 「세션」 칸. 바꾸는 것은 admin 이상이고, 그 밖의 사람에게는 값만 보이고 잠긴다.
  - 정책 「누구나」(기본)·「세션 관리자만」 — 고르는 즉시 저장된다. 「세션 관리자만」이면 세션 관리자와 admin 이상만 새 세션을 만든다 — 다른 사람에게는 「새 세션」이 없고, 새 세션 창 주소로 들어오면 작성기 대신 「이 채널은 세션 관리자만 새 세션을 만들 수 있습니다.」다. 열린 세션에 쓰는 것은 그대로 누구나다.
  - 「세션 관리자」 — 「사람 선택」에서 활성 멤버를 골라 「세션 관리자 지정」. 채널에 없던 사람이면 채널에 참여된다. 줄의 X(「… 세션 관리자 해제」)로 뺀다. 없으면 「세션 관리자가 없습니다.」.
  - 세션 관리자는 그 채널에서 정책과 상관없이 새 세션을 만들고, 남의 세션도 이름을 바꾸고 닫고 다시 연다.
- **에이전트와 세션** — 같은 에이전트라도 세션마다 대화가 따로라, 한 채널의 두 세션에서 동시에 일한다. 에이전트는 지금 세션에만 쓴다 — 다른 세션·다른 채널로 보내라고 해도 보내지지 않는다. 에이전트의 기억을 비우는 「새 대화」는 없다 — 처음부터 다시 하려면 새 세션을 연다. 에이전트가 무엇을 받는지는 `docs/guides/agent-guide.md` 「세션」 절.
- **「이전 대화」** — 세션이 생기기 전부터 있던 채널은 그때까지의 메시지가 모두 「이전 대화」 세션 하나에 들어 있다. 에이전트도 그 세션에서 전과 같은 대화를 이어 간다.
- **자동화** — 자동화는 자기 세션(제목 「⚙ <자동화 이름>」)에 올린다. 그 세션이 닫혀 있으면 다음 게시가 같은 제목의 새 세션을 만든다.
- 읽지 않음·검색·푸시 링크도 세션마다 따로다(「읽지 않음」·「검색」·「알림·앱 설치·오프라인」 절).

## 다이렉트 메시지

채널 없이 정한 상대하고만 대화한다. 셋이 있다.

- **에이전트 DM** — 나와 에이전트 하나. 에이전트마다 내 DM 이 하나 있고, 그 안에서 대화가 세션으로 쌓인다(위 「세션」과 같은 세션이다). **나만 본다.** 이 절의 아래 목록은 에이전트 DM 의 규칙이다.
- **사람 1:1** — 나와 다른 멤버 한 사람.
- **그룹 DM** — 나를 포함해 사람·에이전트 3~9명(사람만이어도, 에이전트가 들어도 된다). 사람 1:1 과 그룹 DM 은 아래 「사람 1:1·그룹 DM」.

어느 쪽이든 **참여자가 아닌 사람은 owner·admin 도** 그 대화를 화면·검색·알림·운영 화면 어디에서도 볼 수 없다.

- **열기** — 사이드바 「다이렉트 메시지」 절의 「+」(「새 메시지」) → 「새 메시지」 대화상자(「최대 8명」)에서 상대를 여럿 고르고 「열기」. **에이전트 하나만 고르면 그 에이전트와의 에이전트 DM** 이 열리고, 그 밖(사람 하나 — 사람 1:1, 둘 이상 — 그룹 DM)은 그 대화가 열린다. 사람은 활성 멤버, 에이전트는 지금 내 역할로 DM 할 수 있는 것만 목록에 있다(아래 「DM 허용」 — 삭제했거나 꺼 둔 에이전트는 없다). 사람 1:1 은 사람 프로필 패널의 「메시지 보내기」로도 연다(「사람 프로필 패널」 절). 에이전트 DM 은 「설정」 → 「연결」의 에이전트 상세 「DM 보내기」로도 연다 — 주소는 `/dm/<에이전트 id>` 이고 열면 그 DM 의 채널 주소(`/c/<DM>/s/<세션>`)로 넘어간다.
  - 열 수 없는 에이전트를 주소로 열면 「이 에이전트와 DM 을 열 수 없습니다」, 없는 에이전트면 「에이전트를 찾을 수 없습니다」.
  - 사이드바의 「다이렉트 메시지」 목록은 세 가지를 한 목록에 최근 활동순으로 보인다 — 글이 하나라도 있는 것, 그리고 지금 연 것(글이 없어도). 읽지 않으면 굵게·배지. 에이전트 DM 은 에이전트 얼굴·이름, 사람 1:1 은 상대 아바타·접속 점·이름(비활성 상대면 흐리게 「(비활성)」), 그룹은 겹친 아바타와 나를 뺀 참여자 이름 나열.
  - 목록의 DM 은 사이드바에서 닫거나 숨길 수 없다.
- **처음 열면** — 세션이 하나도 없는 DM 은 빈 화면에 「아직 메시지가 없습니다.」가 보인다. DM 은 나만 보지만, 에이전트는 자기 기억(메모리·작업 디렉터리의 파일)을 거쳐 여기서 들은 것을 다른 채널의 답에 쓸 수 있다 — dodok 은 이것을 막지 못한다. 첫 메시지를 보내면 첫 세션이 생긴다.
- **보내기** — DM 에서는 **멘션 없이 모든 글이 그 에이전트에게 간다.** 작성기에 @ 후보가 뜨지 않고, 적은 `@핸들` 은 글자로만 남는다 — 다른 에이전트·사람을 부르지 않고 알림도 가지 않는다. 에이전트의 답에 든 `@핸들` 도 글자다(릴레이가 없다).
- **세션** — 채널의 세션과 같다(「새 세션」, 제목 바꾸기, 「세션 닫기」·「다시 열기」, 세션마다 에이전트의 기억이 따로). 머리의 「세션 목록」은 세션을 **오늘·어제·이번 주·이전** 으로 묶어 보인다(이 기기의 시간대, 마지막 활동 기준). 「제목 검색」은 제목만 찾는다 — 본문은 ⌘K 검색에서 찾는다(결과의 채널 자리가 「DM · <에이전트 이름>」).
- **머리** — 에이전트 얼굴·이름·제공자(러너 에이전트면 「러너 · <프로그램> · <러너 이름>」 — 예: 「러너 · Claude Code · 맥북」), 지금 세션 제목, 「이 DM 의 지시」, 「새 세션」, 「세션 닫기」, 「활동」(오른쪽 패널은 활동 탭뿐이다). 채널 설정·참여 에이전트 묶음은 없다 — DM 에는 사람·에이전트를 넣거나 뺄 수 없고, 이름·주제·보관·세션 정책도 없다.
- **「이 DM 의 지시」** — 이 DM 의 에이전트가 매 턴 함께 받는 지시다(채널의 「채널 프롬프트」 자리로 간다 — 반영 시점도 같다, 「채널 설정」 절). 20,000자까지, 「저장」. 비우고 저장하면 지운다. 바꾸는 것은 DM 의 주인뿐이다(역할과 무관).
- **스레드는 없다** — DM 메시지에는 스레드 버튼이 없다. 주제를 가르려면 새 세션을 연다.
- **도구 승인** — DM 안의 도구 승인 카드·확인 카드는 **DM 의 주인이 결정한다**(member 주인도). 알림·푸시도 주인에게만 간다.
- **읽기 전용** — 작성기 자리에 사유 한 줄이 보이고 쓰기·반응·「새 세션」·지시 바꾸기가 막힌다. 기록은 그대로 읽힌다.
  - 「보관된 에이전트라 읽기만 할 수 있습니다」 — admin 이상이 그 에이전트를 삭제했다.
  - 「꺼진 에이전트라 읽기만 할 수 있습니다」 — 그 에이전트의 사용 스위치가 꺼졌다.
  - 「이 에이전트와의 DM 이 허용되지 않아 읽기만 할 수 있습니다」 — 「DM 허용」이 좁아졌거나 내 역할이 내려가 그 범위 밖이 됐다.
  - 되돌리면(되살리기·켜기·허용) 그 자리에서 작성기가 돌아와 이어 쓴다. 읽기 전용이 되기 전에 보냈지만 아직 차례를 기다리던 실행은 돌지 않고 「중지」로 닫힌다 — 이미 돌던 실행은 끝까지 돈다. 그사이 보내던 글은 사유 문구로 실패하고 「다시 보내기」가 없다. 카드의 버튼은 잠긴 것처럼 보이지 않지만, 누르면 거절 문구가 뜨고 아무것도 바뀌지 않는다.
- **「DM 허용」** — 「설정」 → 「연결」의 에이전트 상세에 있다. 누가 그 에이전트와 **새** DM 을 여나다(그 에이전트 연결의 주인과 admin 이상이 바꾼다, 고르는 즉시 저장).
  - 「끔」 — 아무도 열 수 없다. 「admin 이상」(기본) — owner·admin. 「모두」 — member 도. 「모두」면 member 가 그 DM 의 도구 승인을 스스로 결정한다 — 러너 에이전트면 member 가 그 러너 머신에서 도구를 돌리게 된다는 뜻이다.
  - 좁히면 범위 밖 사람의 DM 은 지우지 않고 읽기 전용이 된다(위). 넓히면 그대로 이어 쓴다.
- **누가 보나** — 그 DM 의 주인만이다. owner·admin 의 사이드바·검색·알림·운영 화면에 남의 DM 은 없고, 주소로 직접 열어도 없는 채널과 같다. 운영 화면은 DM 의 실행을 누구의 것인지 없이 「DM」 한 줄로만 센다. 주인이 비활성화되면 DM 은 남고 아무도 못 보며, 다시 활성화하면 돌아온다.
  - **서버 운영자는 DB 로 볼 수 있다** — 메시지는 서버의 DB 파일에 다른 채널과 같이 저장된다. 화면·API 가 막는 것이지 암호화가 아니다.
  - **막지 못하는 것 — 에이전트 자신의 기억.** 에이전트는 DM 에서 들은 것을 자기 메모리·작업 공간 파일(OpenClaw 의 워크스페이스 메모리·`AGENTS.md`, 러너 에이전트의 프로젝트 디렉터리)에 남겼다가 다른 채널의 답에 쓸 수 있다. dodok 이 막는 것은 다른 채널의 에이전트가 도구로 내 DM 을 읽는 길과 DM 의 에이전트가 다른 채널로 보내는 길이다.
- 읽지 않음 — DM 에서 에이전트가 쓴 글은 모두 「나를 멘션한 글」로 세어 사이드바 DM 줄·세션 목록에 배지가 붙는다(「읽지 않음」 절).

### 사람 1:1·그룹 DM

- **같은 상대 묶음이면 같은 대화다.** 고른 순서·누가 열었는지와 무관하게 같은 참여자면 이미 있는 그 대화가 열린다. 참여자는 연 뒤에 더하거나 뺄 수 없다 — 다른 묶음이 필요하면 새로 연다. 이름·주제·「지시」·나가기·보관은 없다.
- **에이전트를 넣을 수 없을 때** — 나를 포함한 참여자 **가운데 한 사람이라도** 그 에이전트의 「DM 허용」 밖이거나 에이전트가 꺼져 있으면 열리지 않고 대화상자에 그 에이전트를 짚은 거절 문구가 뜬다. 누가 범위 밖인지는 말하지 않는다(남의 역할이 드러나지 않게). 예를 들어 「DM 허용」이 「admin 이상」(기본)인 에이전트는 member 가 든 묶음에 넣을 수 없다 — 그 에이전트 상세에서 「모두」로 넓힌 뒤 연다.
- **한 줄기 — 사람 1:1 과 사람만인 그룹.** 세션 목록·「새 세션」·세션 제목·활동 탭이 없고 대화가 하나로 이어진다. 스레드는 연다(「스레드」 절).
- **세션 — 에이전트가 든 그룹.** 채널처럼 세션 목록·「새 세션」·활동 탭이 있고, 새 세션·제목 바꾸기·닫기는 **참여자 누구나** 한다. 세션이 하나도 없으면 빈 화면에 「아직 메시지가 없습니다.」가 보인다. 에이전트는 자기 기억을 거쳐 여기서 들은 것을 다른 자리의 답에 쓸 수 있다 — dodok 은 이것을 막지 못한다. 스레드도 연다.
- **머리** — 사람 1:1 은 상대 아바타·접속 점·이름·상태 메시지(누르면 상대 프로필), 그룹은 겹친 아바타와 이름 나열(누르면 「참여자」 목록 — 줄마다 프로필). 보관된 에이전트를 빼면 상대가 한 사람만 보이는 그룹은 이름 뒤에 「(그룹)」이 붙어 1:1 과 갈린다(사이드바·검색도 같다).
- **@멘션은 참여자에게만 된다.** 작성기의 @ 후보는 참여자뿐이고, 참여자가 아닌 사람·에이전트를 `@핸들` 로 적어도 글자로만 남는다 — 그 사람·에이전트를 끌어들이지 않고 알림도 가지 않는다.
- **에이전트는 멘션받을 때만 답한다**(자동 응답이 없다). 에이전트 답의 `@참여 에이전트` 는 채널처럼 릴레이가 된다(턴 한도 4). 그 실행을 **시킨 사람**(멘션한 사람, 카드는 누른 사람)이 그 에이전트의 「DM 허용」 밖이면 실행되지 않고 그 대화에 「@<핸들> 는 이 요청에 답하지 않았습니다 — 시킨 사람이 이 에이전트의 DM 허용 범위 밖입니다」가 남는다. 카드 누르기·「다시 실행」이 막히면 누른 사람에게 같은 뜻의 알림이 뜨고 아무것도 바뀌지 않는다(버튼은 그대로). 이미 실행 중인 것은 시킨 사람의 역할이 내려가도 끝까지 돈다.
- **도구 승인은 시킨 사람만 결정한다**(역할과 무관 — 참여한 admin 도 시킨 사람이 아니면 못 누른다). 다른 참여자에게는 카드가 보이되 결정 단추 자리에 「@<시킨 사람 핸들> 님이 결정합니다」가 보인다. 승인 알림·실패 알림도 시킨 사람에게만 간다.
- **알림·읽지 않음** — 다른 참여자의 글(사람·에이전트)은 멘션이 없어도 모두 「나를 멘션한 글」로 세어 배지가 붙고 푸시가 간다(제목 「<이름> 님의 메시지」 또는 「@<핸들>이 답했습니다」, 본문 「DM」).
- **검색** — 참여한 대화의 글이 찾힌다. 결과 줄의 채널 자리는 「DM · <참여자 이름>」(1:1 은 상대 이름, 그룹은 나를 뺀 이름 나열)이다.
- **읽기 전용** — 사람 1:1 의 상대가 비활성화되면 「상대가 비활성화되어 읽기만 할 수 있습니다」가 작성기 자리에 보이고 쓰기·반응이 막힌다. 다시 활성화하면 그 자리에서 이어 쓴다. 그 사람이 든 그룹은 그대로 쓴다. 비활성 멤버와는 새 대화를 열 수 없다.
- **누가 보나** — 참여자만이다. 비활성화된 참여자는 볼 수 없고 다시 활성화하면 돌아온다. 운영 화면은 실행을 「DM」 한 줄로만 센다.
  - **서버 운영자는 DB 로 볼 수 있다** — 에이전트 DM 과 같다(위 「누가 보나」).
  - **막지 못하는 것 — 에이전트 자신의 기억.** 그룹 DM 의 에이전트도 들은 것을 자기 메모리·작업 공간 파일에 남겼다가 다른 자리의 답에 쓸 수 있다.

## 읽지 않음

사이드바가 어느 채널에, 세션 목록이 그 채널의 어느 세션에 새 글이 있는지 보인다. 어디까지 읽었는지는 서버가 사람마다·**세션마다** 기억하므로, 한 기기·탭에서 읽으면 다른 기기·탭에서도 함께 지워진다.

- **굵은 채널 이름** — 그 채널의 세션 가운데 하나라도, 마지막으로 읽은 뒤 다른 사람·에이전트·자동화가 쓴 메시지가 있다. 스레드 답글, 시스템 알림(실행 실패·릴레이 한도 같은 카드), 반응은 세지 않는다. 지금 보고 있는 채널은 굵게 하지 않는다.
- **빨간 숫자 배지** — 읽지 않은 메시지 가운데 나를 @멘션한 것의 수(그 채널 모든 세션의 합). 스레드 답글 속 멘션도 센다 — 그래서 굵지 않은 채널에 배지만 있을 수 있다. 99개 이상이면 「99+」. 내가 쓴 글은 굵게·배지 어느 쪽에도 세지 않는다.
- **세션 목록의 점·배지** — 같은 규칙을 세션마다 보인다. 사이드바 채널 링크는 최근 활동한 세션으로 가므로, 배지가 다른 세션 몫이면 세션 목록에서 배지가 붙은 세션을 찾아 연다.
- 아래의 「채널 끝」·「채널에 들어갈 때」는 지금 보는 **세션 하나**를 말한다 — 한 세션을 끝까지 읽어도 같은 채널의 다른 세션은 그대로 안 읽음이다.
- **언제 읽음이 되나** — 세션의 맨 끝 메시지가 화면에 보이고 그 탭이 보이는 동안이면 약 1초 뒤 그 세션이 끝까지 읽음이 된다. 그 세션의 스레드 답글 속 멘션도 함께 읽음이 된다 — 스레드를 따로 열어 보지 않아도 세션을 끝까지 보면 배지가 지워진다. 세션에 메시지를 보내도(스레드 답글 말고) 그때까지 읽음이 된다.
  - **읽음이 되지 않는 때** — 위로 올려 옛 글을 보는 동안, 안 읽은 메시지가 있는 채널을 열어 「새 메시지」 선에서 읽는 동안(끝까지 내리거나 「새 메시지 N개」를 눌러 끝에 가면 그때 읽음이 된다), 검색 결과로 간 자리(「최신 메시지로」를 눌러 끝에 가면 그때 읽음이 된다), 다른 탭에 가려 있거나 창이 내려가 있는 동안, 스레드 패널만 볼 때, 좁은 화면(폰)에서 스레드·활동·설정 시트가 채널을 덮고 있는 동안. 좁은 화면의 채널 목록(메뉴) 시트는 덮고 있어도 뒤의 채널이 읽음이 된다.
  - 읽음은 거꾸로 돌아가지 않는다 — 「안 읽음으로 표시」는 없다.
- **「새 메시지」 구분선** — 세션에 들어갈 때 아직 읽지 않았던 첫 메시지(다른 사람·에이전트의 그 세션 글) 위에 「새 메시지」 선이 그어진다. 읽고 나서도 그 채널을 떠날 때까지 그 자리에 있고, 다시 들어오면 그때의 위치로 다시 그어진다.
  - **안 읽은 채널은 그 선에서 열린다** — 선이 화면 위쪽에 오고 그 위로 앞 메시지가 한두 줄 보인다. 이때는 끝을 본 것이 아니라서 읽음이 되지 않고, 목록 아래에 선 뒤에 온 메시지 수(내 글 말고 — 시스템 알림 카드도 센다)를 센 「새 메시지 N개」가 뜬다. 끝까지 내리거나 그 버튼을 누르면 끝으로 가고 읽음이 된다. 안 읽은 글이 한 화면에 다 들어와 선과 끝이 함께 보이면 곧바로 읽음이 된다. 안 읽은 글이 없거나 한 번도 읽은 적이 없는 채널이면(아래 새 멤버) 끝에서 연다. 채널에 머무는 동안 새 글이 오거나 스레드·설정 패널을 여닫아도 다시 선으로 끌려가지 않고, 채널을 떠났다 다시 들어오면 그때 다시 선에서 연다. 검색 결과로 가기·「처음 안 읽은 곳으로」는 각자 가는 곳으로 간다.
  - 안 읽은 것이 많아 그 자리가 아직 불러오지 않은 옛 메시지 쪽이면 목록 위에 「안 읽은 메시지가 더 있어요 · 처음 안 읽은 곳으로」가 뜬다. 다만 불러온 목록의 맨 앞이 바로 처음 안 읽은 메시지면(그 사이가 스레드 답글뿐) 배너 없이 그 앞 구분선에서 열린다 — 그것을 서버에 묻는 동안 목록 자리에 불러오는 중 표시가 잠깐 보인다. 배너를 누르면 처음 안 읽은 메시지 주변을 불러와 구분선으로 가고, 거기서 아래 「최신 메시지로」로 끝에 돌아온다. 한 번 누른 배너는 그 채널을 떠날 때까지 다시 뜨지 않는다. 배너를 누르지 않고 위로 올려 그 자리까지 불러오면 배너가 사라지고 구분선이 목록 가운데에 생긴다.
  - 이 창에서 열었다가 몇 분(약 5분) 안에 다시 들어간 채널은 안 읽은 메시지까지 이어 받은 뒤 선에서 열린다 — 다 받을 때까지는 선과 끝이 함께 보여도 읽음을 보내지 않고 받는 글을 따라 내려가지도 않으며, 선이 생기면 그 자리로 내려앉고 다 받으면 그 자리에서 끝이 보이는지를 다시 본다. 그 사이 목록을 직접 움직였으면 그 자리에 둔다. 몇 초(약 5초) 안에 다 받지 못하면 그때 가진 것으로 판단한다. 그보다 오래 지났거나 그사이 쌓인 것이 아주 많으면(약 1,000개 넘게) 처음 여는 것처럼 끝에서 열리고 배너가 뜬다.
  - 앱을 막 열었을 때 읽음 현황이 채널보다 늦게 오면 처음 연 그 채널에는 떠날 때까지 구분선이 없다 — 구분선이 늦게 튀어나와 화면이 밀리지 않게 그렇게 한다.
  - 새로 들어온 멤버는 기존 채널의 기록을 처음부터 안 읽은 것으로 본다 — 사이드바에는 굵게·배지로 보이지만, 한 번도 읽은 적이 없는 채널은 선이 아니라 끝에서 열려(채널의 첫 글부터 읽게 하지 않는다) 끝이 보이면 읽음이 된다. 기록이 많으면 위에 「처음 안 읽은 곳으로」 배너가 뜬다.
- **굵게·배지가 하나도 안 보일 때** — 서버와의 실시간 연결이 끊겼거나 현황을 받지 못한 것이다. 틀린 숫자를 보이는 대신 아무것도 그리지 않는다. 현황을 받다가 서버가 잠깐 답하지 못하면(배포 중 등) 몇 초 간격으로 세 번 더(답이 아예 없으면 한 번에 10초씩 기다려 길게는 1분 가까이) 다시 받아 저절로 돌아오고, 그래도 못 받으면 다시 붙을 때 새로 받아 돌아온다. 오프라인 사본으로 보는 동안에도 보이지 않는다.
- 보관한 채널은 사이드바에 없으므로 굵게·배지도 없다. 보관 해제하면 그 사람이 읽었던 자리 그대로 돌아온다.

## 메시지 쓰기

작성기에 「메시지 보내기 — @로 에이전트 부르기」가 보인다. **Enter** 로 보내고 **Shift+Enter** 로 줄을 바꾼다. 한글을 조합하는 중의 Enter 는 조합만 끝낸다.

같은 채널 작성기에 다른 사람이 쓰고 있으면 작성기 위에 「@<핸들> 작성 중…」(여럿이면 「@mia, @jo 작성 중…」처럼 쉼표로)이 보이고, 입력이 멈추면 몇 초 안에 사라진다. 자기 입력(다른 탭 포함)과 스레드 작성기의 입력은 보이지 않고, 에이전트도 여기에 뜨지 않는다 — 에이전트가 일하는 중인지는 답 버블이 보인다(아래 「스트리밍 버블과 중지」).

### 러너 에이전트 상태 줄

그 대화에 러너 에이전트(채널에 넣은 것, DM 이면 그 DM 의 에이전트)가 있으면 작성기 바로 위에 에이전트마다 한 줄이 붙는다 — `@coder  opus · effort high · default · 컨텍스트 42%  변경`. 정하지 않은 값은 「모델 기본」·「effort 기본」·「권한 기본」, 그 세션에서 그 에이전트가 아직 돈 적이 없으면 「컨텍스트 —」. 러너 에이전트가 넷 이상이면 「러너 에이전트 N」 한 줄로 접히고 「펼치기」로 연다. OpenClaw 에이전트에는 줄이 없다.

- **「변경」** — 모델(「기본」·sonnet·opus·haiku·「직접 입력」), effort(「기본」·low·medium·high·xhigh·max), 권한 모드(「기본」·plan·dontAsk·default·acceptEdits)를 골라 「저장」. 바꾼 값은 **다음 실행부터** 쓰이고, 같은 대화를 보는 다른 사람의 줄도 곧바로 바뀐다. 실패하면 팝오버 안에 사유가 남는다.
- **누가 무엇을 고르나** — 그 대화를 볼 수 있는 사람은 모델·effort 와 default 이하의 권한(plan·dontAsk·default·「기본」)을 고른다. acceptEdits 는 그 러너(연결)의 주인과 admin 이상만 — 그 밖의 사람에게는 막혀 「러너 주인·admin 만 올릴 수 있습니다」가 붙는다. 러너 상한 위는 누구도 못 고른다(「러너 상한(<모드>) 위는 고를 수 없습니다」).
- **권한 「기본」** 은 실행 때 default 와 그 러너의 상한 가운데 낮은 쪽이다 — 상한이 plan 인 러너에서도 첫 실행이 거절되지 않는다. 사람이 고른 값이 나중에 내려간 상한보다 높으면 깎지 않는다 — 실행이 「러너 설정이 이 에이전트를 허용하지 않습니다(permissionMode)」 카드로 멈추니 값을 낮추고 「다시 실행」한다.
- **새 세션 창**(첫 글 전)에도 줄이 있다 — 에이전트의 새 세션 시작값에서 출발하고, 바꾼 값은 화면에만 있다가 **첫 글을 보낼 때** 함께 가서 그 세션의 설정이 된다. 보내지 않고 떠나면 버린다.
- **스레드 작성기** 의 줄은 그 대화의 값을 보이고, 컨텍스트 % 만 그 스레드에서의 마지막 실행 값이다.
- 컨텍스트 % 는 그 세션(스레드면 그 스레드)에서 그 에이전트의 마지막 실행이 쓴 컨텍스트를 그 모델의 창 크기로 나눈 것이다 — 실행이 끝날 때마다 바뀐다.

### @멘션

`@` 를 치면 「멘션 후보」 목록이 뜬다 — 이 채널에 넣은 에이전트가 먼저, 그다음 워크스페이스의 사람이다. 핸들·이름의 앞부분으로 좁혀지고 한 번에 8개까지 보인다. 화살표로 고르고 Enter(또는 클릭)로 넣는다. 사용을 꺼 둔 에이전트는 흐리게 「꺼짐」이 붙는다(부를 수는 있지만 답하지 않는다).

- **에이전트를 멘션하면** 그 에이전트가 답한다. 여럿을 멘션하면 각자 답한다.
- **에이전트 멘션이 없으면**(사람만 멘션했어도) 채널 설정에서 「자동 응답」을 켠 에이전트(채널에 하나)가 답한다. 켠 에이전트가 없으면 아무도 답하지 않는다.
- **사람을 멘션하면** 그 사람에게 알림이 간다. 사람 멘션은 에이전트를 부르지 않지만, 에이전트 멘션이 없는 메시지라서 자동 응답 에이전트는 답한다.
- 에이전트가 다른 에이전트를 멘션하면 그 에이전트가 이어받는다(릴레이 — 아래 「에이전트 답 보기」).
- OpenClaw 에이전트는 후보 옆에 Gateway 이름이 작게 붙는다. 두 Gateway 에 같은 id 의 에이전트(예: 둘 다 `main`)가 있으면 등록할 때 정한 핸들로 가른다(`@main`·`@main-home`) — 멘션은 그 핸들의 Gateway 로 간다.

누가 무엇을 받는지의 규칙은 `docs/guides/agent-guide.md` 「릴레이 — 에이전트가 에이전트를 부를 때」 절.

### 서식·코드 블록

작성기는 마크다운을 그 자리에서 바꾼다 — `- `·`1. ` 은 목록, `> ` 는 인용, `**굵게**`, `` `코드` ``, 그리고 ```` ``` ```` 다음에 언어 이름과 공백(예: ```` ```ts ````)을 치면 코드 블록이 된다. 코드 블록 안에서는 Shift+Enter 가 코드 줄을 바꾼다. 제목(`#`)은 쓰지 않는다 — 평문으로 간다.

받은 메시지는 마크다운으로 그려지고, 코드 블록은 언어별로 칠해지며 「코드 복사」 버튼이 붙는다.

### 파일 첨부

작성기 왼쪽의 「파일 첨부」 버튼, **붙여넣기**, **작성기 상자에 끌어다 놓기** 세 길이 있다. 파일 고르기 창은 모든 형식을 보인다.

- **사진**(PNG·JPEG·GIF·WebP)은 한 장 5 MiB(「5 MB 를 넘습니다」), **그 밖의 파일**(PDF·zip·SVG 등 형식 제한 없음)은 한 개 20 MiB(「20 MB 를 넘습니다」)까지다. 한 메시지에 10개까지(「첨부는 한 번에 10개까지 보낼 수 있습니다」).
  - 사진인지는 서버가 파일 내용으로 다시 판별한다. 브라우저가 사진이라 하지 않았는데(예: 확장자가 사진이 아님) 서버가 사진으로 보면 사진 상한이 걸려 같은 「5 MB 를 넘습니다」가 뜬다. 반대로 이름만 `.png` 인 HTML 은 파일로 저장되고 칩·메시지에 파일 카드로 보인다.
- **빈 파일과 폴더는 보낼 수 없다** — 빈 파일은 칩에 「빈 파일은 보낼 수 없습니다」, 폴더를 끌어다 놓으면 칩 없이 「폴더는 보낼 수 없습니다」.
- 고른 파일은 작성기 위 「첨부할 파일」 칩 목록에 올라가며 바로 업로드된다 — 사진은 미리보기, 그 밖은 아이콘·크기, 올리는 중에는 진행 막대. 칩의 X 로 뺀다. 올리는 중에는 「파일을 올리는 중입니다」, 실패한 칩이 있으면 「올리지 못한 파일을 빼 주세요」라며 보내기가 잠긴다.
- 붙여넣기에 글이 함께 있으면 글도 들어간다.
- 작성기 밖(메시지 목록 등)에 놓으면 받지 않고 「파일은 입력 칸에 놓아 주세요」.
- 에이전트는 멘션한 메시지에 붙은 사진을 본다. 사진이 아닌 파일은 에이전트에게 **이름 한 줄로만** 가고 내용은 가지 않는다(`docs/guides/agent-guide.md` 「파일·이미지」 절).
- 보낸 사진·파일은 그 대화의 「파일」 탭과 사이드바 「파일」에 모인다(「파일함」 절).

### 명령 — `/stop`

메시지 맨 앞에 쓰면 보내지 않고 명령으로 처리한다.

- `/stop` — 이 세션 최상위(스레드 작성기면 그 스레드)에서 돌고 있는 에이전트 실행을 모두 멈춘다. 같은 세션의 스레드 실행·다른 세션 실행은 멈추지 않는다. 없으면 「진행 중인 실행이 없습니다」.
- `/new` 는 명령이 아니다 — 보통 글로 간다. 새로 시작하려면 「새 세션」(「세션」 절).

### 보내지 못했을 때

연결이 끊긴 동안은 「연결되면 보낼 수 있습니다」로 보내기가 잠긴다. 보낸 메시지가 서버에 닿지 못하면 그 자리에 「전송 실패」와 「다시 보내기」·「삭제」가 붙는다. 너무 빨리 보내면 「너무 빠르게 보내고 있습니다 — 잠시 뒤 다시」 — 「다시 보내기」는 같은 메시지라 에이전트가 두 번 답하지 않는다.

## 에이전트 답 보기

### 스트리밍 버블과 중지

에이전트가 답을 쓰는 동안 그 자리에 버블이 뜨고 글이 실시간으로 늘어난다. 버블 머리에 상태가 붙는다 — 「대기 중」, 「도구 사용 중」, 「승인 대기 중」. 답이 끝나면 버블이 확정 메시지로 바뀐다.

- 오른쪽 위 「중지」 — 그 실행을 멈춘다(누구나). 멈추면 잠시 「중지됨」이 보이고 버블이 사라진다. 작성기의 `/stop` 도 같다.
- 실행이 실패하면 버블에 잠시(3초) 「실행 실패: <코드>」가 보인다. 무엇이 있었는지는 「활동」 탭에 남는다.

### 실패와 「다시 실행」

에이전트에게 닿지 못했거나(연결 끊김) 시간 안에 끝나지 않은 실행, Gateway 가 사유를 붙이지 않고 실패한 실행(코드 `unknown` — 인증 만료·한도 초과로 CLI 가 죽은 경우가 많다)은 채널에 「@<에이전트> 실행이 실패했습니다」 시스템 카드와 1회용 「다시 실행」 버튼을 남긴다. 코드는 접힌 「자세히」를 펼치면 보인다(「러너의 … 로그인을 확인하세요」처럼 풀어 쓴 사유는 본문에 그대로). 사유가 붙은 Gateway 오류(`provider_error` 등)는 런 버블에만 보이고 카드가 없다.

- 「다시 실행」은 채널의 사람 누구나 누를 수 있고, **24시간** 동안 쓸 수 있다. 같은 메시지로 새 실행을 만든다 — 연결을 고친 뒤 누른다.
- 카드나 「이어가기」로 생긴 실행에는 붙지 않는다(다시 만들 메시지가 없다).
- 답이 이미 채널에 있는 실행에는 붙지 않는다 — 답이 온 뒤 시간 안에 끝나지 않아 실패 카드가 남아도 「다시 실행」은 없고, 실패한 뒤 답이 늦게 오면 그 실행의 「다시 실행」이 닫힌다(누르면 같은 일이 두 번 돈다).
- 실행 중에 OpenClaw Gateway 와의 연결이 끊겼다 다시 붙으면, 그 실행에서 120초 동안 아무 소식이 없을 때 정리된다 — 끊긴 사이 답이 이미 와 있었으면 「다시 실행」 없이 끝난 것으로 닫히고, 답이 없었으면 `ADAPTER_UNAVAILABLE` 실패 카드와 「다시 실행」이 남는다. 도구를 쓰는 중이었거나 도구 승인을 기다리던 실행은 이 정리에서 빠진다 — 승인 만료나 실행 시간 상한(10분)으로 닫힌다.
- 코드별 뜻은 끝의 「자주 겪는 문제」.

### 릴레이와 한도 알림

에이전트가 다른 에이전트를 멘션해 일을 넘기는 사슬(릴레이)은 채널 설정의 「턴 상한」(기본 4)을 넘거나 같은 말이 되풀이되면 멈추고, 채널에 이렇게 남는다.

- 「릴레이 한도(<N>턴)에 도달했습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 또는 「같은 내용의 릴레이가 반복되어 멈췄습니다. 계속하려면 사람이 멘션하거나 이어가기를 누르세요.」 — 1회용 「이어가기」를 누르면 멈췄던 에이전트에게 이어서 간다. 이 채널에 참여한 사람에게 푸시도 간다.
- 일일 실행 한도에 닿으면 「오늘 런 한도(<N>)에 도달했습니다 — 내일 0시에 풀립니다」(채널 한도면 앞에 「이 채널의 」)가 세션마다, 스레드면 그 스레드마다 그날 한 번 남는다 — 스레드에 먼저 남았어도 그 세션 최상위에서 막히면 최상위에 한 번 더 남는다. 사람의 메시지는 그대로 저장되고 에이전트만 답하지 않는다. admin 이상에게는 카드 아래 「채널 설정에서 한도 바꾸기」 또는 「운영에서 한도 바꾸기」 링크가 붙는다. 「0시」는 서버 시간대의 자정이다.

멈추는 네 가지 사유와 이어가기의 동작은 `docs/guides/agent-guide.md` 「릴레이가 멈추는 네 가지」 절.

## 에이전트 카드 — 버튼·셀렉트·모달

에이전트는 답에 카드를 붙여 선택이나 입력을 받는다. 카드를 누른 결과는 에이전트에게 다음 턴으로 가고, 에이전트가 그것을 받아 이어 답한다.

- **버튼** — 누르면 곧바로 보낸다.
- **셀렉트** — 목록에서 고르고(여럿을 고르는 셀렉트는 「최대 <N>개까지 고를 수 있습니다」) 「보내기」. 덜 골랐으면 「하나를 고르세요」·「<N>개 이상 고르세요」가 남는다.
- **모달** — 버튼을 누르면 양식이 열린다. 칸을 채우고 「제출」(「취소」로 닫는다). 칸 아래에 「필수 항목입니다」·「숫자를 입력하세요」 같은 까닭이 뜨면 고친 뒤 제출한다. 필수(`required`) 체크박스는 체크해야 제출된다.
- **결과 줄** — 카드 아래에 누가 무엇을 보냈는지 오래된 것부터 「@<핸들> — <항목>: <값>」 꼴로 남는다(새로고침·다른 기기에서도 보인다). 20줄이 차면 「최근 20건」이 붙는다.
- **눌리지 않을 때** — 버튼 아래에 까닭이 보인다: 「이미 처리되었습니다」(1회용 카드를 누가 이미 눌렀다), 「만료되었습니다」, 「이 항목을 쓸 권한이 없습니다」(에이전트가 누를 사람을 정해 두었다), 「연결이 끊겨 지금은 보낼 수 없습니다」, 「보내는 중입니다」.
- 일일 한도에 막힌 클릭은 「오늘 런 한도에 도달했습니다 — 한도가 풀리면 다시 누를 수 있습니다」 — 카드가 소비되지 않으니 한도가 풀린 뒤 다시 누른다.

카드의 모양·제약·에이전트가 받는 글은 `docs/guides/agent-guide.md` 「components v1 — 카드로 묻고 받기」 절.

## 메시지의 이미지·파일

- **이미지** — 메시지 안에 격자로 보인다. 누르면 크게 보기가 열리고, 여러 장이면 「이전 이미지」·「다음 이미지」로 넘기며, 「원본 내려받기」로 받는다.
- **파일** — 이름·크기·종류가 적힌 파일 카드의 「내려받기」로 받는다. 에이전트 파일은 한 개 20 MiB 까지다(사람이 올리는 상한은 「파일 첨부」).
- 카드가 같은 메시지의 파일을 가리킬 수 있다(「열기」). 가리킨 파일이 없으면 「첨부를 찾을 수 없습니다」.

## 도구 승인 카드

에이전트가 승인이 필요한 도구(파일 쓰기·명령 실행 등)를 부르면 실행이 「승인 대기 중」으로 멈추고, 채널 흐름과 「활동」 탭 맨 위에 같은 승인 카드가 뜬다.

- 카드에는 제목·심각도(「정보」·「주의」·「위험」), `@에이전트 · 도구 이름`, 남은 시간(「<n>분 <n>초 남음」)이 있다. 「인자 보기」로 도구에 넘길 값을 펼친다 — 길면 「잘렸습니다.」가 붙는다.
- 러너 에이전트의 카드는 요약(명령·경로)을 바로 보이고, 「전체 보기」로 도구에 넘길 입력 전체를 편다 — 요약의 가운데가 줄었을 때 묻힌 부분을 여기서 본다. 요약이 비어 있어도(예: 빈 명령) 입력 전체를 펼 수 있다. 입력 전체도 16,000자를 넘으면 끝이 잘리고 「잘렸습니다.」가 붙는다. 입력 전체는 member 도 본다 — `Write` 의 `content` 처럼 파일 본문이 카드에 실릴 수 있다. 「전체 보기」가 없으면 러너가 옛 판이다 — 러너를 다시 설치하면 보인다(`docs/guides/docker-deploy.md` 「러너 설치」 절).
- **admin 이상**이 「이번만 허용」·「항상 허용」·「거절」 중 하나를 누른다(에이전트 쪽이 허용한 결정만 버튼이 된다). member 에게는 버튼 대신 「관리자가 결정합니다」가 보인다. **다이렉트 메시지 안의 승인은 그 DM 의 주인이 결정한다** — 주인이 member 여도 버튼이 보인다(아래 「다이렉트 메시지」). 그룹 DM 안의 승인은 그 실행을 시킨 사람만 결정한다(역할과 무관) — 다른 참여자에게는 「@<시킨 사람 핸들> 님이 결정합니다」가 보인다.
- 결정하면 카드가 「허용됨」·「거절됨」으로 바뀌고 「선택: <결정>」이 남는다. 다른 사람이 먼저 눌렀으면 그 결과가 모든 화면에 같이 반영된다.
- 아무도 누르지 않고 시간이 지나면 「만료됨」·「시간이 지나 답할 수 없습니다.」 — 거절로 확정된다. 기한은 OpenClaw 에이전트면 Gateway 가 정하고, 러너 에이전트면 10분이다. 실행을 중지하면 기다리던 승인은 「취소됨」.
- 승인 요청은 워크스페이스의 owner·admin 전원에게 브라우저 알림·푸시로도 간다(아래 「알림·앱 설치·오프라인」). 다이렉트 메시지 안의 승인은 그 DM 의 주인에게만 간다(알림 본문 「DM」). 그룹 DM 안의 승인은 시킨 사람에게만 간다.
- 「항상 허용」의 범위와 어떤 도구에 승인을 걸지는 에이전트 쪽 설정이다 — `docs/guides/agent-guide.md` 「승인 카드」 절, 러너 에이전트는 그 대화의 권한 모드(「메시지 쓰기」 절 「러너 에이전트 상태 줄」)와 그 상한인 러너 설정(`docs/guides/docker-deploy.md` 「러너 설치」 절).

### 확인 카드 — 에이전트가 채널·에이전트 설정을 바꾸려 할 때

에이전트는 채널 이름·주제·프롬프트·에이전트 구성 같은 설정을 도구로 바꿀 수 있다(`docs/guides/agent-guide.md` 「제어 도구 — 채널·에이전트 설정 읽고 바꾸기」 절). 그 권한은 **그 일을 시킨 사람**의 것이고, 바꾸기 전에 그 사람에게 확인 카드가 뜬다.

- `update_agent` 확인 카드 요약은 에이전트 화면과 같은 이름을 쓴다 — OpenClaw 에이전트는 「메모:」, 러너 에이전트는 「지시:」(러너 에이전트의 지시는 제어 도구로 바꿀 수 없어 카드 전에 거절된다).
- 카드 제목은 「@<에이전트> 가 #<채널> 의 채널 프롬프트를 바꾸려 합니다」 꼴, 그 아래 바뀔 내용(프롬프트는 앞 300자)과 출처 줄 — 「시킨 사람: @mia」, 「시작한 글: @mia · #dev · 42번째 글 「…」」, 다른 에이전트를 거쳐 왔으면 「릴레이: @a → …」. 「주의: … 그 런이 끝난 뒤에 왔습니다 — 직접 시킨 일인지 확인하세요」가 붙으면 내가 시킨 일인지 먼저 확인한다.
- 카드는 **10분** 안에 결정이 없으면 저절로 닫힌다(「만료됨」). OpenClaw 에이전트가 낸 카드는 **5분**이다 — 카드 위의 「N분 N초 남음」을 본다.
- **버튼은 시킨 사람 본인에게만** 「허용」·「거절」로 보인다(「항상 허용」은 없다). owner·admin 이라도 남이 시킨 카드에는 버튼 대신 「@mia 의 확인을 기다립니다」가 보이고, 알림·푸시도 시킨 사람에게만 간다.
- 허용하면 설정이 바뀌고 채널에 「@mia 의 요청으로 @ops 가 채널 프롬프트를 바꿨습니다」가 남는다. 카드에는 「허용됨」과 「선택: 허용 · @mia」. 거절하면 「거절됨」 — 에이전트는 「@mia 가 거절했습니다」를 받는다.
- **10분** 안에 누르지 않으면 「만료됨」, 그 사이 실행이 끝나거나 중지되면 「취소됨 (실행 중지)」이다. 허용할 때 내 역할을 다시 본다 — 그 사이 역할이 내려갔으면 허용해도 바뀌지 않는다.
- 내 역할로 할 수 없는 일(member 가 시킨 채널 프롬프트 바꾸기 등)이면 카드가 뜨지 않는다 — 에이전트가 곧바로 「이 일은 admin 이상만 할 수 있습니다(시킨 사람: @mia, member)」를 받아 답에 적는다. 자동화 글이 시작한 실행은 시킨 사람이 없어 설정을 바꾸지 못한다.

## 활동 탭 — 실행과 도구 기록

채널 패널의 「활동」 탭은 이 채널의 실행(런) 목록이다. 줄마다 `@에이전트`, 상태(「대기 중」·「응답 중」·「도구 사용 중」·「승인 대기」·「마무리 중」·「완료」·「실패」·「중지됨」), 시작 시각·걸린 시간.

줄을 고르면 아래에 그 실행의 도구 타임라인이 열린다 — 도구 이름, 진행 상태(「진행 중」·완료·실패), 걸린 시간, 「인자 보기」·「결과 보기」, 승인이 걸린 도구에는 「승인」 표시와 결정. 도구를 쓰지 않은 실행은 「도구 기록이 없습니다.」. 도는 중인 실행은 실시간으로 늘어난다.

## 스레드

어떤 메시지든(사람·에이전트 모두) 마우스를 올리면 오른쪽 위에 「스레드에서 답하기」 버튼이 보인다(터치 화면에서는 늘 보인다). 누르면 오른쪽 패널에 「스레드」 탭이 열리고, 「스레드에 답하기 — @로 에이전트 부르기」 작성기에서 그 스레드 안으로 쓴다.

- 스레드는 그 메시지가 있는 세션 안에 있다.
- 채널의 원래 메시지 아래에는 「답글 <N>개」와 마지막 답글 시각이 적힌 칩이 붙고, 누르면 스레드가 열린다.
- **에이전트는 스레드마다 대화가 따로다** — 스레드에서 오간 말은 그 세션의 대화에 섞이지 않고, 세션의 에이전트도 스레드 대화를 모른다.
- **누가 답하나** — 스레드에서 멘션한 에이전트가 그 스레드에 답한다. **에이전트 멘션이 없으면** 스레드를 연 메시지가 에이전트의 것일 때 그 에이전트가, 아니면 채널의 자동 응답 에이전트가 답한다 — 에이전트 답에 이어 물을 때는 멘션 없이 스레드에 쓰면 된다.
- 스레드 안의 스레드는 없다. 답글에서 「스레드에서 답하기」를 누르면 그 스레드가 열린다.

## 반응

메시지에 이모지로 짧게 답한다 — 👍 👎 ❤️ 😂 🎉 👀 ✅ ❓ 여덟 개뿐이다. 누구나 단다.

- **달기** — 메시지에 마우스를 올리면(키보드로는 그 메시지 안으로 Tab) 오른쪽 위 「스레드에서 답하기」 옆에 「반응 추가」(웃는 얼굴) 버튼이 보인다. 터치 화면에서는 늘 보인다. 누르면 여덟 개가 한 줄로 뜬다 — 눌러서 고르거나, ←·→(↑·↓)·Home·End 로 옮기고 Enter. Esc 로 닫으면 초점이 버튼으로 돌아온다. 스레드 패널 안의 메시지에서도 같다.
- **칩** — 메시지 아래에 이모지마다 단 사람 수가 `👍 3` 꼴로 붙는다. 내가 단 칩은 테두리·글자가 강조된다. 칩에 마우스를 올리거나 Tab 으로 가면 단 사람이 「@mia, @owner」로 보인다(비활성 멤버는 「@<핸들> (비활성)」).
- **칩 누르기** — 칩을 누르면 그 이모지의 내 반응을 켜고 끈다(내가 단 칩을 누르면 뗀다). 한 메시지에 여러 이모지를 달 수 있고, 같은 이모지는 한 사람이 한 번이다.
- 다른 사람이 달거나 떼면 열린 화면에 곧바로 보인다. 스레드를 연 원래 메시지는 채널과 스레드 패널에 함께 보이는데, 어느 쪽에서 달아도 둘이 같이 바뀐다.
- 저장하지 못하면(연결이 끊겼거나 너무 빨리 눌렀다) 칩이 서버가 아는 상태로 돌아가고 「반응을 저장하지 못했습니다」가 뜬다.
- **달 수 없는 것** — 시스템 카드(실행 실패·세션 닫기 알림 같은 것)와 아직 보내는 중인 내 메시지. 보관한 채널과 닫힌 세션은 「반응 추가」가 없고 칩을 눌러도 바뀌지 않는다(「채널 보관」·「세션」 절).
- **반응은 알리지 않는다** — 채널을 굵게 하거나 배지를 늘리지 않고 푸시도 가지 않는다.
- **에이전트가 쓴 메시지의 반응은 그 에이전트에게 간다** — 반응만으로는 에이전트가 답하지 않는다. 다음에 그 에이전트를 부를 때(그 세션, 스레드 답글이면 그 스레드) 그 사이 달린 반응이 함께 실려, 에이전트가 「지난 답에 👍 가 달렸다」를 안다. 그 전에 뗀 반응은 가지 않는다. 사람이나 자동화가 쓴 메시지의 반응은 에이전트에게 가지 않는다. 에이전트가 무엇을 받는지는 `docs/guides/agent-guide.md` 「반응 — 지난 턴 뒤 내 메시지에 달린 것」 절.

## 검색

사이드바 「검색」 또는 **`⌘K`**(Windows·Linux 는 `Ctrl+K`). 「메시지 검색」 칸에 치면 바로 찾는다.

- **2글자 이상**이어야 찾는다(「2글자 이상 입력하세요」). 2글자 검색은 최근 90일에서 50개까지만 찾는다(「2글자는 최근 90일에서 50개까지만 찾습니다」). 3글자 이상은 전체 기간에서 찾고 「더 보기」로 더 받는다.
- 위의 거르개로 채널(「모든 채널」·내 DM 은 「DM · <에이전트 이름>」), 작성자(「모두」·「사람」·「에이전트」·「자동화」), 시작·끝 날짜를 좁힌다.
- 결과는 채널·세션 제목·작성자·시각과 일치한 부분을 보인다. 일치한 부분은 메시지에 보이는 글자로 나온다 — 멘션은 `@핸들`(모르는 대상은 `@알 수 없음`), 굵게·코드·링크 같은 서식 기호는 빠진다. 스레드 답글은 「스레드 답글」, 보관한 채널의 결과는 「보관됨」 표시가 붙는다 — 누르면 그 채널을 읽기 전용으로 연다. 「모든 채널」 거르개 목록에는 보관한 채널이 없다(「모든 채널」로 찾으면 보관한 채널의 결과도 나온다).
- **`@핸들`로 찾으면 그 멘션이 든 메시지를 찾는다** — 「@dev」는 dev 를 멘션한 메시지, 「@dev 보고서」는 dev 멘션 바로 뒤에 「보고서」가 오는 메시지다. 에이전트·사람의 지금 핸들(삭제한 에이전트·비활성 멤버도 그 핸들)과 채널 별칭으로 찾고, 핸들이 바뀌기 전에 쓴 메시지도 지금 핸들로 찾힌다. 같은 핸들이 사람·에이전트 둘이면 둘 다 찾는다. 멘션이 되지 않고 글자로 남은 `@핸들`(그 채널에 없는 대상, 코드 안)도 함께 찾는다. 모르는 핸들은 글자 그대로 찾는다.
- **결과를 누르면 그 세션의 그 메시지로 간다**(지금 보는 세션이 아니어도) — 오래된 메시지면 그 주변을 불러와 그 자리를 보여 준다. 스레드 답글이면 그 스레드가 열린다. 그 사이 지워진 메시지면 「메시지를 찾을 수 없습니다」. 키보드 초점도 그 메시지에 놓인다(답글이면 스레드 패널의 그 답글) — 다만 도착하기 전에 입력 칸에서 쓰고 있었으면 초점을 뺏지 않는다. 결과를 고르지 않고 Esc 로 닫으면 연 자리로 돌아간다.
- 첨부 파일 이름으로도 찾힌다 — macOS 에서 올린 한글 파일 이름(조합형)도 같은 글자로 찾힌다.
- **다이렉트 메시지** — 내 DM 의 글도 찾힌다. 결과 줄의 채널 자리는 에이전트 DM 이면 「DM · <에이전트 이름>」, 사람 1:1·그룹 DM 이면 「DM · <참여자 이름>」이다. 참여하지 않은 DM 은 owner·admin 에게도 결과·개수 어디에도 나오지 않는다. 위의 채널 거르개 목록에도 내 에이전트 DM 이 「DM · <에이전트 이름>」으로 있다 — 그 DM 하나로 좁힐 수 있다.

## 파일함

대화에서 오간 사진·파일을 모아 본다. 지우는 단추는 없다 — 파일은 메시지의 일부다.

- **대화마다 — 「파일」 탭.** 채널·에이전트 DM·사람 DM(1:1·그룹) 머리의 「파일」 단추(폴더 아이콘)로 오른쪽 패널의 「파일」 탭을 연다. 그 대화(모든 세션과 스레드 답글)의 사진·파일이 최신순으로 보인다.
- **모든 대화 — 사이드바 「파일」.** 내가 볼 수 있는 모든 대화(일반 채널·내 에이전트 DM·참여한 사람 DM)의 파일을 한 화면에 모은다. 줄마다 어느 대화인지(「#채널 · 세션 제목」·「DM · <이름>」)가 붙고, 「대화」(「모든 대화」)로 한 대화만 고른다. 남의 에이전트 DM·참여하지 않은 사람 DM 의 파일은 owner·admin 에게도 보이지 않는다.
- **좁히기** — 「전체」·「사진」·「파일」로 종류를 고르고, 「이름으로 찾기」로 이름 일부를 찾고(macOS 의 조합형 한글도 같은 글자로 찾힌다), 「올린 사람」(「모두」)으로 좁힌다. 「전체」는 사진 격자와 파일 줄을 나눠 보인다. 50개씩 보이고 「더 보기」로 더 받는다. 걸리는 것이 없으면 「조건에 맞는 파일이 없습니다」와 「거름 지우기」, 아직 아무것도 없으면 「아직 주고받은 파일이 없습니다」.
- **줄마다 「내려받기」와 「메시지로 가기」** — 사진은 눌러 크게 본 뒤 「원본 내려받기」·「메시지로 가기」. 「메시지로 가기」는 패널(좁은 화면이면 시트)을 닫고 그 세션의 그 메시지로 가 강조하고 초점을 놓는다 — 넓은 화면에서도 패널이 닫힌다. 스레드 답글이면 그 스레드가 열린다.
- 보관한 채널의 파일도 남고 「보관됨」이 붙는다(사이드바 「파일」의 「대화」 고르기에는 보관한 채널이 없다). 읽기만 되는 DM 의 파일도 보인다.

## 프로필과 접속 상태

사람과 에이전트 모두 프로필이 있고, 아바타 오른쪽 아래의 작은 점이 접속 상태다.

- **프로필 열기** — 세션 화면에서 타임라인의 작성자 이름·아바타, @멘션 칩, 「채널 설정」의 에이전트 줄, DM 머리(에이전트 DM 의 에이전트, 사람 1:1 의 상대, 그룹 DM 의 「참여자」 목록 각 줄)를 누르면 오른쪽 패널에 프로필이 열린다(「설정」·「활동」·「스레드」와 같은 자리 — 좁은 화면에서는 전체 화면, X 로 닫는다). 주소가 따로 있어 새로고침·뒤로 가기가 그대로 된다. 「설정」의 멤버 표처럼 세션 화면 밖에서는 열리지 않는다. 지워졌거나 없는 대상이면 「프로필을 찾을 수 없습니다.」.
- **점이 어디에 있나** — 타임라인의 작성자 아바타, 사이드바 「다이렉트 메시지」 목록의 에이전트 얼굴, 프로필 패널. 점에 마우스를 올리거나 Tab 으로 가면 상태 이름이 뜬다.

### 사람의 점

| 점의 이름 | 뜻 |
| --- | --- |
| 접속 중 | 그 사람의 보이는 탭이 하나라도 있다 |
| 자리 비움 | 탭은 열려 있지만 모두 가려져 있다(다른 창 뒤·접힌 탭). 또는 그 사람이 스스로 「자리 비움」을 골랐다 |
| 다른 용무 중 | 그 사람이 스스로 골랐다 |
| 방해 금지 | 그 사람이 스스로 골랐다 — 아래 「방해 금지」 |
| 오프라인 | 열린 연결이 없다(새로고침·재접속은 20초 안에 다시 붙으면 오프라인으로 바뀌지 않는다). 또는 그 사람이 「오프라인으로 보이기」를 골랐다 — 남에게는 다른 오프라인과 구별되지 않는다 |

- 비활성 멤버는 점이 없고 「비활성」만 보인다.
- 서버를 다시 띄운 직후 몇 초는 사람들이 다시 붙을 때까지 모두 오프라인으로 보인다.

### 에이전트의 점

에이전트는 상태를 고를 수 없다 — 점은 자동이다.

| 점의 이름 | 뜻 |
| --- | --- |
| 응답 가능 | 연결돼 있고 돌고 있는 런이 없다 |
| 작업 중 | 끝나지 않은 런이 있다 — 어느 채널·DM 의 런인지는 드러나지 않는다(남의 DM 런이어도 「작업 중」은 보인다) |
| 연결 끊김 | OpenClaw 는 그 에이전트의 Gateway 가 없거나 플러그인이 붙어 있지 않다. 러너 에이전트는 맡을 러너가 없거나 폐기됐거나 붙어 있지 않다 |
| 꺼짐 | 사용 스위치를 껐다(「연결」 탭의 에이전트 상세) |

보관한 에이전트는 점이 없고 「보관됨」이 보인다.

### 사람 프로필 패널

큰 아바타와 점, 표시 이름, `@핸들`, 「역할」, 「상태」(점의 이름 — 수동 상태에 만료가 있으면 「· 15:00 까지」꼴), 「상태 메시지」(이모지 + 글), admin 이상에게는 「이메일」. 방해 금지 중이면 상태와 따로 「방해 금지 중」(만료가 있으면 「· 15:00 까지」) 줄이 붙는다 — 오프라인이어도 보인다. 단추 「멘션」은 작성기에 그 사람의 `@핸들` 칩을 넣는다. 남의 활성 멤버 패널에는 「메시지 보내기」가 있어 그 사람과의 1:1 을 연다(「다이렉트 메시지」 절). 내 패널에는 「상태 바꾸기」가 있어 「내 계정」의 프로필 섹션과 같은 칸을 패널 안에서 연다.

### 에이전트 프로필 패널

큰 아바타와 점, 이름과 「에이전트」 표지(꺼졌으면 「꺼짐」, 보관했으면 「보관됨」), `@핸들`, 「상태」, 「연결」(OpenClaw 는 Gateway 이름, 러너 에이전트는 러너 이름 · 프로그램 — 묶이지 않았으면 「묶이지 않음」, Gateway 가 지워졌으면 「Gateway 없음」), 「소유자」(그 에이전트를 만든 사람의 `@핸들` — 기록이 없으면 「기록 없음」), 「DM 허용」(「끔」·「admin 이상」·「모두」). 소유자는 보여 주기만 한다 — 에이전트 설정은 그 에이전트 연결의 주인과 admin 이상이 한다. 단추는 「DM 열기」(지금 내 역할로 그 에이전트와 DM 을 열 수 있을 때만)와 「멘션」, admin 이상에게는 「에이전트 설정」(「연결」 탭의 그 에이전트 상세로 간다).

- **member 에게 보이는 것은 여기까지다.** 러너 에이전트의 「금지 도구」·접힌 「기본 프롬프트」와 에이전트 사진 바꾸기는 이 패널에서는 admin 이상에게만 보인다(자기 연결의 에이전트를 관리하는 member 는 「연결」 탭의 에이전트 상세에서 본다).

### 방해 금지

- 알림(푸시)을 멈추는 것은 「방해 금지」 하나뿐이다. 「자리 비움」·「다른 용무 중」·「오프라인으로 보이기」는 남에게 보이는 점만 바꾸고 알림은 그대로 온다.
- 방해 금지 중에는 푸시(멘션·릴레이 한도·내 DM 의 에이전트 답과 실패·사람 1:1·그룹 DM 의 다른 참여자 글)가 오지 않는다. 읽지 않음 배지·멘션 배지·타임라인은 그대로 갱신된다.
- 「도구 승인 요청은 계속 받기」(기본 켜짐) — 켜 두면 방해 금지 중에도 도구 승인 푸시는 온다(놓치면 런이 멈춰 기다린다). 끄면 승인 푸시도 멈춘다. 만료가 지난 방해 금지는 방해 금지가 아니다.

## 채널 설정

채널 머리의 톱니바퀴(「채널 설정」) 또는 패널의 「설정」 탭. 저장은 칸마다 「저장」 버튼으로 하고, 저장되면 「저장했습니다」가 잠깐 뜬다.

- **기본**(누구나) — 「이름」·「주제」.
- **채널 프롬프트**(admin 이상) — 이 채널의 모든 세션·모든 에이전트가 매 턴 함께 받는 지시. 20,000자까지. 저장하면 「다음 턴부터 반영됩니다.」가 뜬다. OpenClaw 에이전트는 이미 대화한 세션(이 채널의 세션)에 온전히 반영되지 않고 새 세션부터 반영된다 — 행동 규칙을 확실히 반영하려면 새 세션을 연다. 러너 에이전트는 채널 프롬프트·릴레이 정책(턴 상한·쌍·일일 실행 상한)·어느 에이전트의 오버라이드든 바뀌면 다음 실행부터 앞 작업 맥락을 이어 가지 않고, 그 자리(스레드면 스레드)에 「채널 규칙이 바뀌어 @<에이전트> 이 앞 작업 맥락(도구 결과·긴 작업)을 이어 가지 않습니다 — 채널의 최근 글은 그대로 봅니다」가 남는다 — 채널의 최근 글은 그대로 보므로 세션의 대화는 이어진다.
- **릴레이 정책**(admin 이상)
  - 「턴 상한」 — 에이전트끼리 이어 부르는 횟수(0~32, 기본 4). 0 이면 릴레이가 없다.
  - 「일일 실행 상한」 — 이 채널에서 하루에 만들 실행 수(1~999,999,999). 비우면 상한 없음.
  - 「모든 에이전트끼리 허용」 — 끄면 쌍 목록이 나와, 체크한 쌍(보내는 쪽 → 받는 쪽)만 릴레이한다(64쌍까지). 에이전트가 둘 이상이어야 고를 수 있다.
- **세션** — 세션 정책(「누구나」·「세션 관리자만」)과 세션 관리자 목록. 바꾸는 것은 admin 이상이다(「세션」 절).
- **멤버** — 이 채널의 에이전트 목록과 「에이전트 추가」. 목록과 「에이전트 추가」 고르기 모두 OpenClaw 에이전트에 Gateway 이름이 붙는다. 줄마다:
  - 「자동 응답」(admin 이상) — 에이전트 멘션이 없는 메시지에 답할 에이전트. 채널에 하나뿐이라 다른 에이전트를 켜면 「자동 응답 바꾸기」 확인이 뜬다.
  - 「채널 프롬프트 오버라이드」(admin 이상, 「편집」) — 이 채널에서 이 에이전트에게만 더하는 지시. 20,000자까지.
  - 「제거」(누구나) — 채널에서 뺀다. 그 에이전트의 오버라이드·자동 응답 설정도 사라진다.

프롬프트가 에이전트에게 언제 어떤 꼴로 닿는지, 무엇을 적으면 좋은지는 `docs/guides/agent-guide.md` 「채널 프롬프트와 채널 지시」·「채널 프롬프트 쓰는 법」 절.

## 설정

사이드바 맨 아래 「설정」(`/settings`). 탭은 역할대로 보인다 — 「내 계정」·「알림」·「연결」·「채널」은 누구나, 「자동화」·「멤버」·「운영」은 admin 이상.

| 탭 | 주소 | 이 문서의 절 |
| --- | --- | --- |
| 내 계정 | `/settings/account` | 「내 계정」 |
| 알림 | `/settings/notifications` | 「알림·앱 설치·오프라인」 |
| 연결 | `/settings/connection` | 「연결」 |
| 채널 | `/settings/channels` | 「채널 보관」 |
| 자동화 | `/settings/automations` | 「자동화 (admin 이상)」 |
| 멤버 | `/settings/members` | 「멤버·역할」 |
| 운영 | `/settings/operations` | 「운영 화면 (admin 이상)」 |

- **넓은 화면** — 채널 목록 옆에 왼쪽 탭 목록이 붙어 있고, 오른쪽 탭 내용만 따로 스크롤한다. `/settings` 를 열면 「내 계정」으로 간다.
- **좁은 화면(폰)** — 「설정」을 누르면 탭 목록이 먼저 나온다. 탭을 누르면 그 화면으로 들어가고, 위에 메뉴 버튼과 「← 설정」이 붙는다(스크롤해도 위에 남는다). 「← 설정」으로 탭 목록에 돌아온다.
- 탭 목록에서 탭을 고르면 초점이 그 탭의 제목으로 간다.
- 운영 탭에도 「설정」과 같은 숫자 배지가 붙는다(admin 이상).
- 옛 주소 `/agents`·`/settings/agents`·`/settings/runners`(즐겨찾기·옛 링크)는 `/settings/connection` 으로 넘어간다.

## 연결

「설정」 → 「연결」 탭(`/settings/connection`, 누구나). OpenClaw Gateway·러너 같은 **연결**과 그 아래 프로젝트·에이전트를 한 화면에서 따라간다. 왼쪽(폰은 첫 화면)이 목록, 줄을 누르면 오른쪽(폰은 다음 화면)에 상세가 열린다. 처음 설치 순서와 토큰 교체 절차는 `docs/guides/docker-deploy.md` 「체크리스트 — 처음 배포」·「브리지 토큰 교체」·「Gateway 수정·끄기·삭제」·「러너 설치」 절이 정본이다 — 여기는 화면에서 하는 일만 적는다.

### 연결의 주인과 승인

- 연결(Gateway·러너)마다 **주인**이 있다 — 그 연결을 만든 사람이다. 이 기능 전부터 있던 연결의 주인은 워크스페이스 owner 다. 주인은 바꿀 수 없고, 주인인 멤버를 비활성화해도 연결은 그대로 돈다(admin 이상이 계속 관리한다).
- 그 연결의 프로젝트·에이전트는 따로 주인이 없고 **연결의 주인을 따른다**. 주인은 member 여도 자기 연결과 그 안의 프로젝트·에이전트를 처음부터 끝까지 관리한다. admin 이상은 모든 연결을 관리한다.
- 거기서 나온 에이전트는 개인 비서가 아니다 — 채널에 넣으면 그 채널 멤버 누구나 부른다.
- **member 가 만든 Gateway 는 「승인 대기」**로 시작한다 — admin 이 승인할 때까지 서버가 그 주소에 접속하지 않는다(member 가 넣은 주소로 서버가 사내망 안을 두드리지 않게). admin 이상이 만든 Gateway 는 만들 때 승인된다. 승인된 Gateway 의 **주소**를 member 가 바꾸면 다시 승인 대기가 된다(이름·토큰만 바꾸면 그대로). 승인 전에도 브리지 토큰 발급·플러그인 설치는 할 수 있다 — 플러그인은 이 서버로 붙는 쪽이다. 「에이전트 가져오기」 목록은 승인 뒤에야 채워진다.
- 러너는 러너 머신에서 이 서버로 나가는 연결이라 승인이 없다 — 대신 러너 머신의 설정(루트·상한)이 그 머신 주인의 유일한 안전장치다(`docs/guides/docker-deploy.md` 「러너 설치」 절의 「드러나는 것 넷」).

### 목록

- 「내 연결」(내가 주인인 연결)과 「다른 사람의 연결」로 나뉜다 — 내 연결이 없으면 묶음 제목 없이 한 묶음이다.
- 줄 하나가 한 항목이다 — Gateway(이름·「Gateway」·상태 배지 「연결됨」·「재연결 중」·「페어링 대기」·「꺼짐」·「연결 안 됨」·「승인 대기」), 러너(이름·「러너」·「연결됨」·「끊김」·「폐기됨」), 그 아래 프로젝트, 그 아래 에이전트(이름·`@핸들`, 꺼진 에이전트는 「(꺼짐)」). 줄에는 이름·핸들·상태만 있고 고치는 것은 모두 상세에서 한다.
- 「연결 없음」(있을 때만) — Gateway 가 삭제된 OpenClaw 에이전트(「— Gateway 가 삭제됨」), 러너가 없거나 토큰이 폐기된 러너 에이전트(「— 러너 없음」·「— 러너 토큰이 폐기됨」).
- 「삭제된 에이전트 N」(있을 때만, 접힌 채) — 누르면 펼쳐 줄마다 그 에이전트 상세로 간다(되살리기는 거기에).
- 「＋ 연결 추가」는 누구에게나 보인다. 연결이 하나도 없으면 「아직 연결이 없습니다.」.
- 넓은 화면에서 탭 주소만 열면 오른쪽에 「왼쪽에서 연결이나 에이전트를 고르세요.」. 폰에서는 상세 화면 위의 「← 연결」로 목록에 돌아온다.
- 상세 주소마다 화면이 있어 새로 고침·링크·뒤로 가기가 그대로 된다 — `/settings/connection/gateway/<id>`·`/runner/<id>`·`/project/<id>`·`/agent/<id>`·`/new`. 없는 id 거나 그새 지워졌으면 「이 연결을 찾을 수 없습니다」(에이전트는 「이 에이전트를 찾을 수 없습니다」, 프로젝트는 「이 프로젝트를 찾을 수 없습니다」)와 「← 연결」.

### 누구에게 무엇이 보이나

트리(이름·상태·주인·프로젝트·에이전트)는 누구에게나 같다. 연결의 주소·토큰·설치 안내가 든 섹션은 **그 연결의 주인과 admin 이상**에게만 보인다.

| | 남의 연결(member) | 자기 연결(member) | admin·owner |
| --- | --- | --- | --- |
| Gateway 상세 | 머리(이름·상태·주인)와 「에이전트 N」 | 전부(플러그인·브리지 토큰·수정·끄기·삭제·「에이전트 가져오기」), 승인 대기면 그 한 줄 | 전부, 승인 대기면 주소와 「승인」 |
| 러너 상세 | 머리(이름·상태·주인)·그 러너의 에이전트 | 전부(판본·루트·프로그램·「프로젝트 N」·「설치 안내」·「러너 토큰」) | 전부 |
| 프로젝트 상세 | 「권한이 없습니다」 | 전부 | 전부 |
| 에이전트 상세 | 값만(「관리자만 바꿀 수 있습니다」) | 전부 | 전부 |
| 연결 추가 | 전부 | 전부 | 전부 |

### Gateway 상세

머리에 이름·상태 배지와 그 Gateway 의 주인·admin 이상에게 「수정」·「끄기」(꺼져 있으면 「켜기」)·「삭제」, 그 아래 한 줄 「OpenClaw Gateway · 주인 <이름> · <주소> · <버전>」(버전이 저장소가 검증한 것과 다르면 「— 저장소가 검증한 버전(<핀>)과 다릅니다」). 다른 사람에게는 「OpenClaw Gateway · 주인 <이름>」만. 주인·admin 이상에게는 섹션 셋이 더 있다.

- **승인 대기**(member 가 만든 Gateway) — admin 이상에게는 「승인 대기 — 승인하면 서버가 이 주소에 접속합니다」와 그 주소 한 줄, 「승인」. 누르면 곧바로 접속을 시작한다(꺼 둔 Gateway 면 꺼진 채). 주인(member)에게는 머리의 「승인 대기」만 보인다.

- **「플러그인」** — 페어링을 기다리면 맨 위에 승인 명령(「승인 명령 복사」, 5분을 넘으면 「5분 넘게 승인을 기다리고 있습니다.」). 켜진 채 끊겨 있으면 「Gateway 주소·토큰과 서버 로그를 확인하세요.」. 그 아래 한 줄 「접속됨 · 플러그인 <판> · SDK <판> · Gateway <판>」(없으면 「접속한 플러그인이 없습니다.」)과 「서버와 같은 빌드입니다」 — 다르면 「다른 빌드입니다 — 「새 토큰 발급」의 설치 명령을 다시 돌리세요」. 설치 상자는 플러그인이 아직 안 붙었으면 「플러그인 설치」로 펼쳐 두고, 붙어 있으면 「다시 설치」로 접는다 — 「아래 「새 토큰 발급」이 주는 명령 한 줄을 Gateway 호스트에서 돌립니다.」(서버에 플러그인 파일이 없으면 만드는 명령). Gateway 가 서비스(systemd·launchd)로 깔려 있지 않으면 그 명령은 「이 호스트의 Gateway 가 서비스로 깔려 있지 않아 설치하지 않았습니다」로 멈춘다 — Gateway 를 직접 내린 뒤 같은 명령의 `bash` 앞에 `DODOK_GATEWAY_SERVICE=0` 을 붙여(`… | DODOK_GATEWAY_SERVICE=0 DODOK_BRIDGE_TOKEN='…' bash`) 다시 돌리고, 끝나면 Gateway 를 직접 올린다(순서는 `docs/guides/docker-deploy.md` 「[웹 → B] 플러그인 설치·브리지 토큰」 절).
- **「브리지 토큰」** — 플러그인이 이 서버에 붙을 때 쓰는 토큰. 「새 토큰 발급」 → 라벨 → 「발급」. 원문(`dbt_…`)과 설치 명령 한 줄은 **발급 직후 한 번만** 보인다 — 복사한 뒤 「복사했습니다」. 목록에서 지금 붙어 있는 토큰에 「지금 접속 중」이 붙고, 새 토큰으로 옮겨 간 뒤 옛 줄에 「이제 폐기해도 됩니다 — 플러그인이 새 토큰으로 접속해 있습니다」가 뜨면 옛 줄의 「폐기」. 마지막 남은 토큰을 폐기하려 하면 확인이 한 번 더 뜬다. 쓸 수 있는 토큰이 없으면 「쓸 수 있는 토큰이 없습니다 — 발급하세요」.
- **「에이전트 N」** — 이 Gateway 의 에이전트 줄(누르면 그 에이전트 상세). 주인·admin 이상에게는 「에이전트 가져오기」(아래 「에이전트 데려오기·만들기」).
- 「수정」 — 이름·주소·토큰(토큰 칸은 「바꾸려면 입력」 — 비우면 그대로). 주소나 토큰을 바꾸면 이 Gateway 만 다시 붙고, 진행 중인 런은 「다시 실행」 카드로 닫힌다. member 가 주소를 바꾸면 승인 대기로 돌아가 끊긴다.
- 「끄기」 — 곧바로 끊는다. 진행 중인 런은 「다시 실행」 카드로 닫히고, 꺼진 동안 그 Gateway 의 에이전트를 부르면 곧바로 실패 카드가 남는다.
- 「삭제」 — 상세 안에서 「「<이름>」 Gateway 를 삭제할까요?」와 「이 Gateway 의 에이전트 N개는 남고 브리지 토큰 M개가 지워집니다」로 한 번 더 묻는다. 지우면 목록으로 돌아가 「「<이름>」 Gateway 를 삭제했습니다」. 남은 에이전트는 「연결 없음」에 서고, 그 에이전트 상세의 「Gateway 옮기기」로 다른 Gateway 에 옮긴다.

### 러너 상세

러너 하나가 러너 토큰 하나다. 머리에 이름과 「연결됨」·「끊김」·「폐기됨」, 그 아래 「러너 · 주인 <이름> · dodok-runner <판본>」. 붙어 있으면 루트 라벨(둘러보기를 끈 러너면 「(둘러보기 꺼짐)」)과 프로그램 줄 「Claude Code <판본> (설치본|내장) · 로그인됨|로그인 안 됨|로그인 모름 (평소 로그인|전용 로그인) · 권한 상한 <모드> · 허용 도구 상한 <목록|없음>」(판본 뒤 괄호는 러너가 띄우는 CLI 다 — 「설치본」은 러너 머신에 설치된 `claude`(또는 러너 설정 `executable` 의 실행 파일)와 그 `claude --version` 판, 「내장」은 그 머신에 `claude` 가 없어 러너 패키지에 든 CLI 와 그 판. 판은 러너가 붙을 때 읽는다 — `claude` 를 업데이트했으면 러너를 다시 띄운 뒤 바뀐다. 로그인 뒤 괄호는 러너가 어느 로그인을 쓰는지다 — 「평소 로그인」은 러너 머신의 평소 `claude` 로그인, 「전용 로그인」은 러너 설정에 `configDir` 을 적어 따로 둔 로그인. 옛 러너는 두 괄호를 싣지 않아 안 보인다)(못 쓰는 프로그램은 흐리게 「<이름> — 쓸 수 없음 · <사유>」). 폐기한 러너는 「토큰이 폐기된 러너입니다.」 — 프로젝트를 다른 러너로 옮기면 그 에이전트가 다시 답한다.

- **「프로젝트 N」**(주인·admin 이상) — 「프로젝트 추가」와 프로젝트 줄. 줄의 이름은 그 프로젝트 상세로 가는 링크이고, 줄에서 바로 「확인」·「이름 바꾸기」·「옮기기」·「보관」도 된다(아래 「프로젝트 상세」).
- **「설치 안내」**(주인·admin 이상) — 러너가 지금 붙어 있거나 한 번이라도 붙었으면 접혀 있고, 아니면 펼쳐 있다. 셋이다 — 설치(`npm i -g @dodok/runner` — 접힌 「서버와 같은 빌드로 설치」를 펼치면 서버가 품은 러너 파일의 「러너 받기」·파일 sha256·크기·「파일 설치 명령 복사」) → 실행(`dodok-runner`) → 실행하면 묻는 값(「서버 주소」 값과 「러너 토큰」 — 토큰 원문은 발급할 때 받은 것). 러너는 설정 파일이 없으면 터미널에서 서버 주소·러너 토큰·루트(경로·라벨)·권한 상한을 차례로 묻고, 러너가 쓸 Claude Code 와 로그인 유무를 보여 준 뒤(로그인이 없으면 `claude` 를 열어 `/login`) 설정을 저장하고 붙는다 — 붙으면 「연결됨」이 뜨고 프로젝트를 더할 수 있다. 설정 파일을 손으로 쓰는 길·전용 로그인은 `docs/guides/docker-deploy.md` 「러너 설치」 4번 「고급 — 직접 쓰기」.
- **「러너 토큰」**(주인·admin 이상) — 이 러너의 토큰 한 줄. 붙어 있으면 「지금 접속 중」과 「서버와 같은 빌드입니다」(다르면 경고가 아닌 안내 「서버와 다른 빌드입니다 — npm 판이면 정상입니다.」 — 서버와 같은 빌드가 필요하면 「설치 안내」의 「서버와 같은 빌드로 설치」), 「다시 발급」·「폐기」.
  - 「다시 발급」 — 「「<이름>」 러너 토큰을 다시 발급할까요?」(붙어 있으면 「옛 토큰은 곧바로 안 통하고 지금 붙은 러너가 끊깁니다.」 — 프로젝트·에이전트는 그대로 남는다. 러너 서비스를 먼저 멈추고 새 토큰을 넣은 뒤 다시 띄운다) → 새 원문을 한 번만 보이고, 그 아래 「실행」(`dodok-runner token` — 러너 머신에서 새 원문만 넣는다. 설정·루트는 그대로라 프로젝트가 「루트 없음」이 되지 않는다). 설치·서버 주소 칸은 없다. 폐기한 토큰은 「폐기한 토큰은 다시 발급할 수 없습니다 — 새 러너 토큰을 발급하세요.」.
- 남의 러너를 연 member 에게는 머리(이름·상태·「러너 · 주인 <이름>」)·그 러너의 에이전트만 보인다.

### 프로젝트 상세 (그 러너의 주인·admin 이상)

머리에 이름과 「<러너> · <루트 라벨>/<상대 경로>」(러너 이름은 그 러너 상세 링크), 줄의 동작 넷, 「에이전트 N」과 「에이전트 만들기」. 보관한 프로젝트는 「보관됨」만 남는다.

- 「확인」 — 러너에 그 자리를 다시 묻는다: 「확인됨 · git 저장소」·「확인됨」, 또는 실패 사유(아래 넷).
- 「이름 바꾸기」 — 줄 안 폼(1~64자, 「취소」로 닫는다).
- 「옮기기」 — 그 프로젝트와 에이전트를 다른 러너로(새 머신으로 옮겼을 때). 「프로젝트와 그 에이전트가 함께 옮겨 갑니다.」 옮길 러너의 같은 루트 id·경로에 같은 디렉터리가 있어야 하고, 에이전트는 새 세션에서 시작한다(앞 작업 맥락은 옛 머신에 남는다) — 붙어 있는 러너만 고를 수 있다(member 는 자기 러너로만 — 남의 컴퓨터에 일을 넘기지 않게). 옮길 러너의 설정이 허용하지 않는 에이전트가 있으면 「이 러너의 설정이 허용하지 않는 에이전트가 있습니다: @a, @b — 먼저 권한·도구를 낮추거나 보관하세요」이고 아무것도 옮기지 않는다. 옮기면 원래 러너 상세로 돌아간다.
- 「보관」 — 「보관하면 이 프로젝트에 새 에이전트를 만들 수 없습니다(있는 에이전트 N개는 계속 답합니다).」 — 멈추려면 그 에이전트를 삭제한다. 보관하면 러너 상세로 돌아가고, 그 러너의 접힌 「보관한 프로젝트 N」에 남는다(되돌리지 않는다).
- 붙은 러너가 그 루트를 알리지 않으면 「루트 없음」 — 러너 머신의 설정에서 루트 id 를 바꿨거나 지웠다. 그 에이전트를 부르면 「러너 설정이 이 에이전트를 허용하지 않습니다(root) — …」 카드가 남고, 설정을 되돌리면 「다시 실행」이 돈다.
- **「프로젝트 추가」**(러너 상세) — 루트 고르기(둘 이상일 때) → 「둘러보기」 또는 「직접 입력」 → 자리·이름을 보고 「확인하고 추가」.
  - 「둘러보기」 — 빵 부스러기로 오르내리며 디렉터리를 고르고 「이 디렉터리로」. git 저장소에 표시가 붙는다. 숨김 디렉터리(`.` 로 시작)는 안 보이고, 디렉터리가 많으면 「500개까지만 보입니다 — 찾는 디렉터리가 없으면 경로를 직접 입력하세요」. 둘러보기는 한 사람이 1분에 60번까지다(「잠시 뒤 다시 시도하세요 — 둘러보기는 1분에 60번까지입니다」). 러너가 둘러보기를 끄고 있으면 「이 러너는 둘러보기를 끄고 있습니다 — 경로를 직접 입력하세요」.
  - 「직접 입력」 — 루트 안의 상대 경로. 「비우면 루트 자신입니다.」(숨김 디렉터리도 경로를 적으면 고를 수 있다), 꼴이 틀리면 「루트 안의 상대 경로로 적으세요 — 앞의 /, .., \ 없이 / 로 나눕니다」.
  - 「확인하고 추가」는 서버가 러너에 그 자리를 물은 뒤 더한다. 실패 사유 넷 — 「러너가 이 루트를 알리지 않습니다 — 러너 머신의 설정에서 루트를 확인하세요」·「디렉터리가 없습니다 — 경로를 확인하세요」·「디렉터리가 아니라 파일입니다 — 디렉터리를 고르세요」·「루트 밖을 가리킵니다(심볼릭 링크 등) — 루트 안의 디렉터리를 고르세요」. 같은 러너의 같은 자리가 이미 있거나 폐기한 러너면 「이 러너에 같은 자리의 프로젝트가 이미 있거나, 토큰이 폐기된 러너입니다」.
  - 러너가 끊겨 있으면 「러너가 연결되어 있지 않습니다 — 러너를 띄운 뒤 다시 시도하세요」, 러너가 늦으면 「러너가 제때 답하지 않았습니다 — 다시 시도하세요」. 대화상자를 연 채 러너가 다시 붙으면 그 단계로 돌아온다.
- 프로젝트는 서버에 **루트 id 와 상대 경로로만** 저장된다 — 러너 머신의 절대 경로는 서버·화면 어디에도 없다.

### 에이전트 상세

머리에 이름(꺼졌으면 「꺼짐」)과 경로 — OpenClaw 는 「<Gateway> · OpenClaw」, 러너 에이전트는 「<러너> › <프로젝트> · Claude Code」(연결 이름은 그 상세 링크, 프로젝트 이름은 admin 이상에게만). 누구나 보고, 고치는 것은 그 에이전트 연결의 주인과 admin 이상이다(아니면 값만 보이고 「관리자만 바꿀 수 있습니다」). 연결이 지워진 에이전트는 admin 이상만 고친다.

- 핸들, 제공자별 id, 사용 스위치(끄면 멘션해도 답하지 않는다 — 사람이 멘션하면 아무 표시 없이 답이 없고, 다른 에이전트가 넘기면 채널에 「@<에이전트> 는 비활성 상태입니다」 꼴이 남는다). OpenClaw 에이전트는 「메모 편집」(「메모(에이전트에게 전달되지 않음)」), 러너 에이전트는 「지시 편집」(만들 때의 「지시」와 같은 칸). OpenClaw 에이전트는 핸들 옆에 Gateway 이름(`@main-home · 집`)이 붙고, 러너 에이전트는 프로그램과 맡은 러너(「Claude Code · 러너 <이름>」 — 그 러너의 토큰을 폐기했으면 「… — 토큰이 폐기돼 맡을 러너가 없습니다. 그 러너 화면에서 프로젝트를 다른 러너로 옮기세요」)를 보인다.
- 그 러너의 주인·admin 이상에게는 러너 에이전트의 **새 세션 시작값** 요약(「새 세션 시작값 · 모델 <값|기본> · effort <값|기본> · 권한 <값|기본>」)과 「시작값 고치기」 — 모델·effort·권한 모드를 고르고 모두 「기본」으로 둘 수 있다. 설정 행이 없는 새 세션이 이 값으로 시작한다(이미 있는 세션은 그 세션의 값을 따른다 — 「러너 에이전트 상태 줄」). 권한 모드는 지금 붙은 러너의 상한까지 — 위는 막히고 「러너 상한(<모드>) 위는 고를 수 없습니다」, 러너가 끊겨 있으면 넷 다 고를 수 있다(서버도 대조를 건너뛰고 런에서 러너가 거절한다). 서버가 러너 설정 밖이라고 거절하면 「러너 설정이 허용하지 않습니다 — 러너 머신의 설정(상한)을 확인하세요」. 프로그램·프로젝트는 읽기만이다 — 프로그램을 바꾸려면 새 에이전트를 만들고, 프로젝트는 프로젝트 화면에서 다른 러너로 옮긴다.
- 「DM 보내기」(지금 내 역할로 그 에이전트와 DM 을 열 수 있을 때만)와 「DM 허용」(주인·admin 이상이 바꾼다 — 그 밖의 사람에게는 「DM 허용: <값>」만 보인다 — 「다이렉트 메시지」 절), 주인·admin 이상에게는 에이전트 사진.
- **「Gateway 옮기기」**(admin 이상, 또는 원래 Gateway 의 주인 member — 옮길 곳도 자기 Gateway 만 고를 수 있다) — OpenClaw 에이전트에 있다. 그 에이전트가 답할 Gateway 를 고르고 「옮기기」. 그 Gateway 의 OpenClaw 에 같은 id 의 에이전트가 있어야 답하고, 그 Gateway 로 이미 등록된 같은 id 가 있으면 「옮길 Gateway 에 같은 id 의 에이전트가 이미 있습니다」. 옮길 다른 Gateway 가 없으면 「옮길 다른 Gateway 가 없습니다.」 — 설정 → 연결의 「연결 추가」로 Gateway 를 더한다. Gateway 를 지우면 그 Gateway 의 에이전트는 남고 연결이 빈다 — admin 이상에게는 「Gateway 가 삭제됨 — 다른 Gateway 로 옮기세요」, member 에게는 「Gateway 가 삭제됨 — admin 이 다른 Gateway 로 옮길 때까지 답하지 못합니다」가 보이고, 그동안 멘션하면 `ADAPTER_UNAVAILABLE` 로 실패한다. 옮긴 뒤 실패 카드의 「다시 실행」은 새 Gateway 로 간다.
- ⚠ **OpenClaw 에이전트**의 「메모」는 에이전트에게 전달되지 않는다 — 그 에이전트에게 줄 지시는 채널 프롬프트나 에이전트 쪽 지시 파일에 적는다(`docs/guides/agent-guide.md` 「채널 프롬프트와 채널 지시」 절). **러너 에이전트**의 「지시」는 매 런 에이전트에게 간다 — 바꾸면 다음 런이 새 세션으로 시작한다(`docs/guides/agent-guide.md` 「러너 에이전트」 절).
- 등록한 뒤 채널 설정 「에이전트 추가」로 채널에 넣어야 멘션할 수 있다.

### 에이전트 데려오기·만들기 (그 연결의 주인·admin 이상)

- **OpenClaw — Gateway 상세의 「에이전트 가져오기」** — 그 Gateway 에 있는 에이전트 중 아직 등록하지 않은 것이 체크 목록으로 나온다 — 같은 Gateway 에 같은 id 로 등록한 것만 숨고, 다른 Gateway 에 등록한 같은 id 는 나온다. 고르면 핸들·이름 칸이 열린다. 핸들은 id 로 채워지고 이미 쓰이는 핸들이면 「이미 쓰이는 핸들입니다 — 다른 핸들을 입력하세요」 — 다른 Gateway 의 같은 id 는 다른 핸들(예: `main-home`)로 바꿔 「<N>개 등록」. 목록을 못 받으면(Gateway 가 끊겼으면 「Gateway 에 연결되지 않았습니다」) 「직접 입력」으로 id·핸들·이름을 적어 등록한다. OpenClaw 에이전트 id 는 같은 Gateway 안에서 겹칠 수 없다. 핸들은 워크스페이스에서 하나다.
- **러너 — 프로젝트 상세의 「에이전트 만들기」** — 가져오는 것이 아니라 **새로 만든다**. 러너·프로젝트는 그 프로젝트로 정해져 있고, 프로그램(지금은 Claude Code — 그 러너가 못 쓰는 것은 흐리게 「쓸 수 없음 — <사유>」) → 핸들·이름·지시·DM 허용 → 「만들기」.
  - 모델·effort·권한 모드는 만들 때 묻지 않는다 — 대화마다 작성기 위 상태 줄에서 고르고(「메시지 쓰기」 절 「러너 에이전트 상태 줄」), 새 세션의 시작값은 에이전트 상세의 「시작값 고치기」. 허용 도구는 고르지 않는다 — 도구는 승인 카드로 그때그때 허락하고, 러너 설정의 도구 상한은 그대로 걸린다. 지시는 이 에이전트가 매 런 받는 지시다(채널 규칙 앞에 붙고, 비워도 된다).
  - 폼을 연 채 러너가 끊기거나 폐기되거나 프로젝트가 보관되거나 프로그램을 못 쓰게 되면 「만들기」가 잠기고 사유가 붙는다 — 「선택된 러너가 끊겼습니다 — 러너를 다시 띄우거나 다른 러너를 고르세요」·「선택돼 있던 러너의 토큰이 폐기됐습니다 — 다른 러너를 고르세요」·「선택된 프로그램을 지금 쓸 수 없습니다 — 다른 프로그램을 고르세요」 등. 서버가 러너 설정 밖이라고 거절하면 「러너 설정이 허용하지 않습니다 — 러너 머신의 설정(상한)을 확인하세요」.
  - 러너 에이전트 id 는 서버가 짓는다(`r-` 로 시작). 러너를 설치하고 붙이는 것은 `docs/guides/docker-deploy.md` 「러너 설치」 절.

### 연결 추가 (누구나)

「＋ 연결 추가」(`/settings/connection/new`) → 「OpenClaw Gateway」·「러너」 둘 중 하나.

- **OpenClaw Gateway** — 이름·주소·토큰 → 「추가」. 저장하면 그 Gateway 상세로 간다(플러그인 설치 상자가 펼쳐진 채 — 「브리지 토큰」의 「새 토큰 발급」부터). admin 이상이 만들면 서버가 곧바로 붙는다. member 가 만든 Gateway 는 「승인 대기」다(admin 이 승인하면 서버가 접속한다) — 그동안 브리지 토큰을 발급해 플러그인을 미리 설치해 둔다.
- **러너** — 「새 러너 토큰 발급」 → 라벨 → 「발급」 — 원문(`drn_…`)이 한 번만 보이고, 그 아래 「설치」(`npm i -g @dodok/runner`)·「실행」(`dodok-runner`)·「서버 주소」가 복사 단추와 함께 있다 — 러너 머신에서 설치하고 실행하면 러너가 서버 주소와 이 원문을 묻는다(루트는 에이전트가 돌 디렉터리로 좁게). 「복사했습니다」를 누르면 그 러너 상세(설치 안내가 펼쳐진 채)로 간다.

### 「AI 에게 맡기기」

브리지 토큰·러너 토큰 발급 대화상자의 원문 바로 아래에 있다. 「복사」로 한 줄(`<서버 주소>/llms.txt 를 읽고 「OpenClaw Gateway 호스트」 절대로 이 호스트에 dodok 플러그인을 설치해 줘. 브리지 토큰: <원문>` — 러너는 「러너 머신」 절·「러너 토큰:」)을 복사해, 설치할 머신에서 도는 AI(Claude Code 등)에게 건네면 AI 가 서버의 설치 안내서(`/llms.txt`)대로 받기·설치·설정을 한다. 토큰이 들어 있으니 원문처럼 다룬다. AI 는 사람이 할 단계에서 멈추고 묻는다 — 끝나면 「설정 → 연결」에서 그 Gateway 의 「플러그인」이 「접속됨」·「서버와 같은 빌드입니다」인지(러너는 「연결됨」인지) 본다. 러너 토큰을 다시 발급한 대화상자의 줄은 설치가 아니라 토큰만 바꾸고 다시 띄우는 줄이다. 안내서가 하는 일과 멈추는 자리는 `docs/guides/docker-deploy.md` 「[웹 → B] 플러그인 설치·브리지 토큰」·「러너 설치」 절의 「AI 에게 맡기는 길」.

### 삭제·되살리기

삭제는 지우는 것이 아니라 숨기는 것이다 — 채팅 기록은 남고, 되살리면 채널·대화가 그대로 돌아온다.

- **삭제** — 에이전트 상세의 「삭제」(그 에이전트 연결의 주인·admin 이상) → 「에이전트 삭제」 대화상자 「@dev 를 삭제합니다.」 → 「삭제」. 목록으로 돌아가고 그 에이전트는 접힌 「삭제된 에이전트 N」으로 간다.
- **삭제하면**
  - 멘션 후보·채널 설정의 멤버 줄·「에이전트 추가」 목록·채널 머리의 에이전트 얼굴에서 빠진다. 손으로 친 `@핸들` 은 그냥 글자로 남고 아무도 답하지 않는다.
  - 그 에이전트가 돌던 실행은 「중지」와 같이 멈추고, 걸려 있던 도구 승인 카드는 「취소됨」이 된다.
  - 채팅 기록의 작성자 이름 옆과 멘션 칩에 「삭제됨」이 붙는다. 운영 화면 에이전트별 표에도 「삭제됨」이 붙는다.
  - 그 에이전트의 실패 카드에서 「다시 실행」을 누르면 「삭제된 에이전트입니다」 — 카드는 그대로 남아 되살린 뒤 다시 누를 수 있다.
- **되살리기** — 「삭제된 에이전트 N」을 펼쳐 그 에이전트를 열면 「삭제된 에이전트」 배지와 「되살리기」(그 에이전트 연결의 주인·admin 이상 — 연결이 지워졌으면 admin 이상)가 있다. 핸들·채널 참여·대화가 그대로 돌아와, 같은 채널에서 멘션하면 앞 대화를 이어 답한다. 삭제한 동안 그 채널에서 다른 에이전트의 자동 응답을 켰으면 되살린 에이전트의 자동 응답은 꺼진 채로 돌아온다 — 자동 응답은 채널에 하나다.
- **다시 가져오려 할 때** — 「에이전트 가져오기」 목록에서 삭제한 에이전트는 체크 대신 「삭제됨 — 되살리기」 버튼으로 나온다. 「직접 입력」에 삭제한 에이전트의 id 를 넣으면 「삭제된 에이전트입니다」와 「되살리기」가 뜬다 — 새로 만들지 않고 되살린다. 삭제한 에이전트의 핸들은 그대로 그 에이전트 몫이라 새 에이전트에 쓸 수 없다.
- 채널 설정에서 삭제한 에이전트를 넣으려 하면 「삭제된 에이전트입니다」.
- 프로젝트가 없는 러너 에이전트(에이전트를 러너 설정에 적던 판에서 등록한 것 — 서버를 올릴 때 저절로 삭제됐다)는 「되살리기」 대신 「프로젝트가 없어 되살릴 수 없습니다 — 새로 만드세요」다. 그 핸들은 그 에이전트 몫으로 남으니 새 에이전트는 다른 핸들로 만든다.

## 멤버·역할

「설정」 → 「멤버」 탭(`/settings/members`, admin 이상). 표에 활성 멤버의 핸들·이름·이메일·역할·가입일과 줄마다의 동작이 있고, 그 아래에 접힌 「비활성 멤버 N」(비활성 멤버가 있을 때)과 「대기 중인 초대」가 있다.

- **초대** — 「초대」 → 「역할」(「멤버」 또는 「관리자」 — 관리자 초대는 owner 만) → 「링크 만들기」. 「초대 링크를 만들었습니다」 대화상자에 링크가 **한 번만** 보인다 — 「복사」해서 메신저로 건네고 「복사했습니다」로 닫는다. 닫으면 다시 볼 수 없다. 잃었으면 「대기 중인 초대」에서 「폐기」하고 새로 만든다.
- **재설정 링크** — 줄의 「재설정 링크」 → 「링크 만들기」. 앞서 만든 그 사람의 재설정 링크는 쓸 수 없게 된다. 링크를 건네는 법은 초대와 같다. admin 은 member 에게만, owner 는 owner 를 뺀 누구에게나 만든다.
- **역할 바꾸기**(owner) — 줄의 역할 칸에서 「관리자」 ↔ 「멤버」. 「멤버」 → 「관리자」(올리기)는 곧바로 바뀐다. 「관리자」 → 「멤버」(내리기)는 확인을 거친다 — 「@<핸들> 을 멤버로 바꿀까요?」 대화상자가 「이 사람이 만든 쓰이지 않은 초대·재설정 링크는 쓸 수 없게 되고, 다시 관리자로 올려도 살아나지 않습니다.」를 알리고, 「멤버로 바꾸기」를 눌러야 바뀐다(취소하면 「관리자」 그대로).
- **비활성화** — 줄의 「비활성화」 → 「멤버 비활성화」 대화상자 「@<핸들> 을 비활성화합니다 — 로그인할 수 없게 됩니다.」 → 「비활성화」. 쓴 메시지는 남고, 다시 활성화하면 그대로 돌아온다. 그 사람의 열린 화면은 곧바로 로그인 화면으로 가고 다시 로그인할 수 없다. 줄은 표에서 「비활성 멤버 N」 묶음으로 옮겨 간다. admin 은 member 만, owner 는 owner 를 뺀 누구나 비활성화한다.
- **비활성화하면** — 계정·핸들·이메일·역할·채널 참여는 그대로 남는다. 쓴 메시지의 작성자 이름 옆과 그 사람을 가리킨 멘션 칩에 「비활성」이 붙는다. 그 사람이 단 반응도 남고, 칩의 이름에 「(비활성)」이 붙는다. 멘션 후보와 에이전트가 받는 「참여자:」에서 빠지고, 손으로 멘션해도 알림이 가지 않는다. 그 사람이 만들어 둔 쓰이지 않은 초대·재설정 링크와 그 사람에게 만든 재설정 링크는 폐기된다.
- **다시 활성화** — 「비활성 멤버 N」을 펼쳐 줄의 「다시 활성화」(권한은 비활성화와 같다). 역할·채널 참여가 그대로 돌아오고, 그 사람은 예전 비밀번호로 로그인한다. 비밀번호를 모르면 다시 활성화한 뒤 「재설정 링크」를 만든다 — 비활성 줄에는 역할 바꾸기와 「재설정 링크」가 없다.

링크가 만료되는 때, 역할을 내리면 폐기되는 링크, 비활성화가 실패했을 때는 `docs/guides/docker-deploy.md` 「멤버 초대·비밀번호 재설정·비활성화」 절.

## 내 계정

「설정」 → 「내 계정」 탭(`/settings/account`).

- **「프로필」** 섹션 — 맨 위에 있다.
  - 사진 — 「사진 고르기」로 그림(png·jpeg·webp·gif)을 고르면 가운데 정사각형으로 잘라 256px 로 줄인 미리보기가 뜨고, 「사진 저장」으로 올린다(「사진 지우기」로 이니셜로 되돌린다). 서버가 형식(png·jpeg·webp)·256KB 이하·정사각형·한 변 64~512px 를 확인하고, 어기면 그 사유가 이 자리에 뜬다. 저장하면 타임라인·DM 목록·프로필에 곧바로 바뀐다(열려 있는 다른 사람의 화면 포함).
  - 「표시 이름」(1~64자)을 바꾸고 「저장」.
  - 「상태」 — 「자동」·「자리 비움」·「다른 용무 중」·「방해 금지」·「오프라인으로 보이기」. 「자동」이 아니면 「상태 만료」를 고른다 — 「안 지움」·「30분」·「1시간」·「4시간」·「오늘」(브라우저 시간대의 자정까지)·「직접 고른 시각」. 이미 만료가 걸려 있으면 「그대로 · 15:00 까지」가 첫 선택지다. 「오프라인으로 보이기」여도 내 화면에서는 내 상태가 그대로 보인다.
  - 「상태 메시지」 — 이모지 한 칸 + 글(「무엇을 하고 있나요?」), 이모지 고르기 줄, 「상태 메시지 만료」(상태 만료와 같은 선택지).
  - 「도구 승인 요청은 계속 받기」 — 켜 두면 방해 금지 중에도 승인 푸시는 보낸다(놓치면 런이 멈춰 기다린다). 모두에게 보인다(채널의 승인 푸시는 admin 이상이 받지만, 「DM 허용」이 「모두」인 에이전트의 DM 승인은 member 인 DM 주인이 받는다).
  - 「상태 저장」을 누르면 「상태를 저장했습니다」가 뜬다. 상태와 메시지는 한 번에 저장된다.
- 「비밀번호 바꾸기」 — 「현재 비밀번호」, 「새 비밀번호」(12자 이상), 「새 비밀번호 확인」. 바꾸면 「비밀번호를 바꿨습니다 — 다른 기기의 로그인은 끊겼습니다」 — 이 기기는 남는다.
- owner 에게는 비밀번호 칸 대신 「owner 비밀번호는 로컬 토큰입니다 — …」 안내가 있다.
- 「MCP 토큰」 — Claude Code 같은 바깥 MCP 클라이언트가 **내 권한으로** 채널·에이전트를 읽고 바꿀 때 쓰는 개인 토큰이다. 「새 토큰 발급」 → 이름(1~40자) → 「발급」. 토큰 원문(`dpt_…`)과 붙이는 명령(`claude mcp add --transport http dodok <이 화면의 주소>/mcp --header "Authorization: Bearer dpt_…"`)이 **한 번만** 보인다 — 「닫으면 다시 볼 수 없습니다.」 「복사」로 옮긴 뒤 「복사했습니다」로 닫는다(그 전에는 Esc·바깥 누르기로 닫히지 않는다). 잃었으면 폐기하고 새로 발급한다.
  - 목록에는 이름·앞부분(`dpt_abc123…`)·만든 때·마지막 사용이 보인다. 한 사람에 **10개까지** — 꽉 차면 「새 토큰 발급」이 잠긴다.
  - 「폐기」 → 확인(「이 토큰을 쓰는 MCP 클라이언트는 곧바로 거절됩니다.」 — 되돌릴 수 없다). 폐기한 토큰을 넣어 둔 클라이언트는 연결이 실패한다 — 클라이언트 설정에서도 지운다(`claude mcp remove dodok`).
  - 토큰을 가진 사람은 나와 같은 일을 할 수 있다 — 비밀번호처럼 다룬다. 바깥 클라이언트의 쓰기에는 확인 카드가 없다(클라이언트가 도구를 부르기 전에 묻는 확인이 전부다). 비활성화되면 내 토큰은 모두 폐기되고, 다시 활성화돼도 새로 발급해야 한다.

「로그아웃」은 이 탭 아래에 있다. 로그아웃하면 이 기기의 푸시 구독과 오프라인 사본도 지워진다.

## 알림·앱 설치·오프라인

「설정」 → 「알림」 탭(`/settings/notifications`)이 이 기기에서 받을 알림이다.

- **푸시 알림** — 「푸시 알림 켜기」 → 브라우저가 권한을 물으면 허용 → 「이 기기에서 알림을 받습니다」. 「끄기」로 끈다. 기기마다 따로 켠다.
  - 받는 것: 나를 멘션한 메시지, 도구 승인 요청(owner·admin — 다이렉트 메시지 안의 승인은 그 DM 의 주인), 내가 참여한 채널의 에이전트 릴레이 한도, 내 다이렉트 메시지에서 에이전트의 답과 실행 실패(제목 「@<에이전트>가 답했습니다」, 본문 「DM」), 사람 1:1·그룹 DM 에서 다른 참여자의 글(제목 「<이름> 님의 메시지」 또는 「@<핸들>이 답했습니다」, 본문 「DM」)과 그룹 DM 에서 내가 시킨 실행의 실패·승인 요청. 알림에는 누가·어디만 실리고 본문은 실리지 않는다. 누르면 그 세션(또는 그 세션의 스레드)이 열린다.
  - 그 세션을 지금 보고 있으면 푸시를 보내지 않는다 — 같은 채널의 다른 세션을 보고 있으면 간다.
  - 「브라우저 설정에서 알림을 허용해 주세요」 — 전에 거절한 것이다. 브라우저의 사이트 설정에서 알림을 허용한다.
  - 「이 브라우저는 푸시 알림을 지원하지 않습니다」 — 대신 「탭이 열려 있을 때만 알림 켜기」가 있으면 그것으로 탭이 열린 동안의 승인 알림을 받는다(owner·admin — member 에게는 탭 알림이 없다).
- **앱 설치** — 크롬·엣지 등에서는 이 탭의 「앱 설치」로 설치형 앱(PWA)으로 둔다. iPhone·iPad 는 Safari 의 공유 → 「홈 화면에 추가」로 설치해야 푸시를 받는다(이 탭에 「홈 화면에 추가하면 알림을 받을 수 있습니다 — 공유 → 홈 화면에 추가」). 새 버전이 나오면 「새 버전이 있습니다」 토스트의 「새로고침」으로 바꾼다.
- **오프라인 사본** — 최근 본 채널 5개마다 마지막으로 본 세션 하나(와 그 세션에서 마지막으로 연 스레드 하나)의 최근 메시지 50개가 이 기기에 7일 동안 남는다. 연결이 없을 때 「오프라인 — 저장된 내용을 보여 줍니다」 띠와 함께 그것을 보여 주고, 연결되면 새로 받는다. 오프라인에서는 보낼 수 없다. 다이렉트 메시지 목록은 사본에 담지 않아 오프라인 사이드바의 「다이렉트 메시지」 절은 비어 있다 — 최근에 본 DM 은 위 최근 채널 사본으로 열린다.

폰에서 설치·푸시를 처음 확인하는 순서는 `docs/guides/docker-deploy.md` 「체크리스트 — 처음 배포」 절의 폰 단계.

## 자동화 (admin 이상)

「설정」 → 「자동화」 탭(`/settings/automations`). 정한 시각(**예약**)이나 바깥 서비스가 보낸 **웹훅**에 맞춰 정한 채널의 자기 세션(「⚙ <이름>」 — 「세션」 절)에 정한 문구를 올린다. 문구에서 @로 부른 에이전트가 그 글에 답한다 — 사람이 멘션한 것과 같은 실행이라 일일 런 한도도 함께 센다. member 에게는 탭이 없고, 주소로 열면 「권한이 없습니다 — 자동화는 관리자만 볼 수 있습니다.」가 뜬다.

- **만들기** — 「만들기」 → 「자동화 만들기」: 「이름」(40자까지, 워크스페이스에서 겹치면 「같은 이름의 자동화가 있습니다」), 「채널」, 「종류」(「예약」·「웹훅」 — 만든 뒤에는 바꾸지 못한다), 「문구」(4,000자까지), 예약이면 「반복」(「매일」·「평일(월~금)」·「매주」 + 「요일」·「매시간」 + 분)과 「시각」.
  - 「문구」 칸에서 `@`를 치면 작성기처럼 후보(그 채널의 에이전트 다음 사람)가 뜨고, 고르면 `@핸들` 글자가 들어간다. 후보가 열린 동안 Esc 는 후보만 닫는다.
  - **문구에서 부른 에이전트만 답한다** — 에이전트를 부르지 않은 자동화 글에는 채널의 자동 응답 에이전트도 답하지 않는다. 사람을 부르면 그 사람에게 멘션 알림(배지·푸시)이 가고, 그 채널에 없던 사람이면 채널에 참여한다.
- **예약** — 시각은 **워크스페이스 시간대** 기준이다(목록 위 「시간대 <이름>」, 기본 `Asia/Seoul` — 운영 화면에서 바꾼다). 서버가 1분마다 보고 올리므로 정한 시각에서 1분 안에 게시된다.
  - 서버가 꺼져 있다가 켜지면 놓친 회차가 10분 안이면 한 번 올리고, 10분이 넘었으면 건너뛰고 운영 화면에 「자동화 예약을 놓쳐 건너뜀」을 남긴다. 여러 회차를 놓쳐도 몰아 올리지 않는다 — 가장 이른 놓친 회차로 재므로, 하루 넘게 꺼져 있었으면 마지막 회차가 10분 안이었어도 건너뛴다.
  - 서머타임이 있는 시간대에서 봄에 없는 시각이면 그 뒤 첫 시각에 한 번 돌고(「매시간」은 그 회차를 건너뛴다), 가을에 두 번 있는 시각이면 첫 번째에만 돈다.
- **웹훅** — 만들면 「웹훅 주소를 만들었습니다」에 주소(`https://<서버>/hooks/whk_…`)가 **한 번만** 보인다 — 「닫으면 다시 볼 수 없습니다.」 「복사」로 복사하고 「복사했습니다」로 닫는다. 주소가 보이는 동안 페이지를 떠나려 하면 「이 페이지를 떠나면 주소를 다시 볼 수 없습니다.」(「머무르기」·「주소를 버리고 떠나기」)가 묻는다.
  - 그 주소를 바깥 서비스(GitHub 등)의 웹훅 주소 칸에 넣으면 POST 가 올 때마다 문구 아래에 받은 본문을 코드 블록으로 붙여 올린다 — JSON 이면 읽기 좋게 들여 쓰고, 길면 8,000자에서 자른다. 본문은 64 KiB 까지, 한 주소에 1분 30번까지 받는다.
  - **본문 안의 `@핸들` 은 아무도 부르지 않는다** — 부르는 것은 문구뿐이다. 본문은 바깥에서 온 글이라 에이전트도 그 안의 지시를 따르지 않는다(`docs/guides/agent-guide.md` 「자동화가 게시한 글」 절).
  - 주소를 잃었거나 새었으면 「수정」 → 「주소 다시 만들기」 → 「다시 만들기」 — 「옛 주소는 곧바로 쓸 수 없게 됩니다.」 바깥 서비스의 주소도 새 주소로 바꿔야 한다. 새 주소가 한 번 보인다. 이때 그 대화상자에서 저장하지 않은 다른 칸의 수정은 버려지므로 먼저 「저장」한다.
  - 꺼 둔 자동화의 주소, 지운 자동화의 주소, 다시 만들기 전의 옛 주소는 모르는 주소와 똑같이 거절된다(404). 목록에는 주소 앞부분(`…/hooks/whk_abc123…`)만 남는다.
- **목록** — 줄마다 이름·종류(「예약」·「웹훅」, 꺼 두었으면 「꺼짐」)·`#채널`, 예약이면 「매일 09:00 · 다음 실행 10월 8일 (목) 오전 9:00」 꼴(워크스페이스 시간대로), 웹훅이면 「주소 …/hooks/whk_abc123…」, 「마지막 실행 … · 성공」(「건너뜀」·「실패」) 또는 「아직 실행하지 않았습니다」.
  - **경고 줄** — 「문구의 @fin 이 이 채널에 없습니다」, 「문구의 @ops 가 꺼져 있거나 삭제되었습니다」, 「문구의 @nobody 를 찾을 수 없습니다」(그런 핸들이 없다 — 에이전트의 핸들을 바꾼 뒤에도 이렇게 보인다), 「채널이 보관되었습니다」. 에이전트 경고가 있어도 글은 올라가고 그 에이전트만 불리지 않는다. 보관된 채널에는 올리지 못한다 — 예약은 「실패」와 운영 화면 「자동화 실행 실패 (CHANNEL_ARCHIVED)」, 웹훅은 거절(409).
  - **켜기 스위치** — 끄면 예약이 돌지 않고 웹훅 주소가 거절된다. 다시 켜면 그때부터 다음 회차를 센다 — 꺼 둔 사이 지난 회차가 곧바로 올라가지 않는다.
  - **「지금 실행」** — 종류와 상관없이 문구만 곧바로 올린다(웹훅이면 본문 없이). 꺼 둔 자동화도 올린다. 다음 실행 시각은 그대로다. 올리는 동안 그 줄의 버튼이 「게시하는 중…」으로 잠기고, 끝나면 「「<이름>」을 게시했습니다」. 한 번 누르면 한 번 올린다.
  - 「수정」·「삭제」(「자동화 삭제」 확인 — 이미 올린 메시지는 남는다).
- **채널에서 보이는 모양** — 자동화 글의 작성자 자리는 「⚙ 자동화 · <이름>」이고, 지운 자동화의 글은 「⚙ 지운 자동화」다. member 의 화면에도 「⚙ 자동화 · <이름>」이 보인다(서버가 글에 이름을 실어 준다 — 이름을 고치면 새로 불러온 뒤에 바뀐 이름으로 보인다). 다만 검색 결과 줄에서는 member 에게 이름 없이 「⚙ 자동화」다. 멘션 푸시에는 「자동화 <이름>이 … 불렀습니다」가 간다. 자동화 글도 읽지 않음(굵게, 나를 부르면 배지)에 들고 반응을 달 수 있으며, 그 반응은 에이전트에게 가지 않는다. 검색은 작성자 「자동화」로 거를 수 있다.
- **시간대 바꾸기** — 「운영」 탭의 「시간대」에서 「워크스페이스 시간대」를 고르고 「저장」. 켜진 예약의 다음 실행 시각을 그 시간대로 다시 센다. 일일 런 한도의 「하루」는 이 시간대가 아니라 서버 설정 `TZ` 의 자정이다(`docs/guides/docker-deploy.md` 「운영 화면」 절).

## 운영 화면 (admin 이상)

「설정」 → 「운영」 탭(`/settings/operations`). 지난밤 무슨 일이 있었는지 보는 화면이다 — 「상태」(켜진 Gateway 마다 「Gateway 「<이름>」」·「플러그인 「<이름>」」·「Gateway 「<이름>」 버전」 줄, 러너 연결(「러너」 줄), 디스크 여유, 직전 종료, 서버 — 꺼진 Gateway 는 줄이 없다), 「런」(「오늘」·「7일」, 채널별·에이전트별 런·실패·중지·차단·토큰·금액 — 에이전트별 줄은 이름 옆에 `@핸들 · Gateway 이름`(러너 에이전트는 핸들만)이 붙어, 같은 이름(`main`)을 다른 Gateway 에서 가져온 둘이 갈린다. 다이렉트 메시지의 런은 누구의 DM 인지 없이 「DM」 한 줄로 합쳐진다), 「한도」(「워크스페이스 일일 런 상한」 — 기본 300, 1~10,000, 비우면 무제한), 「시간대」(「워크스페이스 시간대」 — 예약 자동화의 시각 기준, 위 「자동화 (admin 이상)」), 「최근 사건」(심각도 거르개·「모두 확인」·「더 보기」 — Gateway 사건에는 「Gateway 「집」 연결 끊김」처럼 Gateway 이름이 붙는다).

사이드바 「설정」과 「운영」 탭의 숫자 배지는 확인하지 않은 주의·오류 사건 수다(좁은 화면에서는 메뉴 버튼의 빨간 점). 「모두 확인」을 누르면 사라진다. 칸마다의 뜻(「측정 불가」·「환산 포함」·「런 m/n개만」, 사건 종류, 한도를 세는 법)은 `docs/guides/docker-deploy.md` 「운영 화면」 절이 정본이다.
