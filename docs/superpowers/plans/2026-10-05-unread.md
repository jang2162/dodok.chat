# 읽지 않음 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 이 저장소에서는 Orca 워커가 태스크를 맡는다(`CLAUDE.md` 「작업 방식」). 태스크 하나 = 워크트리 하나 = 브리프 하나. 태스크마다 main 에 병합해도 초록이어야 한다.

**Goal:** 사용자별 읽음 위치를 서버에 두고, 사이드바의 굵은 채널·멘션 배지와 타임라인의 「여기부터 새 메시지」 구분선을 보이며, 기기 사이에 읽음을 맞춘다.

**Architecture:** 새 표 `channel_reads` 와 서버 모듈 `modules/reads/` 가 읽음 위치(커지기만 함)와 현황 계산을 맡는다. 웹은 처음·재연결 때 `GET /api/v1/me/unread` 스냅숏을 받고, 그 뒤는 워크스페이스 룸의 본문 없는 신호 `channel.activity` 로 더해 간다. 읽음은 wire `channel.read` 로 보내고, 서버가 같은 사용자의 user 룸에 `channel.read` 로 돌려 다른 기기를 맞춘다.

**Tech Stack:** Fastify 5 · Socket.IO 4.8 · drizzle-orm 0.45 + better-sqlite3 · zod 4 · React 19 + TanStack Router/Query · zustand. **새 의존성 없음.**

**Spec:** `docs/superpowers/specs/2026-10-05-unread-design.md` — 결정 0장, 정의 2장, 데이터 모델 3장, 계약 4장, 서버 5장, 웹 6장, 권한 7장, 오류 8장, 검증 9장, 완료 기준 10장. **태스크를 시작하기 전에 스펙의 해당 장을 읽는다.**

## Global Constraints

- 굵게 = `seq > R`·`kind = "normal"`·`thread_root_id IS NULL`·내가 쓰지 않음. 배지 = `seq > R`·`kind = "normal"`·`mentions_json.users` 에 나·내가 쓰지 않음, 스레드 답글 포함, **99 에서 자름**. `R` 은 행이 없으면 0.
- 읽음 위치는 **커지기만 한다**(`max(old, new)`), 요청 seq 는 `channels.last_seq` 로 깎는다.
- 읽음 전송 조건: 채널 타임라인의 끝이 보임(떨어진 창이 아님) **그리고** `document.visibilityState === "visible"`, 같은 채널 1초 디바운스. 스레드 패널만 보는 것은 채널 읽음을 올리지 않는다.
- 최상위 메시지를 보내면 서버가 작성자 읽음을 올린다. 스레드 답글·멱등 재전송은 올리지 않는다.
- 공용 `Channel` 타입에 읽음 값을 넣지 않는다.
- **자동화와의 얽힘**: 자동화 스펙(`docs/superpowers/specs/2026-10-05-automations-design.md`)이 `Message.authorType "automation"` 을 더한다. 자동화가 먼저 병합돼 있으면 `channel.activity` 조건과 `ChannelActivity.authorType` 에 `automation` 을 넣고(`authorId` 는 자동화 id), 굵게·배지 질의의 「내가 쓰지 않음」 조건은 그대로 둔다. 이 계획이 먼저면 자동화 계획이 넣는다.
- wire `channel.read`(클라이언트 → 서버)의 버킷은 `chatter`. 레이트리밋 숫자는 `apps/server/src/modules/ops/limits.ts` 한곳(새 숫자 없음).
- 「틀린 배지보다 없는 배지」 — 스냅숏을 못 받았거나 오프라인이면 굵게·배지를 그리지 않는다.
- 외부 입력(HTTP 쿼리·wire 페이로드)은 경계에서 Zod 파싱. shared 는 Node 전용 API 금지.
- 웹 문구는 합쇼체. 스펙의 문구를 그대로: 「안 읽은 메시지가 더 있어요 · 처음 안 읽은 곳으로」, 구분선 「새 메시지」, 배지 「99+」.
- 포트 5173·3000 금지(사용자 인스턴스 3100·5180 도 건드리지 않는다 — 워커는 브리프가 주는 포트). 프로세스는 자기 PID 로만, `pkill` 금지. **모델 런 없음.**
- 커밋: `git add -A`·`git commit -a` 금지, 경로 명시. Conventional Commits + 스코프(`feat(shared): …`·`feat(server): …`·`feat(web): …`). 워커 트레일러 `Co-Authored-By: <네 실제 모델명> <noreply@anthropic.com>`.

## 계획 판정 (스펙과 맞춘 것)

조사한 코드에 맞춰 스펙을 구체화한 것. 태스크 5 가 스펙에 「구현과 맞춘 것」 장을 만들어 옮긴다.

- **PU1 — `ChannelUnread` 에 `latestSeq`(그 채널의 `channels.last_seq`)를 더한다.** 재연결 때 스냅숏 요청이 나가 있는 동안 도착한 `channel.activity` 를 스냅숏 위에 다시 얹을 때, `seq <= latestSeq` 인 것은 이미 스냅숏에 든 것이라 버린다(중복 배지 방지 — Review Focus 5).
- **PU2 — 서버 → 클라이언트 `channel.read` 는 버스를 거친다.** `BusEvents` 에 `"channel.read": { userId: Id; channelId: Id; lastReadSeq: number }` 를 더하고, `realtime/events.ts` 의 팬아웃이 `userRoom(userId)` 로 `{ channelId, lastReadSeq }` 만 낸다. 모듈은 Socket.IO 를 직접 만지지 않는다(버스 주석의 규칙).
- **PU3 — `channel.activity` 는 `realtime/events.ts` 의 `message.created` 처리기 옆에서 낸다**(`kind = "normal"` 이고 `authorType` 이 `user`·`agent` 일 때만, `silent` 메시지도 낸다 — 저장된 메시지이므로 안 읽은 것이다).
- **PU4 — 작성자 읽음 올리기는 `realtime/socket.ts` 의 `message.send` 처리기**에서 `res.data.created && message.threadRootId === undefined` 일 때 ack 뒤에 `markRead` 후 버스 `channel.read` 를 낸다.
- **PU5 — 보관·비활성화(채널 보관·멤버 비활성화 스펙 `docs/superpowers/specs/2026-10-06-channel-archive-member-deactivate-design.md`)에 맞춘다.** 비활성화(`deactivateMember`)는 읽음 행을 건드리지 않는다(다시 활성화하면 그대로). `unreadFor` 는 `channels.archived_at IS NULL` 인 채널만 돌려준다. 보관한 채널의 `channel.read` 는 받는다(읽기는 막지 않는다 — `assertChannelWritable` 을 쓰지 않는다).
- **PU6 — 「끝이 보임」은 `MessageList.tsx` 의 `stuck` 상태**(`fromBottom <= STICK_PX && !hasNewer`)를 쓴다. 떨어진 창에서는 `stuck` 이 거짓이라 읽음을 보내지 않는다.
- **PU7 — 보내는 seq 는 채널 타임라인 캐시의 `lastSeq`**(`features/messages/timeline.ts` 의 `Timeline.lastSeq`)다.

## Review Focus

1. **같은 사용자의 탭 둘 — 한 탭은 채널 끝을 보고, 다른 탭은 가려져 있음** — 가려진 탭은 읽음을 보내지 않지만 서버의 `channel.read` 를 받아 사이드바가 지워진다. → 태스크 3.
2. **검색 결과로 가기로 받은 떨어진 창의 아래 끝을 보고 있음** — 진짜 끝이 아니므로 읽음을 보내지 않는다. 「최신 메시지로」를 눌러 끝에 붙으면 그때 보낸다. → 태스크 3.
3. **채널에 들어갔는데 스냅숏이 아직 안 옴(또는 실패)** — 구분선을 짐작해 긋지 않는다(없음). 스냅숏이 들어와도 이미 들어간 채널의 `entryReadSeq` 는 다시 잡지 않는다(구분선이 나중에 튀어나오지 않게). → 태스크 4.
4. **다른 사람이 방금 만든 채널(`channel.created`) 에 첫 글이 옴** — 스토어에 그 채널 항목이 없어도 `lastReadSeq 0` 으로 만들어 굵게 한다. → 태스크 3.
5. **재연결 직후 스냅숏 요청이 나가 있는 동안 activity 가 도착** — 스냅숏에 이미 든 메시지는 다시 세지 않고(PU1), 스냅숏 뒤의 것은 잃지 않는다. → 태스크 3.

각 줄의 테스트는 해당 태스크의 단계에 들어 있다.

  lastReadSeq: z.int().min(0),
  latestSeq: z.int().min(0), // PU1 — 재연결 때 activity 중복을 거른다

export const UnreadSnapshot = z.object({ channels: z.array(ChannelUnread) });
export type UnreadSnapshot = z.infer<typeof UnreadSnapshot>;

export const ChannelRead = z.object({ channelId: Id, seq: z.int().min(0) });

```sql

  COALESCE(r.last_read_seq, 0) AS lastReadSeq,
  c.last_seq AS latestSeq,
  EXISTS (SELECT 1 FROM messages m
    WHERE m.channel_id = c.id AND m.seq > COALESCE(r.last_read_seq, 0)

      AND NOT (m.author_type = 'user' AND m.author_id = :me)) AS unread,

    WHERE m.channel_id = c.id AND m.seq > COALESCE(r.last_read_seq, 0)
      AND m.kind = 'normal'

FROM channels c
LEFT JOIN channel_reads r ON r.channel_id = c.id AND r.user_id = :me
WHERE c.workspace_id = :ws AND c.archived_at IS NULL
```
