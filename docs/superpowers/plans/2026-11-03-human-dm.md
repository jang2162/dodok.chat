# 사람 간 DM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 이 저장소에서는 Orca 워커가 태스크를 맡는다(`AGENTS.md` 「작업 방식」). 태스크 하나 = 워크트리 하나 = 브리프 하나. 태스크마다 main 에 병합해도 초록이어야 한다.

**Goal:** 활성 멤버끼리 사람 1:1 DM 과 그룹 DM(사람 여럿, 에이전트를 넣을 수 있다)을 연다. 참여자가 아닌 사람(owner·admin 포함)은 그 대화를 어느 화면·API·검색·알림·운영 표·제어 도구에서도 볼 수 없다.

**Architecture:** 사람 DM·그룹 DM 은 `channels.kind = 'direct'` 인 채널이다 — 참여자는 만들 때 고정한 `channel_members` 행, 같은 참여자 묶음은 `direct_key` 유일 색인으로 한 채널. 읽기 판정은 「사람 참여자 행이 있다」(`membersOnly`). **먼저 접근 판정을 「`channel` 만 열림, 나머지는 닫힘」으로 뒤집어 모든 진입점에 `direct` 를 막아 두고**(태스크 1·2 — 아직 `direct` 를 만들 길이 없다), 그다음 열기·쓰기(태스크 3), 그룹 DM 의 런(태스크 4), 웹(태스크 5)을 연다. 에이전트 DM(`kind = 'dm'`)의 동작은 바꾸지 않는다.

**Tech Stack:** Fastify 5 · Socket.IO 4.8 · drizzle-orm 0.45 + better-sqlite3 · zod 4 · React 19 + TanStack Router/Query · OpenClaw 2026.9.4 플러그인 SDK · Claude Agent SDK(러너). **새 의존성 없음.**

**Spec:** `docs/superpowers/specs/2026-11-03-human-dm-design.md` — 결정 1장, 접근 2장, 데이터 3장, **접근 규칙 4장(정본)**, 열기·목록 5장, 화면·런 6장, 알림·검색·운영 7장, 오류 8장, 범위 9장, 검증 10장, 완료 기준 11장. 그 아래 에이전트 DM 스펙 `docs/superpowers/specs/2026-10-25-agent-dm-design.md` — **9장 「구현과 맞춘 것」이 지금 코드다**(접근 판정이 지나는 자리·DM 런·푸시·읽지 않음). **태스크를 시작하기 전에 두 스펙의 해당 장을 읽는다.**

## Global Constraints

- 판정의 정본은 `apps/server/src/auth/channel-access.ts` 한 파일이다. **접근 판정(404)이 역할 판정(403)·`VALIDATION`·보관(409)보다 먼저다**(에이전트 DM 스펙 9장 「접근 판정」의 순서 그대로).
- **기본이 닫힘** — 서버·웹의 모든 `kind` 갈래는 「`kind === "channel"` 이면 열림, `"dm"` 은 지금 규칙, `"direct"` 는 참여자, 그 밖은 닫힘」 꼴로 쓴다. `kind !== "dm"` 처럼 「DM 이 아니면 일반 채널」로 읽는 꼴을 남기지 않는다. 태스크 1 이 지금의 자리 목록(아래 「`kind` 갈래 지도」)을 모두 뒤집는다.
- 참여자가 아닌 사람 → HTTP 404 `NOT_FOUND`, wire 는 같은 코드의 ack, 문구는 없는 채널·대화·런·승인과 같다. `direct` 에 채널 관리 → 400 `VALIDATION`. 1:1 상대 비활성 뒤 쓰기 → 409 `DM_READ_ONLY` `details.reason: "peer_deactivated"`.
- 데이터: `ChannelKind` `"channel" | "dm" | "direct"`. 새 열 `channels.direct_key`(text, nullable), 유일 색인 `channels_direct_key (workspace_id, direct_key) WHERE kind = 'direct'`. 마이그레이션 `0035_human_dms` — `pnpm -F @dodok/server db:generate` 로 만들고 다시 generate 해 「No schema changes」, 이름만 관례대로 바꾼다.
- `direct` 채널 행: `name` `direct`, `visibility` `private`, `topic`·`prompt` null, `dm_owner_id`·`dm_agent_id` null, `relay_policy` `{ maxRelayTurns: 4, allowPairs: "all" }`, `session_policy` `{ create: "members" }`, `created_by` = 연 사람. `channel_members` 는 참여자마다 한 행(사람 `role: "member"`, 에이전트 `autoRespond: false`) — 만든 뒤 더하거나 빼지 않는다.
- `direct_key` 꼴: 참여자(연 사람 포함)를 `u:<userId>`·`a:<agentId>` 로 적어 사전순 정렬해 `,` 로 이은 문자열. 만드는 함수는 하나(`modules/directs/service.ts directKey`).
- 참여자 수: 나를 포함해 2 ~ 9(`DIRECT_MAX_PARTICIPANTS = 9` — shared). 「나 + 에이전트 1」은 `direct` 가 아니라 에이전트 DM(`POST /dms`) — `POST /directs` 는 `VALIDATION`.
- 한 줄기(에이전트 참여자 없음)는 채널을 만들 때 대화 하나를 같은 트랜잭션에 만든다. 세션(에이전트 참여자 있음)은 첫 보내기 `newConversation` 이 만든다.
- 문구(합쇼체, 그대로):
  - 사이드바 「+」 대화상자 제목 「새 메시지」, 확인 버튼 「열기」, 사람 프로필 버튼 「메시지 보내기」.
  - 읽기 전용 사유 `peer_deactivated` 「상대가 비활성화되어 읽기만 할 수 있습니다」.
  - 그룹 DM 첫 안내(에이전트가 있는 그룹, 세션이 하나도 없을 때): 「이 대화는 참여자만 봅니다. 다만 에이전트는 자기 기억(메모리·작업 디렉터리의 파일)을 거쳐 여기서 들은 것을 다른 자리의 답에 쓸 수 있습니다 — dodok 은 이것을 막지 못합니다.」
  - 에이전트 헤더 줄 `그룹 DM: 참여자만 보는 대화`(shared `formatGroupDmLine()` 하나).
  - 런을 막은 시스템 메시지: `@<에이전트 핸들> 는 이 요청에 답하지 않았습니다 — 시킨 사람이 이 에이전트의 DM 허용 범위 밖입니다`(시킨 사람이 없으면 `— 시킨 사람이 없습니다`).
  - 승인 카드의 잠긴 결정 줄 `@<시킨 사람 핸들> 님이 결정합니다`.
  - 푸시 제목: 사람 글 `<보낸 사람 이름> 님의 메시지`, 에이전트 최종 답 `@<핸들><이/가> 답했습니다`(`util/josa.ts`), 본문 「DM」. 운영 런 표의 묶음 줄 이름 「DM」(지금 그대로).
- 권한은 서버가 요청마다 판정한다(웹이 숨기는 것은 편의). 새 경로는 `apps/server/test/roles.matrix.test.ts` 와 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md` 「역할과 권한」 표에 더한다.
- 외부 입력은 경계에서 Zod 파싱. shared 는 Node 전용 API 금지. 레이트리밋 숫자는 `apps/server/src/modules/ops/limits.ts` 한곳(새 숫자 없음 — `/directs` 는 기존 사용자 버킷).

- 포트 5173·3000 금지(사용자 인스턴스 3100·5180 도 건드리지 않는다 — 워커는 브리프가 주는 포트). 프로세스는 자기 PID 로만, `pkill` 금지. **모델 런 없음.**

## 계획 판정 (스펙과 맞춘 것)

조사한 코드에 맞춰 스펙 12장 「빌더에게 맡긴 것」을 정한 것. 태스크 7 이 스펙에 「구현과 맞춘 것」 장을 만들어 옮긴다.

- **PH1 — `canReadChannel` 은 db 를 받는다.** `canReadChannel(db: DbOrTx, viewer: { userId: string }, channel: { id: string; kind: string; dmOwnerId: string | null }): boolean` — `direct` 면 `channel_members` 에 (채널, user, viewer) 행이 있는지 읽는다. `assertChannelReadable(db, channel, userId)` 도 같다. 부르는 자리(`channels/service.ts loadReadableChannel`·`components/service.ts`·`realtime/socket.ts`·`reactions/service.ts`·`attachments/service.ts readableBy` 와 codegraph `canReadChannel` 호출자 전부)를 함께 고친다.
- **PH2 — `membersOnly(channel: { kind: string }): boolean`** 은 `kind === "direct"` 하나. `readableChannelSql(userId)` 은 `kind = 'channel' ∨ dm_owner_id = userId ∨ (kind = 'direct' ∧ EXISTS(channel_members: channel_id = channels.id, member_type = 'user', member_id = userId))`. K 는 `membersOnly` 와 이 EXISTS 갈래의 조건에 `visibility = 'private'` 를 더하면 된다 — 함수 머리 주석에 한 줄.
- **PH3 — 한 줄기인지는 저장하지 않는다.** `directHasAgents(db, channelId): boolean`(`modules/directs/service.ts` — 에이전트 참여자 행 존재). 웹은 `DirectSummary.agents.length > 0` 으로 가른다.
- **PH4 — 한 줄기 `direct` 의 대화 규칙**: `message.send { newConversation }` → `VALIDATION`(「이 대화에는 세션이 없다」), `PATCH /conversations/:id`(제목·닫기) → `VALIDATION`. 웹 URL 은 `/c/<채널 id>` 하나 — 한 줄기면 채널 레이아웃이 그 대화를 바로 그리고 `s/<id>` 로 오면 그대로 그린다.
- **PH5 — 세션 `direct` 의 세션 권한은 참여자 누구나**: `authorizeConversationCreate`·제목·닫기 판정(`conversations/service.ts`·웹 `features/conversations/permissions.ts`)에 「`direct` 면 접근 판정을 지난 사람 모두」 갈래. 세션 관리자·세션 정책은 쓰지 않는다.
- **PH6 — 멘션**: `direct` 의 사람 글은 `tokenize(body, channelParticipants(tx, channelId))`(참여자만 — `userMessageParticipants` 가 아니다), 에이전트 글은 지금 `agentMentions(…, channelParticipants)`. 둘 다 그 뒤 참여자가 아닌 id 의 토큰 꼴을 중화한다(`directMentions(text, participants)` — `modules/directs/service.ts`). `joinChannelIfAbsent` 는 `direct` 에서 부르지 않는다(보낸 사람도 이미 참여자).
- **PH7 — 그룹 DM 의 승인 결정자는 `approvals.requested_by`.** 지금은 `dodok_control` 만 채우는 열을 **채널이 `direct` 면 모든 kind 에** 런의 `runs.requested_by` 로 채운다. `approval.resolve`(`realtime/socket.ts:387`)·`approvals/service.ts` 의 결정자 판정: `direct` 면 `userId === approval.requestedBy`(null 이면 `FORBIDDEN`), 역할은 보지 않는다. 웹 `canDecideApproval` 은 채널이 `direct` 면 `approval.requestedBy === me.user.id`.
- **PH8 — 시킨 사람 관문 `directRunBlock(db, input: { channelId: string; agentId: string; requestedBy: string | null }): "no_requester" | "dm_not_allowed" | null`**(`modules/directs/service.ts`) — `direct` 가 아니면 늘 null. 시킨 사람의 지금 역할로 `dmAccessAllows(agent.dmAccess, role)` 를 본다(비활성이면 역할 없음 → `dm_not_allowed`). 라우터가 런을 만들기 전에 부르고 막히면 런 없이 그 대화(스레드면 그 스레드)에 `system` 메시지(`systemMeta.kind: "info"`, 문구는 Global Constraints) 하나. 디스패치(`runs/orchestrator.ts dispatch` 의 `dmClosedTarget` 자리)도 같은 함수로 막아 `abort_requested`(시스템 메시지 없음).
- **PH9 — REST**: `POST /api/v1/directs` 본문 `CreateDirectBody = { userIds: Id[]; agentIds: Id[] }`(나 제외, 기본 `[]`) → `200 { channel: Channel; created: boolean }`. `GET /api/v1/directs` → `DirectList = { directs: DirectSummary[] }`, `DirectSummary = { channel: Channel; users: Person[]; agents: Agent[]; lastMessageAt: IsoDateTime | null; readOnlyReason: DmReadOnlyReason | null }` — `users` 는 나를 뺀 사람 참여자(비활성 포함 — `deactivatedAt` 으로 웹이 흐리게), `agents` 는 `agentForRole` 을 지난 참여 에이전트(보관된 것 제외). 최근 활동순은 `listDms` 와 같은 식. 403 의 `details.agentId` 는 막은 에이전트 하나.
- **PH10 — `DmReadOnlyReason` 에 `"peer_deactivated"`.** `directReadOnlyReason(db, channel): DmReadOnlyReason | null` — 1:1(사람 참여자 둘, 에이전트 없음)이고 상대의 membership 이 비활성이면 그 값. 쓰기 경로의 `assertDmWritable` 이 `direct` 면 이 함수를 본다(메시지·카드·반응·첨부 올리기).
- **PH11 — 실시간 대상**: `channelAudience(db, channel): string[]`(`realtime/events.ts`) — `channel` 은 `[workspaceRoom]`, `dm` 은 `[userRoom(주인)]`, `direct` 는 사람 참여자(비활성 제외) 각자의 `userRoom`, 그 밖은 `[]`. `io.to(rooms)` 로 낸다. `channel.activity` 의 `mentionedUserIds` 는 `direct` 의 normal 글이면 작성자를 뺀 사람 참여자 전원.
- **PH12 — 에이전트가 받는 것**: `InboundDeliver.groupDm?: true`(shared `bridge`). `buildInboundDeliver` 가 `direct` 면 채우고, 플러그인 `formatInboundContext`·러너 턴 사실이 `[dodok context]` 다음 줄에 `formatGroupDmLine()`. 참여자는 `channelParticipants`(비활성·보관 제외) 그대로. 러너는 채널 틀을 받되 자리 문구를 `a group direct message in dodok` 로(`packages/shared/src/runner/prompt.ts`). 그룹 DM 은 채널 프롬프트가 늘 없다. 옛 플러그인은 `groupDm` 을 버리고 받는다.
- **PH13 — 푸시**: `direct` 의 사람 normal 최상위·스레드 글과 에이전트 normal 정본은 작성자를 뺀 사람 참여자 전원에게, `run_error`·승인 요청은 그 런의 `requestedBy` 에게만. payload `kind` 는 `"mention"`(새 값 없음), tag `direct:<conversationId>`. 발송 직전 거름(`push/service.ts attachPushTriggers` — 지금 `dmOwner` 자리)에 `directParticipants` 를 더해 `direct` 를 겨눈 알림은 사람 참여자 말고 모두 걷는다.
- **PH14 — 읽지 않음**: `reads/store.ts` 의 멘션 셈에 `OR (channels.kind = 'direct' AND m.kind = 'normal')`(작성자 본인 제외는 지금 조건이 한다).

## Review Focus

1. **참여하지 않은 admin 이 그룹 DM 의 승인 id 로 `approval.resolve`** — 지금 일반 채널 갈래(「admin 이상이면 결정」)로 새지 않고 404. 참여한 admin 이어도 시킨 사람이 아니면 `FORBIDDEN`. → 태스크 1(404)·태스크 4(`FORBIDDEN`).
2. **`direct` 가 「DM 이 아니니 일반 채널」로 읽히는 자리가 하나라도 남음** — 지도 밖의 갈래(예: 새로 생긴 `?.kind !== "dm"`)로 workspace 룸·채널 목록·운영 표에 실린다. → 태스크 1 의 「모르는 kind」 실증(`kind = 'zzz'` 행을 DB 에 직접 넣고 어떤 목록·이벤트에도 없음)과 태스크 2 의 팬아웃 시험.
3. **그룹 DM 에서 참여자가 아닌 `@jun`(활성 멤버)을 씀** — 글자로 남고 jun 은 채널 멤버가 되지 않으며(`channel_members` 불변) 푸시·배지·검색 어디에도 그 글이 없다. 토큰 꼴 `<@u:jun-id>` 을 손으로 적어 보내도 같다. → 태스크 3.
4. **1:1 상대가 비활성화된 사이 보내기 중이던 탭** — 보내기는 409 `DM_READ_ONLY` `peer_deactivated`, 웹 항목은 「다시 보내기」 없이 사유로 남고 작성기 자리가 사유 줄로 바뀐다(`people.changed` → `/directs` 다시 받기). 다시 활성화하면 이어 보낸다. → 태스크 3(서버)·태스크 5(웹).
5. **같은 참여자 묶음을 순서만 바꿔 두 탭에서 동시에 열기**(`[mia, @dev]` 와 `[@dev, mia]`) — 채널 행 하나, 같은 id, 대화(한 줄기면) 하나. → 태스크 3.

각 줄의 테스트는 해당 태스크의 단계에 들어 있다.
