# 파일함 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 이 저장소에서는 Orca 워커가 태스크를 맡는다(`AGENTS.md` 「작업 방식」). 태스크 하나 = 워크트리 하나 = 브리프 하나. 태스크마다 main 에 병합해도 초록이어야 한다.

**Goal:** 채널·에이전트 DM·사람 DM 마다 오른쪽 패널 「파일」 탭과 사이드바 「파일」 전체 화면에서, 그 사람이 읽을 수 있는 대화의 사진·파일을 최신순으로 보고 종류·이름·올린 사람(전체 화면은 대화도)으로 좁히며, 사람도 이미지가 아닌 파일(20 MiB)을 보낸다.

**Architecture:** 서버는 `attachments ⋈ messages ⋈ channels` 를 바로 조회하는 `GET /api/v1/attachments`(새 표 없음, 색인 하나)를 더하고, 읽기 거름은 C 의 `readableChannelSql` 을 SQL 단계에 붙인다. 사람 올리기는 판별 종류별 상한(이미지 5 MB · 그 밖 20 MiB)으로 바꾼다 — 에이전트 쪽은 이미 일반 파일을 이름 한 줄로 받으므로 코드가 바뀌지 않는다. 웹은 작성기가 모든 파일을 받고, `features/files` 가 패널 탭·전체 화면을 그린다.

**Tech Stack:** Fastify 5 · drizzle-orm 0.45 + better-sqlite3 · zod 4 · React 19 + TanStack Router/Query. **새 의존성 없음.**

**Spec:** `docs/superpowers/specs/2026-11-09-files-hub-design.md` — 결정 1장, 접근 2장, 싣는 것 3장, 서버 4장, 웹 5·6장, 오류 7장, 문서 8장, **범위 9장(「A 가 들어올 때」·「C 위에서 짓는다」)**, 검증 10장, 완료 기준 11장, C 와 맞춘 자리 13장. 접근 규칙의 정본은 사람 간 DM 스펙 `docs/superpowers/specs/2026-11-03-human-dm-design.md` 4장(지금 코드는 그 13장). **태스크를 시작하기 전에 두 스펙의 해당 장을 읽는다.**

## Global Constraints

- **읽기 판정을 따로 짓지 않는다.** 목록은 `readableChannelSql(userId)`(`apps/server/src/auth/channel-access.ts`)을 SQL 단계에, 채널 거름은 `loadReadableChannel(db, channelId, workspaceId, userId)`(`modules/channels/service.ts`)로. `channel-access.ts` 는 고치지 않는다. 결과를 뽑은 뒤 거르지 않는다(커서·개수가 남의 DM 을 세지 않게).
- 못 읽는·없는·모르는 kind·다른 워크스페이스의 `channelId` → 404 `NOT_FOUND`(빈 목록이 아니다). 꼴 오류 → 400 `VALIDATION`.
- **A(메시지 수정·삭제)는 보류다 — 이 계획에 A 를 기다리는 단계는 없다.** 「지운 메시지」 거름·열을 만들지 않는다. A 가 들어오면 바꿀 자리 둘(목록 조회의 WHERE·파일 탭 무효화)은 스펙 9장 「A 가 들어올 때」에 있고, 태스크 2·4 의 코드 주석에 그 절을 한 줄로 가리킨다.
- 상한: `ATTACHMENT_LIMITS.userImageMaxBytes` 5 MiB(그대로) · **새 `ATTACHMENT_LIMITS.userFileMaxBytes = 20 * 1024 * 1024`** · `agentFileMaxBytes` 그대로 · `perMessage` 10 그대로. 사람 업로드는 서버 `sniff` 판별이 `image` 면 이미지 상한, `file` 이면 파일 상한.
- 목록 페이지: 기본 50(`FILE_PAGE_SIZE`), 최대 100(`FILE_PAGE_MAX`). 이름 거름 `q` 는 trim 뒤 1~100 코드 포인트, NFC 로 바꿔 `LIKE … ESCAPE '\'`.
- 정렬: `messages.created_at DESC, messages.id DESC, pos ASC` — `pos` 는 그 첨부의 `messages.attachments_json` 안 자리(`json_each` 의 key). 커서는 `{ createdAt, messageId, pos }`.
- 문구(합쇼체, 그대로):
  - 탭·사이드바 「파일」, 종류 세그먼트 「전체」·「사진」·「파일」, 이름 칸 자리 「이름으로 찾기」, 단추 「내려받기」·「메시지로 가기」·「더 보기」.
  - 빈 상태 「아직 주고받은 파일이 없습니다」, 거름 결과 없음 「조건에 맞는 파일이 없습니다」 + 단추 「거름 지우기」.
  - 작성기: 「첨부는 한 번에 10개까지 보낼 수 있습니다」, 「5 MB 를 넘습니다」(이미지 — 지금 문구 그대로), 「20 MB 를 넘습니다」(그 밖), 칩 목록 라벨 「첨부할 파일」, 작성기 밖에 놓기 「파일은 입력 칸에 놓아 주세요」.
- 권한은 서버가 요청마다 판정한다. 새 경로는 `apps/server/test/roles.matrix.test.ts` 와 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md` 「2. 역할과 권한」 표에 더한다.
- 외부 입력은 경계에서 Zod 파싱. shared 는 Node 전용 API 금지. 레이트리밋 숫자는 `apps/server/src/modules/ops/limits.ts` 한곳(새 숫자 없음).
- 포트 5173·3000 금지(사용자 인스턴스 3100·5180 도 건드리지 않는다 — 워커는 브리프가 주는 포트). 프로세스는 자기 PID 로만, `pkill` 금지. **모델 런 없음.**
- 커밋: `git add -A`·`git commit -a` 금지, 경로 명시. Conventional Commits + 스코프. 워커 트레일러 `Co-Authored-By: <네 실제 모델명> <noreply@anthropic.com>`.
- 문서·주석을 쓰기 전에 `docs/guideline/base/03-comments.md`·`04-citation.md` 를 읽는다.
- 끝내기 검사: 루트 `pnpm test`(**다른 검사와 동시에 돌리지 않는다**) → `pnpm typecheck && pnpm lint && pnpm fmt:check`, 각 exit code, 테스트 수는 자기 실행 출력에서 패키지별로(0개는 통과가 아니다). 웹을 바꿨으면 `pnpm -F @dodok/web build`, 서버를 바꿨으면 `pnpm -F @dodok/server build && pnpm -F @dodok/server bundle:smoke`.

## Review Focus

1. **페이지 경계에 첨부 여러 개인 메시지가 걸림** — 첨부 1개짜리 49개 뒤 첨부 10개짜리 메시지 하나면 첫 쪽 50번째가 그 메시지의 첫 첨부, 둘째 쪽이 나머지 9개를 `attachments_json` 순서로. 겹침·빠짐 없음. → 태스크 2.
2. **첫 쪽과 둘째 쪽 사이에 새 첨부 글이 옴** — 둘째 쪽에 겹치는 항목이 없다(새 글은 커서보다 앞이라 다음에 처음부터 받을 때 보인다). → 태스크 2.
3. **이름 칸에 `%`·`_`·`\`·NFD 한글(macOS 조합형)** — `%` 는 글자 그대로 찾고 모든 줄이 걸리지 않으며, NFD 「보고서」 가 NFC 로 저장된 「보고서.pdf」 를 찾는다. → 태스크 2.
4. **사람이 `.png` 이름의 HTML 을 올림** — 판별이 `file` 이라 20 MiB 상한, GET 은 `application/octet-stream`·`attachment`·sandbox CSP·`nosniff`, 파일함 「사진」 칸에 없고 「파일」 칸에 있다. → 태스크 1(서버)·태스크 2(종류 거름).
5. **패널 「파일」 탭을 연 채 다른 채널로 옮김** — 거름이 초기화되고 옛 채널의 줄이 한 틱도 보이지 않으며(키에 채널 id), 옮긴 채널이 그 종류에서 파일 탭을 허용하면 탭이 유지된다. → 태스크 4.

각 줄의 테스트는 해당 태스크의 단계에 들어 있다.
