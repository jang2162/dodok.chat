# 설정 통합·에이전트 보관·llms.txt 설계

- 상태: 설계 승인(브레인스토밍 2026-10-05), 구현 전
- 범위: 웹 설정 화면 통합, 에이전트 삭제(보관·되살리기), 노드 설치 안내서 `llms.txt`
- 관련: 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md`(역할·멤버 내보내기), 멀티 Gateway 스펙 `docs/superpowers/specs/2026-10-04-multi-gateway-design.md`(Gateway·에이전트 정체), 러너 스펙 `docs/superpowers/specs/2026-09-27-claude-runner-design.md`(러너 설치·토큰), 운영 절차 `docs/guides/deploy.md`

## 0. 결정

| # | 결정 | 까닭 |
| --- | --- | --- |
| 1 | 에이전트 삭제는 **보관**이다 — 행·핸들·채널 참여·세션을 남기고 숨긴다. 되살리면 그대로 돌아온다 | 사용자 결정(슬랙의 비활성화처럼). 채팅 기록이 그 에이전트를 계속 가리킨다 |
| 2 | 같은 Gateway·같은 id(러너는 같은 id)를 다시 가져오면 **새로 만들지 않고 되살린다** | 1 의 따름 — 예전 대화와 이어진다 |
| 3 | 사이드바 하단은 **연결 점 + 「설정」 하나**다. 에이전트·멤버·연결·운영·알림·내 계정·로그아웃은 `/settings` 의 탭으로 간다 | 사용자 결정. 하단 링크가 너무 많다 |
| 4 | `llms.txt` 는 **노드에서 도는 AI 가 설치를 대신하는 안내서**다 — 서버가 자기 주소를 채워 로그인 없이 내준다. 토큰은 싣지 않는다 | 사용자 결정. 사람은 AI 에게 「안내서 주소 + 토큰」만 건넨다 |
| 5 | 설치 파일(`plugin.tgz`·`runner.tgz`)은 owner 세션 **또는 발급한 토큰**(브리지 토큰·러너 토큰)으로 받는다 | 사용자 결정. 노드의 AI 는 owner 세션이 없다 |

## 1. 범위

**한다**

- 에이전트 보관·되살리기(서버·shared·웹), 보관한 에이전트가 채팅 기록에 「삭제됨」으로 보이기
- `/settings` 탭 화면(내 계정·알림·에이전트·멤버·연결·운영), 사이드바 하단 정리, 옛 주소 넘겨주기
- `GET /llms.txt`, 토큰으로 설치 파일 받기, 발급 대화상자의 「AI 에게 맡기기」 한 줄
- 문서(`deploy.md`·`user-guide.md`·`project-structure.md`·`agent-guide.md` 해당 줄)

**하지 않는다**

- 에이전트 영구 삭제(행 지우기) — 보관만 한다
- 채널 설정 패널(채널 머리의 설정)의 자리 — 채널 단위라 그대로 둔다
- 노드 쪽 자동 실행 스크립트 — 안내서는 명령을 적을 뿐 서버가 노드에서 무엇을 돌리지 않는다

## 2. 에이전트 보관

### 2.1 데이터

- `agents.archived_at`(시각, null 이면 살아 있음) — 새 마이그레이션.
- shared `Agent` 에 `archivedAt: string | null`.
- 핸들·`(gateway_id, provider_agent_id)` 유일 규칙은 그대로다 — 보관한 에이전트도 자리를 잡고 있다. 그래서 보관한 에이전트의 핸들로 새 에이전트를 등록하면 지금처럼 409 다.
- `channel_members`·`agent_sessions` 의 그 에이전트 행은 지우지 않는다(되살리면 그대로 돌아온다).

### 2.2 API (admin 이상 — 에이전트 등록과 같은 권한)

| 요청 | 뜻 |
| --- | --- |
| `DELETE /api/v1/agents/:id` | 보관. 이미 보관됐으면 200 그대로(멱등). 없는 id 404 |
| `POST /api/v1/agents/:id/restore` | 되살리기. 살아 있으면 200 그대로. Gateway 가 지워져 연결이 빈 에이전트도 되살아난다(지금처럼 owner 가 옮긴다) |
| `GET /api/v1/agents` | **보관한 것도 함께** 내준다(`archivedAt` 로 가른다) — 채팅 기록의 작성자·멘션 칩을 그리려면 웹이 보관한 에이전트도 알아야 한다. 고르는 자리(멘션 후보·채널에 넣기·가져오기)는 웹이 거른다 |
| `GET /api/v1/agents/discover` | 보관한 에이전트와 같은 Gateway·id 인 항목에 `archivedAgentId` 를 싣는다 |
| `POST /api/v1/agents` | 같은 Gateway·id 의 보관한 에이전트가 있으면 409 `AGENT_ARCHIVED`(본문에 그 id) — 웹은 「되살리기」로 안내한다 |

보관·되살리기는 모든 소켓에 wire 이벤트 `agents.changed`(본문 없음)를 보낸다 — 웹은 에이전트·채널 멤버 질의를 다시 받는다. 지금은 에이전트가 바뀌어도 다른 탭이 알 길이 없어, 이 이벤트로 함께 메운다(등록·수정·옮기기도 같은 이벤트를 보낸다).

### 2.3 보관할 때 서버가 하는 일

1. `archived_at` 을 쓴다.
2. 그 에이전트의 **열린 런을 사람 「중지」와 같은 경로로 멈춘다**(대기열에 선 런은 시작하지 않고 닫는다). 걸린 승인은 「철회됨」으로 닫는다.
3. 그 뒤로 런을 만들지 않는다 — 런 관문이 보관한 에이전트를 거절한다(사람 멘션·자동 응답·릴레이·상호작용·다시 실행 모두). 멘션 해석이 보관한 에이전트를 대상으로 잡지 않으므로, 손으로 친 `@핸들` 은 그냥 글자다.
4. 에이전트 헤더 「참여자:」·채널 멤버 응답·릴레이 대상·자동 응답 대상에서 빠진다.
5. 러너가 hello 로 그 id 를 알려도 무시한다(되살리면 다시 받는다).

### 2.4 웹

- **에이전트 탭**: 살아 있는 에이전트 목록 + 줄마다 「삭제」(admin 이상, 확인 대화상자 — 「@핸들 을 삭제합니다. 채팅 기록은 남고, 되살리면 채널·대화가 그대로 돌아옵니다.」). 아래에 접힌 「삭제된 에이전트 N」 묶음 — 줄마다 「되살리기」(admin 이상).
- **채팅 기록**: 작성자 이름 옆과 멘션 칩에 「삭제됨」. 프로필·멘션 후보에서는 빠진다.
- **가져오기**: `archivedAgentId` 가 있는 항목은 「삭제됨 — 되살리기」 단추로 바뀐다.
- **채널 설정**: 에이전트 넣기 셀렉트에 보관한 에이전트가 없다. 멤버 줄에도 없다.
- **운영 화면 에이전트별 표**: 기록이라 남기고 「삭제됨」을 붙인다.

## 3. 설정 통합

### 3.1 사이드바

하단은 연결 점(지금 그대로)과 「⚙ 설정」 링크 하나다. admin 이상이면 확인 안 한 운영 사건 수 배지가 이 링크에 붙는다(지금 「운영」 링크의 배지와 같은 값). 「내 계정」 대화상자·로그아웃 단추·알림 위젯·에이전트·멤버·연결·운영 링크는 사이드바에서 사라진다.

### 3.2 주소와 탭

| 주소 | 탭 | 보이는 역할 |
| --- | --- | --- |
| `/settings` | `/settings/account` 로 넘긴다 | — |
| `/settings/account` | 내 계정 — 표시 이름·비밀번호(지금 대화상자 내용)·**로그아웃** | 누구나 |
| `/settings/notifications` | 알림 — 이 기기 푸시 켜기·끄기·앱 설치(지금 사이드바 위젯 내용) | 누구나 |
| `/settings/agents` | 에이전트(지금 `/agents` 화면 + 2.4) | 누구나(동작은 역할대로) |
| `/settings/members` | 멤버 | admin 이상 |
| `/settings/connection` | 연결 | owner |
| `/settings/operations` | 운영(탭에도 배지) | admin 이상 |

- 옛 `/agents` 는 `/settings/agents` 로 넘긴다(즐겨찾기·푸시 알림 링크가 깨지지 않게).
- 보이지 않는 탭의 주소로 직접 오면 지금처럼 「권한이 없습니다」다(서버가 막는 것은 그대로).
- 배너의 「연결 설정 보기」·시스템 카드의 운영 링크·가져오기 대화상자의 연결 링크는 새 주소를 가리킨다(주소가 같으면 그대로).

### 3.3 레이아웃

- **넓은 화면**: 페이지 영역 안에서 왼쪽 탭 목록(고정) + 오른쪽 탭 내용(따로 스크롤). 사이드바(채널 목록)는 그대로 보인다.
- **좁은 화면(768px 미만)**: `/settings` 는 탭 목록만 보인다(넘기지 않는다). 탭을 누르면 그 페이지로 들어가고, 머리에 「← 설정」과 사이드바 메뉴 단추가 붙는다. 이 머리는 스크롤해도 위에 붙어 있다.
- 탭 목록은 `nav` + 현재 탭 `aria-current="page"`. 탭 이동 뒤 초점은 그 탭 내용의 제목으로 간다.

## 4. `llms.txt`

### 4.1 내주는 것

- `GET /llms.txt` — 로그인 없음, `text/plain; charset=utf-8`, IP 버킷(분당 30 — `modules/ops/limits.ts` 에 더한다). 배포 Caddy 의 `@backend` 와 개발 Vite 프록시에 `/llms.txt` 를 더한다.
- 서버가 채우는 값: 공개 오리진(`BRIDGE_PUBLIC_URL` 의 오리진, 없으면 `APP_ORIGIN`), 플러그인 `bridgeUrl`(발급 조각과 같은 값), 서버가 품은 플러그인·러너 파일의 파일 sha256·번들 sha256(없으면 그 절에 「서버에 파일이 없습니다」). 토큰·Gateway 목록·사람 이름은 싣지 않는다.

### 4.2 내용

머리에 이 서버가 무엇인지 한 단락과 **AI 가 지킬 규칙**:

- 토큰을 화면·로그·명령 줄 인자에 찍지 않는다 — 파일(0600)이나 표준 입력으로 넘긴다.
- 토큰은 안내서가 지정한 자리에만 둔다.
- 사람이 할 단계(Claude 로그인, 기기 페어링 승인 확인)에서는 멈추고 사람에게 묻는다.
- 받은 파일은 안내서의 sha256 과 대조하고, 다르면 멈춘다.

**「OpenClaw Gateway 호스트」 절** — `deploy.md` 「[웹 → B] 플러그인 설치·브리지 토큰」 절과 같은 순서를 명령으로:

1. 사람에게 받은 브리지 토큰을 0600 파일에 둔다.
2. `curl -fsS -H "Authorization: Bearer $(cat <토큰 파일>)" <오리진>/api/v1/setup/plugin.tgz -o <파일>` → 파일 sha256 대조.
3. Gateway 를 내린다 → `openclaw plugins install <파일> --force --accept-capabilities` → `openclaw plugins inspect dodok --json` 으로 `loaded` 확인 → 번들 sha256 대조.
4. 계정 설정 패치 파일(`channels.dodok.accounts.default` 의 `bridgeUrl`·`token`)을 0600 으로 만들어 `openclaw config patch --file` → 지운다.
5. Gateway 를 올린다 → 사람에게 연결 페이지 그 Gateway 카드의 「접속됨 · 서버와 같은 빌드입니다」를 확인받는다. 카드에 페어링 대기가 보이면 그 요청 id 를 사람에게 받아 `openclaw devices approve <id>`.

**「Claude 러너 머신」 절** — `deploy.md` 「Claude 러너 설치」 절과 같은 순서를 명령으로:

1. 사람에게 받은 러너 토큰을 `~/.dodok-runner/token`(0600)에 둔다.
2. `curl … /api/v1/setup/runner.tgz` → sha256 대조 → `npm install -g <파일>`.
3. 러너 전용 로그인은 사람이 한다 — 명령(`CLAUDE_CONFIG_DIR=~/.dodok-runner/claude claude`)을 보여 주고 멈춘다.
4. `~/.dodok-runner/config.json` 을 만든다(`serverUrl`·`tokenFile`·`claudeConfigDir`·`agents` — 에이전트 id·작업 디렉터리는 사람에게 묻는다).
5. `dodok-runner` 실행 → 첫 줄 `연결됨` 확인 → 사람에게 연결 페이지 러너 카드를 확인받는다.

### 4.3 토큰으로 설치 파일 받기

- `GET /api/v1/setup/plugin.tgz` — owner 세션, 또는 `Authorization: Bearer <브리지 토큰>`(폐기되지 않았고 묶인 Gateway 가 켜져 있을 것).
- `GET /api/v1/setup/runner.tgz` — owner 세션, 또는 `Authorization: Bearer <러너 토큰>`(폐기되지 않았을 것).
- 틀린 토큰은 브리지 실패 카운터(`BridgeAuthGuard`)에 센다 — 핸드셰이크·첨부 HTTP 와 같은 버킷이라, 이 경로로 토큰을 맞혀 보는 길이 따로 열리지 않는다. 응답 본문은 다른 거절과 같은 401 이다.
- 꺼진 Gateway 의 브리지 토큰은 핸드셰이크처럼 401 로 거절하되 카운터에 세지 않는다(멀티 Gateway 스펙 「구현과 맞춘 것」 장의 꺼진 Gateway 토큰 규칙과 같다).

### 4.4 발급 대화상자

브리지 토큰·러너 토큰 발급 대화상자의 원문 아래에 「AI 에게 맡기기」 한 줄과 「복사」:

- 브리지: `<오리진>/llms.txt 를 읽고 「OpenClaw Gateway 호스트」 절대로 이 호스트에 dodok 플러그인을 설치해 줘. 브리지 토큰: <원문>`
- 러너: `<오리진>/llms.txt 를 읽고 「Claude 러너 머신」 절대로 이 머신에 dodok 러너를 설치해 줘. 러너 토큰: <원문>`

원문과 같은 규칙이다 — 이 대화상자에서 한 번만 보이고, 복사 확인 전에는 닫히지 않는다.

## 5. 오류

| 상황 | 결과 |
| --- | --- |
| 보관한 에이전트를 멘션(손으로 친 `@핸들`) | 런 없음 — 글자로 남는다 |
| 보관 중 그 에이전트의 런이 돌고 있었음 | 사람 「중지」와 같은 결과로 닫힌다 |
| 보관한 에이전트의 「다시 실행」 카드를 누름 | 거절 — 「삭제된 에이전트입니다」, 카드는 소비하지 않는다 |
| 보관한 에이전트를 등록하려 함(같은 Gateway·id) | 409 `AGENT_ARCHIVED` → 웹 「되살리기」 안내 |
| 되살리려는데 같은 핸들을 다른 에이전트가 씀 | 생길 수 없다 — 보관 중에도 핸들은 그 에이전트 몫이다 |
| 토큰 없이·틀린 토큰으로 설치 파일 요청 | 401, 틀린 토큰은 실패 카운터 |
| 서버에 플러그인·러너 파일이 없음 | 설치 파일 404, `llms.txt` 의 그 절은 「서버에 파일이 없습니다」 |
| member 가 `/settings/members` 직접 주소 | 「권한이 없습니다」(지금과 같다) |

## 6. 테스트·검증

- **서버**: 보관·되살리기 권한(역할 매트릭스에 두 경로 추가), 보관 뒤 런 관문이 모든 경로를 거절, 열린 런 중지·승인 철회, 채널 멤버·헤더 참여자에서 빠짐, discover `archivedAgentId`, 등록 409, 러너 hello 무시, `agents.changed` 팬아웃, 설치 파일 토큰 인증(유효·폐기·꺼진 Gateway·틀린 토큰 카운터), `llms.txt` 공개·버킷·값 채우기·토큰 없음.
- **안내서 대조**: `llms.txt` 의 명령·설정 키가 코드와 맞는지 테스트로 묶는다 — 플러그인 계정 키(`bridgeUrl`·`token`), `RunnerConfig` 키, 경로(`/api/v1/setup/plugin.tgz`·`runner.tgz`).
- **웹**: 사이드바 하단(설정·배지·역할), 탭 역할별 노출, 옛 `/agents` 넘김, 좁은 화면 단계 이동·고정 머리, 에이전트 삭제·되살리기·「삭제됨」 표시·가져오기 되살리기, 발급 대화상자 한 줄.
- **브라우저(dev:fake)**: owner·admin·member 로 설정 탭, 에이전트 삭제 → 채팅 기록 「삭제됨」 → 멘션 후보에서 빠짐 → 되살리기 → 같은 채널에서 이어 답함, 390px.
- **실연(모델 런 0회)**: 실물 dev Gateway 호스트 자리에서 `llms.txt` 절차를 사람 손으로 한 번 따라 해(명령 그대로) 플러그인이 「접속됨 · 서버와 같은 빌드입니다」가 되는지. 러너 절은 런 0회 하네스 설치본으로 `연결됨` 까지.

## 7. 완료 기준

1. 사이드바 하단이 연결 점과 「설정」뿐이고, 모든 설정이 `/settings/<탭>` 에서 역할대로 열린다.

3. 노드의 AI 가 `llms.txt` 와 토큰만으로 플러그인(또는 러너)을 설치해 연결 페이지에서 접속이 확인된다.

**계획 판정 PS1~PS6**

- **PS1 — 「철회됨」 승인 상태는 기존 `cancelled` 다.** shared `ApprovalStatus` 에 새 값을 더하지 않았다. 보관 훑기가 사람 「중지」와 같은 `orchestrator.abort` 를 부르고, 그 종료 전이가 걸린 승인을 `cancelled` 로 닫는다. 웹 승인 카드는 `cancelled` 를 그리는 문구 그대로다(계획, t1 「Review Focus」).
- **PS2 — 「활성」 판정은 `apps/server/src/modules/agents/service.ts` 의 `isAgentActive`(`enabled && archivedAt === null`) 한 함수다.** `router/decide.ts`·`components/service.ts` 의 `assertDeliverable`·런 관문(`ops/budget.ts`)이 쓴다. 러너 hello 만은 이 함수가 아니라 SQL 조건 `agentNotArchived` 다 — 아래 「서버 — 에이전트 보관」(계획, t1 리뷰 Minor 4).
- **PS3 — 채널 멤버 응답에서 보관한 에이전트를 빼는 자리는 서버 조회 한곳**(`channels/service.ts` 의 `listMembers`·`channelParticipants`)이다. `channel_members` 행은 그대로 둔다(계획, t1).
- **PS4 — `agents.changed` 는 본문 `{}` 로 workspace 룸에 보낸다.** 웹은 `qk.agents` 를 exact 로(가져오기 대화상자의 찾기 목록 `qk.discover` 는 그대로 — 고르는 중인 찾기를 다시 부르지 않게) 무효화하고, 채널 멤버 질의(`qk.membersAll`)도 무효화한다(계획, t4 판단 6).
- **PS5 — 웹 설정 화면은 TanStack Router 의 레이아웃 라우트 하나**(`/settings`, 자식 탭 라우트)다(계획, t3).
- **PS6 — `llms.txt` 본문 틀은 `apps/server/src/modules/setup/llms.ts` 의 템플릿 한곳이고, 채울 값은 `renderLlmsTxt` 인자(오리진·`bridgeUrl`·두 파일의 해시)뿐이다.** 대조 테스트 `apps/server/test/setup.llms.test.ts` 가 플러그인 계정 키·`RunnerConfig`·설치 경로·웹 「AI 에게 맡기기」 줄의 절 제목을 코드와 맞춘다(계획, t2).

**서버 — 에이전트 보관 (태스크 1, 곁가지 c1)**

- **런 관문도 보관을 본다.** 「보관할 때 서버가 하는 일」 절 3 을 런 행 INSERT 직전 한곳에서 지킨다 — 런 관문의 검사와 런 INSERT 사이에 await 가 없어, 보관 쓰기 뒤에 도착한 계획은 런을 만들지 못한다. 보관 쓰기 전에 만든 런은 보관 훑기가 대기 런부터 `orchestrator.abort` 로 닫고, 훑기 전에 디스패치 차례를 받은 대기 런은 `dispatch` 의 보관 가드가 보내지 않는다(두 겹). `DELETE /api/v1/agents/:id` 는 열린 런이 닫힐 때까지 기다린 뒤 응답한다. 끈(`enabled=false`) 에이전트도 관문에서 막히지만, 앞 경로가 원래 막고 있어 동작은 같다(t1 판단 1·2·3, t1 리뷰 이탈 판정·Minor 2).
- **보관한 에이전트를 채널에 넣으면 409 `AGENT_ARCHIVED`** 다. 행은 남아 있는데 멤버 조회에서 빠지므로, 막지 않으면 「이미 채널 멤버다」 409 와 섞인다. 「오류」 표에 더할 줄 — **보관한 에이전트를 채널에 넣으려 함 → 409 `AGENT_ARCHIVED`, 웹은 칸 아래 「삭제된 에이전트입니다」**(t1 판단 4, t1 리뷰 Minor 6, t4 판단 3).
- 등록(`POST /api/v1/agents`)은 보관 검사가 핸들 검사보다 먼저다 — 같은 자리의 보관한 에이전트가 있으면 핸들이 겹쳐도 `AGENT_ARCHIVED`(되살리기 안내)가 나간다. `AGENT_ARCHIVED` 의 문구는 등록·채널 넣기·「다시 실행」 모두 「삭제된 에이전트입니다」다(t1 판단 5·10).
- **보관 때 `channel.member.changed` 는 내지 않고 `agents.changed` 만 보낸다** — 웹이 그 이벤트로 멤버 질의를 다시 받는다(PS4). `agents.changed` 는 설계의 다섯 동작(등록·수정·옮기기·보관·되살리기)에 더해 러너 「이 러너로 묶기」와, 에이전트가 묶여 있던 Gateway 의 삭제(풀린 에이전트가 있을 때만)에서도 보낸다(t1 판단 7, t1 리뷰 Minor 5, 원장 판정 m5, t1 수정 보고).
- **m1 — 보관한 에이전트의 늦은 정본은 저장만 한다.** 런의 에이전트가 보관이면 `onCanonical` 이 연결이 닫힌 런의 늦은 정본과 같이 `silent` 로 저장한다 — 릴레이·푸시·자동 응답 없음. 보관 뒤 그 에이전트가 원천인 활동이 0 인 것이 자연스럽다고 봤다. 되살린 뒤에 온 정본은 평소처럼 릴레이·푸시한다(t1 리뷰 Minor 1, 원장 판정 m1, t1 수정 보고).
- **m3 — 에이전트 문맥의 글 풀기는 보관한 에이전트를 포함하고, 「참여자:」만 거른다.** 트리거 글·최근 메시지·스레드 루트의 멘션 토큰은 보관한 에이전트까지 넣은 참가자 목록(`channelParticipants(…, { includeArchived: true })`)으로 풀어 옛 멘션이 그 핸들로 보인다. 헤더 「참여자:」와 릴레이 규칙은 거른 목록이다. 채널에서 뺀 멤버의 옛 멘션은 지금처럼 `@unknown` 이다(t1 리뷰 Minor 3, 원장 판정 m3, t1 수정 보고).
- **러너 hello 는 `agentNotArchived` SQL 조건으로 거른다**(`runners/bindings.ts` 의 `claimRunnerToken`) — 보관한 에이전트는 묶지 않고 런도 보내지 않는다. 끈 에이전트를 묶는 기존 동작은 그대로다(PS2 와 글자가 다른 까닭)(t1 리뷰 Minor 4, 원장 판정 m4).
- 되살린 러너 에이전트는 곧바로 묶이지 않는다 — 묶기는 러너가 붙거나 끊길 때만 돈다. 그동안은 묶임 없는 러너 에이전트처럼 그 id 를 알린 러너가 런을 맡는다. 보관한 에이전트에 「새 대화」를 부르면 멤버 조회에서 빠져 404 다(t1 판단 8·9).
- **F3 (b) — 되살릴 때 같은 채널에 다른 살아 있는 자동 응답이 있으면 되살린 쪽을 끈다.** 「보관할 때 서버가 하는 일」 절 끝에 더할 줄: 되살릴 때 그 에이전트가 자동 응답을 켠 채널 가운데, 살아 있는(보관 안 된) 다른 에이전트가 자동 응답을 켠 채널에서는 되살린 에이전트의 자동 응답을 끄고 그 채널에 `channel.member.changed` 를 보낸다 — 자동 응답은 채널당 하나다(보관 중에는 멤버 응답이 그 에이전트를 걸러, 웹이 다른 에이전트를 켤 때 그 행을 끌 수 없다). 「그대로 돌아온다」를 가장 덜 깨는 쪽을 골랐다. 「살아 있는」은 보관 여부만 본다(끈 에이전트도 자동 응답이 켜져 있으면 겹침이다). 실제로 보관돼 있던 에이전트를 되살릴 때만 돌고(살아 있는 것을 되살리면 아무것도 바꾸지 않는다), 겹친 채널에서만 끈다(t4 리뷰 F3, 원장 판정 F3 (b), t4 수정 보고, c1).
- 마이그레이션 `0015_agent_archive.sql` 은 `ALTER TABLE agents ADD archived_at integer` 한 줄이다(FK·인덱스 없음)(t1, t1 리뷰).

**`llms.txt`·설치 파일 (태스크 2)**

- **토큰은 어떤 외부 명령의 인자에도 나오지 않는다.** 「내용」 절의 「OpenClaw Gateway 호스트」 2번 명령 `curl -fsS -H "Authorization: Bearer $(cat <토큰 파일>)" …` 은 토큰이 curl 의 명령 줄 인자로 `ps` 에 보여 같은 절 「AI 가 지킬 규칙」 첫 줄을 어긴다. 설치 파일 받기는 `printf 'header = "Authorization: Bearer %s"\n' "$(cat <토큰 파일>)" | curl -fsS -K - <오리진>/api/v1/setup/<파일> -o <파일>` 이다(curl 은 표준 입력의 설정으로 머리를 받는다). 계정 설정 패치 파일도 셸 내장 `printf` 가 토큰 파일에서 채운다(t2 판단 1, t2 리뷰 이탈 판정 1).
- **토큰·패치 파일** — 토큰 파일은 이미 있어도(토큰 교체·재설치) `chmod 600` 으로 좁힌다. 패치 파일은 `mktemp -d "${TMPDIR:-/tmp}/dodok.XXXXXX"` 안에 두고(템플릿을 줘야 macOS 도 `TMPDIR` 을 따른다), `trap` 이 성공·실패와 상관없이 패치 디렉터리와 브리지 토큰 파일을 지운다 — 실패하면 1번부터 토큰을 다시 받는다. 고정 `/tmp` 경로는 다른 사용자가 미리 만들어 둘 수 있어 쓰지 않는다(t2 리뷰 Minor 2·3, t2 수정 보고).
- **러너 절** — 3번은 `claude` 가 없는 머신을 위해 `docs/guides/deploy.md` 「Claude 러너 설치」 절과 글자까지 같은 번들 CLI 줄을 싣는다. 2번은 설치한 뒤 번들 sha256(`$(npm root -g)/@dodok/claude-runner/dist/main.js`)도 대조한다. 5번은 `dodok-runner` 가 전경에 머무니 출력에 `연결됨` 이 보이면 사람에게 넘기라고(끄려면 Ctrl+C) 말한다(t2 판단 5, t2 리뷰 I1·Minor 4, t2 수정 보고).
- **설치 파일 인증** — 살아 있는 세션이 있으면 지금 규칙 그대로다(owner 가 아니면 403 — 토큰 쪽으로 넘어가지 않는다). 세션이 없을 때만 Bearer 를 본다. Bearer 가 아예 없으면 401 이되 실패 카운터에 세지 않는다 — 세션이 만료된 owner 가 브라우저로 받는 경로이기도 해서, 맞혀 보는 시도만 센다. 틀린 값·폐기된 토큰·다른 종류 토큰(`plugin.tgz` 에 러너 토큰 등)은 센다. 토큰 검증은 `apps/server/src/http/agent-token.ts` 의 `requireAgentToken` 한 함수라 첨부 HTTP 와 설치 파일이 같은 `BridgeAuthGuard` 를 지나고, 「owner 세션 또는 토큰」 판정은 `modules/setup/installer-auth.ts` 다(t2 판단 2·3·4).
- 서버는 `llms.txt` 를 부팅 때 한 번 렌더한다 — 파일 해시도 부팅 때 재므로 수명이 같다. 레이트리밋 이름은 `LIMITS.llmsTxtPerMin`(30)이다(t2).
- PWA 서비스 워커의 탐색 폴백 denylist(`apps/web/src/pwa/sw-logic.ts` 의 `NAVIGATION_DENYLIST`)에 `/^\/llms\.txt(\?|$)/` 를 더했다 — 설치형 PWA 가 깔린 브라우저에서 주소창으로 연 `/llms.txt`(쿼리가 붙어도)가 index.html 로 떨어지지 않게(t2 판단 6, t2 리뷰 Minor 1).
- **발급 대화상자** — 「AI 에게 맡기기」 아래 설명 한 줄 「설치할 머신에서 도는 AI 에게 이 한 줄을 건네면 안내서대로 설치합니다. 토큰이 들어 있으니 원문처럼 다루세요.」는 구현이 더했다. 제목·「복사」·두 줄 본문은 「발급 대화상자」 절 그대로다. 브리지 줄의 오리진은 연결 상태의 `bridge.publicUrl` 에서(`publicOriginOf`), 러너 줄은 발급 응답의 `runnerConfig.serverUrl` 에서 온다 — 둘 다 서버의 공개 오리진과 같은 값이다(t2 판단 7·8, t2 리뷰 이탈 판정 6).

**웹 — 설정 화면 (태스크 3, 곁가지 c2)**

- **「⚙ 설정」은 lucide 톱니 아이콘(`SettingsIcon`, `aria-hidden`) + 글자 「설정」이다** — 이모지 ⚙ 는 플랫폼마다 컬러 이모지로 그려질 수 있다. 「← 설정」은 글자 그대로이고 화살표는 `aria-hidden`(접근 이름 「설정」)이다(t3 판단 2).
- 페이지가 제목·설명·동작 단추를 그리고, 좁은 화면 탭 페이지의 고정 머리(사이드바 메뉴 단추 + 「← 설정」)는 레이아웃이 그린다. 탭 페이지는 메뉴 단추를 그리지 않는다 — 메뉴 단추가 둘이면 좁은 화면 시트의 초점이 엇갈린다(t3 판단 1).
- 탭 이동 뒤 초점(내용 `h1`)은 설정 안의 이동(탭 목록·「← 설정」)에서만 옮긴다. 사이드바·주소창·뒤로 가기로 들어온 이동은 옮기지 않는다 — 좁은 화면 시트가 닫히며 메뉴 단추에 주는 초점을 뺏지 않게(t3 판단 3).
- 넓은 화면 탭 칸은 `aside` 가 아니라 `div` 다 — 랜드마크는 `nav aria-label="설정"` 하나다. 알림 탭은 대화상자가 아니라 페이지라 「켜고 끄는 동안 닫히지 않는다」가 없다. 역할을 모르는 옛 응답은 member 처럼 본다(t3 판단 4·5·6).
- **O1 — 보이지 않는 탭은 직접 주소로 가도 탭 목록에 나타나지 않는다.** 내용 자리는 「권한이 없습니다」다(원장 판정 O1, c2 — 코드는 처음부터 그랬고 테스트로 고정).
- **D1 — 공용 대화상자(`apps/web/src/ui/dialog.tsx` 의 `DialogContent`)는 기본이 `max-h-[calc(100dvh-2rem)] overflow-y-auto` 다.** 화면보다 큰 대화상자(러너 토큰 발급 등)는 화면 안에서 스크롤해 「복사했습니다」에 닿는다. 부르는 쪽이 `max-h` 를 주면 그것이 이긴다(t5 D1, c2).
- **O2 — 가져오기 대화상자에서 「삭제됨 — 되살리기」를 눌러도 대화상자는 열린 채 남는다**(남은 항목을 계속 고르게)(t5 O2, 원장 판정 O2).

**웹 — 에이전트 보관 (태스크 4)**

- 고르는 자리의 보관 판정은 `features/agents/archived.ts` 의 `isArchived` 한곳이고 `Boolean(archivedAt)` 이다 — 보관 열 이전 웹이 남긴 오프라인 사본의 에이전트에는 키가 없어, `!== null` 이면 복원 직후 모두 「삭제됨」으로 보인다(t4 판단 1).
- 고르는 자리(멘션 후보·채널 멤버 줄·「에이전트 추가」 셀렉트·채널 머리의 에이전트 아바타)는 웹도 거른다 — 보관은 `channel.member.changed` 를 내지 않아, `agents.changed` 뒤 멤버를 다시 받기 전 틈에 낡은 멤버가 남는다(t4 판단 2).
- `AGENT_ARCHIVED` 는 전역 토스트가 아니라 폼 오류다 — 직접 입력 폼은 id 칸에 「삭제된 에이전트입니다」 + 「되살리기」(보관한 id 를 넣으면 요청 전에 막는다), 채널 「에이전트 추가」는 칸 아래 같은 문구(t4 판단 3·4).
- 설계에 없던 문구 — 확인 대화상자 제목 「에이전트 삭제」, 확인 단추 「삭제」·진행 중 「삭제하는 중…」, 되살리기 진행 중 「되살리는 중…」(t4 판단 5).
- 멘션 칩과 운영 화면 표 이름의 「삭제됨」(`ArchivedTag`)은 보이는 글자를 `aria-hidden` 으로 두고 스크린 리더에는 「 (삭제됨)」을 준다 — 여백으로만 떨어진 글자는 앞 핸들과 한 낱말로 읽힌다. 작성자 줄은 플렉스 항목이라 따로 읽혀 그대로다(t4 리뷰, t4 수정 보고).
- 초점 — 삭제 뒤에는 「삭제된 에이전트 N」 묶음 단추로 간다. 되살린 뒤 보관한 것이 남으면 묶음 단추로, 마지막 하나였으면 돌아온 줄의 「@핸들 사용」 스위치로 간다(t4 리뷰 F1·F2, t4 수정 보고).
- Gateway 삭제 확인의 에이전트 수는 보관한 에이전트도 센다 — 보관한 에이전트도 Gateway 를 잃는다. 「채팅 기록」 항목의 「프로필」은 앱에 프로필 화면이 없어 해당하는 자리가 없다(t4 판단 7·8).

**실연 (태스크 6)**

- 실물 dev Gateway(스크래치 `openclaw@2026.9.5`)와 소스 실행 서버에서 「AI 에게 맡기기」 줄이 가리키는 `llms.txt` 의 두 절을 명령 그대로 따라 해, Gateway 카드 「접속됨 · 서버와 같은 빌드입니다」와 러너 카드 「연결됨 · 서버와 같은 빌드입니다」까지 갔다(모델 런 0). 안내서가 dev 에서 맞지 않는 자리와 결과는 `docs/guides/live-smoke.md` 「llms.txt 실연」 절(t6).
