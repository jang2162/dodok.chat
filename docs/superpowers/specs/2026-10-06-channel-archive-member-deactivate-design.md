# 채널 보관·멤버 비활성화 설계

- 상태: 설계 승인(브레인스토밍 2026-10-06), 구현 전
- 범위: 채널 보관·보관 해제, 멤버 내보내기를 비활성화·다시 활성화로 바꾸기
- 관련: 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md`(역할·지금의 내보내기 — 이 스펙이 그 「내보내기」를 대신한다), 설정·에이전트 보관 스펙 `docs/superpowers/specs/2026-10-05-settings-agents-llms-design.md`(같은 꼴의 에이전트 보관, `/settings` 탭), 운영 절차 `docs/guides/deploy.md` 「멤버 초대·비밀번호 재설정·내보내기」 절

## 0. 결정

| # | 결정 | 까닭 |
| --- | --- | --- |
| 1 | 채널은 **보관만** 한다 — 영구 삭제는 두지 않는다 | 사용자 결정(「꼭 삭제될 필요는 없다」). 슬랙의 채널 보관을 따른다 |
| 2 | 채널 보관·보관 해제는 **admin 이상** | 사용자 결정. member 가 남의 채널을 숨길 수 없다 |
| 3 | 멤버 「내보내기」를 **비활성화·다시 활성화**로 바꾼다 — 계정·핸들·이메일·역할·비밀번호·채널 참여를 남기고 로그인만 막는다 | 사용자 결정. 슬랙의 계정 비활성화를 따른다 |
| 4 | 지금의 「핸들을 `left-…` 로 바꾸고 이메일을 비우는」 길을 걷는다 | 3 의 따름. 배포 전이라 옮길 데이터가 없다 |

## 1. 범위

**한다** — 채널 보관(서버·shared·웹), 「설정 → 채널」 탭, 멤버 비활성화·다시 활성화(서버·shared·웹), 기록 표시(「보관됨」·「비활성」), 문서(`deploy.md`·`user-guide.md`·`project-structure.md`).

**하지 않는다** — 채널 영구 삭제, 계정 영구 삭제(데이터 삭제 요청), 비활성 계정 자동 정리.

## 2. 채널 보관

### 2.1 데이터

- `channels.archived_at`(시각, null 이면 살아 있음) — 새 마이그레이션.
- shared `Channel` 에 `archivedAt: IsoDateTime | null`.
- 메시지·스레드·런·승인·채널 멤버·에이전트 세션·첨부는 지우지 않는다.

### 2.2 API (admin 이상)

| 요청 | 뜻 |
| --- | --- |
| `POST /api/v1/channels/:id/archive` | 보관. 이미 보관됐으면 200 그대로(멱등). 없는 id 404 |
| `POST /api/v1/channels/:id/unarchive` | 보관 해제. 살아 있으면 200 그대로 |
| `GET /api/v1/channels` | 기본은 살아 있는 채널만. `?archived=1` 이면 보관한 채널만(누구나 — 읽기는 막지 않는다) |
| `GET /api/v1/channels/:id`·메시지 목록·스레드·검색 | 보관한 채널도 읽힌다 |

보관·보관 해제는 workspace 룸에 `channel.updated`(`archivedAt` 이 실린 채널)를 보낸다.

### 2.3 보관한 채널에서 서버가 막는 것 — 409 `CHANNEL_ARCHIVED`

메시지 보내기(최상위·스레드), 카드 상호작용(버튼·셀렉트·모달·「다시 실행」·「이어가기」), 채널 수정(이름·설명·프롬프트·릴레이 정책), 멤버 넣기·빼기·멤버 설정, 「새 대화」, 첨부 올리기(그 채널 대상). 보관 해제만 받는다.

### 2.4 보관할 때 서버가 하는 일

1. `archived_at` 을 쓴다.
2. 그 채널의 열린 런을 사람 「중지」와 같은 경로로 멈추고 대기열 런을 닫는다. 걸린 승인은 `cancelled`.
3. 그 뒤로 그 채널에 런을 만들지 않는다 — 런 관문이 보관한 채널을 거절한다(에이전트 보관과 같은 자리).
4. 그 채널의 늦게 온 정본은 저장만 한다(릴레이·푸시 없음 — 에이전트 보관과 같은 규칙).
5. 그 채널을 겨눈 푸시를 보내지 않는다.

### 2.5 웹

- **사이드바**: 채널 목록에서 빠진다. 지금 보고 있던 채널이 다른 탭에서 보관되면 그 화면은 읽기 전용으로 바뀐다(목록에서만 빠진다).
- **보관한 채널 화면**: 머리에 「보관됨」, 작성기 자리에 「보관된 채널입니다.」와 (admin 이상) 「보관 해제」. 카드의 단추·셀렉트는 비활성(사유 「보관된 채널입니다」), 「새 대화」·채널 설정 편집은 숨긴다. 스레드 패널도 읽기 전용.
- **채널 설정 패널**: 맨 아래 「채널 보관」(admin 이상) — 확인 대화상자 「#<이름> 을 보관합니다. 기록은 남고 누구나 읽을 수 있으며, 보관 해제하면 그대로 돌아옵니다.」.
- **「설정 → 채널」 탭**(`/settings/channels`, 누구나): 보관한 채널 목록(이름·보관한 날·채널 열기), admin 이상은 줄마다 「보관 해제」. 보관한 채널이 없으면 「보관된 채널이 없습니다」.
- **검색**: 보관한 채널의 결과에 「보관됨」.

## 3. 멤버 비활성화

### 3.1 데이터

- `memberships.deactivated_at`(시각, null 이면 활성) — 새 마이그레이션.
- `users.left_handle` 열과 `left-` 핸들 예약·`leftHandleOf` 를 걷는다. 핸들·이메일은 비활성 중에도 그 사람 몫이다(유일 인덱스 그대로).
- shared `Person`(people 목록)·`Member`(멤버 표)에 `deactivatedAt: IsoDateTime | null`.

### 3.2 API

| 요청 | 권한 | 뜻 |
| --- | --- | --- |
| `POST /api/v1/members/:userId/deactivate` | admin 은 member, owner 는 admin 까지. owner 는 대상이 될 수 없다 | 비활성화. 이미 비활성이면 200(멱등) |
| `POST /api/v1/members/:userId/reactivate` | 같은 권한 | 다시 활성화. 활성이면 200 |
| `DELETE /api/v1/members/:userId` | — | 없앤다(웹·문서도 비활성화로 바꾼다) |
| `GET /api/v1/members` | admin 이상 | 비활성 멤버도 `deactivatedAt` 과 함께 |
| 초대 만들기 | admin 이상 | 같은 이메일이 비활성 멤버면 409 `MEMBER_DEACTIVATED`(details `{ userId }`) |

비활성화·다시 활성화는 `people.changed` 를 보낸다(지금 내보내기와 같다).

### 3.3 비활성화할 때 서버가 하는 일

1. 그 사람의 세션을 지우고 열린 소켓을 끊는다(지금 내보내기의 「지우기 → 끊기」 순서). Better Auth 사용자·계정(비밀번호)은 지우지 않는다.
2. 푸시 구독을 지운다.
3. 그 사람이 발급했거나 그 사람을 겨눈, 쓰이지 않은 초대·재설정 링크를 폐기한다.
4. `deactivated_at` 을 쓴다. 채널 참여 행은 지우지 않는다 — 읽을 때 거른다.
5. 그 뒤 요청마다 membership 을 읽는 자리(`auth/roles.ts`)가 비활성을 「membership 없음」처럼 401 로 본다. 로그인은 비밀번호가 맞으면 403 `MEMBER_DEACTIVATED`(「비활성화된 계정입니다. 관리자에게 문의하세요.」) — 비밀번호가 틀리면 지금의 실패 문구 그대로(계정 존재를 더 드러내지 않는다).

### 3.4 기록과 목록

- 그 사람이 쓴 메시지 작성자·멘션 칩에 「비활성」(접근 이름은 `@핸들 (비활성)`).
- 멘션 후보·채널 멤버 줄·에이전트 헤더 「참여자:」에서 빠진다. 멘션해도 푸시가 가지 않는다.
- 다시 활성화하면 역할·채널 참여가 그대로 돌아오고 예전 비밀번호로 로그인한다. 비밀번호를 모르면 지금의 재설정 링크.

### 3.5 웹

- **멤버 탭**: 줄 동작 「내보내기」를 「비활성화」로(확인 문구 「@<핸들> 을 비활성화합니다. 로그인할 수 없게 되고, 쓴 메시지는 남습니다. 다시 활성화하면 그대로 돌아옵니다.」). 아래에 접힌 「비활성 멤버 N」 — 줄마다 「다시 활성화」.
- **초대**: 409 `MEMBER_DEACTIVATED` 면 「비활성 멤버입니다 — 다시 활성화하세요」와 그 줄로 가는 링크.
- **로그인 화면**: `MEMBER_DEACTIVATED` 면 위 문구.

## 4. 오류

| 상황 | 결과 |
| --- | --- |
| 보관한 채널에 보내기·상호작용·설정 | 409 `CHANNEL_ARCHIVED` |
| 보관한 채널의 「다시 실행」 카드 | 거절, 카드는 소비하지 않는다(보관 해제 뒤 다시 누를 수 있다) |
| member 가 채널 보관 | 403 |
| 비활성 멤버가 열어 둔 탭 | 소켓이 끊기고 다음 요청 401 → 로그인 화면 |
| 비활성 멤버의 로그인(비밀번호 맞음) | 403 `MEMBER_DEACTIVATED` |
| 비활성 멤버의 이메일로 초대 | 409 `MEMBER_DEACTIVATED` |
| owner 비활성화 | 403 |

## 5. 테스트·검증

- **서버**: 역할 매트릭스(새 경로 넷), 채널 보관 뒤 막히는 요청 전부(2.3 목록마다), 열린 런 중지·승인 취소·런 관문, 늦은 정본 저장만, 목록 `?archived=1`, `channel.updated`. 멤버 비활성화 뒤 세션·소켓·푸시·링크, 다음 요청 401, 로그인 403(비밀번호 맞을 때만), 초대 409, 다시 활성화 뒤 같은 비밀번호 로그인·채널 참여 복귀, 「참여자:」·멘션 푸시에서 빠짐, 걷은 `left-` 의 흔적 없음.
- **웹**: 사이드바 거름·보관 채널 화면·카드 비활성·설정 → 채널 탭·검색 「보관됨」, 멤버 탭 비활성화·「비활성 멤버 N」·다시 활성화, 기록 「비활성」·접근 이름, 초대·로그인 문구.
- **브라우저(dev:fake)**: owner·admin·member 로 채널 보관 → 다른 탭 사이드바·읽기 전용 → 보관 해제, member 비활성화 → 그 사람의 열린 탭이 로그인 화면 → 다시 활성화 → 같은 비밀번호 로그인, 390px.

## 6. 완료 기준

1. admin 이 채널을 보관하면 사이드바에서 사라지고 누구나 읽기만 할 수 있으며, 보관 해제하면 그대로 돌아온다.
2. 멤버를 비활성화하면 그 사람은 곧바로 끊기고 로그인하지 못하며 기록은 「비활성」으로 남고, 다시 활성화하면 같은 계정·역할·채널로 돌아온다.
3. 문서가 「내보내기」 대신 「비활성화」를, 채널 보관을 말한다.

## 7. 열린 문제 (범위 밖 기록)

- 채널 영구 삭제(메시지·첨부·FTS 정리), 계정 데이터 삭제 요청 처리.
- 기본 채널(슬랙 #general 처럼 보관할 수 없는 채널) 개념.
