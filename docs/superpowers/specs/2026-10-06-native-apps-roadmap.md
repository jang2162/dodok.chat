# 데스크톱·모바일 앱 — 로드맵

**상태**: 방향 확정(2026-10-06). 하위 스펙 넷 가운데 「서버: 네이티브 푸시와 기기 등록」은 스펙을 거쳐 구현까지 끝났고, 데스크톱·모바일 스펙은 스파이크 뒤에 쓴다.

**앞선 근거**:

## 스파이크 — 원격 페이지의 네이티브 다리

**질문**: 앱 웹뷰가 **실행 중에 사람이 입력한** `https://<서버>` 를 열었을 때, 그 페이지의 JavaScript 가 앱의 네이티브 기능(푸시 토큰 받기·배지·트레이 갱신)을 부를 수 있는가.

**확인 방법**:
- **Tauri 2**(macOS 에서): 최소 앱이 실행 중에 받은 주소로 창을 열고, capabilities 의 원격 도메인 허용(`remote.urls`)으로 그 페이지에서 플러그인 명령(알림·배지)을 부른다. 주소가 빌드 때가 아니라 실행 중에 정해질 때 허용 목록을 어떻게 주는지가 관건이다(와일드카드·실행 중 권한 추가 가능 여부).
- **Capacitor**(iOS 시뮬레이터·Android 에뮬레이터): 최소 앱이 실행 중에 받은 주소로 이동한 뒤 그 페이지에 다리(`window.Capacitor`)가 주입되고 `@capacitor/push-notifications` 의 `register()` 가 토큰을 돌려주는지(`server.url` 은 빌드 때 값이므로, 실행 중 이동 — `allowNavigation` — 에서 다리가 유지되는지).
- 둘 다 **dev:fake 서버**(로컬 https 가 필요하면 로컬 Compose 의 `https://localhost:8443`)를 연다.

**결과에 따라**:
- 둘 다 되면 결정 4 그대로 데스크톱·모바일 스펙을 쓴다.
- 안 되는 쪽은 「빌드 때 서버 주소를 박는다」(직접 빌드 배포 — 결정 2 — 와 맞는다) 또는 「웹 빌드를 앱에 넣고 출처 허용 목록」으로 그 쪽 스펙을 바꾼다.
- 결과는 ADR 로 남긴다.

## 수동 빌드 원칙

- 플랫폼마다 필요한 기기·도구·서명 자료(Apple 개발자 계정·인증서·APNs 키, Android 서명 키, Windows 서명 인증서 — 없으면 SmartScreen 경고)와 명령을 데스크톱·모바일 스펙이 `docs/guides/` 의 빌드 안내 하나에 적는다.
- 서명 자료는 저장소에 넣지 않는다(시크릿 규칙 — `data/`·`.env` 와 같은 취급, 앱 빌드용은 저장소 밖 경로).
- 산출물 이름에 앱 버전과 빌드한 커밋을 싣는다.

## 범위 밖 (기록)

알림에서 바로 처리(승인 「허용/거절」·빠른 답장), 스토어 공개 배포와 중앙 푸시 중계 운영, 공유 시트·카메라·생체 잠금, CI 빌드.
