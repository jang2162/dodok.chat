# 세션·DM·러너 일반화 — 로드맵

**상태**: 방향 초안(2026-10-25) — 사용자 확인 전. 하위 스펙 셋은 이 문서와 함께 썼다.
**범위**: 사용자 요청 셋(2026-10-25) — ① 다른 프로그램(Codex·OpenCode 등)도 돌릴 수 있게 사람 머신의 러너를 일반화하고 프로젝트·에이전트를 앱에서 구성 ② 에이전트와 1:1 DM, 세션 단위로 쌓임 ③ 채널 안에서도 주제마다 세션으로 나눔, 채널마다 세션 관리 권한. 그리고 Slack 같은 채팅 앱에서 가져올 만한 기능 후보.

## 결정

| # | 결정 | 까닭 |
| --- | --- | --- |
| 1 | **기존 판과의 호환은 고려하지 않는다** — 마이그레이션은 새 열·표를 넣고 기존 행을 한 번 옮기는 것까지만, 옛 플러그인·옛 러너·옛 URL 은 받지 않는다 | 사용자 결정(지금 쓰는 곳이 없다). |
| 2 | **사용자가 「릴레이」라 부른 것은 「러너」를 일반화해 이름을 잇는다** — CLI `dodok-runner`, 패키지 `packages/runner`(옛 `packages/claude-runner`), 토큰 `drn_`, 네임스페이스 `/runner` 그대로 | 「릴레이」는 이 저장소에서 이미 에이전트 간 @멘션 릴레이(`relayPolicy`·`relay_limit`)를 뜻한다. 같은 말을 두 뜻으로 쓰면 문서·코드·화면이 갈린다. 지금 러너가 바로 「사람 머신에 까는 것」이라 그 이름을 넓힌다. **사용자가 다른 이름을 원하면 이 줄만 바꾼다.** |
| 3 | **채널 세션과 DM 세션은 같은 모델이다** — 코드 이름 `conversation`(표 `conversations`), 화면 이름 「세션」. DM 은 「주인 한 명 + 에이전트 하나만 보는 채널」에 세션이 쌓인 것 | 사용자는 둘을 같은 말(세션)로 설명했다. 한 모델이면 목록·읽지 않음·검색·푸시 링크·에이전트 세션 키가 한 번에 맞는다. 코드에서 `session` 은 이미 에이전트 세션(`agent_sessions`)과 로그인 세션이 쓰고 있어 `conversation` 으로 가른다. |
| 4 | **에이전트 세션 키는 「세션(대화)마다 에이전트별 1개」** — 키의 `channel:` 자리에 대화 id 를 넣는다: `agent:<agentId>:dodok:channel:<conversationId>[:thread:<rootId>]` | 키 모양(정규식)이 그대로라 OpenClaw 코어·플러그인 라우팅이 대화를 별개 피어로 본다. 새 세션 = 새 키라 OpenClaw 의 「채널 프롬프트는 새 세션 키에서만 반영」(ADR 0003)도 저절로 맞는다. `AGENTS.md` 불변 규칙 줄을 바꾼다(스펙 A). |
| 5 | **「새 대화」(에이전트 세션 리셋)는 없앤다 — 「새 세션」이 그 자리** | 새 세션이 같은 일(깨끗한 맥락)을 하면서 앞 대화도 남긴다. 리셋은 같은 창 안에서 맥락이 끊겨 기록과 에이전트 기억이 어긋나는 원인이었다. |
| 6 | **러너의 천장은 여전히 사람 머신의 로컬 설정이다** — 앱은 그 천장 안에서만 프로젝트·에이전트를 만든다 | 러너 스펙 결정 5 를 지킨다. 앱에서 경로를 더할 수 있게 되면 서버가 털렸을 때 그 머신의 아무 경로에서나 도구를 돌릴 수 있게 된다 — 로컬 설정의 루트·권한 상한이 막는다. |

## 하위 프로젝트

각자 「스펙 → 계획 → 구현」을 따로 밟는다.

| 순서 | 하위 프로젝트 | 스펙 | 의존 |
| --- | --- | --- | --- |
| A | **채널 세션** — 대화 모델·세션 목록·세션 관리 권한·에이전트 세션 키 | `docs/superpowers/specs/2026-10-25-channel-sessions-design.md` | 없음 |
| B | **에이전트 DM** — 주인만 보는 1:1 채널, 접근 판정 한 함수 | `docs/superpowers/specs/2026-10-25-agent-dm-design.md` | A |
| C | **러너 일반화** — 프로그램 드라이버·로컬 천장·앱에서 프로젝트·에이전트 구성 | `docs/superpowers/specs/2026-10-25-runner-generalization-design.md` | 없음(A 와 오케스트레이터·에이전트 등록이 겹쳐 순차를 권한다) |

**권하는 순서는 A → B → C.** B 는 A 의 대화 모델 위에 선다. C 는 따로 설 수 있지만 A 와 같은 파일(오케스트레이터 `send` 경로·세션 행·에이전트 등록)을 크게 고치므로 병렬이면 병합 충돌이 크다. C 를 먼저 원하면 C → A → B 도 된다 — 그때 C 의 세션 키는 지금 키(채널 id)로 짓고 A 가 바꾸며, C 의 DM 관련 두 자리(에이전트 추가의 「DM 허용」·DM 승인 결정자)는 빼고 B 가 더한다.

## Slack 류 앱에서 가져올 만한 기능 (후보 — 이번 범위 밖)

지금 있는 것: 스레드·검색·리액션·읽지 않음·멘션 배지·파일 첨부·웹 푸시·자동화(예약 게시·웹훅). 아래는 없는 것 가운데 이 앱에 맞는 것을 고른 것이다. 「권함」은 A·B 뒤 바로 할 만한 것이다.

| 후보 | 무엇 | 이 앱에서의 값 | 크기 | 권함 |
| --- | --- | --- | --- | --- |
| **세션 결과 공유(전달)** | DM·세션의 메시지(에이전트 답·카드·파일)를 다른 채널·세션에 출처 링크와 함께 올린다 | DM 에서 혼자 다듬은 결과를 팀 채널로 옮기는 길. DM 이 생기면 바로 아쉬워진다 | 중 | **권함** |
| **비공개 채널** | 초대된 사람만 보는 채널 | `channels.visibility` 열은 이미 있고 아무 데서도 막지 않는다. B 의 접근 판정 함수(`canReadChannel`)에 규칙 한 줄을 더하면 된다 | 중 | **권함** |
| **사람 메시지 수정·삭제** | 내가 쓴 글을 고치고 지운다(`(수정됨)` 표시) | `messages.edited_at` 은 있으나 사람이 고치는 길이 없다. 에이전트가 이미 읽은 글을 고칠 때 무엇을 알릴지 정해야 한다 | 중 | **권함** |
| **멘션·활동 모아보기** | 나를 부른 글·내 승인 카드·DM 답을 한 화면에 | 세션·DM 이 늘면 「어디서 불렸지」를 찾기 어려워진다. 배지는 있고 모음이 없다 | 중 | 권함 |
| 사람 간 DM·그룹 DM | 사람끼리 1:1·여럿 | B 의 모델(멤버만 보는 채널)을 사람에게 열면 된다. 에이전트 네이티브 앱의 핵심은 아니다 | 중 | |
| 세션 포크 | 이 세션의 요약을 들고 새 세션 시작 | 긴 세션을 맥락 일부만 들고 끊는 일. 요약을 누가 만드나(에이전트) 정해야 한다 | 중 | |
| 핀·저장한 항목 | 채널에 고정, 나만의 북마크 | 에이전트 답 중 쓸 만한 것을 다시 찾기 | 소 | |
| 사이드바 즐겨찾기·음소거 | 채널·DM 정렬과 알림 끄기 | DM 과 세션이 늘면 사이드바가 길어진다 | 소 | |
| 개인 리마인더 | `/remind` — 정한 때 나에게 알림·DM 에 글 | 자동화(예약 게시)가 채널 단위로는 있다 | 소 | |
| 세션 제목을 에이전트가 짓기 | 첫 답 뒤 짧은 제목 | 스펙 A 는 첫 메시지 앞부분으로 짓는다. 모델 호출 한 번이 더 든다 | 소 | |
| 링크 미리보기 | URL 카드 | 서버가 남의 URL 을 가져와야 한다(SSRF 방어) | 중 | |
| 사람 상태(온라인·자리 비움) | 접속 표시 | wire `presence.update` 가 안에 있지만 보이지 않는다 | 소 | |

허들(음성)·앱 디렉터리·워크플로 빌더는 이 앱의 쓰임새(사람과 에이전트가 같은 채널에서 일)와 멀어 뺐다.
