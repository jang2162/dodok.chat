# 프로필·상태 설계 (기본 메신저 하위 프로젝트 B)

**상태**: 확정(2026-11-02, 사용자 승인).
**범위**: 사람과 에이전트가 프로필을 가진다. 이름·아바타를 누르면 오른쪽 패널에 프로필이 열린다. 사람은 사진을 올리고, 상태 메시지와 수동 상태(방해 금지 포함)를 정한다. 에이전트는 사진과 설정 요약, 소유자(만든 사람)를 보인다. 접속 점은 사람·에이전트 모두 자동으로 바뀐다.

- 팀 스펙 `docs/superpowers/specs/2026-09-26-team-members-design.md` 「역할과 권한」(이메일은 admin 이상)·「열린 문제」(멤버 아바타·접속 상태)

## 0. 결정

사용자가 정한 것은 「사용자」, 설계자가 정한 것은 「설계자 판단」으로 적는다. 설계자 판단은 사용자가 검토 때 바꿀 수 있다.

| # | 결정 | 출처 · 까닭 |
| --- | --- | --- |
| 1 | **에이전트도 프로필을 가진다** — 사진, 이름·핸들, 연결, 모델, 소유자, DM 허용 범위 | 사용자 |
| 2 | **에이전트의 소유자 = 그 에이전트를 만든 사람.** 소유자에게 따로 권한은 없다(에이전트 설정은 지금처럼 admin 이상). **양도는 이번에 없다** — 나중에 고려한다 | 사용자. 권한을 안 붙이는 것은 설계자 판단: 에이전트를 만드는 길(REST·제어 도구 `register_agent`)이 이미 admin 이상이라 소유자는 늘 admin 이상이었다 |
| 3 | **멤버에게 보이는 에이전트 정보**: 사진·이름·핸들·연결(Gateway 이름 / 러너 머신 이름 + 프로그램)·모델·소유자·DM 허용 범위·꺼짐·보관. **admin 이상만**: 권한 모드·허용·금지 도구·기본 프롬프트 | 사용자. 지금 규칙(PR11)을 지키고 모델만 멤버에게 연다 |
| 4 | **사람 프로필은 일반 메신저의 기본**: 사진·표시 이름·핸들·역할·접속 점·상태 메시지(이모지 + 글 + 만료). 이메일은 지금처럼 admin 이상에게만 | 사용자(기본 정보). 이메일은 설계자 판단 — `listPeople` 이 일부러 싣지 않는다 |
| 5 | **사람의 상태 다섯**: 자동(기본) · 자리 비움 · 다른 용무 중 · 방해 금지 · 오프라인으로 보이기. 수동 상태에는 만료를 걸 수 있다 | 사용자(수동 상태 추가). 값 다섯과 만료는 설계자 제안을 사용자가 받았다 |
| 6 | **알림을 멈추는 것은 방해 금지 하나뿐** — 나머지 상태는 표시만 바꾼다 | 사용자 |
| 7 | **방해 금지에 「도구 승인 요청은 계속 받기」 옵션, 기본 켜짐** | 옵션은 사용자, 기본값은 설계자 판단 — 승인을 놓치면 런이 멈춰 기다린다 |
| 8 | **에이전트의 점은 자동만**: 응답 가능 · 작업 중 · 연결 끊김 · 꺼짐. 에이전트에게는 수동 상태·상태 메시지가 없다 | 사용자 |
| 9 | **프로필은 오른쪽 패널에 열린다**(활동·설정·스레드 패널과 같은 자리). 좁은 화면에서는 그 패널처럼 전체 화면 | 사용자(시안 B) |
| 10 | **자동 접속 점은 서버 메모리에서 계산해 가벼운 wire 이벤트 `presence.changed` 로 보낸다.** 수동 상태·상태 메시지·방해 금지는 DB 에 두고 사람 목록(`people.changed`)에 싣는다 | 사용자(방식 A). 탭을 오갈 때마다 사람 목록 전체를 전원에게 다시 보내지 않는다 |
| 11 | **아바타는 브라우저가 정사각형으로 잘라 줄여 올리고, 서버는 형식·크기·가로세로만 확인한다.** 새 의존성 없음 | 사용자(방식 A). 서버에 이미 `image-size` 와 첨부의 바이트 형식 검사(`apps/server/src/modules/attachments/sniff.ts`)가 있다 |
| 12 | **아바타 파일은 첨부 저장소와 따로 둔다** — `<DATA_DIR>/avatars/` | 설계자 판단. 첨부 청소(`sweepAttachments`)는 「어느 `attachments` 행도 안 가리키는 블롭」을 지운다. 같은 디렉터리에 두면 아바타가 지워진다. 첨부 GET 의 채널 읽기 판정도 아바타에는 맞지 않는다 |
| 13 | **현지 시각(시간대)은 이번에 없다** | 설계자 판단 — 사람마다 시간대 설정이 하나 더 생긴다 |

## 1. 범위

**한다**
- 프로필 패널(사람·에이전트) — 타임라인의 이름·아바타, 채널 멤버 목록, @멘션 칩, DM 목록·DM 머리에서 연다
- 「내 계정」에 프로필 섹션 — 사진 올리기·지우기, 상태 메시지, 수동 상태, 방해 금지 옵션
- 내 프로필 패널에서도 상태를 바꾼다(빠른 길)
- 에이전트 사진 올리기·지우기(admin 이상, 에이전트 설정 화면과 프로필 패널)
- 에이전트 소유자 기록(`agents.created_by`)과 표시
- 사람·에이전트 접속 점 — 아바타 위 작은 점(타임라인·멤버 목록·DM 목록·프로필 패널)
- 방해 금지 동안 푸시(웹 푸시·APNs·FCM)를 멈춤
- 백업에 아바타 디렉터리 포함, 매뉴얼·운영 문서 갱신

**하지 않는다**
- 소유자 양도·소유자 권한
- 현지 시각·시간대
- 입력이 없을 때 「자리 비움」으로 바꾸는 유휴 감지 — 자동 자리 비움은 「보이는 탭이 하나도 없음」뿐이다
- 채널·DM 별 알림 끄기(로드맵 후보 F)
- 손으로 자르는 화면(크롭 UI) — 가운데를 정사각형으로 자동으로 자른다
- 에이전트의 수동 상태·상태 메시지, 에이전트에게 사람의 상태를 알리기(인바운드 헤더·`docs/guides/agent-guide.md` 는 그대로)
- 제어 MCP 도구로 프로필·상태 읽기·쓰기
- 설정 탭 구조 바꾸기(`apps/web/src/features/settings-shell/tabs.ts` — 같은 날 다른 작업 `settings-connect-merge` 의 몫)

**실패로 볼 것(안티 목표)**
- 방해 금지를 켰더니 승인 요청까지 말없이 사라져 런이 멈춘 채 아무도 모르는 것 — 그래서 결정 7 의 기본이 켜짐이다
- 접속 점이 재접속·탭 전환마다 깜빡이는 것
- 접속 점이나 「작업 중」이 남의 DM 내용·상대를 드러내는 것(3.4 「작업 중」의 범위)

## 2. 데이터

마이그레이션 하나(다음 번호, 지금 마지막은 `0032_drop_session_reset_cols.sql`).

**`users` 에 열 더하기**

| 열 | 값 |
| --- | --- |
| `status_mode` | `auto` · `away` · `busy` · `dnd` · `invisible`, 기본 `auto` |
| `status_mode_until` | 수동 상태가 `auto` 로 돌아갈 시각, null 이면 직접 바꿀 때까지 |
| `status_emoji` | 이모지 하나(문자열, 짧은 상한), null 가능 |
| `status_text` | 상태 메시지 — 공백 정리 뒤 1~100자, null 가능 |
| `status_text_until` | 상태 메시지가 지워질 시각, null 이면 직접 지울 때까지 |
| `dnd_allow_approvals` | 불리언, 기본 true(결정 7) |

`avatar_url` 열은 이미 있다 — 올린 사진이면 `/api/v1/avatars/<sha256>.<ext>`(같은 오리진 상대 경로)를 넣는다.

**`agents` 에 열 더하기**: `created_by`(users.id 참조, null 가능). 기존 행은 null 로 둔다 — 화면은 「기록 없음」. 설계자 판단: 마이그레이션이 owner 로 채우면 사실이 아닌 기록이 생긴다.

**아바타 파일**: `<DATA_DIR>/avatars/<sha256>.<ext>`(`png`·`jpeg`·`webp`). 같은 내용이면 한 파일. 바꾸거나 지우면, 그 경로를 가리키는 `users`·`agents` 행이 하나도 없을 때 옛 파일을 지운다. 부팅 때 한 번, 어느 행도 안 가리키는 파일을 치운다(첨부 청소와 따로).

**공유 스키마**(`packages/shared`)
- `Person` 에는 **상태 메시지만**(이모지·글·글 만료) 더한다. **수동 상태 모드와 그 만료는 `Person` 에 싣지 않는다** — `people.changed` 는 워크스페이스 전원에게 같은 목록을 보내므로, 모드를 실으면 「오프라인으로 보이기」인 사람이 드러난다. 남에게 보이는 상태는 3.3 의 유효 상태로만 간다. 본인의 모드·만료·`dndAllowApprovals` 는 `/auth/me` 의 `user` 에 싣는다.
- `Agent` 에 `createdBy: Id | null`(모두에게)과 멤버에게도 보이는 `model`(러너 에이전트의 모델, OpenClaw 는 null — dodok 이 Gateway 쪽 모델을 모른다)을 더한다. `runnerAgent`(admin 이상)는 그대로.
- `Agent.avatarUrl` 은 지금 `z.url()` 이라 상대 경로를 거절한다 — 올린 사진의 상대 경로(`/api/v1/avatars/…`)와 기존 https URL 둘 다 받게 넓힌다. `Person.avatarUrl` 도 같은 규칙.
- `UpdateMeBody` 는 표시 이름 하나에서, 상태·방해 금지 옵션을 받는 별도 본문(`UpdateMyStatusBody` 꼴)을 더한다 — 이름은 빌더가 정한다.
- wire `presence.changed` 와 접속 스냅숏 타입(3.3).

## 3. 동작

### 3.1 프로필 패널

- 오른쪽 패널의 새 탭. 경로는 세션 화면 아래(`/c/$channelId/s/$conversationId/…`) — 설정·활동·스레드 패널과 같은 방식이라 새로고침·뒤로 가기가 그대로 된다. 사람과 에이전트를 가르는 경로 모양은 빌더가 정한다.
- 여는 곳: 타임라인 작성자 이름·아바타, 채널 설정의 멤버 목록, @멘션 칩, DM 머리의 에이전트. 세션 화면 밖(예: `/settings/members` 표)에서는 열지 않는다 — 이번 범위 밖.
- **사람 패널**: 큰 아바타 + 점, 표시 이름, `@핸들`, 역할, 상태 줄(점의 이름 + 수동 상태 만료 「15:00 까지」), 상태 메시지(이모지 + 글), admin 이상이면 이메일. 비활성 멤버는 「비활성」 표시만 하고 점을 그리지 않는다. 단추: 「멘션」(작성기에 `@핸들` 넣기). 「메시지 보내기」는 C(사람 간 DM) 가 더한다.
- **내 패널**이면 「상태 바꾸기」 단추 — 「내 계정」 프로필 섹션과 같은 칸을 패널 안에서 연다.
- **방해 금지 중**이면 점과 따로 「방해 금지 중 · 만료」 줄을 보인다 — 오프라인이어도 보인다(설정은 접속과 상관없이 살아 있다).
- **에이전트 패널**: 큰 아바타 + 점, 이름 + 「에이전트」 표지, `@핸들`, 점 이름, 연결(OpenClaw: Gateway 이름 / 러너: 러너 라벨 + 프로그램 이름, 묶이지 않음·폐기·Gateway 없음이면 그 사정), 모델(러너만, 없으면 「기본」), 소유자(`@핸들`, null 이면 「기록 없음」), DM 허용 범위, 꺼짐·보관이면 그 표시. admin 이상이면 아래에 권한 모드·허용·금지 도구·기본 프롬프트(접힘). 단추: 「DM 열기」(그 사람이 열 수 있을 때만 — 지금 `dmAccess` 판정과 같다), 「멘션」, admin 이상이면 「설정」(에이전트 설정 화면으로).

### 3.2 사람의 상태

**보이는 점(유효 상태)** — 서버가 계산한다. 위에서부터 먼저 맞는 것.

1. 비활성 멤버 → 점 없음
2. `status_mode = invisible` → 오프라인
3. 열린 소켓이 없음(아래 유예 포함) → 오프라인
4. `status_mode` 가 `away`·`busy`·`dnd` → 그 값
5. 보이는 탭이 하나라도 있음 → 접속 중
6. 그 밖(소켓은 있으나 모두 숨김) → 자리 비움

- 「보이는 탭」은 지금 웹이 보내는 `presence.update` 의 `visible` 이다. 화면 위치(`conversationId`)는 이 계산에 쓰지 않는다.
- **유예**: 마지막 소켓이 끊긴 뒤 20초 안에 다시 붙으면 오프라인을 내지 않는다(새로고침·재접속에 깜빡이지 않게). 숫자는 빌더가 조정한다.
- **만료**: `status_mode_until`·`status_text_until` 이 지나면 서버가 `auto`·null 로 되돌리고 사람 목록을 다시 알린다. 읽을 때도 지난 값은 지난 것으로 본다(타이머가 늦어도 틀린 값이 보이지 않게). 만료 확인 주기는 빌더가 정한다(1분 이하).
- **만료 고르기**(화면): 안 지움 · 30분 · 1시간 · 4시간 · 오늘 · 직접 고른 시각. 「오늘」의 경계는 브라우저 시간대의 자정 — 서버에는 계산된 시각만 간다.
- **오프라인으로 보이기**인 사람도 자기 화면에서는 자기 상태를 그대로 본다. 남에게는 오프라인이다.

### 3.3 실시간 전달

- **스냅숏**: wire 연결 직후(재접속 포함) 그 워크스페이스의 지금 접속 점 전체를 받는다 — 핸드셰이크 뒤 서버가 보내는 이벤트든 REST 조회든 빌더가 고른다. 사람·에이전트를 함께 싣는다.
- **변화**: 유효 상태가 바뀐 사람·에이전트만 `presence.changed`(워크스페이스 룸)로 보낸다. 같은 값이면 보내지 않는다.
- **유효 상태 한 줄**은 `{ 사람 또는 에이전트, id, 상태 }` 에, 수동 `away`·`busy`·`dnd` 이면 그 만료 시각을, 방해 금지면 오프라인이어도 `dnd` 표지와 만료를 싣는다(3.1 「방해 금지 중」 줄). `invisible` 은 다른 오프라인과 구별되지 않게 싣는다 — 표지·만료 없음.
- **상태 메시지**를 바꾸면 DB 에 쓰고 `broadcastPeople`(지금 있는 `people.changed`) — 사람 목록에 실리는 정보다.
- **수동 상태**를 바꾸면 DB 에 쓰고 유효 상태가 바뀌었으면 `presence.changed`. 본인의 다른 탭·기기는 user 룸으로 받아 「내 계정」·내 패널을 맞춘다(지금 `conversation.read` 처럼 user 룸 — 이벤트 모양은 빌더). `dndAllowApprovals` 도 같은 길.
- 서버 재시작 직후 몇 초는 소켓이 다시 붙을 때까지 모두 오프라인이다 — 지금 푸시 거르기와 같은 성질(`presence.ts` 주석).

### 3.4 에이전트의 점

위에서부터 먼저 맞는 것.

1. 보관 → 점 없음(「보관됨」)
2. `enabled = false` → 꺼짐
3. 연결이 없음 → 연결 끊김. OpenClaw: 그 에이전트의 Gateway 가 없거나 플러그인이 붙어 있지 않음. 러너: 묶인 러너 토큰이 없거나 폐기됐거나 그 러너가 붙어 있지 않음
4. 그 에이전트의 끝나지 않은 런이 하나라도 있음 → 작업 중
5. 그 밖 → 응답 가능

- 「작업 중」은 **어느 채널·DM 의 런인지 싣지 않는다** — 점 하나만 바뀐다. 남의 DM 런이어도 「작업 중」은 보인다(누가 무엇을 시켰는지는 드러나지 않는다). 설계자 판단: 운영 화면이 DM 런을 내용 없이 세는 것과 같은 수준이다.
- 바뀌는 계기: 어댑터 상태(`adapter.status`·러너 붙음·끊김), 런 시작·끝, 에이전트 수정·보관·되살리기. 계기마다 그 에이전트들의 점을 다시 계산해 바뀐 것만 보낸다.

### 3.5 방해 금지와 푸시

- `forUser`(`apps/server/src/modules/push/service.ts`)에서 「보고 있으면 건너뜀」 옆에 「방해 금지면 건너뜀」을 더한다. 예외: 알림 종류가 `approval` 이고 그 사람의 `dnd_allow_approvals` 가 true 면 보낸다.
- 방해 금지 판정은 접속과 상관없다 — 오프라인이어도 방해 금지면 멈춘다. 만료가 지났으면 방해 금지가 아니다.
- 멈추는 것은 푸시뿐이다 — 읽지 않음 배지·멘션 배지·타임라인·앱 안 승인 알림은 그대로다.
- 거른 것은 지금처럼 debug 한 줄(`push skipped — dnd`).

### 3.6 아바타 올리기

- **브라우저**: 고른 그림(png·jpeg·webp·gif 첫 장면)을 가운데 정사각형으로 잘라 256×256 으로 줄인 뒤 webp(지원 안 되면 png)로 만든다. 미리보기를 보이고 「저장」을 누르면 올린다.
- **서버**: 사람은 `PUT /api/v1/me/avatar`·`DELETE /api/v1/me/avatar`, 에이전트는 `PUT`·`DELETE /api/v1/agents/:id/avatar`(admin 이상 — 지금 에이전트 수정과 같은 역할 판정). 본문은 그림 바이트 그대로. 확인: 바이트 형식 검사로 png·jpeg·webp 만, 256KB 이하, 정사각형, 한 변 64~512px. 어기면 400 `VALIDATION`(어느 조건인지 문구에).
- 저장하면 `avatar_url` 을 바꾸고 사람이면 `people.changed`, 에이전트면 `agents.changed`.
- **내려받기**: `GET /api/v1/avatars/:file` — 로그인한 세션만(쿠키), 내용 주소라 `Cache-Control: private, max-age=31536000, immutable`, `X-Content-Type-Options: nosniff`, 저장한 형식의 `Content-Type`. 남의 워크스페이스는 생각하지 않는다(워크스페이스 하나).
- 레이트리밋: 첨부 업로드처럼 사용자당 분당 상한 하나를 더한다(숫자는 빌더, `apps/server/src/modules/ops/limits.ts`).
- 에이전트의 외부 https 아바타(제어 도구로 넣은 것)는 그대로 받는다 — CSP `img-src` 가 이미 `https:` 를 허용한다.

### 3.7 에이전트 소유자

- 에이전트를 만드는 모든 길이 `created_by` 를 채운다: REST(`registerAgentAndNotify`·`createRunnerAgentAndNotify` — 요청한 사람), 제어 도구 `register_agent`(그 주체의 사람 — 바깥 MCP 면 토큰 주인, 채널 안 에이전트면 시킨 사람), `dev:fake` 씨앗(owner).
- 보관·되살리기는 소유자를 바꾸지 않는다. 소유자가 비활성 멤버가 되어도 그대로 보인다(「비활성」 표시).

### 3.8 「내 계정」 프로필 섹션

- 지금 「내 계정」(`apps/web/src/features/settings-shell/AccountPage.tsx`)의 표시 이름 칸 위에 프로필 섹션: 아바타(바꾸기·지우기), 표시 이름(지금 칸을 이리로), 상태(다섯 가지 + 만료), 상태 메시지(이모지 + 글 + 만료), 방해 금지 옵션 「도구 승인 요청은 계속 받기」(모두에게 보인다 — 채널 승인 푸시는 admin 이상이 받지만, `dmAccess = everyone` 인 에이전트의 DM 승인은 member 인 DM 주인이 받는다).
- 탭 목록·탭 이름은 바꾸지 않는다.

## 4. 오류 처리

| 상황 | 동작 |
| --- | --- |
| 아바타 형식·크기·가로세로가 틀림 | 400 `VALIDATION`, 「내 계정」 섹션 안에 문구 |
| 남의 에이전트 아바타를 member 가 바꾸려 함 | 403(지금 에이전트 수정과 같은 판정) |
| 없는 아바타 파일 | 404 — 웹은 아바타 대체(이니셜)로 그린다 |
| 상태 만료가 지금보다 과거 | 400 `VALIDATION` |
| 디스크 쓰기 실패 | 500, `avatar_url` 은 바꾸지 않는다(파일을 먼저 쓰고 성공한 뒤 행을 바꾼다) |
| wire 가 끊긴 동안 | 점은 마지막 값으로 두고, 다시 붙으면 스냅숏으로 맞춘다 |

## 5. 테스트·검증

- 서버 단위: 유효 상태 계산(3.2 의 여섯 줄 순서, 유예, 만료), 에이전트 점(3.4 의 다섯 줄), 방해 금지 거르기(승인 예외 켜짐·꺼짐, 오프라인 방해 금지, 만료 지난 방해 금지).
- 서버 통합: 「오프라인으로 보이기」인 사람이 `people.changed`·`presence.changed`·스냅숏 어디에서도 다른 오프라인과 구별되지 않는지(모드·만료가 새지 않음).
- 서버 통합: 아바타 PUT·GET·DELETE(형식 검사·크기·정사각형·옛 파일 지움·부팅 청소), `presence.changed` 가 바뀐 것만 나가는지, 스냅숏, 상태 바꾸기 → `people.changed`, `created_by` 가 세 길에서 채워지는지. 역할 매트릭스 시험(`apps/server/test/roles.matrix.test.ts`)에 새 경로들.
- 웹 단위: 프로필 패널(사람·에이전트, admin 과 member 의 보이는 칸 차이), 상태 고르기·만료 계산, 아바타 자르기·줄이기.
- `dev:fake` 위 브라우저: 두 계정(owner·`mia`)으로 점이 서로 보이는지, 탭 숨김 → 자리 비움, 방해 금지 → 푸시가 안 가는지(서버 debug 로그), 에이전트 연결 끊기(`/__devfake/runner`·`plugin-token`) → 연결 끊김, 런 → 작업 중.
- 백업: `node dist/backup.js` 결과에 `avatars/` 가 들어가는지.

## 6. 완료 기준

- 사람·에이전트 프로필 패널이 3.1 대로 열리고, member 에게 admin 칸이 안 보인다.
- 사진을 올리면 타임라인·멤버 목록·DM 목록·프로필에 곧바로 바뀐다(다른 탭·다른 사람 화면 포함).
- 상태 다섯·상태 메시지·만료가 3.2 대로 보이고, 방해 금지가 푸시를 멈추며 승인 예외가 옵션대로 동작한다.
- 에이전트 점이 3.4 대로 바뀐다.
- 새로 만든 에이전트에 소유자가 보이고, 기존 에이전트는 「기록 없음」.
- 매뉴얼(`docs/manual/user-guide.md`)에 프로필·상태·방해 금지, 운영 문서(`docs/guides/docker-deploy.md` 「백업」·「볼륨째 옮기기」)에 `avatars/`.
