# 설정의 연결·러너·에이전트 통합 — 「연결」 탭 하나와 연결의 주인

- 날짜: 2026-11-02
- 슬러그: `settings-connect-merge`
- 상태: 설계(사람 승인 2026-11-02)
- 관련: 설정 마법사 `2026-09-24-setup-wizard-design.md`(연결 페이지), 멀티 Gateway `2026-10-04-multi-gateway-design.md`(「웹」 절), 러너 일반화 `2026-10-25-runner-generalization-design.md`(6·7장), 설정 통합 `2026-10-05-settings-agents-llms-design.md`(「주소와 탭」 절). 이 문서가 그 문서들의 탭·화면 배치 결정을 대신한다.

## 1. 사람의 요청과 까닭

> 설정에 연결, 러너, 에이전트를 통합해서 보기 쉽게 만들어줘 복잡한 설명들 정리하고

지금은 에이전트 하나를 붙이는 일이 탭 셋에 흩어져 있다. 러너 에이전트는 「연결」(owner — 토큰·설치) → 「러너」(admin — 프로젝트) → 「에이전트」(누구나 보기, admin 등록) 를 오가고, OpenClaw 는 「연결」(Gateway·플러그인·브리지 토큰) → 「에이전트」(가져오기)다. 페이지끼리 「러너 탭에서…」「연결 페이지에서…」로 서로 가리키고, 화면 문구에 내부 사정을 풀어 쓴 긴 문단이 많다.

대화에서 요청이 넓어졌다 — 사람이 정한 것:

- 화면은 **연결 중심**이다. Gateway 아래 그 에이전트, 러너 아래 프로젝트와 그 에이전트.
- **member 도 자기 연결(Gateway·러너)을 만들고 관리한다.** 거기서 나온 에이전트는 **팀 채널에 넣어 누구나 부른다**(개인 비서가 아니다).
- **admin 은 모든 멤버의 연결에서 에이전트 설정을 관리한다.**
- member 가 추가한 Gateway 는 **admin 승인 뒤에 켜진다**(SSRF 때문 — 5.4).
- 화면 꼴은 **목록 + 상세**(시안 B). 탭 이름은 **「연결」**.
- 설명은 한 줄로 걷고, 긴 사정은 「?」 펼침·사용 설명서로 보낸다(시안 「상세」).
- 만드는 순서는 **두 단계, 화면 먼저**(4장).

## 2. 목표·비목표·실패

**목표**

- 「에이전트」·「러너」·「연결」 세 탭을 「연결」 탭 하나로 합친다 — 한 화면에서 연결 → 프로젝트 → 에이전트를 따라간다.
- 화면 문구를 한 줄로 줄인다. 위험 경고만 늘 보인다.
- (2단계) 연결마다 주인을 두고, member 가 자기 연결을 처음부터 끝까지 스스로 붙이고 관리한다.

**비목표**

- 채널에 에이전트를 넣는 규칙, DM 허용(`dmAccess`), 러너 로컬 천장(roots·programs 상한)은 바꾸지 않는다.
- 플러그인 설치 블록의 **내용**(무엇을 받고 어떤 명령을 보이나)은 이 문서가 정하지 않는다 — `plugin-install-cmd` 작업 몫. 여기서는 그 상자의 **자리**만 정한다.
- 러너 전용 Claude 로그인을 기본에서 빼는 일(`CLAUDE_CONFIG_DIR` 없이 평소 로그인)은 따로 넘겼다(슬러그 `runner-default-claude-login`). 여기서는 설치 안내 2단계(로그인)를 「그 작업 결과에 맞춰 바뀌는 자리」로 둔다.
- 「내 계정」 탭의 프로필은 `messenger-basics` 몫이다. 이 문서는 탭 목록만 바꾼다.

**실패로 칠 것(동작해도)**

- member 가 남의 연결의 토큰 원문·주소·설치 명령을 볼 수 있다.
- member 의 Gateway 가 승인 없이 서버를 바깥(사내망 포함) 주소로 접속시키거나, 승인 뒤 주소만 바꿔 승인을 우회한다.
- 합친 첫 화면이 owner 기준으로 한 화면을 넘게 길어진다(시안 A 로 되돌아간 꼴).
- 옛 주소·옛 링크(배너·실패 카드·문서)가 404 나 빈 화면으로 간다.

## 3. 화면

### 3.1 탭

| 탭 | 주소 | 누가 |
| --- | --- | --- |
| 내 계정 | `/settings/account` | 누구나 |
| 알림 | `/settings/notifications` | 누구나 |
| **연결** | `/settings/connection` | **누구나** |
| 채널 | `/settings/channels` | 누구나 |
| 자동화 | `/settings/automations` | admin 이상 |
| 멤버 | `/settings/members` | admin 이상 |
| 운영 | `/settings/operations` | admin 이상 |

- 「에이전트」·「러너」 탭은 없어진다. 「연결」의 자리는 옛 「에이전트」 자리(알림 다음)다 — 누구나 보는 탭끼리 위에 모은다(내 판단).
- 옛 주소 `/settings/agents`·`/settings/runners`·`/agents` 는 `/settings/connection` 으로 `replace` 넘긴다.

### 3.2 목록(왼쪽, 폰은 첫 화면)

머리: 제목 「연결」, 한 줄 설명(예: 「에이전트가 어디에 붙어 있는지 보고 관리합니다.」), 「＋ 연결 추가」.

트리 — 줄 하나가 한 항목이고 누르면 상세가 열린다.

```
내 연결
  사무실                 Gateway   [연결됨]
    ● Dev  @dev
    ● Fin  @fin
다른 사람의 연결
  mia 의 맥북            러너      [연결됨]
    📁 dodok
      ● Coder  @coder
    ＋ 프로젝트 추가                     (관리할 수 있는 사람만)
연결 없음                                (있을 때만)
  ● Old  @old  — Gateway 가 삭제됨
▸ 삭제된 에이전트 3                       (접힘, 있을 때만)
```

- 묶음은 「내 연결」·「다른 사람의 연결」·「연결 없음」·「삭제된 에이전트」. **1단계에서는 주인이 없으므로** 「내 연결」·「다른 사람의」 가름이 없다 — 한 묶음 「연결」로 그린다(묶음 자리는 2단계를 위해 컴포넌트로 남긴다).
- 상태 배지: Gateway 는 지금 `gatewayStateLabel`(연결됨·재연결 중·페어링 대기·꺼짐·연결 안 됨) + 2단계의 「승인 대기」. 러너는 연결됨·끊김·폐기됨.
- 줄에 보일 것은 이름·핸들·상태뿐이다. 사용 스위치·DM 허용·지시 같은 것은 상세로 간다.
- 「연결 없음」: OpenClaw 에이전트의 `gateway === null`(Gateway 삭제됨), 러너 에이전트의 `runner` 없음·`revoked`.
- 「삭제된 에이전트 N」: 지금 `ArchivedAgents` 묶음을 그대로 옮긴다.

**역할별로 보이는 트리(1단계, 지금 서버가 주는 값으로)**

| | Gateway 목록 | 러너 목록 | 프로젝트 |
| --- | --- | --- | --- |
| member | wire `adapter.status` 의 `gateways`(id·이름·상태) — 에이전트 없는 Gateway 도 보인다 | 에이전트의 `runner`(라벨·폐기)에서만 — 에이전트 없는 러너는 안 보인다, 상태 모름 | 없음(서버가 안 준다 — 러너 아래 에이전트를 바로 단다) |
| admin | 위와 같다 | `GET /runners` | `GET /runners/:id/projects` |
| owner | `setup.status` | `GET /runners` | 위와 같다 |

2단계에서 누구나 읽는 연결 목록 API 를 더해 member 의 빈 칸을 메운다(5.3).

1단계에서 상세를 열 수 있는 범위(내 판단 — 지금 API 권한을 넘지 않게): owner 아닌 사람이 Gateway 를 누르면 상세에 머리(이름·상태)와 「에이전트 N」 섹션만 보이고(admin 이상이면 「에이전트 가져오기」 포함), 플러그인·브리지 토큰 섹션은 없다. member 가 러너를 누르면 머리(이름)와 그 러너의 에이전트만 보인다. 다른 사람이 읽기만 할 수 있는 것은 2단계에서도 같은 규칙 — 주소·토큰·설치 명령이 든 섹션은 주인·admin 이상에게만 그린다.

### 3.3 상세(오른쪽, 폰은 다음 화면)

주소마다 화면이 있다(새로 고침·링크·뒤로 가기가 그대로 된다):

| 주소 | 화면 |
| --- | --- |
| `/settings/connection` | 목록만(넓은 화면 오른쪽은 「왼쪽에서 고르세요」 한 줄, 또는 첫 항목 — 빌더 판단) |
| `/settings/connection/gateway/$gatewayId` | Gateway 상세 |
| `/settings/connection/runner/$runnerId` | 러너 상세 |
| `/settings/connection/project/$projectId` | 프로젝트 상세(admin 이상) |
| `/settings/connection/agent/$agentId` | 에이전트 상세 |
| `/settings/connection/new` | 연결 추가 |

넓은 화면은 설정 탭 목록 | 트리 | 상세 의 세 칸이 된다. 설정 탭 목록이 이미 왼쪽에 있으므로 트리 칸은 좁게 둔다(폭은 빌더 판단, 390px 폰에서는 한 칸씩 — 설정 셸의 「← 설정」과 같은 꼴로 「← 연결」).

**Gateway 상세** — 머리: 이름·상태 배지·「수정」「끄기/켜기」「삭제」. 한 줄 메타: 「OpenClaw Gateway · 주인 <이름>(2단계) · <주소> · <버전>」(드리프트면 지금 문구 유지). 그 아래 섹션 셋:

1. **플러그인** — 접속 상태 배지(지금 `PluginStatus`·`BuildMatch` 의 판정을 한 줄로). 그 아래 **플러그인 설치 상자**(내용은 `plugin-install-cmd` 몫). 플러그인이 아직 안 붙었으면 상자를 펼쳐 두고, 붙어 있으면 「다시 설치」 접힘. 페어링 대기면 지금의 승인 명령 블록이 이 섹션 맨 위에 온다.
2. **브리지 토큰** — 「새 토큰」, 한 줄 「플러그인이 이 서버에 붙을 때 쓰는 토큰.」 + 「?」(교체 절차·브리지 주소). 목록은 지금 `TokenList`.
3. **에이전트 N** — 「에이전트 가져오기」(지금 `DiscoverDialog` 를 이 Gateway 로 고정해 연다). 줄은 트리와 같다.

**러너 상세** — 머리: 이름·상태·「이름 바꾸기」(2단계에서 라벨 PATCH 가 없으면 빼도 된다 — 빌더 판단)「토큰 다시 발급」「폐기」. 메타: 「러너 · 주인 <이름> · dodok-runner <판본>」, 프로그램 줄(지금 `ProgramLine`), 루트. 그 아래:

1. **경고 한 줄**(늘 보임): 「이 러너의 에이전트는 채널 멤버 누구나 부를 수 있고, 루트 안 파일을 읽습니다. 루트는 좁게, 상한은 낮게.」 + 「?」(지금 「러너를 붙이면 드러나는 것」 네 줄 전부).
2. **프로젝트 N** — 「＋ 프로젝트」(지금 `AddProjectDialog`), 줄은 트리와 같다.
3. **설치 안내** — 러너가 한 번이라도 붙었거나 지금 붙어 있으면 접힘, 아니면 펼침. 4단계(설치·로그인·설정 파일·실행)를 단계마다 한 줄 + 명령 블록으로. 「claude 명령이 없을 때」·「서버와 같은 빌드로 설치」는 접힘. 2단계(로그인)의 명령·문구는 `runner-default-claude-login` 결과를 따른다.
4. **러너 토큰** — 지금 `RunnerTokenList` 의 그 러너 줄(지금 접속 중·같은 빌드 안내).

러너 하나 = 러너 토큰 하나다(서버 모델 그대로). 지금 연결 페이지의 「러너 토큰 목록」은 사라지고 러너 상세가 그 토큰 하나를 맡는다.

**프로젝트 상세**(admin 이상, 2단계에서는 그 러너의 주인도) — 이름·자리(`<루트 라벨>/<상대 경로>`), 「확인」「이름 바꾸기」「옮기기」「보관」(지금 `ProjectList` 줄의 버튼과 대화상자 그대로), 「에이전트 N」과 「＋ 에이전트」(지금 `RunnerAgentForm` 을 이 프로젝트로 고정해 연다).

**에이전트 상세** — 지금 `AgentRow` 의 내용을 옮긴다: 이름·핸들·제공자 id·경로(「mia 의 맥북 › dodok · Claude Code」 또는 「사무실 · OpenClaw」), 사용 스위치, 「DM 보내기」, 러너 정의 요약과 「러너 설정 고치기」, 메모/지시, DM 허용, 「Gateway 옮기기」, 「삭제」. 고칠 수 없는 사람에게는 값만 보인다(지금 `readOnly` 규칙).

**연결 추가**(`/new`) — 「Gateway」·「러너」 둘 중 하나를 고른다.

- Gateway: 지금 `GatewayForm`(이름·주소·토큰) → 저장하면 그 Gateway 상세로 간다(플러그인 설치 상자가 펼쳐진 채). 2단계에서 member 가 만들면 상세 머리에 「승인 대기 — admin 이 승인하면 서버가 접속합니다」.
- 러너: 이름(라벨) → 토큰 발급(지금 `IssueRunnerTokenDialog` 의 한 번만 보이는 원문·「AI 에게 맡기기」) → **「러너를 붙이면 드러나는 것」 네 줄 전부** → 그 러너 상세(설치 안내 펼침)로 간다.

### 3.4 문구 원칙

- 화면 문구는 **한 줄**. 한 줄을 넘는 사정은 「?」 펼침(누르면 그 자리에 펼쳐지는 `details` 꼴 — 접근성 이름은 「<섹션> 도움말」)이나 사용 설명서 절 링크로 보낸다.
- **위험 경고는 늘 보인다**(러너 경고 한 줄, 다른 빌드 경고, 쓸 수 있는 토큰 없음, 5분 넘은 페어링, 상한 초과).
- 화면 문구에 스펙 이름·계획 판정 번호를 쓰지 않는다(지금도 화면 문구에는 거의 없다 — 코드 주석의 스펙 참조는 그대로 둔다).
- 걷을 것의 예(시안 「상세」에서 사람이 승인):
  - 연결 페이지 머리 「OpenClaw Gateway·플러그인과 러너가 이 서버에 어떻게 붙어 있는지 보고…」 → 탭 머리 한 줄로.
  - 브리지 토큰 설명 → 「플러그인이 이 서버에 붙을 때 쓰는 토큰.」 + 「?」.
  - 러너 「드러나는 것」 네 줄 → 경고 한 줄 + 「?」(추가 흐름에서는 네 줄 전부).
  - 설치 3단계(설정 파일)의 긴 문단 → 「roots 는 좁게, label 은 꼭.」 + 「?」.
  - 「서버와 같은 빌드로 설치」의 설명 문단 → 접힘 안 한 줄.
  - 에이전트 탭 머리 「OpenClaw·러너 에이전트를 등록하고…메모는 에이전트에게 전달되지 않습니다」 → 메모 칸 옆 한 줄로만.
- 서버 버전 칸(연결 페이지의 「서버」 섹션)은 지운다 — 「운영」 탭 상태 카드가 이미 「서버 <버전> · …부터 가동」을 보인다.

## 4. 만드는 순서 — 두 단계, 화면 먼저

**고른 길**: 두 단계, 화면 먼저(사람 선택). 설계는 이 문서 하나, 구현계획은 단계별로 나눈다.

| 길 | 무엇 | 득실 |
| --- | --- | --- |
| 한 번에 | 서버 소유권과 화면 통합을 한 흐름으로 | 중간 상태가 없지만 변경이 커서 리뷰가 길고 고장 자리를 가리기 어렵다 |
| **두 단계, 화면 먼저 (고름)** | ① 지금 권한 그대로 화면 통합·문구 정리 ② 주인·member 관리·Gateway 승인 | 사람이 원한 「보기 쉽게」가 먼저 나가고, 보안이 걸린 권한 변경은 따로 리뷰. ① 이 묶음·상세 주소 자리를 미리 가져 ② 에서 화면을 다시 짜지 않는다 |
| 두 단계, 권한 먼저 | 서버 소유권 먼저, 화면 나중 | member 가 쓸 화면이 아직 세 탭이라 권한을 넣어도 못 쓰는 기간이 생긴다 |

### 4.1 1단계 — 화면 통합(서버 권한 그대로)

- 웹: 3장 전부. 단 「내 연결」 묶음·「주인」 메타·「승인 대기」·member 의 「연결 추가」는 없다. 버튼은 지금 권한대로 보인다(Gateway·러너 토큰 일은 owner, 프로젝트·에이전트 일은 admin 이상).
- member 에게 「＋ 연결 추가」는 1단계에서 보이지 않는다.
- 서버: 바꾸지 않는다. 다만 화면 문구에 「연결 페이지」·「러너 탭」을 가리키는 서버 쪽 사람용 문구가 있으면(5.6) 새 이름으로 고친다 — 동작은 그대로.
- 문서: 6장.

### 4.2 2단계 — 연결의 주인

5장 전부와 그에 맞춘 화면(「내 연결」 묶음, 주인 메타, 승인 대기, member 의 연결 추가, member 가 자기 연결에서 쓰는 버튼).

## 5. 2단계 — 권한 모델

### 5.1 주인

- `gateways` 에는 `owner_user_id`(users.id 참조) 칸이 이미 있다(멀티 Gateway 때 「사람마다 붙이기의 자리 — 지금은 늘 null」로 둔 것, `GatewaySummary.ownerUserId` 로 응답에도 실린다). `runner_tokens` 에 같은 칸을 더한다. 마이그레이션은 지금 있는 행을 그 워크스페이스의 owner 로 채운다(내 판단 — 사람이 승인한 「지금 있는 연결은 워크스페이스 owner 를 주인으로」).
- 주인 = 만든 사람. 주인을 바꾸는 기능은 넣지 않는다(비목표 — 필요하면 다음).
- 러너 프로젝트·러너 에이전트·OpenClaw 에이전트는 따로 주인을 갖지 않는다 — **자기가 속한 연결의 주인**을 따른다.
- 주인인 멤버를 비활성화해도 연결은 그대로 돈다(팀 자원). 그 연결은 admin 이상이 계속 관리한다.

### 5.2 권한 표

「관리」 = 그 연결 안에서 할 수 있는 모든 쓰기(연결 수정·끄기·삭제, 토큰 발급·다시 발급·폐기, 프로젝트 추가·이름·확인·옮기기·보관, 에이전트 가져오기·만들기·고치기·삭제·되살리기, 둘러보기).

| 할 일 | member | 그 연결의 주인(member) | admin | owner |
| --- | --- | --- | --- | --- |
| 트리 보기(이름·상태·에이전트) | ✅ | ✅ | ✅ | ✅ |
| 연결의 주소·토큰 목록·설치 명령 보기 | — | ✅ | ✅ | ✅ |
| Gateway·러너 추가 | ✅(Gateway 는 승인 대기) | — | ✅ | ✅ |
| 자기 연결 관리 | — | ✅ | ✅ | ✅ |
| 남의 연결 관리 | — | — | ✅ | ✅ |
| member 의 Gateway 승인 | — | — | ✅ | ✅ |
| 「Gateway 옮기기」 | — | 옮길 곳과 원래 곳이 둘 다 자기 Gateway 일 때 | ✅ | ✅ |
| 프로젝트 「옮기기」 | — | 두 러너가 다 자기 것일 때 | ✅ | ✅ |

- 「Gateway 옮기기」는 지금 owner 만인데 admin 까지 넓힌다(사람 승인).
- 옮기기의 주인 조건은 내 판단이다 — 남의 연결로 에이전트를 밀어 넣으면 남의 Gateway·컴퓨터가 일을 떠맡기 때문.
- 삭제된 에이전트의 「되살리기」도 그 에이전트 연결의 주인 또는 admin 이상. 연결이 없으면(삭제됨) admin 이상.

### 5.3 서버가 바뀌는 곳

- **정책 함수가 자원을 본다.** `apps/server/src/auth/policies.ts` 의 `authorizeAgentDiscover`·`authorizeAgentRegister`·`authorizeAgentPatch`·`authorizeAgentArchive`·`authorizeRunnerManage` 는 지금 역할만 받는 순수 함수다. 「역할 + 이 연결의 주인인가」를 받도록 바꾼다(주인 여부는 부르는 쪽이 읽어 넘긴다 — 지금 `authorizeConversationManage` 의 `actor` 꼴). 제어 MCP(`apps/server/src/modules/control/handlers.ts`)가 같은 함수를 부르므로 REST 와 제어 도구가 같이 바뀐다 — member 가 제어 도구로 자기 Gateway 의 에이전트를 등록할 수 있게 된다(정합 유지, 따로 막지 않는다 — 내 판단).
- **owner 전용 라우트**(`requireOwner`)를 정책으로 바꾼다: `apps/server/src/modules/gateways/routes.ts`(목록·추가·수정·삭제·브리지 토큰), `apps/server/src/modules/runners/routes.ts`(러너 토큰 목록·발급·다시 발급·폐기), `apps/server/src/modules/agents/routes.ts` 의 `PUT /agents/:id/gateway`.
- **`GET /api/v1/setup/status`** 는 owner 전용으로 남긴다(서버 전체 사정 — 플러그인 파일·러너 파일·브리지 주소). 화면이 상세에 필요한 것(브리지 주소, 플러그인·러너 파일 정보, Gateway 하나의 상세)은 연결 단위 읽기로 나눈다 — 정확한 꼴은 빌더 판단, 조건은 「주인·admin 이상만 그 연결의 주소·토큰을 본다」.
- **누구나 읽는 연결 목록** `GET /api/v1/connections`(가칭): Gateway·러너마다 id·종류·이름·상태·주인(id·이름)·승인 대기 여부. 주소·토큰·호스트는 싣지 않는다. 1단계의 member 빈 칸(에이전트 없는 러너, 러너 상태, 프로젝트 이름)을 메운다 — 프로젝트는 id·이름·러너 id 만.
- **러너 에이전트 정의**(`runnerAgent`)를 지금은 admin 이상에게만 싣는다 — 그 러너의 주인에게도 싣는다.
- 실시간: 연결이 추가·승인·삭제되면 열린 화면이 바뀌어야 한다. 지금 `adapter.status`·`agents.changed` 로 부족하면 연결 목록 무효화 이벤트를 더한다(빌더 판단).

### 5.4 member 의 Gateway 승인

- 까닭: 서버는 Gateway 주소로 WebSocket 을 연다(`packages/openclaw-adapter` 의 Gateway WS 클라이언트). member 가 아무 주소나 넣을 수 있으면 서버가 사내망 안을 두드리는 통로(SSRF)가 된다. 러너는 러너 → 서버로 나가는 연결이라 이 문제가 없다.
- `gateways` 에 승인 상태를 둔다(예: `approved_at`·`approved_by`). member 가 만든 Gateway 는 미승인 — **서버는 미승인 Gateway 에 접속하지 않는다**(켜기 상태와 별개로 어댑터가 건너뛴다). admin 이상이 만든 것은 만들 때 승인된다.
- 승인된 Gateway 의 **주소를 member(주인)가 바꾸면 미승인으로 돌아간다**(우회 방지 — 내 판단, 사람에게 알림). 이름·토큰만 바꾸면 그대로. admin 이상이 바꾸면 승인 유지.
- 화면: 트리 배지 「승인 대기」, Gateway 상세 머리에 admin 이상에게 「승인」 버튼과 주소를 한 줄로 크게(무엇을 승인하는지 보이게). 미승인 Gateway 에서도 브리지 토큰 발급·플러그인 설치 안내는 보인다(주인이 미리 준비할 수 있게 — 플러그인은 브리지로 **서버에** 붙는 쪽이라 위험이 없다).
- 운영: 승인 대기 Gateway 가 있으면 admin 이상의 「설정」 배지·운영 사건으로 알릴지 — 빌더 판단(있으면 좋음, 필수 아님).

### 5.5 러너의 보안 문구

member 가 자기 컴퓨터의 러너를 팀에 내놓게 되므로, 추가 흐름의 「드러나는 것」 네 줄을 그 사람 기준으로 다시 쓴다: 「채널 멤버 누구나 이 러너의 에이전트를 부를 수 있습니다」, 「admin 은 루트 안 아무 디렉터리에서 상한까지의 도구로 에이전트를 만들 수 있습니다 — 루트는 좁게, 상한은 낮게」 등. 천장(로컬 설정)이 기계 주인의 유일한 안전장치라는 것을 그 자리에서 말한다.

### 5.6 바뀌는 사람용 문구(서버·공유)

「연결 페이지」·「러너 탭」·`/settings/runners`·`/settings/agents` 를 사람에게 보이는 문구로 쓰는 곳이 있다(실패 카드 사유, llms.txt, 운영 사건, 제어 도구 설명). 서버 `apps/server/src/modules/setup/llms.ts`·`modules/runs/orchestrator.ts`·`modules/ops/health.ts`·`modules/control/handlers.ts`·`modules/runners/*`·`modules/gateways/service.ts`·`realtime/events.ts`, shared `setup/index.ts`·`domain/index.ts`·`control/runner-bodies.ts`, 어댑터 `openclaw-adapter/src/connection/gateway-connection.ts` 를 `grep -rnE '연결 페이지|러너 탭|「러너」 탭|settings/(runners|connection|agents)'` 로 찾아, 사람에게 보이는 문구면 「설정 → 연결」로 고친다. 주석은 그대로 둬도 된다. 1단계에서 한다.

## 9. 내가 정한 것(사람이 읽으며 확인할 것)

- 「연결」 탭 자리는 옛 「에이전트」 자리(알림 다음).
- 1단계에서 member 에게 「연결 추가」를 숨긴다(서버가 막으므로).
- 러너 상세가 그 러너의 토큰 하나를 맡고, 따로 있던 「러너 토큰 목록」은 사라진다.
- 주인을 바꾸는 기능은 넣지 않는다. 주인이 비활성화돼도 연결은 돈다.
- 「Gateway 옮기기」·프로젝트 「옮기기」를 member 주인에게는 두 쪽이 다 자기 것일 때만 허락한다.
- member 가 승인된 Gateway 의 주소를 바꾸면 다시 승인 대기. 이름·토큰 변경은 그대로.
- 미승인 Gateway 에서도 브리지 토큰 발급·플러그인 설치 안내는 보인다.
- 제어 MCP 도구도 REST 와 같은 주인 규칙을 따른다(member 가 도구로 자기 Gateway 에이전트를 등록할 수 있다).
- 서버 버전 칸은 운영 탭에 이미 있으므로 지우기만 한다.
- 1단계에서 owner 아닌 사람이 Gateway·러너를 열면 이름·상태·에이전트만 보인다(3.2 끝).
- member 한 사람이 만들 수 있는 연결 수에 한도를 두지 않는다 — 기존 레이트리밋 밖의 한도는 필요해지면 다음에.
- 미승인 Gateway 는 서버가 접속하지 않으므로 「에이전트 가져오기」 목록이 비고, 승인 뒤에야 에이전트를 데려올 수 있다.
