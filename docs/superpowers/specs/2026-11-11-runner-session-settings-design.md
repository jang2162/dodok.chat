# 러너 에이전트의 세션 설정 — 설계

상태: 승인 대기(2026-11-11) · 결정: 사용자와의 대화(2026-11-11), 빌더 확인 1회

## 1. 왜

러너 에이전트를 만들 때 「모델·권한 모드·허용 도구」를 정하라고 하는데, 만드는 시점에는 무엇을 넣어야 할지 모호하다(사용자). 이 값들은 에이전트의 성질이 아니라 **그 대화에서 어떻게 일을 시킬지**에 가깝다. 그래서 생성에서 빼고, 대화(세션)마다 채널 화면에서 보고 바꾸게 한다. 함께, 그 세션에서 에이전트의 **컨텍스트 사용률·모델·노력치(effort)·권한 모드**를 늘 볼 수 있게 한다.

## 2. 목표 · 하지 않을 것

**목표**
- 러너 에이전트 생성·수정 화면에서 모델·권한 모드·허용 도구 입력을 없앤다.
- 대화(채널의 세션·DM 의 세션) × 러너 에이전트마다 모델·effort·권한 모드를 둔다. 채널 작성기 바로 위 상태 줄에서 보고 바꾼다.
- 상태 줄은 그 에이전트의 컨텍스트 사용률(%)을 보인다.

**하지 않을 것**
- OpenClaw 에이전트(사용자 결정 — 러너만). OpenClaw 에이전트에는 상태 줄을 그리지 않는다.
- 허용 도구를 세션에서 고르는 것. 허용 도구는 생성에서도 채널에서도 뺀다 — 도구는 승인 카드로 그때그때 허락하고, 러너 로컬 설정의 도구 상한(`disallowedTools`·`allowedToolsCeiling`)은 그대로다.
- 도는 중인 실행에 바꾼 값을 적용하는 것(다음 실행부터).

**실패로 볼 것(돌아가도)**
- member 가 세션 설정으로 권한 모드를 올려 러너 머신에서 묻지 않고 파일을 고치게 되는 것(3장 권한).
- 러너 로컬 상한(천장)을 세션 설정이 넘는 것 — 넘는 값은 지금처럼 러너가 `RUNNER_CEILING` 으로 거절해야 하고, 화면은 넘는 값을 고르게 두지 않는다.

## 4. 접근

**고른 것 — 대화 × 에이전트 설정 행 + 실행 때 실어 보내기.** 서버가 `(conversationId, agentId)` 마다 설정 행을 갖고, 실행을 만들 때 그 값으로 `run.start.agent` 의 `model`·`permissionMode` 와 새 `effort` 를 채운다. 러너는 지금처럼 실행마다 천장과 견주고 SDK `query()` 옵션으로 넘긴다.

- 다른 길 1 — 세션 설정을 러너가 기억(러너 메모리·파일): 러너를 다시 띄우면 잃고, 여러 사람이 보는 값을 서버가 모른다. 버림.
- 다른 길 2 — 실행 중 `setModel`·`setPermissionMode`(SDK 가 지원): 러너는 실행마다 CLI 를 새로 열므로 다음 실행에 넘기는 것과 결과가 같고, 도는 실행 중 변경은 목표가 아니다(S6). 버림.

화면 자리는 두 후보(작성기 위 상태 줄 / 채널 머리 팝오버) 중 사용자가 상태 줄을 골랐다 — 컨텍스트 % 는 늘 보여야 쓸모가 있다.

## 5. 설계

### 5.1 데이터

- 새 표 `conversation_agent_settings`: `conversation_id`(FK, 대화 삭제 시 함께), `agent_id`(FK), `model` text null, `effort` text null(`low|medium|high|xhigh|max`), `permission_mode` text null(null = 「기본」, S5), `updated_by`(users, null), `updated_at`. PK `(conversation_id, agent_id)`. 행이 없으면 S5 의 시작값.
- `agents` 에 「새 세션 시작값」 세 열(`session_default_model`·`session_default_effort`·`session_default_permission_mode`, 모두 null 허용 — S10)을 둔다. 기존 `model`·`permission_mode` 는 마이그레이션이 S8 대로 기존 세션에 옮기고, **같은 값을 시작값 열에도 옮긴다**(지금 쓰던 에이전트가 새 세션에서도 같은 값으로 돌게 — 조율자 판단). 그 뒤 `model`·`permission_mode`·`allowed_tools_json` 열은 지운다(`disallowed_tools_json` 은 — 화면에서 고르지 않지만 이미 값이 있으면 실행에 실리는지 확인하고, 생성 화면에 입력이 없으면 같이 지운다. 빌더 판단, 4·7장).
- 컨텍스트 사용률: 러너의 실행 끝 보고(`RunnerRunFinalBody.usage`)에 `contextTokens`(마지막 API 호출의 입력+캐시 토큰)와 `contextWindow` 를 더한다(SDK `result` 의 `modelUsage[model].contextWindow`). 서버는 그 실행의 행(`runs.usage`)에 담고, 상태 줄은 그 세션(스레드면 그 스레드 세션)에서 그 에이전트의 마지막 실행 값으로 `round(contextTokens / contextWindow × 100)` 을 그린다. 값이 없으면 「—」.

### 5.2 계약(shared)

- `RunnerRunAgent` 에 `effort: z.enum([...]).nullable()` 를 더하고 `allowedTools` 는 빼거나 늘 null 로(옛 러너 호환 — 아래). 
- 옛 러너(0.3.0 이하)와 섞임: 서버가 `effort` 를 실어 보내도 옛 러너가 모르면 무시해야 한다 — 지금 스키마가 strict 인지 확인하고, strict 면 hello 의 러너 판본으로 보내지 않는다(빌더 판단, 근거를 남긴다). `RUNNER_PROTOCOL` 은 올리지 않는 쪽을 먼저 본다.
- 새 세션의 첫 글(S11): 새 대화를 만드는 첫 글 전송 계약(지금 새 세션 창의 첫 `message.send` 와 그 생성 표지)에 선택 필드 `agentSettings: [{ agentId, model?, effort?, permissionMode? }]` 를 더한다. 서버는 대화 생성과 같은 트랜잭션에서 설정 행을 만들고, 그 글이 부른 실행이 그 값으로 돈다. 권한 규칙(5.3)을 같은 자리에서 보고 어기면 글 전체를 거절한다(화면은 애초에 고르지 못하게 하므로 방어선). 글이 실패하면 행도 없다.
- 새 REST: `GET /api/v1/conversations/:id/agent-settings`(그 대화의 러너 에이전트별 설정 + 컨텍스트 %), `PATCH /api/v1/conversations/:id/agent-settings/:agentId`(`model`·`effort`·`permissionMode` 일부). 바뀌면 wire 로 그 채널 룸에 알린다(다른 사람 화면의 상태 줄이 따라 바뀐다). 경계에서 Zod.

### 5.3 권한(S2)

- 읽기·모델·effort·권한 모드 낮추기: 그 대화를 읽을 수 있는 사람(`canReadChannel` — DM 은 참여자).
- 권한 모드 올리기(`permissionModeRank` 로 지금보다 큰 값): 그 에이전트의 러너(연결) 주인 또는 admin 이상(`canManageConnection` 과 같은 판정). 그 밖이면 403, 화면은 그 선택지를 비활성화하고 사유(「러너 주인·admin 만 올릴 수 있습니다」)를 `DisabledHint` 로.
- 러너 천장: 화면은 그 러너가 알린 상한(`ceiling.maxPermissionMode`) 넘는 권한을 고르지 못하게 한다. 서버도 PATCH 때 같은 상한으로 거절한다(지금 에이전트 저장 때의 천장 검사와 같은 길).

### 5.4 화면(S3)

```
 @coder  opus · effort high · default · 컨텍스트 42%   [변경]
 ───────────────────────────────────────────────
 메시지 보내기 — @로 에이전트 부르기
```

- 그 대화에 든 러너 에이전트(S13)마다 한 줄. 새 세션 창(첫 글 전)에서도 그린다 — 값은 S5 의 시작값에서 출발하고, 바꾼 값은 화면에만 있다가 첫 글과 함께 간다(S11). 창을 떠나면 버린다. 셋이 넘으면 「러너 에이전트 N」 한 줄로 접고 펼친다.
- 「기본」 값은 「기본」으로 보인다(모델 기본·effort 기본).
- 「변경」 팝오버: 모델(기본·sonnet·opus·haiku + 직접 입력), effort(기본·low·medium·high·xhigh·max), 권한 모드(기본·`plan`·`dontAsk`·`default`·`acceptEdits` — 천장·권한으로 막힌 것은 비활성+사유). 저장하면 바로 반영, 실패는 그 자리 오류.
- 실행 중인 에이전트의 줄에는 「다음 실행부터」 표시는 두지 않는다(문구 정리 기준 — 설명 문장 없음).
- 화면 문구는 2026-11-10 문구 정리 기준(라벨·값·단추만).

### 5.5 에이전트 생성·수정

- `RunnerAgentForm`(만들기)에서 모델·권한 모드·허용 도구 칸을 걷는다. 에이전트 상세에는 「새 세션 시작값」(모델·effort·권한 모드, 모두 비워 둘 수 있음)을 둔다(S10) — 권한은 그 러너 상한까지. 서버 생성·수정 API 와 제어 도구(`create_agent`·`update_agent` 가 이 필드를 받으면)에서도 걷는다 — 옛 클라이언트가 보내면 무시할지 400 일지는 빌더 판단(무시 쪽을 권함, 근거 남김).
- 에이전트 상세의 이 값 표시도 걷는다.

### 5.6 러너

- `run.start.agent.effort` 를 SDK `query()` 옵션 `effort` 로 넘긴다(null 이면 넣지 않음). 고정한 SDK 0.3.283 의 `effort` 옵션 꼴(`sdk.d.ts`)을 따른다. 천장 검사는 지금 그대로(effort 는 천장 없음).
- 실행 끝 보고에 `contextTokens`·`contextWindow` 를 싣는다.
- 러너 판본은 이 변경으로 minor(0.5.0 — 0.4.0 은 마법사).

## 6. 확인

- 서버 시험: 권한 행렬(`default` 이하 누구나·`acceptEdits` 는 주인·admin·천장·DM 참여자·남의 대화 404), 「기본」 권한의 상한 계산, 첫 글과 함께 온 설정(저장·권한 위반이면 글 거절·글 실패면 행 없음), 에이전트 시작값이 새 세션·자동화의 새 세션에 쓰이는지, 마이그레이션(S8 — 기존 세션이 있는 대화에만 행, 에이전트 열 삭제), 실행에 설정이 실리는지, 설정 변경 wire 알림, 컨텍스트 % 계산(스레드 세션 구분).
- 러너 시험: effort 가 SDK 옵션으로, 사용량 보고.
- 웹 시험: 상태 줄(값·「기본」·「—」·접기), 팝오버 권한별 비활성, 다른 사람의 변경이 wire 로 반영, 생성 폼에 세 칸이 없음.
- dev:fake: 가짜 러너가 `contextTokens`·`contextWindow` 를 실어 상태 줄을 볼 수 있게. 화면 확인.
- 런 0회 하네스(가짜 Messages API)로 effort·모델이 실제 CLI 요청에 실리는지. 실제 모델 런 금지.

## 7. 빌더에게 남긴 것

- `disallowed_tools_json` 을 함께 지울지(5.1).
- 옛 러너가 `effort` 를 받을 때의 호환 처리(5.2).
- 옛 클라이언트가 생성 API 로 세 필드를 보낼 때 무시/거절(5.5).
- 상태 줄을 접는 기준 3 과 접힌 모양.
