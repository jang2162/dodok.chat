# 작성기 도구 줄과 러너 에이전트 여럿 — 설계

상태: 승인(2026-11-18) · 결정: 사용자와의 대화(2026-11-18, UI 개선 시안 5번 「작성기 설정 칩을 입력창 안으로(에이전트 여럿 포함)」 승인)

## 1. 왜

러너 세션 설정(`docs/superpowers/specs/2026-11-11-runner-session-settings-design.md` S3)과 작성기 칩(`docs/superpowers/specs/2026-11-17-composer-agent-chips-design.md`)은 작성기 **바로 위**에 러너 에이전트마다 한 줄(`@coder [기본 모델 ⌄] [기본 노력 ⌄] [기본 권한 ⌄] ○ —`)을 두고, 셋이 넘으면 「러너 에이전트 N · 펼치기」 한 줄로 접는다.

UI 점검(2026-11-18, UI UX Pro Max 가이드라인 대조)에서 이것이 걸렸다.

- 칩 줄이 입력창과 떨어져 있어 「이 글에 적용되는 설정」이라는 관계가 약하다.
- 게이지(`○ —`)에 이름이 없고, 「기본 모델」은 이름인지 값인지 헷갈린다.
- 3명이면 줄이 셋 쌓여 타임라인을 밀어 올린다. 4명부터는 전부 접혀 누구의 컨텍스트가 차고 있는지조차 안 보인다.
- 「초대됨」 표시가 10px 다.

## 2. 목표 · 하지 않을 것

**목표**
- 작성기를 두 줄로 — 위는 입력, 아래는 **도구 줄**(첨부 · 에이전트 칸 · 빈칸 · 보내기). 러너 칩은 도구 줄 안으로 들어간다.
- 러너 에이전트 수와 화면 폭에 따라 에이전트 칸의 모양을 정한다(T2~T5). 몇 명이든 모든 에이전트의 컨텍스트 상태가 닫힌 상태에서 보인다(4명 이상은 70% 이상만 — T4).
- 초안이 부르는 러너 에이전트를 보내기 전에 보이게 한다(T6).

**하지 않을 것**
- 칩이 하는 일 — 선택지·저장(PATCH·새 세션 창의 보류 값)·잠금 사유·게이지 세부 팝오버는 바꾸지 않는다(작성기 칩 스펙 5.4 그대로). 이 문서는 **자리와 모양**만 바꾼다.
- OpenClaw 에이전트 칩(작성기 칩 스펙 C5 그대로).
- 채널 머리의 「초대됨」(10px)·메시지 머리의 「AI」 배지 — UI 점검의 다른 항목이라 따로 한다.
- 알약에 기본값이 아닌 노력치·권한을 표시하는 것(T9 — 이월).

**실패로 볼 것(돌아가도)**
- 칩·게이지의 접근 이름(`@coder 모델: 기본` 꼴)이 바뀌어 스크린 리더 사용자가 다른 이름을 듣는 것.
- 390px 에서 가로 스크롤이 생기는 것(작성기 칩 스펙 5.4 「좁은 화면」).
- 입력하는 동안 알약 순서가 바뀌어 누르려던 것이 움직이는 것.
- 러너 에이전트가 없는 대화(OpenClaw 만·사람끼리)에 빈 에이전트 칸이 자리를 차지하는 것.

## 3. 결정

| T4 | 알약 수 — 3명 이하면 전부, **4명 이상이면 앞의 2개 + 「+N」**(누르면 패널, 첫 줄로 초점). 접는 기준 3(`FOLD_OVER`)은 그대로. 순서는 **컨텍스트 70% 이상인 에이전트가 앞**(게이지 주의 구간과 같은 기준), 그 안과 나머지는 지금 순서(채널 멤버 → 세션에 초대한 순). 패널 안 줄 순서도 같다 | 사용자(시안 C) |

## 4. 접근

- **그 자리에서 칩을 바꿔 끼우기(고른 것).** `AgentSettingsBar` 가 칸의 모양(T2·T3·T5)만 고르고, 줄 하나의 일(`SettingsLine` — 저장·오류·잠금)과 칩(`AgentSettingChips`)·게이지(`ContextGauge`)는 그대로 쓴다. 패널 안의 줄이 지금의 한 줄이다.
- 다른 길 1 — 멘션한 에이전트의 칩만 도구 줄에 펼치기: 입력 중 칩이 바뀌어 흔들리고, 멘션 없이 보내는 글(자동 응답)의 대상이 안 보인다. 버림.
- 다른 길 2 — 도구 줄 폭을 재서 들어가는 만큼 알약을 보이기: 폭 측정·리사이즈 관찰이 들고 시험이 jsdom 에서 재지 못한다. 수로 정하는 T4 로 대신. 버림.

## 5. 설계

### 5.1 작성기(`apps/web/src/features/composer/Composer.tsx`)

- 지금 `<AgentSettingsBar>`(입력 상자 밖, 위)와 `[첨부][입력][보내기]` 한 줄을, 입력 상자 안의 두 줄로 바꾼다: 첨부 미리보기 → 입력(`EditorContent`, 전체 폭) → 도구 줄. 도구 줄의 에이전트 칸이 `AgentSettingsBar` 다.
- 보내기·첨부 버튼의 동작·접근 이름·`aria-describedby`·드롭·막힘 안내(`blocked`)는 그대로.
- 초안의 멘션한 에이전트 id 를 에디터 문서에서 모아(`mention` 노드의 `attrs.id` 가 `a:` 로 시작하는 것) `AgentSettingsBar` 에 넘긴다(T6). 에디터 갱신마다 다시 모으되, 같은 집합이면 다시 그리지 않게 한다.

### 5.2 에이전트 칸(`AgentSettingsBar.tsx`)

- 러너 에이전트 목록·`rowOf`·`useAgentSettings`·`useAgentCeilings`·보류 값 흐름은 그대로.
- 모양 고르기: 0명 → `null`. 1명 → T2. 2명 이상 → 좁은 화면이거나 스레드 작성기면 T5, 아니면 T3·T4.
- 순서(T4): `contextPercent >= 70` 인 줄이 앞, 나머지는 지금 순서. 70 은 `ContextGauge` 의 주의 구간 값과 **한 상수**를 같이 쓴다(지금 `tone` 안의 70·90 을 내보낸다).
- 알약·「+N」·모은 알약은 버튼이다: 접근 이름 `@reviewer 설정 — 모델 opus, 컨텍스트 31%`(T6 이면 뒤에 「 — 이 글에서 부름」), 「+N」은 `에이전트 N명 더`, 모은 알약은 `러너 에이전트 N 설정`. 셋 다 `aria-haspopup="dialog"`·`aria-expanded`.
- 패널: 넓은 화면은 팝오버(`radix-ui` 의 Popover — `ui/popover.tsx` 를 shadcn 꼴로 새로 둔다, `side="top"`·`align="start"`), 좁은 화면은 `ui/sheet.tsx` 의 아래 시트. 줄은 지금의 `SettingsLine`(T2 라벨·T7). Esc·바깥 누름으로 닫히고 초점은 연 버튼으로 돌아간다. 칩의 드롭다운이 패널 안에서 열려도 패널이 닫히지 않아야 한다.
- 데이터 시험용 `data-testid`: 칸 `agent-settings-bar`, 줄 `agent-settings-<핸들>`(패널 안·T2 묶음), 알약 `agent-pill-<핸들>`, 「+N」 `agent-pill-more`, 모은 알약 `agent-pill-summary`.

### 5.3 칩·게이지

- `AgentSettingChips.tsx`: 보이는 글을 「이름 값」으로 — 이름 부분은 흐린 색. `DEFAULT_MODEL_LABEL`·`DEFAULT_EFFORT_LABEL`·`DEFAULT_PERMISSION_LABEL`(「기본 모델」 꼴)은 보이는 글에서 빠진다. 다른 파일이 쓰지 않으므로(시험 포함) 지운다. 접근 이름·선택지·잠금·「직접 입력」은 그대로.
- `ContextGauge.tsx`: 보이는 글에 「컨텍스트」를 붙이는 표시(`label`)를 받는다 — T2 에서만 켜고, 패널 줄·알약은 퍼센트만. 접근 이름 `컨텍스트 <값>` 그대로. 알약 안의 작은 게이지는 같은 원 그리기를 쓰되 세부 팝오버 없이(알약 자체가 버튼이므로 버튼 안에 버튼을 두지 않는다).

### 5.4 문서

- 세션 설정 스펙 S3·5.4 의 해당 문장에 「→ 2026-11-18 작성기 도구 줄 스펙 T1~T6 으로 바뀜」을 붙인다(지우지 않는다).
- 작성기 칩 스펙 5.4 「접기」 줄에 같은 표시.
- `docs/manual/user-guide.md` 「러너 에이전트 상태 줄」 절을 새 모양으로 고치고 제목을 「러너 에이전트 칩」으로 바꾼다. 「상태 줄」을 말하는 다른 자리도 함께 — 같은 문서의 「세션에 에이전트 초대」(「작성기 위 상태 줄에도 「초대됨」 줄이 생긴다」)·「승인 카드」 끝의 절 인용·러너 에이전트 상세의 시작값 설명·「에이전트 만들기」의 「작성기 위 상태 줄에서 고르고」·오류 표의 「작성기 위 상태 줄의 권한 칩」, 그리고 `docs/guides/agent-guide.md` 러너 절의 「채널 작성기 위 상태 줄」과 절 인용. 고친 뒤 `grep -nE '상태 줄' docs/manual/user-guide.md docs/guides/agent-guide.md` 로 남은 것이 없는지 본다(`docs/guides/plan.md` 의 완료 기록은 이력이라 그대로).
- `docs/guides/plan.md` 8장 「이월」에 T9.

## 6. 시험

- 웹(`AgentSettingsBar.test.tsx` 를 고친다): 1명 — 칩 셋이 칸에 바로 있고 보이는 글이 「모델 기본」 꼴, 게이지가 「컨텍스트 —」. 2명·3명 — 알약 2·3개, 패널을 열면 줄 2·3개, 알약을 누르면 그 줄로 초점. 4명 — 알약 2 + 「+2」, 70% 이상인 에이전트가 앞으로. 좁은 화면·스레드 작성기 — 모은 알약 하나, 퍼센트는 가장 높은 값. T6 — 멘션하면 그 알약(또는 「+N」·모은 알약)의 접근 이름에 「이 글에서 부름」, 순서는 그대로. 패널 안 칩 저장·잠금·오류는 지금 시험을 패널을 연 뒤로 옮긴다. 0명이면 칸 없음.
- 작성기(`Composer.mentions.test.tsx` 등): 첨부·보내기 접근 이름 그대로, 러너 없는 대화에 에이전트 칸 없음.
- 브라우저(`dev:fake`): 러너 에이전트 1·3·5명(가짜 러너 「dev-fake」에 앱에서 러너 에이전트를 더 만든다), 1440px·390px, 라이트·다크. 390px 가로 스크롤 없음. 패널·시트 키보드(Tab·Esc·초점 복귀).

## 7. 빌더에게 남긴 것

- 모은 알약(T5)의 점 셋이 색만으로 구별되는 것 — 접근 이름이 수와 퍼센트를 말하므로 받아들였다. 다르게 판단되면 보고.
- 패널 너비(시안은 작성기 폭)와 시트 높이.
