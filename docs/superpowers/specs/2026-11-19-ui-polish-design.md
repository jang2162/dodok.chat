# UI 점검 반영 — 연결 상태·글자 크기·아바타·모바일 헤더·로그인 — 설계

상태: 승인(2026-11-19) · 결정: 사용자와의 대화(2026-11-18 UI 개선 시안 1·2·3·4·6번, 2026-11-19 「진행해줘」). 5번(작성기)은 `docs/superpowers/specs/2026-11-18-composer-toolbar-design.md` 로 먼저 끝났다.

## 1. 왜

UI 점검(2026-11-18, UI UX Pro Max 가이드라인 대조, dev:fake 1440·390px 캡처)에서 걸린 것들이다.

- **(1) 연결 상태가 색으로만 전달된다.** 사이드바 아래 점 두 개(Gateway·플러그인)는 올려야만 뜻을 알고, 초록·노랑·빨강 구분이 색뿐이다.
- **(2) 12px 미만 글자.** 메시지 머리의 「AI」 배지 10px(23×16px), 이어진 메시지의 시각 10px, 「삭제됨」·「비활성」 10px, 아바타 이니셜 10px(`text-[10px]` 가 `ChannelHeader`·`DirectRow`·`MessageItem`·`ThreadChip` 등에).
- **(3) 사람 아바타가 안 보인다.** 이니셜 배경 `bg-muted`(밝기 0.945)가 사이드바(0.952)와 거의 같아 원이 보이지 않고, 그룹 DM 의 겹친 아바타(`GroupAvatars`)는 두 원이 절반 넘게 겹쳐 「미」가 「ㅁ」로 잘린다(실제 결함). 이니셜이 소문자(o, d)라 구별도 약하다.
- **(4) 모바일 헤더 제목이 두 글자만 남는다.** 390px 에서 헤더 버튼 6개(사이드바·세션 목록·새 세션·세션 닫기·파일·활동, 각 32px)가 제목을 「미아, …」로 민다.
- **(6) 로그인 화면에 제품 얼굴이 없다.** 「로그인」 한 단어뿐이고, 비어 있을 때의 주 버튼은 흐린 파랑(`disabled:opacity-50`)이라 눌러도 되는 것처럼 보인다.

## 2. 목표 · 하지 않을 것

**목표** — 3장의 결정대로 다섯 가지를 고친다. 데스크톱 헤더의 배치, 색 토큰의 강조색·회색 램프는 바꾸지 않는다.

**하지 않을 것**
- 사이드바 「⋯」 같은 24px 버튼 키우기(WCAG 2.2 AA 최소치는 통과 — 점검 결론).
- 웹폰트 들이기(스펙 7.2 「웹폰트는 번들하지 않는다」 그대로).
- 「자동화」 화면(`AutomationsPage.tsx`)·멘션 후보(`MentionList.tsx`)의 10px — 이번 점검 화면 밖이다. 이월에 적는다.

**실패로 볼 것(돌아가도)**
- 사람 아바타의 색이 에이전트 색(테두리 8색)과 헷갈리는 것 — 사람은 테두리 없이 옅은 채움, 에이전트는 2px 테두리(스펙 7.2)가 구별의 축이다.
- 연결 상태의 접근 이름이 Gateway·플러그인 둘 중 하나를 빠뜨리는 것.
- 좁은 화면 「더 보기」로 옮긴 동작 하나가 사라지는 것(데스크톱에서 할 수 있는 일은 좁은 화면에서도 할 수 있어야 한다).
- 390px 가로 스크롤.

## 4. 접근

- **이니셜 아바타를 한 곳에서 만든다.** 지금은 `AvatarFallback` 에 `text-[10px]`·`name.slice(0, 1)` 이 일곱 자리에 흩어져 있다. 이니셜·색을 내는 부품 하나(`ui/identity-avatar.tsx` — 사람·에이전트 둘)를 두고 그 자리들이 그것을 쓴다. 다른 길(자리마다 고치기)은 다음 아바타 자리가 또 10px 로 생기므로 버림.
- **좁은 화면 「더 보기」는 머리마다 같은 틀**(`app/layout/HeaderOverflow.tsx`)에 항목만 넘긴다. 대화상자를 여는 동작(에이전트 초대 등)은 그 대화상자를 열린 상태를 받는 꼴로 바꿔 메뉴에서 연다.
