# 러너·플러그인 판 비교와 원격 업데이트 — 설계

상태: 승인(2026-11-23) · 결정: 사용자와의 대화(2026-11-23)

## 1. 왜

웹에서 러너(`dodok-runner`, 사용자는 「릴레이」라 부른다)와 OpenClaw 플러그인의 최신 판과 붙어 있는 판을 비교하고, 웹에서 업데이트하고 싶다(사용자). 지금은 판을 올릴 때마다 사람이 각 러너 머신·Gateway 호스트에서 명령을 돌려야 한다.

## 2. 목표 · 하지 않을 것

**목표**
- 러너 상세·Gateway 상세에 「판 X · 최신 Y」와 「업데이트」.
- 원격 업데이트는 **기본 허용**, 그 머신의 로컬 설정으로 끌 수 있다(사용자 B+C).

**하지 않을 것**
- 판 내리기(지금보다 높은 판만), 판 고르기(최신 하나).
- 러너를 npm 밖의 방식(소스·서버 tgz)으로 띄운 경우의 원격 업데이트 — 명령 한 줄 안내만.
- 자동 업데이트(누르지 않아도 올리기).

**실패로 볼 것**
- 서버가 러너·Gateway 호스트에 npm 레지스트리·서버 번들 밖의 임의 파일을 설치시킬 수 있는 것.
- 업데이트가 실패했는데 러너·Gateway 가 내려간 채로 남는 것(다시 붙지 않음).
- 끈 머신(`remoteUpdate: false`)이 업데이트되는 것.
- 진행 중인 런이 알림 없이 끊기는 것.

## 4. 남은 것(빌더 몫)

- 러너가 자기 npm 전역 자리를 아는 법(`process.argv[1]` 의 realpath 가 `npm root -g` 아래 `@dodok/runner` 인지), 다시 띄우기(분리된 자식·같은 argv·같은 env, 부모는 끝남 — 사람이 터미널에서 띄웠으면 그 터미널은 자식 출력을 계속 받지 않을 수 있다: 안내 한 줄).
- 플러그인 스크립트의 자리(Gateway 상태 디렉터리 아래), Gateway 가 서비스 관리자(launchd·systemd) 아래일 때 `openclaw gateway stop/start` 가 그대로 되는지 — 지금 설치 스크립트가 쓰는 길과 같다.
- 시험·dev:fake(가짜 러너·플러그인이 업데이트에 답하는 대본)·문서(`docs/manual/user-guide.md`·`docs/guides/docker-deploy.md`·`docs/guides/runner-release.md`·`docs/guides/plan.md`).
