# 러너 봇 2부 — 봇 전용 도구(앱에서 고치는 MCP)와 「이 러너 설정 제어」 — 설계

상태: 승인 대기(2026-11-23) · 결정: 사용자와의 대화(2026-11-23), 빌더 확인 1회 · 1부: `docs/superpowers/specs/2026-11-23-runner-bots-design.md`(6절이 이 문서로 넘긴 결정)

## 1. 왜

1부로 프로젝트 없는 봇(러너가 만든 `botsDir/<봇 id>` 에서 도는 러너 에이전트)을 만들 수 있게 됐다. 그런데 봇이 쓸 수 있는 도구는 지금 `dodok` MCP 하나(글 올리기·제어 도구)뿐이다 — 러너 런은 `strictMcpConfig: true`·`settingSources: []` 로 돈다(`packages/claude-runner/src/drivers/claude/run.ts`). Orca 의 bots 처럼 봇마다 GitHub·Linear 같은 외부 도구를 붙이고 싶다(사용자). 그리고 러너를 돌보는 봇이 앱에 있는 그 러너의 설정을 대화로 고칠 수 있게 「이 러너 설정 제어」 내장 도구를 둔다(사용자, 1부 6절).

3부(도구 로그인 — OAuth)는 따로 설계한다.

## 2. 목표 · 하지 않을 것

**목표**
- 봇마다 MCP 서버 설정(`.mcp.json` 의 `mcpServers` 꼴)을 **앱에서** 적고 고친다. 러너는 런마다 받은 설정을 SDK `mcpServers` 로 넘긴다.
- 러너 머신의 로컬 설정이 앱에서 온 MCP 를 종류별로 허용한다 — 기본은 원격(HTTP) 서버만.
- 봇을 만들거나 고칠 때 내장 도구 「이 러너 설정 제어」를 켤 수 있다. 켠 봇은 앱에 있는 **자기 러너의** 설정을 대화로 읽고 고친다. 쓰기는 지금 제어 도구처럼 시킨 사람의 확인 카드를 거친다.

**하지 않을 것**
- 도구 로그인(OAuth) — 3부.
- 프로젝트 러너 에이전트에 MCP 붙이기(봇만 — 조율자 판정 T12).
- 러너 머신의 로컬 설정(천장 — 루트·프로그램·권한 상한·`remoteUpdate`·이 문서의 `appMcp`)을 앱이나 도구로 바꾸기.
- 봇 폴더에 `.mcp.json` 파일을 쓰기(설정은 런마다 메모리로만 넘긴다).
- 사람 저장소·`~/.claude` 의 MCP 설정 끌어오기(`settingSources: []`·`strictMcpConfig` 는 그대로).

**실패로 볼 것**
- 앱의 admin 이나 러너 주인 계정이, 러너 로컬 설정이 허락하지 않았는데 사람 머신에서 명령을 실행하게 되는 것(stdio MCP 는 승인 카드 없이 세션이 열릴 때 바로 실행된다 — 지금 Bash 는 권한 모드·승인 카드를 거친다. 그 천장을 비켜 가는 길이 생기면 안 된다).
- 러너가 막은 서버가 소리 없이 빠지는 것(앱에 「이 러너가 막음 — 사유」가 보여야 한다).
- MCP 헤더·env 의 비밀값이 웹·REST 응답·로그·감사 기록·run.start 로그에 원문으로 나가는 것.
- 「이 러너 설정 제어」로 다른 러너나 워크스페이스 전체 설정을 바꾸는 것.

## 3. 결정

| # | 결정 | 출처 |
| --- | --- | --- |
| T1 | MCP 설정은 **앱에서** 봇마다 적는다. 꼴은 Claude Code `.mcp.json` 의 `mcpServers` 값과 같다 — 서버 이름 → `{ type: "http" \| "sse", url, headers? }` 또는 `{ type?: "stdio", command, args?, env? }`. 편집기는 JSON 붙여넣기(`.mcp.json` 을 통째로 붙여도 `mcpServers` 를 꺼낸다) | 사용자 |
| T2 | 러너 로컬 설정 `appMcp: "off" \| "http" \| "all"`(기본 `"http"`). `"http"` 는 http·sse 만 받고 stdio 는 막는다. `"all"` 이면 stdio 도 받되, `appMcpCommands`(선택, 실행 파일 이름 목록 — 예 `["npx", "uvx"]`)가 있으면 `command` 의 basename 이 그 안에 있을 때만. `"off"` 는 앱의 MCP 를 모두 막는다 | 사용자(조율자 제안 승인) |
| T3 | 막힌 서버는 런에서 빼고, 러너가 hello 에 `appMcp` 천장(종류·명령 목록)을 싣는다(자리는 strict 가 아닌 `programs[].ceiling` 안 — `RunnerHello` 최상위는 `z.strictObject` 라 키를 더하면 옛 서버가 새 러너를 거절한다. 빌더 확인) — 서버·웹은 그것으로 봇 상세에 서버마다 「쓸 수 있음 / 이 러너가 막음(stdio 를 받지 않음 · 명령 npx 가 허용 목록에 없음 · 앱 MCP 꺼짐)」을 보인다. 런 때 러너도 같은 판정을 다시 한다(서버를 믿지 않는다) | 사용자 |
| T4 | 비밀값: `headers` 와 `env` 의 **값**은 쓰기 전용이다. REST 읽기는 키 이름과 `"••••"` 만 돌려주고, 편집 때 값을 안 바꾸면 그 자리 표시를 그대로 보내 원래 값을 지킨다. DB 에는 평문으로 둔다(서버에 비밀 암호화 층이 아직 없다 — 브리지 토큰은 해시지만 MCP 값은 러너로 원문을 보내야 한다). 백업에 들어간다는 것을 `docs/guides/docker-deploy.md` 백업 절에 적는다. 로그 가림(`logger.ts`)·run.start 로그에서 빠지게 한다 | 사용자(토큰을 서버에 둔다는 것), 저장 꼴은 조율자 |
| T5 | 런 정의: `RunnerRunAgent.bot` 에 `mcpServers?: Record<string, McpServer>` 를 더한다(봇에만). 서버는 러너 능력 `botMcp` 가 있을 때만 싣고, 없는 러너에 MCP 가 있는 봇 런이 가면 「러너를 업데이트하세요(봇 도구는 0.10.0 부터)」 run_error. 봇에 MCP 가 없으면 옛 러너에도 그대로 간다 | 조율자 |
| T6 | 러너는 받은 서버를 SDK `mcpServers` 에 `dodok` 과 나란히 넣는다. 이름 `dodok` 은 거절(앱 검증 + 러너 판정). 그 서버들의 도구는 T15 의 자동 허용 목록에 든 것만 allowedTools 에 넣고, 나머지는 권한 모드·승인 카드(PreToolUse `preToolDecision`)를 지난다. 지금 `allowedToolsCeiling` 은 에이전트 `allowedTools` 목록만 보므로(`ceiling.ts`) 외부 MCP 도구를 런타임에 묶지 않는다 — T15 가 그 목록을 천장에 견준다 | 조율자(빌더 확인으로 고침) |
| T7 | 「이 러너 설정 제어」: 봇 정의에 `builtinTools: ("runnerControl")[]` 를 둔다(기본 빈 목록). 켠 봇의 런에만 러너 제어 도구가 `dodok` MCP 에 더 실린다(능력 `runnerControl`). 능력이 없는 러너에서는 웹의 켜기를 사유와 함께 잠그고, 이미 켠 봇의 런은 도구만 빼고 돈다(런을 막지 않는다 — 대화는 되게). `RunnerRunAgent.bot` 에 `builtinTools` 를 싣는다 | 사용자, 없는 능력의 처리는 조율자 |
| T8 | 러너 제어 도구의 범위는 **앱에 있는 그 봇의 러너** 하나: 프로젝트 목록·추가·고치기·보관·워크트리 추가, 그 러너의 러너 에이전트·봇 목록·만들기, 세션 시작값(에이전트의 `sessionDefaults`) 바꾸기, 러너 상태·판 보기, 원격 업데이트 실행(T16). 대상 러너는 도구 인자로 받지 않고 서버가 런의 연결(러너 토큰)에서 정한다. 권한을 올리는 것은 빼고(T14) | 사용자 |
| T9 | 권한은 지금 제어 도구 규칙 그대로 — 주체는 그 런을 시킨 사람(`principalForRunner`), 역할 요구는 같은 REST 경로의 정책 함수(러너 주인·admin), 쓰기는 확인 카드, 자동화로 시작한 사슬(`requested_by` null)은 읽기만. 도구 정의는 shared 에 `RUNNER_CONTROL_TOOLS` 로 두고 입력은 같은 REST 본문 스키마를 재사용한다(`CONTROL_TOOLS` 와 같은 방식) | 조율자 |
| T10 | 러너 제어 도구는 러너 머신의 로컬 설정을 바꾸지 못한다 — 도구 설명에 그 사실을 적어, 「루트를 더해 줘」 같은 요청에 봇이 「러너 머신의 config.json 에서 사람이 고쳐야 한다」고 답하게 한다 | 사용자 |
| T11 | 봇 정의 리비전(1부 B10)에 MCP 설정·내장 도구 변경도 건다 — 바뀌면 그 봇의 세션이 새로 열린다(도구 목록은 세션 중에 바뀌지 않는다) | 조율자 |
| T12 | 2부의 MCP 는 봇만. 프로젝트 러너 에이전트는 지금처럼 `dodok` 하나 | 조율자 |
| T14 | **도구로 권한을 올리지 못한다.** 러너 제어 도구로 봇·러너 에이전트를 만들거나 고칠 때 MCP 설정(`mcpServers`)·자동 허용(T15)·내장 도구(`builtinTools`)·권한 모드(`sessionDefaults.permissionMode`)는 입력 스키마에 없다 — 그 넷은 사람이 웹에서만. 그래서 REST 본문 스키마를 그대로 쓰지 않고 그 필드를 뺀 `pick`/`omit` 로 만든다(T9 의 재사용 규칙의 예외). 자기 자신(부른 봇)은 고치기 대상에서 뺀다 | 사용자 |
| T15 | **서버마다 자동 허용.** MCP 서버마다 「묻지 않음: 없음 / 전부 / 도구 이름 목록」을 앱에서 고른다(기본 없음). 러너는 그것을 `mcp__<서버>__<도구>`(전부면 `mcp__<서버>`)로 allowedTools 에 넣는다. 러너 로컬 `allowedToolsCeiling` 이 있으면 그 목록에 든 이름만 받고 나머지는 「이 러너가 막음 — 도구 상한」으로 보인다(T3 판정 함수에 함께). 자동화로 깬 런(승인할 사람 없음)도 자동 허용한 도구는 쓴다 | 사용자 |
| T16 | **업데이트는 런이 끝나면.** 러너는 런이 하나라도 돌면 업데이트를 거절한다(`self-update.ts` `busy()`). 그래서 러너 제어의 업데이트 도구는 확인 카드 뒤 「예약됨」으로 답하고, 서버가 그 러너에 「업데이트 대기」를 둔다 — 그 러너의 열린 런이 모두 끝나면 서버가 지금 웹 「업데이트」와 같은 요청을 보낸다. 웹 러너 상세에 「업데이트 대기 — 런이 끝나면 올립니다」와 「취소」. 대기는 서버 재시작을 넘어 남고, 러너가 끊겼다 붙으면 그때 판정한다. 웹 단추는 지금처럼 바로(바쁘면 거절) | 사용자 |
| T17 | `"http"` 천장은 주소 글자로 루프백·사설·링크 로컬(`localhost`·`127.0.0.0/8`·`::1`·`10/8`·`172.16/12`·`192.168/16`·`169.254/16`·`fc00::/7`)을 막는다 — 앱 권한자가 러너 머신의 로컬 서비스를 부르지 않게. 이름 풀이 뒤 주소(DNS 리바인딩)까지는 막지 못한다 — 문서에 적는다. `"all"` 은 그것도 받는다 | 조율자(빌더 확인) |
| T18 | `"all"` 은 **앱의 러너 주인·admin 을 그 머신에서 코드를 돌려도 되는 사람으로 믿는다**는 뜻이다 — `appMcpCommands` 는 실행 파일만 좁히고 `args`(`npx -y 아무패키지`)·`env` 로 임의 코드가 돈다. 러너 README·설정 설명에 그대로 적는다. 그래도 `env` 의 `NODE_OPTIONS`·`LD_PRELOAD`·`DYLD_*`·`PATH` 키는 거절한다(명령 목록을 비켜 가는 쉬운 길만 막는다) | 조율자(빌더 확인) |
| T13 | 판 — 러너 0.10.0(능력 `botMcp`·`runnerControl`). 배포는 `docs/guides/runner-release.md` 를 따른다 | 조율자 |

## 4. 방법

| 길 | 장단 | 판정 |
| --- | --- | --- |
| **A 앱에서 편집, 러너 로컬이 종류별로 허용(채택)** | 사람이 앱에서 다 한다. 비밀값이 서버 DB 에 있다. stdio 는 러너 로컬이 켤 때만 | 사용자 채택 |
| B 러너 로컬 설정에 서버 목록, 앱은 이름만 고르기 | 명령·토큰이 머신 밖으로 안 나간다. 서버를 더할 때마다 머신에서 config.json 을 고친다 | 사용자가 앱 편집을 원함 |
| C 봇 폴더의 `.mcp.json` 을 사람이 손으로 | 앱에서 안 보인다 | 뺌 |
| 앱에서 명령까지 무조건 받기 | 앱 권한자가 머신에서 아무 명령이나 실행 | 뺌(실패로 볼 것 1) |

## 5. 남은 것(빌더 몫)

- shared: `McpServerConfig` Zod(종류별 strict, 서버 이름 꼴·개수 상한·URL 은 http(s)), 판정 함수 `appMcpVerdict(ceiling, server)` — 서버(표시)와 러너(런)가 같은 함수를 쓴다.
- 서버: 저장 자리(`agents.runner_bot` JSON 에 넣을지 별도 칸인지), 비밀값 가림·보존 병합, 능력 판정, 정의 리비전.
- 러너 제어 처리기: 기존 REST 처리 함수를 재사용하고, 대상이 런의 러너인지 확인(다른 러너의 프로젝트 id 를 넘기면 NOT_FOUND). 업데이트 대기(T16)의 저장 자리와 「런이 모두 끝남」을 잡는 자리.
- 웹: 봇 상세·만들기의 「도구」 칸(JSON 편집 + 서버마다 허용 표시·자동 허용 고르기 + 비밀값 가림), 「이 러너 설정 제어」 켜기, 러너 상세의 「업데이트 대기」·「취소」.
- 러너: 설정 스키마 `appMcp`·`appMcpCommands`, hello 천장·능력, 런 조립, 막은 서버의 로그 한 줄(비밀값 없이).
- dev:fake: 가짜 러너 둘의 `appMcp`(dev-fake 는 `"http"`, 제한은 `"off"`) — 허용 표시를 손으로 볼 수 있게.
- 시험·런 0회 하네스(가짜 HTTP MCP 하나를 붙여 도구 목록에 뜨는지)·문서(`user-guide.md`·`agent-guide.md`·`plan.md` 8장·`live-smoke.md`·`docker-deploy.md` 백업 절·러너 README 의 설정 예).
