# 첨부 저장소 S3 연동 — 설계

상태: 승인(2026-11-23) · 결정: 사용자와의 대화(2026-11-23)

## 1. 왜

첨부 블롭은 지금 서버 디스크(`ATTACHMENTS_DIR`, 기본 `/data/attachments`)에 DB 와 같은 볼륨으로 쌓인다. 디스크가 차면 SQLite 까지 위험하고(그래서 256 MiB 미만이면 업로드 507), 백업에 첨부가 들어가지 않으며, 서버를 옮기려면 볼륨째 옮겨야 한다. 사용자는 첨부를 S3(호환) 저장소에 두는 기능을 원한다.

## 2. 목표 · 하지 않을 것

**목표**
- 첨부 블롭을 S3 호환 저장소(AWS S3·MinIO·R2 등)에 저장하는 모드를 더한다. 모드는 env 로 고른다.
- 업로드·내려받기·정리·권한·주소(웹 `/api/v1/attachments/:id`, 플러그인 `/bridge/attachments`, 러너 `/runner/attachments`)는 그대로.

**하지 않을 것**
- 기존 볼륨 블롭 이관(사용자 — 새 앱으로 올린다).
- 서명 URL로 S3 직접 내려받기(권한 경계가 달라진다 — 다음에).
- 서버 여러 대(sha 잠금은 한 프로세스 그대로).

**실패로 볼 것**
- 잘못된 S3 설정으로 서버는 뜨는데 업로드만 조용히 실패하는 것.
- S3 모드에서 정리가 매번 버킷 전체를 훑는 것(비용·지연).
- 정리가 올리는 중인 객체를 지우는 것.
- S3 키·시크릿이 로그·오류 응답에 나가는 것.

## 3. 결정

| # | 결정 | 출처 |
| --- | --- | --- |
| S1 | `ATTACHMENTS_STORAGE=local|s3`, 기본 `local`(개발·시험·`dev:fake` 는 그대로) | 조율자, 사용자 승인 |
| S2 | S3 env: `S3_ENDPOINT`(선택 — 없으면 AWS 기본), `S3_REGION`, `S3_BUCKET`, `S3_PREFIX`(선택, 기본 빈 값), `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE`(`true`/`false`, 기본 false). `s3` 모드에서 필수 값이 없으면 부팅 실패. 키는 `.env` 에만 | 조율자, 사용자 승인 |
| S3 | 부팅 때 `HeadBucket` 으로 접근 확인 — 실패면 부팅 실패(사유에 키·시크릿 없음) | 조율자, 사용자 승인 |
| S4 | 키 `<S3_PREFIX><sha 앞 2자>/<sha>`, 같은 바이트는 한 번만(`HeadObject` 로 있으면 건너뜀) | 조율자, 사용자 승인 |
| S5 | 내려받기는 서버가 권한 확인 뒤 `GetObject` 를 그대로 흘린다. 객체 크기가 저장값과 다르면 지금처럼 500, 없으면 404 | 조율자, 사용자 승인 |
| S6 | 정리: 오래된 미묶음 행을 지우며 돌려받은 sha 는 그 자리에서 (행이 0 이면) 지운다. 그 밖의 고아(채널 cascade·쓰기 뒤 행 넣기 전 죽음)는 S3 모드에서 **하루 한 번** 버킷 목록을 훑어, 행이 없고 `LastModified` 가 1시간 넘은 객체만 지운다(올리는 중인 것 보호). 로컬 모드 정리는 지금 그대로 | 조율자, 사용자 승인 |
| S7 | 의존성 `@aws-sdk/client-s3` 를 서버 dependencies 에 정확 핀. 서버 번들(`build`·`bundle:smoke`)이 통과해야 한다 | 조율자 |
| S8 | 디스크 여유 검사(507)는 그대로 — DB 가 여전히 디스크를 쓴다 | 조율자, 사용자 승인 |

## 4. 방법

저장소 계층 하나(`BlobStore`)를 두고 로컬·S3 두 구현을 같은 시험 묶음으로 검증한다. 다른 길(S3 SDK 호출을 서비스 곳곳에 넣기)은 모드가 둘이라 분기가 퍼져 버린다.

## 5. 남은 것(빌더 몫)

- `BlobStore` 의 정확한 모양, 하루 한 번 훑기의 시각 관리(마지막 훑은 시각을 메모리에 두면 재시작마다 한 번 도는 것은 받아들인다).
- 시험: 가짜 S3(메모리 `BlobStore` 또는 SDK 클라이언트 흉내), 임시 MinIO 컨테이너로 한 번(이름을 정해 만들고 그것만 지운다 — `docker … prune` 금지).
- 문서: `docs/guides/docker-deploy.md`(S3 설정·버킷 버전 관리를 켜면 첨부 보존·「S3 모드의 백업」), `.env` 예시, `docs/guides/plan.md` 8장.
