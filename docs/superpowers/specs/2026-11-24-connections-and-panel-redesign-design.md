# 설정 › 연결 탭과 채널 오른쪽 패널 재설계 — 설계

날짜: 2026-11-24 · 상태: 초안

## 왜

사용자 요청: 「설정 › 연결」과 「채널 화면 오른쪽 패널」의 UI 를 전반적으로 다시 설계한다. 방향은 맡겼고, 전후 시안을 먼저 보고 이 방향을 승인했다(시안: https://claude.ai/artifact/7gJsBvbHjuvNACCyy6vWex — 윗줄이 지금 화면 캡처, 아랫줄이 바꾼 뒤). 덧붙인 조건: 러너는 지금 Claude Code 만 붙지만 **Codex·OpenCode 같은 다른 프로그램이 들어올 것을 화면 구조가 미리 받아야 한다.**

지금 화면에서 짚은 문제(dev:fake 캡처 기준):

- 연결 트리: 모든 줄에 파란 「연결됨」 알약 — 강조색(코발트)이 상태 표시에 쓰여 「선택됨」과 겹친다. Gateway·러너가 한 목록에 섞이고, 에이전트 점 색(에이전트 색)이 상태 점처럼 읽힌다.
- 상세: 정보가 문장으로 이어지고(「접속됨 · 플러그인 0.0.0-fake · SDK …」) 주요 버튼(파랑)이 한 화면에 여럿 겨룬다(새 토큰 발급·에이전트 가져오기·프로젝트 추가). 프로젝트 줄 하나에 버튼 다섯. 에이전트 상세는 켜기 스위치에 이름표가 없고 모든 것이 카드 하나에 섞였다.
- 러너 상세의 프로그램은 「Claude Code …」「Codex — 쓸 수 없음 · 설치되지 않음」 두 줄 글이다 — 프로그램이 늘면 읽기 어렵다.
- 오른쪽 패널: 제목(「채널 설정」)과 탭 줄이 두 줄로 같은 것을 말한다. 설정 탭은 섹션마다 「저장」 버튼(넷). 활동 탭은 런이 한 줄 머리 + 밑줄 링크(「인자 보기」·「결과 보기」)뿐이다.

## 목표

1. **연결 트리**: Gateway·러너를 묶음 머리(「GATEWAY 2」·「러너 2」)로 가르고, 줄 앞 아이콘으로 종류를 보인다. 상태는 초록·주황·회색 점 + 작은 글(강조색을 쓰지 않는다). 에이전트는 에이전트 색 테두리의 이니셜 아바타. 러너 에이전트 줄 끝에 프로그램 배지(아래 「프로그램 표시」). 머리에 「연결·에이전트 찾기」 검색칸(이름·핸들로 거른다). 접힌 연결은 「에이전트 N」·「프로젝트 N」 요약을 줄 끝에.
2. **상세 머리**: 종류 아이콘 · 이름 · 상태 칩 한 줄, 아래 핵심 값 줄(판·주인·주소·루트). 오른쪽에 자주 쓰는 동작 하나(Gateway 「이름·주소 수정」, 러너 「러너 업데이트」)와 「⋯」 메뉴(끄기·삭제·설치 안내 등 드문 것·위험한 것).
3. **상세 몸통 = 카드**: 카드 머리 = 제목 + 개수 + 그 카드의 동작(고스트 버튼). 한 화면의 주요(파랑) 버튼은 없거나 하나.
   - Gateway: 상태(Gateway·플러그인 두 칸 — 경고는 카드 안 노란 안내 띠, 「다시 설치」는 그 안내의 링크) · 에이전트(행 → 그 에이전트 상세) · 브리지 토큰(브리지 주소 복사 + 토큰 행).
   - 러너: 에이전트 프로그램(아래) · 프로젝트(행마다 「워크트리 만들기」 + 「⋯」 — 확인·이름 바꾸기·옮기기·보관) · 봇 · (있을 때만) 프로젝트 밖 에이전트 · 러너 토큰. 지금 러너 상세에 있는 섹션은 하나도 없애지 않는다 — 꼴만 카드로.
   - 에이전트: 머리에 큰 아바타, 칩 줄(프로그램 또는 OpenClaw · 러너/Gateway 링크 · 프로젝트 링크), 오른쪽 「DM 보내기」와 이름표 있는 「켜짐」 스위치. 카드: 실행(러너 에이전트만 — 프로그램(읽기 전용)·새 세션 시작값·지시. 봇이면 지시 자리에 지금의 봇 정의·도구 칸) · 프로필(사진. OpenClaw 에이전트는 여기에 「메모 — 에이전트에게 전달되지 않음」 — 같은 `basePrompt` 칸을 OpenClaw 에서는 일부러 메모라 부른다, `AgentRow.tsx` `promptCopy`) · DM 허용(세그먼트 — 끔 / admin 이상 / 모두) · 관리(옮기기·삭제, 붉은 테두리).
4. **프로그램 표시 — 여러 프로그램 대비**: 러너 상세의 「에이전트 프로그램」 카드가 hello 의 `programs`(`RunnerProgramStatus[]`)를 **한 줄씩** 그린다. 줄 = 프로그램 배지 · 이름 · 판·로그인·권한 상한 요약 · 상태 칩(「쓸 수 있음」 초록 / 「설치 안 됨」 회색 + 설치 방법 / 「로그인 필요」 주황 — `auth: "missing"`). 러너가 드라이버 없음 사유(`RUNNER_NO_DRIVER_REASON`)로 알린 프로그램과 `RunnerProgram` enum 에 있는데 러너가 알리지 않은 프로그램은 「지원 예정」 회색 줄(앞의 것은 그 사유 글, 뒤의 것은 「이 러너 판은 아직 모름」 — 아래 「정한 것」). **끊긴 러너**는 `programs` 가 빈 목록으로 오므로 이 규칙을 쓰지 않고 카드 안에 「끊김 — 다시 접속하면 프로그램이 보입니다」 한 줄만 둔다. `auth: "unknown"` 은 상태 칩 없이 판 줄에 「로그인 확인 안 됨」. 프로그램별 이름·배지 글자·색은 웹 한 곳의 표(`RUNNER_PROGRAM_NAME` 옆)에서 — 새 프로그램은 그 표에 한 줄 더하면 트리 배지·러너 카드·에이전트 칩·활동 카드가 함께 따라온다. 배지는 글자 둘(CC·CX·OC) + 옅은 바탕, 상표 로고를 쓰지 않는다.
5. **오른쪽 패널 머리**: 제목 줄을 없애고 탭 한 줄(세그먼트 꼴, 아이콘 + 글) + 닫기. 패널 제목은 스크린 리더용으로 남긴다(지금 `titleId` 의 역할). 활동 탭에 승인 대기 수 배지(있을 때만).
6. **설정 탭**: 섹션 머리를 작은 회색 대문자 꼴로, 섹션 사이는 선. 저장 버튼이 있던 세 섹션(기본·채널 프롬프트·릴레이 정책)의 「저장」을 없애고 **패널 아래 저장 막대 하나** — 바뀐 칸이 있을 때만 나타나 「바뀐 항목 N개 · 되돌리기 · 저장」. **고르는 즉시 저장되던 것은 그대로 즉시**(세션 정책, 자동 응답, 세션 관리자 지정, 멤버 넣기·빼기, 멤버 칸의 에이전트별 채널 프롬프트 오버라이드 — 그 행의 편집기와 저장은 지금 그대로) — 저장 막대가 즉시 반영을 「저장해야 반영」으로 바꾸지 않는다. 바뀐 것이 남은 채 다른 탭·다른 채널로 가거나 패널을 닫으면 확인 대화상자(「저장하지 않은 변경 N개 — 저장 / 버리기 / 취소」, 라우터 차단). 바뀐 칸은 강조 테두리. 턴 상한은 −/+ 스텝퍼, 세션 권한은 세그먼트, 「모든 에이전트끼리 허용」은 설명 있는 스위치 줄, 채널 보관은 맨 아래 접힌 줄. 멤버 칸(통합 초대 — 이미 병합됨)은 꼴만 맞춘다.
7. **활동 탭**: 런마다 카드 — 머리(에이전트 아바타 · 이름 · 프로그램 배지 · 상태 칩 · 걸린 시간 · 진행 중이면 중지). 몸통은 세로 선으로 이은 타임라인(생각 · 도구 · 승인). 도구 줄 = 상태 원 + 도구 이름 + 인자 한 줄 요약(고정폭), 누르면 인자·결과 펼침(밑줄 링크 대신). 승인 대기 줄 안에 승인 카드. 끝난 런은 접힌 채 「생각 1 · 도구 1(Read) · 답 1」 요약 한 줄. 위에 거르기 칩(전체 / 진행 중 / 승인 대기 / 실패, 수 포함).

## 비목표

- 서버·wire·shared 계약 변경 없음. 화면에 필요한 값은 이미 웹에 온다: 러너 `programs`(available·version·auth·login·cli·reason·ceiling), 에이전트 `program`, 새 세션 시작값, 지시(`basePrompt`).
- 에이전트의 프로그램을 만든 뒤 바꾸기 — API 가 없다. 상세에서는 읽기 전용.
- 새 프로그램 드라이버(Codex·OpenCode) 자체.
- 설정 › 연결 밖의 설정 탭들, 왼쪽 사이드바, 작성기, 응답 안의 활동(별도 작업 `inline-activity`).
- 다크 모드 새 색 — 기존 토큰(`apps/web/src/theme/tokens.css`)의 `--success`·`--warning`·`--muted` 를 쓴다. 상태 칩 바탕이 토큰에 없으면 `color-mix` 로 그 토큰에서 만든다(새 하드코딩 색 금지).

## 반목표(이러면 실패)

- 패널 재설계가 패널의 기존 보장을 깬다: 탭을 옮겨도 머리 링크가 언마운트되지 않음(초점이 `<body>` 로 떨어지지 않음, 브라우저 검증 D3), 넓은 화면 ↔ 좁은 화면 시트 전환에서 고치던 초안이 사라지지 않음(같은 `host` 로 포털), 닫을 때 여는 자리로 초점 복귀(D14), DM 종류별 탭 목록(`only`).
- 저장 막대로 합치면서 한 섹션만 실패했을 때 무엇이 저장됐는지 모르게 된다.
- 상태가 색으로만 전달된다(점마다 글이 함께, 칩은 글자).
- 연결 탭의 기존 초점 이동(보관·삭제 뒤 트리의 자리로)과 라이브 알림이 사라진다.

## 제약

- 지금 구조 위에서 고친다: `apps/web/src/features/connections/*`(트리·상세 넷·새 연결), `apps/web/src/features/agents/AgentRow.tsx`(상세가 쓰는 칸들), `apps/web/src/app/layout/PanelTabs.tsx`(패널 틀), `apps/web/src/features/settings/*`(설정 탭 섹션), `apps/web/src/features/activity/*`(활동 탭).
- shadcn `@/ui/*` 컴포넌트(버튼·스위치·드롭다운 메뉴·시트)를 쓴다. 「⋯」 메뉴는 드롭다운 메뉴, 확인이 필요한 동작(삭제·폐기)은 지금의 확인 대화상자를 그대로 연다.
- 좁은 화면: 연결 탭은 지금처럼 한 칸씩(트리 → 상세), 패널은 전체 화면 시트. 카드 2열 격자는 좁으면 1열.
- 접근성: 아이콘만 있는 버튼은 `aria-label`, 세그먼트는 `role="group"` + `aria-pressed`, 스위치는 보이는 이름표, 접근 이름은 기존 시험이 찾는 이름을 되도록 지킨다(바꾸면 그 시험을 함께 고친다).
- 기존 시험을 지운 동작으로 통과시키지 않는다 — 고친 꼴에 맞게 단언을 옮긴다.

## 접근

검토한 셋:

- **A. 겉모양만**(색·여백·카드) — 작업은 가장 작지만 사용자가 짚은 「여러 프로그램」과 「저장 버튼 넷」·「버튼 다섯」이 그대로 남는다. 버렸다.
- **B. 구조까지 손보는 재설계(고름)** — 위 목표 1~7. 기존 데이터·라우트·틀(`PanelTabs` 포털, `ConnectionsLayout`)은 유지하고 그 안의 컴포넌트를 다시 짠다. 서버 무변경.
- **C. 연결 탭을 한 화면 대시보드로 합치기**(트리 없이 카드 격자) — 연결·에이전트가 늘면 오히려 길을 잃고, 지금 주소 구조(`/settings/connection/<종류>/<id>`)를 다 바꿔야 한다. 버렸다.

사용자가 시안을 보고 B 를 승인했다(「좋아, 이 방향으로 진행해」).

## 일의 나눔(워크트리 셋)

1. **connections** — 목표 1~4. 지금 시작.
2. **panel-settings** — 목표 5·6. 지금 시작(`PanelTabs`·`features/settings/*`).
3. **panel-activity** — 목표 7. **`inline-activity` 워커가 병합된 뒤 시작**(그 작업이 `activity/RunTimeline.tsx`·`timeline.ts`·`useRunActivity.ts` 를 고치는 중이다). 응답 안의 활동과 같은 도구 줄 컴포넌트를 쓰면 둘이 같은 꼴이 된다 — 빌더가 그 병합 뒤의 컴포넌트를 보고 정한다.

2와 3은 패널 머리의 「활동」 배지만 닿는다 — 2가 배지 자리를 만들고(수를 받는 prop), 3이 수를 채운다.

## 정한 것(사용자)

- 방향 B 와 시안 전체. 동작이 바뀌는 넷도 함께 승인했다 — 저장 막대 하나, 에이전트 상세의 「실행」 카드, 프로그램 표시, 활동 거르기.

## 정한 것(내 판단 — 고쳐도 된다)

- 「실행」 카드의 프로그램은 고르는 칸이 아니라 읽기 전용 — 만든 뒤 바꾸는 API 가 없다(시안의 셀렉트는 이 판단으로 바꾼다). 새 세션 시작값은 지금의 `RunnerSessionDefaults` 를 이 카드로 옮긴다.
- 「지원 예정」 줄의 글: 러너 hello 에 없는 프로그램은 「이 러너 판은 아직 모름」(러너 판이 오래돼서일 수도 있다), 드라이버 없음 사유로 온 프로그램은 그 사유만(러너는 그 프로그램을 안다 — 바로 아래 줄).
- 상태 색: 연결됨 = success, 끊김·승인 대기 = warning, 꺼짐·보관 = muted. 강조색은 선택·링크·주요 버튼·포커스에만.
- 저장 막대: 「저장」은 바뀐 섹션의 기존 변경 요청을 차례로 보낸다(서버 무변경). 하나가 실패하면 그 섹션 칸 옆에 오류를 두고, 성공한 섹션은 저장된 상태로, 막대는 남은 바뀐 항목 수를 보인다. 권한이 없는 사람(member 가 admin 칸)에게는 지금처럼 읽기 전용.
- 패널 폭 360 → 384px.
- 활동 탭의 승인 카드는 지금처럼 **패널 맨 위에 고정**한다(목표 7 의 「승인 대기 줄 안에 승인 카드」를 바꾼다, 2026-11-24 `inline-activity` 병합 뒤 코드를 보고 정함). 옛 런 카드를 펼쳐 보는 동안에도 답해야 할 카드가 보여야 하고(기존 설계 5.3), 메시지 흐름의 카드와 같은 스토어다. 런 카드의 승인 줄은 「승인 대기 — 위 카드에서 답하세요」 표시만.
- 「지원 예정」 판정(connections 리뷰 Important, 2026-11-24): 실제 러너는 드라이버가 없는 프로그램도 hello 에 `available: false` + 사유 「이 러너 판본에는 이 프로그램의 드라이버가 없습니다」(`packages/claude-runner/src/connection.ts` `NO_DRIVER_REASON`)로 싣는다. 이 사유 문자열을 shared 상수로 옮겨 러너와 웹이 같은 값을 쓰고, 웹은 그 사유이거나 hello 에 없는 프로그램을 「지원 예정」으로 그린다. 비목표 「shared 무변경」의 예외 — 상수 하나를 옮길 뿐 wire 모양은 그대로다.
- 활동 거르기: 진행 중 = 끝나지 않은 모든 상태(`queued`·`streaming`·`tool`·`awaiting_approval`·`finalizing`), 승인 대기 = `awaiting_approval`, 실패 = `error`(사람이 멈춘 `aborted` 는 실패가 아니다 — 전체에만).
- 저장 막대 범위와 떠날 때의 확인(목표 6) — 검토자 질문에서 정했다. 초안을 탭 사이에 남기려면 상태를 라우트 밖으로 올려야 해 구조가 커지므로, 남기지 않고 떠나기 전에 묻는다.
