# 스레드 칩 — 참여자 아바타 그룹과 작업 중 표시 (짧은 설계)

## 의도

메시지 아래 「답글 N개」 칩(`apps/web/src/features/threads/ThreadChip.tsx`)이 작아 눈에 덜 띄고, 스레드에 누가 있는지(사람 포함)와 지금 그 스레드에서 에이전트가 일하는 중인지 채널 화면에서 알 수 없다. 칩을 키우고, 채널 헤더의 「참여 에이전트」처럼 아바타 그룹으로 참여자를 보이고, 진행 중인 런이 있으면 함께 보인다.

## 목표

- 칩을 키운다 — 평소에도 보이는 버튼 꼴(테두리 `border-border`·옅은 배경 `bg-muted/40`·`rounded-lg`·`px-2.5 py-1.5`, 호버는 배경 한 단계 진하게 `bg-muted`), 아바타 28px(`size-7`, `+N` 도 같은 크기), 글자 `text-sm`·「답글 N개」 `font-semibold`. 좁은 화면(390px)에서는 문구가 잘린다(`truncate`). 진행 중 에이전트는 참여자 순서와 상관없이 맨 앞 — 보이는 4개 안에 늘 든다.
- 참여자 = 루트 작성자 + 답글 작성자(사람·에이전트). 최근에 쓴 순으로 4명까지, 나머지는 `+N`(`AvatarGroup`·`AvatarGroupCount`, 채널 헤더와 같은 모양).
- 그 스레드에 진행 중인 런(끝나지 않은 상태 — 대기·응답·도구·승인 대기·마무리)이 있는 에이전트는 아바타에 링(움직임 줄이기 설정이면 정지)을 두르고, 칩 옆에 「@핸들 응답 중…」처럼 상태 문구(`runStatusLabel`). 둘 이상이면 「@dev 외 1 …」.
- 답글이 아직 없어도(요약 없음) 그 스레드의 진행 중 런이 있으면 칩을 보인다.

## 비목표

- 사람의 스레드 안 「작성 중」 — typing 페이로드에 스레드가 없다(wire 변경). 이번에는 하지 않는다.
- 에이전트 typing 신호 — 플러그인이 내지 않는다. 작업 중 표시는 런 상태로만.

## 접근

1. (고른 것) 서버 `ThreadSummary` 에 `userIds`(사람 작성자, 최근 순, 최대 10 — 루트 작성자 포함)를 더하고, 작업 중은 웹 런 저장소(`threadRootId` 를 이미 안다)에서 계산. 서버 변경이 요약 한 칸뿐이고 실시간 상태는 이미 있는 저장소를 쓴다.
2. 웹이 스레드 타임라인을 받아 참여자를 센다 — 열어 본 적 없는 스레드는 캐시가 없어 칩마다 요청이 생긴다. 버린다.
3. 서버가 작업 중 에이전트도 요약에 싣는다 — 런 상태가 바뀔 때마다 요약을 다시 보내야 하고 웹이 이미 아는 것을 겹친다. 버린다.

## 정한 것

- `packages/shared` `ThreadSummary.participants?: { kind: "user" | "agent"; id }[]`(최대 10) — 사람·에이전트를 한 목록에 섞어야 순서가 서므로 `userIds` 대신 이 꼴로 정했다(계획 단계의 결정). `agentIds` 는 그대로 두고, 옛 서버면 웹이 `agentIds` 로 대신 그린다.
- 참여자 순서: 작성 시각 최근 순, 사람·에이전트를 섞어서. 루트 작성자는 답글을 안 썼으면 맨 뒤.
- 진행 중 런 에이전트는 맨 앞으로 올린다 — 참여자 목록에 없으면(아직 답글 전) 더하고, 이미 있어도 자리를 옮긴다(진행 중끼리는 런 순).
- 접근성: 그룹 `role="group" aria-label="스레드 참여자"`, 작업 중 문구는 `aria-live` 를 두지 않는다(채널 목록마다 소리가 나면 시끄럽다) — 문구 자체는 칩 링크 이름에 들어간다.

## 빌더에게 남긴 것

- 링·문구의 정확한 스타일, 좁은 화면에서 문구 줄임.
- 서버 시험(`summarizeThreads`)·웹 시험(`ThreadChip`) 추가, `docs/manual/user-guide.md` 스레드 절 한 줄 갱신.
