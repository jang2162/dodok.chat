# 스레드 글을 채널에도 보이기 — 설계

날짜: 2026-11-25 · 상태: 검토 대기

## 왜

사용자 요청(2026-11-25): 「스레드에서 에이전트 다중 호출 한 경우 호출한 메시지를 스레드 밖에서 표시하고(Slack 화면 참고) 그 메시지 아래로 다중 호출 UI 표시」. 참고 화면은 Slack 의 「스레드에 댓글 남김: …」 줄 — 스레드 답글이 채널 타임라인에도 한 번 더 보이는 꼴이다.

지금은 스레드 안에서 에이전트를 여럿 불러도 채널에는 루트 아래 「답글 N개」 칩만 남는다. 채널만 보는 사람은 지금 누가 무슨 일을 하는지 모른다. 시안: UI 개선 시안 05 절(아티팩트 `https://claude.ai/artifact/V58LQN2ti5dD46iN2mHDtr`).

## 목표

- 스레드 답글 하나를 **채널 타임라인에도** 보인다(이하 「채널에도 보낸 답글」). 채널에서는 그 글 위에 「스레드에 댓글 남김: <루트 발췌>」 줄이 붙고, 누르면 그 스레드가 열린다.
- 그 글이 서로 다른 에이전트 2명 이상의 런을 일으켰으면, 채널의 그 글 아래에 **답 묶음**(`2026-11-24-multi-agent-reply-bundle-design.md`)과 같은 줄 목록을 그린다 — 에이전트마다 한 줄, 상태(진행 중·완료·실패).
- 언제 채널에도 보내나: 스레드 작성기의 「채널에도 보내기」 체크. **체크의 기본값은 초안이 서로 다른 에이전트 2명 이상을 멘션할 때 켜짐**, 아니면 꺼짐. 사람은 언제든 바꾼다.

## 비목표

- 에이전트가 쓴 답글을 채널에도 보내는 것. 에이전트 답은 스레드에만 남는다(묶음 줄이 상태와 미리보기를 보인다).
- 에이전트가 받는 문맥(채널 「최근 대화」·스레드 소식)은 바꾸지 않는다. 채널에도 보낸 답글도 에이전트 문맥에서는 지금처럼 스레드 답글이다.
- 이미 보낸 답글을 뒤늦게 채널에 올리거나 내리는 것.
- 검색 결과 모양.

## 접근

1. **(고른 것) A. 답글에 표시 하나 — 서버가 채널 타임라인에 함께 싣는다.** 메시지 행에 `alsoInChannel` 표시. 채널(세션) 타임라인 조회가 「루트 또는 채널에도 보낸 답글」을 낸다. 한 행이라 반응·수정·읽지 않음이 한곳에서 맞고, 새로고침·다른 기기에서도 같다. Slack 과 같은 꼴.
2. B. 웹만 — 런 저장소를 보고 루트 아래 칩 자리에 진행 중 묶음을 그린다. 서버 변경이 없지만 자리가 루트(옛 시각)라 지금 일이 채널 맨 아래에 보이지 않고, 런이 끝나 새로고침하면 사라진다. 요청한 Slack 꼴이 아니다.
3. C. 복사본 메시지 — 채널에 새 메시지를 하나 더 만든다. 반응·수정·읽지 않음이 둘로 갈리고 에이전트 문맥에 같은 글이 두 번 실린다. 버렸다.

방법 고르기는 사용자가 맡겼다(「너가 생각하는 순서대로 진행해줘」) — A 는 이 문서 작성자의 판단이다.

## 정한 것

### 데이터·계약

- DB `messages.also_in_channel`(정수 0/1, 기본 0) 마이그레이션. 사람 답글(`authorType: "user"`, `threadRootId` 있음)에만 1 이 될 수 있다.
- shared `Message` 에 `alsoInChannel: z.literal(true).optional()` — 참일 때만 싣는다. 옛 웹은 버리고 받는다(지금처럼 스레드에만 보인다).
- 보내기 입력(wire `message.send` — 사람 글을 저장하는 길은 이것 하나다, `apps/server/src/realtime/socket.ts` 의 `sendUserMessage` 호출)에 `alsoInChannel?: boolean`. 서버 판정:
  - `true` 이고 스레드 답글이면 1. 스레드 답글이 아니면 무시(오류 아님).
  - `false` 면 0.
  - 없으면(옛 웹) **서버 자동 판정** — 토큰화한 멘션의 서로 다른 에이전트가 2명 이상인 스레드 답글이면 1. (내 판단: 배포 직후 캐시된 옛 웹에서도 요청한 동작이 나오게. 자동화 글은 사람 답글이 아니라 대상이 아니다)
- 채널 kind: 일반 채널과 그룹 DM(`direct` — 스레드가 있는 두 갈래). 에이전트 DM 에는 스레드가 없다.

### 서버 조회

- `listMessages` 에 새 범위 `channel`: `thread_root_id IS NULL OR also_in_channel = 1`. 웹의 세션 타임라인 REST(`apps/server/src/modules/messages/routes.ts`)가 이것을 쓴다. **기존 `roots` 는 그대로 둔다** — 제어 도구 `read_messages`(`control/handlers.ts`)가 기본값 `roots` 로 부르므로, 바꾸면 에이전트가 읽는 채널에 답글이 섞인다(비목표: 에이전트 문맥 불변. 내 판단). `rootSeqAt`(결과로 가기 가운데 잡기)도 `channel` 범위에서는 채널에도 보낸 답글을 그 자리로 친다.
- 재동기화(`lastSeq`)·구독 ack 는 지금처럼 루트·답글을 섞어 보낸다 — 웹이 가른다(아래).
- `withRootRuns`·`canRootRuns`: 채널에도 보낸 사람 답글도 대상(그 글이 `rootMessageId` 인 런을 싣는다). 스레드 안 사람 글로 시작한 런의 `rootMessageId` 는 이미 그 트리거 글이고 릴레이도 이어받는다(`apps/server/src/modules/router/decide.ts` — 빌더 점검에서 확인).
- 읽지 않음: 스레드 전용 읽음 상태는 없다 — 읽음 위치는 대화마다 seq 하나(`conversation_reads.last_read_seq`)이고 채널 굵게는 `thread_root_id IS NULL` 만 센다(`apps/server/src/modules/reads/store.ts`). **굵게 세기를 `thread_root_id IS NULL OR also_in_channel = 1` 로 넓힌다** — 채널에도 보낸 답글은 채널 글처럼 굵게를 켜고, 그 세션을 읽으면(지금처럼 끝까지 보면) 꺼진다. 스레드만 열어 읽는 것으로는 지우지 않는다(스레드 읽음 모델을 새로 만들지 않는다. 내 판단). 멘션 배지는 이미 답글까지 세므로 그대로.
- 실시간: `ChannelActivity`(wire `channel.activity`)에 `alsoInChannel?: true` 를 싣는다 — 웹은 지금 `threadRootId` 가 있으면 굵게에서 빼므로(`apps/web/src/features/reads/useUnread.ts`) 이 표시가 있으면 세게 한다.

### 웹

- `timeline.ts` 의 `isRoot` 를 「루트 또는 `alsoInChannel`」로, 실시간 처리기 `apps/web/src/realtime/handlers.ts` 의 `applyMessage`(지금 `threadRootId` 로 직접 가른다)도 같은 판정으로. 세션 타임라인과 스레드 타임라인 양쪽 캐시에 같은 메시지가 든다 — `message.updated`(반응·수정)는 양쪽을 갱신한다.
- 묶음 런 목록: `MessageList.tsx` 가 `r.threadRootId === undefined` 로 스레드 런을 뺀다 — `rootMessageId` 가 세션 타임라인에 있는 채널에도 보낸 답글이면 넣는다.
- 메시지 행: `alsoInChannel` 이고 세션 타임라인에서 그릴 때만 글 위에 「↳ 스레드에 댓글 남김: **<루트 발췌 40자>**」 링크 줄. 누르면 그 스레드를 연다(마지막으로 쓴 보기 — 패널/메인, UI 시안 06). 이 행에는 스레드 칩·「스레드에서 답하기」를 그리지 않는다. 스레드 안에서는 지금 모양에 작은 「채널에도 보냄」 표시만.
- 묶음: `computeBundles` 의 `canRoot` 를 「사람 최상위 글 또는 사람의 채널에도 보낸 답글」로. 이 경우 답 메시지는 스레드에 있어 세션 타임라인에 없다 — **줄은 런으로 서고**(런 저장소·`rootRuns`), 줄의 미리보기는 그 스레드 캐시에 그 런의 메시지가 있으면 첫 줄, 없으면 상태 문구만. **줄을 누르면 그 자리에서 펼치지 않고 스레드를 열어 그 답으로 간다**(내 판단 — 답은 스레드에 있고, 채널에서 펼치면 같은 답이 두 화면에 생긴다). 묶음 머리 문구는 「@a·@b 답 · 스레드에서 진행」.
- 스레드 작성기: 보내기 단추 옆(또는 위) 「채널에도 보내기」 체크. 기본값은 위 「목표」의 규칙, 초안이 바뀌면 사람이 손대지 않은 동안만 다시 계산. 보낼 때 그 값을 `alsoInChannel` 로 명시해 싣는다.

## 시험

- 서버: 세 판정(true·false·없음+멘션 2명), 비스레드 글의 true 무시, `channel` 조회·around 에 포함, **`roots`(제어 도구 `read_messages`)에는 없음**, `rootRuns` 실림, 굵게 세기에 포함·멘션 배지 이중 계산 없음, `channel.activity` 의 표시.
- 웹: 세션 타임라인에 그려짐·링크 줄·칩 없음, 반응이 양쪽에 반영, 묶음 줄이 런으로 섬·누르면 스레드로, 체크 기본값과 손댄 뒤 고정.
